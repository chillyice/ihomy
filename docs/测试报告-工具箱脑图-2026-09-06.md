## 4. 缺陷清单（按严重级排序，**均未修改代码**）

### BUG-1（P0·致命）脑图编辑器画布完全空白，核心功能不可用

- **现象**：新建/打开任意脑图，编辑器画布区域空白，根节点不可见；切换主题后重绘仍空白。用户无法看到、编辑任何节点。
- **证据**：![编辑器初始状态-画布空白](file:///C:/Users/chill/OneDrive/WorkStation/Projects/ihomy/gui-test-screenshots/t06_editor_initial.png)
- **只读诊断**（DOM+DB，未改动任何状态）：
  - `.mm-canvas` 尺寸 1028×640 正常；SVG 已渲染，根节点文本存在于 SVG；
  - 根节点内容本身画在用户空间 (514,320)≈画布中心，而视口容器 `g.smm-container` 又带 `transform="matrix(1,0,0,1,513,319)"`——**内容被双重偏移到 (1027,639)，恰好整体裁出 1028×640 视口**；
  - 自动保存落库的 `view.transform.translateX/Y=513/319` 与上述一致；
  - 深色主题切换后 container transform 不变、节点 rect fill=none，重绘未恢复。
- **修改意见**：
  1. 首查 `MindMapEditor.vue` init 中手动调用的 `mm.view.fit()`：与库内建的首帧居中逻辑叠加造成双重偏移。建议移除手动 fit，或改用构造参数方式让库自身完成初始定位，并以官方 demo 的初始化时序为基准核对；
  2. 回归场景须覆盖四个：新建空图、打开带 view 数据的存量图、切换主题/结构触发重绘、刷新恢复；
  3. 连带修复点：`view.fit()` 当前位于 `initing` 守卫之外，其触发的 `data_change` 导致**每次打开编辑器都多写一次库**（实测创建后 01:52、刷新后 02:02 各多一次冗余 PUT）——修复时一并纳入守卫；
  4. 修复后补充验证深色主题下画布背景与节点配色（当前画布恒为浅色 rgb(250,250,250)，与暗色 UI 反差大，疑似库未应用主题背景）。

### BUG-2（P0·严重）ElMessageBox 无样式：弹窗掉到页面底部，用户不可见（全站预存在缺陷，本次暴露）

- **现象**：新建脑图/重命名/删除确认等所有 `ElMessageBox` 弹窗不显示遮罩、不居中，而是以裸 DOM 形态渲染在**文档流末尾（视口 y=720 之下）**，用户在屏幕上看不到任何弹窗。填值/确认只能靠"盲操作"，**删除确认流对真实用户等于不可用**。
- **证据**：滚动到页面底部可见无遮罩裸弹窗（同图可见 BUG-3）：![未 styling 弹窗掉底部](file:///C:/Users/chill/OneDrive/WorkStation/Projects/ihomy/gui-test-screenshots/t05c_unstyled_dialog_bottom.png)
- **只读诊断**：`.el-overlay` computed `position: static`（EP 基础样式应为 `position:fixed; inset:0`）；样式表扫描确认已加载 CSS 中**不存在** EP 的 `.el-overlay { position:fixed }` 基础规则（仅有 main.css 的覆写类规则）。即 **message-box/overlay 的 Element Plus 基础样式块未被加载**。弹窗 DOM 本身存在且可交互（Playwright 可填可点），纯视觉缺失。
- **影响面**：全站所有 ElMessageBox 调用点（博客/相册等删除确认、工具箱新建/重命名/删除）。AGENTS.md「已知问题」中「ElMessageBox 动画未生效」很可能与本案同根因，建议一并复核。
- **修改意见**：
  1. 在入口（main.js）或 main.css 显式引入 `element-plus/es/components/message-box/style/css`（并顺带核对 ElMessage/ElNotification/ElLoading 等命令式 API 的样式是否存在同样缺口——unplugin 按需样式只覆盖模板组件，命令式 API 需显式引入）；
  2. 修复后回归：全站搜索 ElMessageBox 的调用点逐个点一遍弹窗可见性与居中/遮罩。

### BUG-3（P2·低）新建脑图弹窗预填值显示原始 i18n key `tools.mindmap.untitled`

- **现象**：新建弹窗输入框预填了字面量 `tools.mindmap.untitled`，应为「未命名脑图」；同弹窗的标题「新建脑图」与提示语均正常解析。
- **证据**：同 BUG-2 截图（输入框内可见 raw key）。
- **根因（已核实）**：`MindMap.vue:64` 引用 `t('tools.mindmap.untitled')`，但 **zh-CN.js 与 en.js 中均未定义该键**（实现时遗漏），vue-i18n 回退返回键名。
- **修改意见**：在两个语言文件的 `tools.mindmap` 下补 `untitled: '未命名脑图'`（en: `Untitled map`）；建议 CI 加一个 zh/en 键集合一致性 diff 检查，防止同类遗漏。

### BUG-4（P2·低，全站通用）路径参数类型非法时返回 HTTP 200 + code 500，并打全堆栈 ERROR

- **现象**：`GET /api/mindmap/abc` → HTTP **200**，body `{code:500, message:"服务器内部错误"}`，后端记录 `MethodArgumentTypeMismatchException` 全堆栈 ERROR（根因 NumberFormatException: "abc"）。
- **修改意见**：`GlobalExceptionHandler` 增加 `MethodArgumentTypeMismatchException`（及 `MissingServletRequestParameterException`、`HttpMessageNotReadableException`）→ `BAD_REQUEST(400)` 的映射，既给前端正确码又消除 ERROR 日志噪音。属全局行为，非脑图独有（本次用例暴露）。
