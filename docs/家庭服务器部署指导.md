# 家庭服务器部署指导（云 VPS + J4125 + 树莓派 2B/3B）

> 定位:**ihomy 生产留在云上**;家里这几台机器承担重活(媒体/备份/NAS)与局域网服务。
> 本文只讲硬件分工、组网、落地顺序与坑;ihomy 业务实现见 `docs/需求设计说明书.md`,生产部署见 `docs/部署指导-Linux.md`。
>
> 现状(2026-11-11 核对):J4125 16G 内存、**硬盘未装**;树莓派 2B + 3B 在手;家庭宽带**未开通**;米家温湿度计 3(`XMWSDJ04MMC`)在米家 App 里。

## 一、定位与分工

四台机器的关系不是互相替代,而是「一台对外 + 一台重活 + 两台轻活」。

| 机器 | 真实能力 | 角色 | 明确不做 |
|---|---|---|---|
| **云 VPS** 2vCPU(1 核 2 线程 Xeon 2.5G)/1.6G 可用/40G 云盘 | 单核最强、有公网 IP、顺序写 658MB/s、已稳 101 天 | 唯一公网入口:ihomy 后端 + Nginx + MySQL/Redis;WireGuard hub;对外证书与反代 | 不跑 Jellyfin/转码;不托管家庭大文件 |
| **J4125** 4 核/16G/UHD 600 | 内存充裕、有 QuickSync 硬解、可挂多盘 | 家里重活机:NAS + Jellyfin + 备份落地(+ 以后 Immich) | 不做公网入口;不直接对外开端口 |
| **树莓派 3B** 4×A53@1.2G/1G/BT4.1/百兆 | 64 位可跑,有 BLE,内存紧 | Home Assistant(HAOS rpi3-64)+ BLE 温湿度网关 | 不跑 Jellyfin;不用 SD 卡做系统盘 |
| **树莓派 2B** 4×A7@900M/1G/无 Wi-Fi/百兆 | ARMv7 32 位,新镜像大量缺 armhf | AdGuard Home + Uptime Kuma | 不装 HA/Grafana/Jellyfin;不当网关或文件服务器 |

J4125 是这套里**唯一 7×24 依赖的机器**,它的可用性就是全家数据服务的可用性——UPS 迟早要加。

## 二、J4125 能不能做 NAS

### 结论

**能,而且 16G 内存对家用 NAS 是舒适配置**(TrueNAS 官方最低 8G,ZFS ARC 在 16G 下无需担心;Unraid 更宽松)。真正的瓶颈不是 CPU/内存,是**盘位**。

### 先确认三件事(决定方案,买盘前必须看清)

1. **机箱能装几块 3.5 寸盘**?J4125 多为软路由/NUC 型,常见只有 **1×SATA + 1×M.2**。
2. **M.2 是 NVMe 还是 SATA 协议**?部分 J4125 板子的 M.2 只接 SATA。
3. **有没有空余 PCIe**(哪怕是 x1)?有就可以上 JMB585(M.2 或 PCIe 转 5×SATA)。

对应三种情况:

| 盘位情况 | 建议 |
|---|---|
| 2 个及以上 3.5 寸位 | 两块 4–8TB CMR 盘(西数红盘 Plus / 希捷 IronWolf)做 **ZFS mirror**,可用容量 = 单盘 |
| 1×SATA + M.2 | 系统装 M.2(NVMe),数据盘 1 块大容量 + 关键数据同步到 VPS/云;或加 JMB585 转接卡扩到 4 盘 |
| 只有 USB3.0 | 只能临时用;USB 硬盘柜长期跑 NAS 会因为 UAS 掉盘,不推荐 |

> J4125 只有 **PCIe 2.0 ×6 lane**,M.2 常被配成 x1(≈500MB/s)。机械盘单盘 150–200MB/s,接 4 块顺序读会撞到总线上限——**家用够,但别指望全闪阵列**。

### 系统选型(推荐第二个)

| 方案 | 适合 | 代价 |
|---|---|---|
| TrueNAS SCALE | 确定 2 盘镜像、要 ZFS 快照与校验和、要 Web UI | 加盘必须同尺寸 vdev,不能一块一块加;ZFS 吃内存需限 ARC |
| **Ubuntu Server 24.04 + ZFS + Docker** | **推荐**:免费、可脚本化、和 ihomy 部署风格一致、加盘灵活 | 需要自己写 compose / systemd |
| Unraid | 混盘、随时加盘、社区模板多、Jellyfin 一键 | 付费(约 $50 起);**必须用 U 盘引导**,U 盘坏了要重做授权 |

无论选谁:**不要用主板 RAID / 硬件 RAID 卡**,交给 ZFS 或 Unraid 的软件层。

### 系统盘与数据盘分离

系统盘用一块独立 SSD/M.2(128G 即可),数据盘单独放 ZFS 池。系统盘和数据盘混用,重装系统就要搬数据。

### 16G 内存下的 ZFS 参数

ZFS 默认会尽量占用空闲内存做 ARC,不设上限会和 Jellyfin/MySQL 抢内存。16G 机器建议:

```bash
# /etc/modprobe.d/zfs.conf
options zfs zfs_arc_max=4294967296   # 4G 上限
```

重建 initramfs 后重启:`update-initramfs -u -k all`。

推荐池结构(两块 4TB):

```bash
zpool create -o ashift=12 tank mirror /dev/disk/by-id/ata-XXX /dev/disk/by-id/ata-YYY
zfs set compression=lz4 tank
zfs set atime=off tank
zfs create tank/media      # Jellyfin 影片
zfs create tank/backup     # VPS 备份落地
zfs create tank/home       # 家庭文件共享
```

加一块小 SSD 做 `special` vdev 没有必要(家用 metadata 量小);**不要加 L2ARC**,16G 下没有收益。

## 三、家庭宽带:办的时候就把这 4 件事问清

宽带还没装,所以这一步要先于所有联网工作。到营业厅/客服**必须书面问到**:

1. **上行带宽多少?** 国内 300M 下行通常只有 30M 上行,1000M 也可能只有 50M。远程看 Jellyfin 每路 1080p 需 4–8Mbit/s,30M 上行 ≈ 3 路同时看,4K 不够。
2. **给不给公网 IPv4?** 家宽默认是 CGNAT 大内网(没有公网地址)。部分地区打客服可免费开通,企业宽带才稳。
3. **IPv6 是不是 PD 前缀、能不能入站?** 三大运营商家宽基本都下发 IPv6(/56 或 /60),但光猫防火墙默认拦入站,要能关掉或做放行;前缀可能变化,必须配 DDNS。
4. **光猫能不能桥接?** 桥接后用自己的路由拨号,才谈得上端口/防火墙可控。

三种入站形态与对应方案:

| 拿到的条件 | 组网方式 |
|---|---|
| 有公网 IPv4 | WG 仍建议保留(家里 NAT 后设备多),外网访问可直接端口映射到 J4125 的 8096/8123 |
| 只有 IPv6 | 手机移动网络大多有 IPv6,可直连;企业/公共 Wi-Fi 常没有,所以**VPS 隧道仍是兜底** |
| 纯 CGNAT(最常见) | 全靠 VPS 作 hub,**家里设备主动连出**,不做任何端口映射 |

> 无论哪种,**不要把 8123(HA)/8096(Jellyfin)直接暴露到公网**。走隧道 + VPS 反代是唯一安全姿势。

## 四、组网:WireGuard(云 VPS 作 hub)

### 拓扑

```
公网用户 ──443──> [云 VPS] nginx ──┬─ /api    → 127.0.0.1:8080 (ihomy)
                                   ├─ /files  → 本地 uploads
                                   └─ media.ihomy.top → 10.10.0.2:8096 (Jellyfin)
                                          ▲
                          WireGuard 隧道  │  VPS = hub 10.10.0.1:51820/UDP
                                          │
   家里(NAT 内,无法入站)────────────────┘ 由家里主动连出,PersistentKeepalive=25
        J4125 10.10.0.2 ── 3B 10.10.0.3 ── 2B 10.10.0.4
             │
        局域网 192.168.x.0/24(3B/2B 之间走局域网直连,不必都连隧道)
```

要点:

- **只有 VPS 放行 51820/UDP**,家里路由器**不做任何端口转发**。
- 家里设备的 `AllowedIPs` 只写 `10.10.0.0/24`,**不要写 `0.0.0.0/0`**——否则全屋流量绕 VPS,家宽速度暴跌还吃 VPS 带宽。
- 3B/2B 只有需要被 VPS 访问时才连隧道;HA 与 AdGuard 都不需要。
- **不用 Tailscale**:到它的控制面/DERP 中继在国内不稳,打洞失败时延迟 100–300ms;自建 WG 走 VPS 中转 20–50ms。

### VPS 侧

```bash
apt install -y wireguard
cd /etc/wireguard && umask 077

# 生成 hub 密钥
wg genkey | tee hub.key | wg pubkey > hub.pub

cat > wg0.conf <<'EOF'
[Interface]
Address = 10.10.0.1/24
ListenPort = 51820
PrivateKey = <hub.key 内容>
# 反代 Jellyfin 等家里服务时用
PostUp   = sysctl -w net.ipv4.ip_forward=1
PostDown = sysctl -w net.ipv4.ip_forward=0

[Peer]   # J4125
PublicKey = <j4125.pub>
AllowedIPs = 10.10.0.2/32

[Peer]   # 3B
PublicKey = <rpi3b.pub>
AllowedIPs = 10.10.0.3/32

[Peer]   # 2B
PublicKey = <rpi2b.pub>
AllowedIPs = 10.10.0.4/32
EOF

systemctl enable --now wg-quick@wg0
ufw allow 51820/udp
```

### J4125 侧(家里每台同理,只改地址)

```bash
cd /etc/wireguard && umask 077
wg genkey | tee j4125.key | wg pubkey > j4125.pub

cat > wg0.conf <<'EOF'
[Interface]
Address = 10.10.0.2/24
PrivateKey = <j4125.key 内容>

[Peer]
PublicKey = <hub.pub>
Endpoint = ihomy.top:51820
AllowedIPs = 10.10.0.0/24
PersistentKeepalive = 25
EOF

systemctl enable --now wg-quick@wg0
```

### 验证

```bash
# VPS 上
wg show                      # 每台 peer 有 latest handshake
ping -c3 10.10.0.2
# 家里设备上
ping -c3 10.10.0.1
curl -s -o /dev/null -w '%{http_code}\n' http://10.10.0.2:8096/health
```

## 五、J4125:Jellyfin(硬解)与 ihomy 放映厅

### 硬解前提

J4125 的 UHD 600(Gemini Lake,Gen9.5)可硬解 H.264/HEVC 8bit+10bit/VP9,**不支持 AV1**;HEVC 编码性能弱,1080p 勉强。Linux 下需要 `iHD` 驱动:

```bash
apt install -y intel-media-va-driver-non-free vainfo
vainfo        # 应列出 H264/HEVC/VP9 的 VLD profile
```

Jellyfin 官方镜像已带 VAAPI 支持,只需把 `/dev/dri` 直通进容器。

### compose(只监听隧道地址)

```yaml
# /opt/jellyfin/docker-compose.yml
services:
  jellyfin:
    image: jellyfin/jellyfin:10.10.7   # 固定版本,别用 latest;按官方 release 取当前 10.10.x 最新
    container_name: jellyfin
    restart: unless-stopped
    network_mode: host          # 便于硬解与局域网发现
    devices:
      - /dev/dri:/dev/dri
    group_add:
      - "44"                     # video 组,按 getent group video 实际值改
      - "109"                    # render 组,按 getent group render 实际值改
    environment:
      - JELLYFIN_PublishedServerUrl=https://media.ihomy.top
    volumes:
      - /opt/jellyfin/config:/config
      - /tank/media:/media:ro
      - /tank/media/cache:/cache
```

> `network_mode: host` 时 Jellyfin 会监听所有网卡。要么在 Jellyfin 控制台把「网络 → 绑定地址」填 `10.10.0.2`,要么改回 `ports: - "10.10.0.2:8096:8096"`。**不能让它裸听 0.0.0.0**。

首次进 `http://10.10.0.2:8096` 走向导:建管理员、加「电影」「剧集」两个库。

### VPS 反代(做法 A,见 `docs/部署指导-Linux.md` §十二)

```nginx
server {
    listen 443 ssl http2;
    server_name media.ihomy.top;
    # ssl 证书沿用主站配置

    client_max_body_size 0;
    proxy_buffering off;

    location / {
        proxy_pass http://10.10.0.2:8096;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

然后在 ihomy 后台「放映厅 → 媒体服务器」填 `https://media.ihomy.top` + API Key。

> 代价:视频流量走 VPS 中转,吃 VPS 出口带宽与流量。**只给自己家看**,不要开放公网注册;多人同时看会撞家宽上行。

## 六、树莓派 3B:Home Assistant + BLE 温湿度计

### 刷机

用 **HAOS 的 `rpi3-64` 镜像刷到 USB SSD**,不要用 SD 卡(SD 卡跑 HA 一年内必坏)。

1. Raspberry Pi Imager → 选列表中「Home Assistant OS(最新版本)」的 **RPi 3 / 64-bit** 映像 → 目标选 USB SSD(别选 RPi 2 / 32-bit)
2. 首次启动后浏览器 `http://<3B IP>:8123`,建账号
3. 固定 IP:路由器 DHCP 绑定 3B 的 MAC

> 3B 只有 1G 内存,**add-ons 少装**。ESPHome/Node-RED/Mosquitto 全套上会 swap,要装拆到 2B 或 J4125 上。

### 温湿度计:三条路线(按现有条件选)

**前提认知**:`XMWSDJ04MMC` 是 BLE 广播设备,**数据能进米家 App 说明家里已有蓝牙网关**(多模网关/带蓝牙网关的音箱/中枢)。先确认是哪台,决定路线。

| 路线 | 条件 | 做法 | 优劣 |
|---|---|---|---|
| **A. 多模网关本地** | 有小米多模网关(ZNDMWG02LM/03LM,带网口) | HA 装 `AlexxIT/XiaomiGateway3` 集成,填网关 IP + token,集成**自动提取** bindkey,温湿度直接本地读 | 最省事、全本地、不依赖云;推荐 |
| **B. bindkey + 板载 BLE** | 只有音箱/灯带类网关,或想彻底脱离网关 | 取 bindkey → HA 装 `xiaomi_ble` 集成 → 3B 板载 BT 直接收广播 | 无网关依赖;3B 天线弱,隔墙丢包 |
| **C. 云模式** | 不想折腾 token | HA 装 `Xiaomi Miot` 集成选云端,登录米家账号 | 最快接通;依赖小米云、刷新慢、云端接口会变 |

### 取 bindkey(路线 B 用)

在**本机**(不要在 VPS 上跑,涉及小米账号密码)执行:

```bash
git clone https://github.com/PiotrMachowski/Xiaomi-cloud-tokens-extractor
cd Xiaomi-cloud-tokens-extractor
pip install -r requirements.txt
python token_extractor.py      # 输入小米账号 → 选服务器 cn → 过二次验证
```

输出表格里找温湿度计那行的 **BLE KEY / bindkey**(32 位十六进制)。注意:

- bindkey 和 token 一样属于凭证,**不要提交到仓库、不要贴聊天记录**;
- **改小米账号密码会让 token/bindkey 失效**,要重新提取;
- 脚本因小米云端改版偶尔失效,备选 `python-miio` 的 `miiocli cloud`,再不行走路线 C。

然后在 HA:`设置 → 设备与服务 → 添加集成 → Xiaomi BLE`,按提示填设备 MAC + bindkey。

> e-ink 温湿度计为省电广播间隔长(几分钟到十几分钟),HA 里数值刷新慢是**正常现象**,不是集成坏了。信号弱时按记忆里的方案加 **ESP32 bluetooth_proxy** 中继,别折腾换天线。

## 七、树莓派 2B:AdGuard Home + Uptime Kuma

2B 是 ARMv7 32 位,很多新镜像已无 armhf tag,只能跑老牌轻量服务。它只有百兆网口 + 无 Wi-Fi,**必须走网线**。

```yaml
# /opt/adguard/docker-compose.yml
services:
  adguard:
    image: adguard/adguardhome:latest
    container_name: adguard
    restart: unless-stopped
    network_mode: host
    volumes:
      - ./work:/opt/adguardhome/work
      - ./conf:/opt/adguardhome/conf
  uptime-kuma:
    image: louislam/uptime-kuma:1
    container_name: uptime-kuma
    restart: unless-stopped
    ports:
      - "3001:3001"
    volumes:
      - ./kuma:/app/data
```

**DNS 是全屋单点**,两步必须做:

1. 上游 DNS 配两个(如 `223.5.5.5` + `119.29.29.29`),2B 挂了客户端会回退;
2. 开始时**只把想拦截的设备**的 DNS 指到它(路由器按 MAC 单独下发),确认稳定后再考虑全屋。

系统盘同样用 USB SSD,或装 `log2ram` 减少 SD 写入。

Uptime Kuma 里加三个监控:`https://ihomy.top/api/public/health`(VPS)、`http://10.10.0.2:8096/health`(Jellyfin)、`http://10.10.0.3:8123`(HA)。

## 八、备份闭环

VPS 上的 `scripts/prod-backup.sh` 产出(`mysqldump` + uploads 增量)落到 `/opt/ihomy/backups`。由 J4125 **主动拉**(方向同样是家里发起):

```bash
# J4125 上 /etc/cron.d/ihomy-pull,每天 04:00
0 4 * * * root rsync -az --delete -e "ssh -p 19068" root@ihomy.top:/opt/ihomy/backups/ /tank/backup/vps/
```

保留策略:日备 14 天 + 每月 1 号一份冷备(ZFS 快照 `zfs snapshot tank/backup@2026-11-01`)。

**验收**:随机删掉一个备份文件 → 从 ZFS 快照恢复成功 → 才算闭环。

## 九、坑清单

| # | 坑 | 后果 | 对策 |
|---|---|---|---|
| 1 | 用 SD 卡跑 HA/AdGuard | 半年到一年卡死或数据损坏 | 3B/2B 都上 USB SSD,或至少 `log2ram` |
| 2 | 硬盘 APM 休眠 | Jellyfin 首次读取卡 5 秒 | `hdparm -B 255 /dev/sdX`,写进 systemd 或 udev |
| 3 | WG `AllowedIPs = 0.0.0.0/0` | 全屋流量绕 VPS,速度骤降 + 吃 VPS 流量 | 只写 `10.10.0.0/24` |
| 4 | 家里端口映射到 8096/8123 | 公网扫到即被爆破,HA 历史漏洞多 | 只走隧道 + VPS 反代 |
| 5 | AdGuard 全屋 DNS 单点 | 2B 一挂全屋上不了网 | 上游双备份 + 先小范围试点 |
| 6 | 单一 SATA 口直接单盘裸奔 | 一块盘坏 = 数据全没 | ZFS mirror,或关键数据同步出机 |
| 7 | J4125 原装小电源带多盘 | 掉盘/重启 | 换足瓦数电源(单盘启动电流按 2A 算) |
| 8 | 断电 | ZFS 相对安全,但 Jellyfin 库/HA 可能损坏 | 加 UPS(几百元),比事后恢复便宜 |
| 9 | 在 VPS 上跑 bindkey 提取脚本 | 小米账号密码过第三方服务器 | 只在本机跑,取完即弃 |
| 10 | `mvn clean` / 大构建放 J4125 | 单核弱,构建时间翻倍 | 构建留在开发机或 VPS |

## 十、落地顺序与验收

按这个顺序做,**每步验收不过不进下一步**:

| 步 | 内容 | 前提 | 验收 |
|---|---|---|---|
| 0 | 办宽带,四项问清(上行/公网 IPv4/IPv6/桥接) | 无 | 拿到书面/截图答复 |
| 1 | J4125 装 Ubuntu 24.04 + Docker + ZFS 池 | 硬盘到位 | `zpool status` 正常、重启自动挂载 |
| 2 | 3B 刷 HAOS(rpi3-64)到 USB SSD | 宽带通 | `:8123` 可访问、重启后自恢复 |
| 3 | 2B 上 AdGuard + Uptime Kuma | 宽带通 | 拦截生效、2B 断电其他设备仍能上网 |
| 4 | VPS + 三台家里设备组 WG | 宽带通 | `wg show` 全部有 handshake、双向 ping 通 |
| 5 | J4125 上 Jellyfin + VAAPI | 第 1、4 步 | 4G 网络能播、`intel_gpu_top` 看到 Video 引擎占用 |
| 6 | VPS 反代 `media.ihomy.top` + ihomy 放映厅对接 | 第 5 步 | 放映厅能列出影片、播放进度回写 |
| 7 | 备份拉取 + 恢复演练 | 第 1、4 步 | 删文件后从快照恢复成功 |
| 8 | 温湿度计接入 HA | 第 2 步 | 24h 数据不断线 |

## 十一、升级路线与触发条件

> 本节的实测数字是 2026-11-11 在生产机上取的;价格是当时国内行情区间,买入前自行核对。

### 结论:现在没有硬件瓶颈

| 指标 | 实测 | 说明 |
|---|---|---|
| 生产 load | 0.03 / 0.02 / 0.00 | 2 vCPU 远没吃满 |
| 生产内存 | MemAvailable **646MB** | 有余量,不是持续告急 |
| uploads 总量 | **1.7G**(书 657M / 照片 216M / kada 213M) | 40G 盘还剩 24G |
| 备份 | 324M | — |

`swap` 已用 579MB 是**历史积累,不是持续换页**(当前 `si/so` 接近 0),不必据此升配。但查到 `mysqld` 被换出 333MB —— 这意味着 MySQL 部分热页在磁盘上,个别查询会偶发延迟抖动。这是唯一「花钱能直接改善」的点,而且只是抖动,不是故障。

### 升级边界:四台里只有 VPS 能升配

| 机器 | 能升什么 | 结论 |
|---|---|---|
| **J4125** | CPU **BGA 焊死不可换**;内存 16G 已到该平台实用上限 | 只能加盘、加 UPS、换机箱/转接卡,没有 CPU 升级路径 |
| **树莓派 3B** | 内存焊死 1GB | 不能升,只能换整机 |
| **树莓派 2B** | 全部焊死 | 零升级价值,只会退役 |
| **云 VPS** | 支持变配(2G→4G) | 唯一「花钱就变强」的一台 |

### 路线 A|省钱(约 1000–1500 元),推荐先用这条

| 买什么 | 钱 | 理由 |
|---|---|---|
| 2TB **CMR** 盘 ×2 做 ZFS mirror | 700–900 | 现有数据 1.7G,按年增 100–300G 算够用 5 年,**别买 4–8TB** |
| 系统 SSD 128–256G | 100–150 | 系统盘与数据盘分离(见 §二) |
| UPS(山特 TG-BOX 850 级别) | 400–600 | 唯一能防「数据全没」的投入 |

### 路线 B|均衡(约 2500–3000 元)= A + 一台 N100

用途:**替代 2B + 3B 两台**,一机跑 HA + AdGuard + Uptime Kuma;3B 降级为纯 BLE 网关(它在家、BT 好,正好干这个)。

| 对比 | 树莓派 3B | N100 小主机(8G/256G) |
|---|---|---|
| PassMark 单核 | ~500 | ~1900 |
| PassMark 多核 | ~1200 | ~5500 |
| 内存 | 1G 焊死 | 8–16G 可换 |
| 硬解 | 无 | UHD 24EU,**支持 AV1 解码** |
| 价格 | — | 600–800 准系统 / 800–1000 含内存硬盘 |
| 功耗 | 3–5W | 6–10W |

### 路线 C|一步到位(约 4000–5000 元)

J4125 专用做 NAS(4 盘位机箱或 JMB585 转接 + RAIDZ1)+ N100 做服务机 + VPS 升 4G。只有要存影视库(一部 4K 电影 20–60G,100 部就 2–6TB)或跑 Immich 全家照片 AI 识别时才值得。

### 什么时候才该掏钱

| 升级项 | 触发条件 |
|---|---|
| 买盘 | uploads 超 20G,或决定存影视库(**先算片库大小,盘是大头**) |
| VPS 升 4G | `grep pswpout /proc/vmstat` 持续增长,或 MySQL 常驻 swap >200M 不回落导致接口 P95 抖动 |
| N100 替换 3B/2B | HA 装第 3 个 add-on 就 OOM,或嫌两台树莓派各管一件事太碎 |
| 换 J4125 | 要 4K 硬解转码或跑 Immich AI 识别(UHD 600 不支持 AV1) |
| 2B | 不用等,直接退役当备件 |

### 明确不要买

1. **4–8TB 大盘**:数据才 1.7G,先买 2TB。
2. **SMR 盘**(桌面移动硬盘拆盘/部分监控盘):做 ZFS 写放大严重,必须 CMR。
3. **树莓派 5 做服务器**:价格接近 N100,性能只有一半。
4. **给 J4125 换更强 CPU**:焊死,不存在。
5. **品牌 NAS(群晖/威联通)**:已有 16G 的 J4125,买成品机等于重复付费。
6. **现在升 VPS**:先跑两周 Uptime Kuma 看接口延迟,有抖动再升。

> 一句话:先花约 1200 元把 J4125 变成「能存数据 + 能扛断电」的 NAS,其余的钱等触发条件出现再花。
