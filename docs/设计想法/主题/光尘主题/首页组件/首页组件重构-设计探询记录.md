# 首页组件重构 — 设计探询记录

> 状态：需求探询中（苏格拉底式提问）。本文件记录目标、现状事实、历轮问答、已定结论与待澄清开放问题，供跨会话续接。**每次问答后更新本文件**，避免上下文被压缩后丢失进度。

## 目标（用户原话）
优化首页组件：设计排版方案、优化组件展示内容、不同功能组件不同大小设计不同内部排版、调整默认组件大小（不同组件默认大小不同）。用苏格拉底式提问连续引导澄清。

## 现状事实（读代码所得）
- `frontend/src/views/Home.vue`：12 列 × 9 行栅格仪表盘，组件绝对定位 + 编辑模式拖拽缩放。
- 11 种组件：feed 家人动态 / task 悬赏任务 / today 今日 / weather 天气 / anni 纪念日 / recipe 今日推荐 / search 物品寻找 / wish 愿望单 / finance 本月收支 / album 相册 / music 背景音乐。
- 默认布局只含 8 个：feed(5×5)、anni(3×4)、weather(3×2)、today(3×2)、recipe(4×4)、wish(3×2)、album(5×3)、finance(2×2)；task / search / music 需手动拖入。
- 拖入任何新组件默认统一 `w:4, h:5`。
- 组件内部结构 = 标题 + 内容 + 滚动（`.card-scroll`），大小变化只伸缩容器、不换内部排版。
- 编辑模式右下角自由拖拽缩放；`resetLayout` 恢复默认。
- **响应式现状**：`@media (max-width: 960px)` 时 `.dash-card` 整页隐藏，提示「请使用电脑或平板访问首页仪表盘」——仪表盘当前只服务宽屏 + 鼠标，移动端/窄屏整个隐藏。
- **点击跳转现状**：几乎所有组件内容都是「点击 = 跳页面」（天气→/weather、动态→博客/日记、相册→查看器、签到→签到…）——这是触摸「点按展开」与「点按跳转」冲突的根源。
- **音乐已存在悬浮播放器**：`components/MusicPlayer.vue`（左下角悬浮黑胶，可拖拽、点黑胶展开歌名+进度条+歌单，播放「当前家庭背景音乐歌单」）。首页「背景音乐」widget 与它共享同一数据源，存在功能冗余。
- **户型图渲染可复用**：`views/item/FloorPlanCanvas.vue` 是完整 SVG 画布（底图 PDF 转图 + 房间多边形 + 家具 + 物品圆点 + 标签，缩放/平移/命中高亮/编辑手柄），有 `mode='view'` 只读查看态。后端已有 `itemApi.floorPlan(houseId, floor)` 接口一次返回 rooms/furnitures/items/imageUrl/scale。首页内嵌户型图可行，但需额外取 houseId+楼层，且小格子内物品点/标签会挤。

## 历轮问答

### 第 1 轮
| 问题 | 回答 |
|------|------|
| 核心痛点 | 内容太浅太薄 |
| 组件定位（速览 vs 工具） | 两者按组件性质分 |
| 默认大小依据 | 功能重要性 |

### 第 2 轮
| 问题 | 回答 |
|------|------|
| 天气 vs 相册谁该大 | 展开为「AI 底图 + 拍立得」方案（见下） |
| 内容太浅难受点 | 以上都有（大组件很空 / 信息被藏 / 空壳占位） |
| 大小自适应方式 | 渐进展开 |

第 2 轮关键补充（用户主动展开）：
- 天气：生图 AI 按「城市 + 天气 + 季节 + 时间」生成底图背景，天气信息浮图上；图可稍大但不能太大。
- 相册：拍立得相纸「散开堆叠、不集中」；hover 自动展开 + 缓慢随机播放。
- 关键共识：默认不占大空间，前提是「hover 组件自动放大展示更多、移走恢复原大小」，小组件用波浪/文字提示引导。

### 第 3 轮
| 问题 | 回答 |
|------|------|
| 默认态呈现程度 | 不能太挤（信息淹没）也不能太空（冷冷清清不温暖）；排版分配合理、内容不过度拥挤、有留白、舒适温暖 |
| hover 放大形态 | 动效「推开邻居」：组件放大、其他组件缩小，如「油膜上滴洗洁精」/「鲜花绽开挤开绿叶」，为增加美感 |
| 缩放去留 | 组件不同大小内容不同，分巨大/大/中/小；质疑自由调节（不好断定组件处于什么大小） |
| 生图 AI 底图 | 赞同分组缓存（城市+天气+白天夜晚+季节），但保新鲜如一周一换；无 AI 底图→无底图模式触发 hover；纯色渐变不如毛玻璃 |

第 3 轮附注：用户要求每完成一次问答都记录本文件，避免上下文撑爆，以便下个会话继续。

### 第 4 轮
| 问题 | 回答 |
|------|------|
| 「推开邻居」推到什么程度 | 邻居要**缩小 + 移位**：缩小到「一个个圆角矩形」；移位**不是真实重排**，只是「看起来位置被移到缩小后的地方」（即 transform 视觉位移，不做真实 grid reflow）。例：天气在最边 hover 放大，邻居若也很小、只缩小不移位则天气仍展不开很大，所以必须缩小也要移位 |
| 四档与 hover 的关系 | **四档 + hover 两套并存**：巨大/大/中/小是「永久摆放尺寸」，hover 是另一套临时放大预览 |
| 内容太浅要不要默认态解决 | 用户重新定义「默认大小」为两层含义：①**拖出时的默认生成尺寸**；②**从未调整布局时的默认展示效果**（家庭数据充实后应「各组件排版布局内容详略得当」） |

## 已定结论
1. 核心方向：解决「内容太浅太薄」（大组件空、信息藏、空壳占位三宗罪）。
2. 默认态：不挤不空、有留白、温暖；「详略得当」是默认布局的验收标准。
3. 交互范式：hover 组件放大展示更多、移走复原；小组件波浪/文字提示引导。
4. 放大动效「推开邻居」：邻居**缩小成「图标+标题胶囊」+ transform 视觉移位**（非真实重排），追求油膜/花朵美感。
5. 尺寸体系：**四档（巨大/大/中/小）= 永久摆放尺寸 + hover 临时放大两套并存**；不用自由拖拽，改为**拖拽 snap 档位**。
6. hover 触发：**加悬停延迟（~300-400ms）防扫视抖动**；**只有中小档 hover 放大**，大/巨大档不再放大。
7. **hover 仍补内容**：默认「中」详略，hover 再多展示一档增量内容（不是纯美感动效）。
8. 「默认大小」= 两层：①拖出时各组件默认生成尺寸不同；②从未调整时默认布局各组件详略得当。
9. 天气：生图 AI 底图（城市+天气+季节+时间），分组缓存 + 一周一换保鲜；无 AI → 毛玻璃兜底。
10. 相册：拍立得散开堆叠不集中；hover 自动展开 + 缓慢随机播放。
11. 触摸端：**桌面 hover 优先**，触摸/平板只览不展开（点组件进页面），tap 展开后续迭代。
12. **删掉首页「音乐」格子**（悬浮黑胶播放器已覆盖播放需求，避免同数据两入口）。
13. **找物组件形态**：大/巨大档=搜索框+语音输入+户型图（搜索后 hover 展示物品位置+列表，item 页缩小版、只搜索不加列表/编辑）；中档=小缩略图；小档=搜索框（hover 显示同大档效果）。
14. **相册 hover 播放**：横版翻牌式，像真实相册缓缓翻页、翻过去那页淡出消失、露下一张，每张约 2 秒；点击进相册页。
