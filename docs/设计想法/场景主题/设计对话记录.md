## 1. 主题定位（一句话）

整个网站不再是一堆「页面」，而是一间**会呼吸的房间**：一张面对推拉窗的书桌，窗外是随真实天气/时间/季节变化的动态场景；桌面的手机、电脑、相册等物件即功能入口，墙上的便签与挂图可切换功能，鼠标移动带动镜头游走。**颠覆现有主题与规划中的「光尘」主题。**

## 2. 原始设想（要点，已获授权）

- **场景**：面对推拉窗的桌子；窗外 = 天气场景，随地区/天气/时间/季节变化；阳台有花盆，偶有鸟/蜂飞过、落叶飘落，整体动态变换。
- **桌面**：手机、电脑、相册/拍立得等可交互物品，每个对应一种功能。
- **墙/窗边**：贴着便签；窗边有挂户型图/地图等图片的框，可切换显示 = 切换功能。
- **两侧纱窗飘动**；窗随天气开关；窗外植物可搬进桌面。
- **交互**：鼠标移动带动镜头——下移 = 拉近聚焦桌面，左右 = 拉近聚焦窗两侧，久停不动 = 拉远回默认正视窗；每物件有丰富 hover 动效（开关电脑、解锁手机、翻相册、看便签、看户型图），像游戏界面。
- **示例情绪**：晴天，光透过窗打在桌面，浮尘隐隐漂浮，唱片机响着，绿植点缀，中古风房间。
- **授权**：全部画面用出图 AI 生成；动效可借鉴高级动效网站；风格/颜色/细节需持续磨合。
- **要求**：抛弃传统页面、重新设计整个前端；详细记录；长期分期（几十期可接受）；另立分支；上下文过长要有续会话方案。

## 5. 技术关键点（我方观察，待对齐）

1. **静态 vs 会呼吸**：AI 出图本质是「静态一帧」，而「会呼吸」（纱窗、浮尘、落叶、飞鸟、天气）必须叠加**实时动效层**（CSS / Canvas / WebGL），或局部循环视频。这是本主题最核心的工程决策。
2. **分层而非全图矩阵**：天气 × 季节 × 昼夜 若每格单独出一整张图，成本爆炸且难统一 → 倾向「房间底图基本不变 + 窗外景独立可替换层」。
3. **移动端无鼠标**：PWA 的移动端用户不可忽视，视差/镜头需要倾斜传感器或自动漂移兜底。
4. **文字内容可读性**：博客/聊天/表格等无法「物件化」，用毛玻璃浮层面板（游戏「暂停菜单」式）承载，与本项目既有毛玻璃语言一致。

### 8.2 视觉解读通道（重要基建，跨会话可用）

主控模型无视觉输入能力。**打通方法**（新会话照做即可让我"看见"图片）：

1. 从 DB 取模型密钥密文：`sys_family_ai_model`（family_id=1）的 `api_key` 字段（`ENC(...)` 格式）；
2. 用运维账号 `ops@ihomy.local` 登录，调 `GET /api/ops/crypto/decrypt?ciphertext=ENC(...)` 解出明文密钥（**密钥绝不写入任何仓库文件**）；
3. 调 tshl 代理 `POST https://tshl.rawlinson.life:6006/v1/chat/completions`，model 用 **`deepseek-v4-flash-vision-exp`**，messages 用多模态 content 数组（`{"type":"text",...}` + `{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,..."}}`）；
4. **注意**：该模型有 reasoning，`max_tokens` 给小（如 2000）会被推理 token 吃光导致 `content=None`，**必须给到 8000**。
5. 代理可用模型仅两个：`deepseek-v4-flash-vision-exp`（视觉）、`deepseek-v4-pro`。

### 8.4 主控模型对三张的解读与待解决问题

**共同点**：三张构图高度相似（窗户居中、木桌横贯、纱帘分列两侧、相册+唱片机+盆栽三件套），说明 Seedream 对「质感形容词」的响应**偏弱**，真正被拉开的是**光照方向与细节丰富度**（写实=左上光+背景虚化+电线杆；另两张=右上光+花纹壁纸）。

**必须解决的问题（三张都中招）**：
1. **右下角「AI生成」水印**——`AiImageDTO.watermark` 传 `false` 即可关闭。正式素材一律关水印。
2. **相册位置不对**——用户要求「相册斜放桌子**最中央**」，三张都在左侧/中央偏左且是**平放**，需明确的「斜放/立起」姿态，且居中。
3. **缺用户核心设定的元素**——没有一个提示词写了：`推拉窗`（实际出的是双开窗/三扇窗格）、`便签`、`挂户型图/地图的框`、`手机`、`电脑`、`阳台花盆`。当前只是"窗边静物"通用场景，还不是**功能地图**。
4. **写实风格的既有风险**（待用户确认）：素材要在 天气×季节×时段 多条件下成批生成，写实摄影对**跨图一致性**要求最高；且文字/按钮浮层叠在写实照片上容易「贴上去」。

**两版取舍**：D 版构图像「整间房的全景」，适合做**默认远景镜头**（久停不动回正的那一档）；E 版构图像「推近后的桌面」，适合做**向下移镜头的近景**。可作为两层镜头的素材基准。

### 8.6 主控模型结论

1. **质感形容词对 Seedream 影响很弱**——三张不同质感词的图，构图与观感高度雷同。真正能拉开差异的是**光照方向/角度**（左光 vs 右光）与**细节密度**（是否加电线杆、花纹壁纸、玻璃杯等）。→ 后续控风格要靠**具体物件+具体光位**，不能只写"写实/3D"。
2. **写实风格已由用户选定**，v2 两版均为写实路线，用户需确认观感。
3. 未解决问题：v2 依然**没有明确出现「横向推拉窗」**（视觉解读仍描述为「窗户/大窗」），且**纱窗飘动（风感）是静态图中最难体现的**——这部分注定要交给动效层，不能指望出图。

- **去边缘**：PIL 后处理——alpha < 20 置 0 + `MinFilter(3)` 1px 腐蚀，砍掉白/灰描边。
- **比例修正**：手机 8%→5.5%（宽 320×169，平躺侧视）、唱片机 16%、电脑 15%、相册 13%。
- **落地感（CSS）**：sprite 统一 `sepia(0.15) saturate(1.05)` 暖色 tint 柔化色温差；投射阴影改为偏移右下（`drop-shadow(10px 18px 14px ...)`，光从左上 → 阴影偏右）；新增 `.obj-shadow` 接触阴影椭圆（底座 AO）。
- **窗外景融合（关键，占「贴纸感」大头）**：真正的违和源是 P2 的窗外远景层（冷蓝/高亮/高饱和，像另一张照片贴上去）。加 `brightness(0.8) saturate(0.72) sepia(0.12)` 压暗降饱和 + `::after` 径向雾化边缘（四周渐隐融入室内），消除硬接缝与「悬浮面板」感。

**教训（写回，后续 P3.5/P6 沿用）**：

- **物件 sprite 不能各自独立生成**：必须用同一套「光照方向 + 相机角度 + 桌面语境」的共享 prompt 模板批量出图，否则色温/透视必然打架。写实素材对跨图一致性最敏感（§8.4 早已预警）。
- **窗外层是「贴纸感」第一来源**：静态写实底图 + 独立窗外层，若不压暗/降饱和/雾化边缘，冷蓝高亮窗景会盖过暖调室内。`mix-blend-mode: screen` 的窗光溢散层实测会过曝/显假（像灰雾蒙版），**已否决**——真正的窗光动效留到 P6 用 Canvas 光斑 + 太阳方位角做，不用静态遮罩。
- **接触阴影比投射阴影更决定「落地感」**：`drop-shadow` 只能做投射影，底座 AO 需要独立的径向渐变椭圆（`.obj-shadow`）。

**验证结果**：视觉模型评分从「贴纸感明显」提升到 8/10（窗外压暗+雾化后）；窗光溢散层实验反而降到 6.5/10 故回退。遗留小瑕疵：手机色温仍略偏冷、透明防尘盖高光明显、物件底边朝向未完全统一——均属 P3.5/P6 或后续逐张精调范畴，不影响 P3 验收。
