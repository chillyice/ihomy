# 主题系统设计 — 主题 × 晨暮 矩阵 + 旗舰「光尘」

> 本文是 ihomy 主题系统重构成熟的 **跨会话交接底稿**(2026-09-09 由 plan 批准后写起)。凡涉及主题/晨暮/主色 token 化的改动,一律先读本文再动手;实现事实以 `../../../frontend/src` + `backend/src/main/java` 为准。
> 相关:设计灵魂见 `docs/设计理念.md`(会呼吸的家/摆家具方法论);历史踩坑见 `docs/变更归档.md`。

## 一、锁定决策(用户拍板,不可逆)

1. **现有主题改叫「暖居」(Warm Dwelling)**:奶油暖底 + 玻璃磨砂 + 主色 `#b88c6e`,保留打造不变,只改名 + 归入主题体系。
2. **全新旗舰主题叫「光尘」(Light & Dust)**:中古风、会呼吸的家——暖木 + 陶土 + 鼠尾草绿 + 奶油;签名 = 一扇"会呼吸的窗"(尘粒在光柱里浮动、光影随晨昏缓移、暮时暖灯亮起)。
3. **两轴心智模型**:
   - **主题(theme)= 装修风格**,手动选,决定全局主色/材质。
   - **晨/暮(mode)= 时间光照档**,沿用现有「日出日落自动」逻辑自动切晨暮,也可手动;`autoMode` 只切晨暮、**不切主题**。
4. **「光尘」天气→AI生图**做**全局全屏氛围背景层,光尘默认开启**;复用 `FEATURE_WEATHER_BG`(未绑回落 `IMAGE`),家庭级去重 + 7 天缓存,随天气/晨暮/季节再生。生图**优先绑 seedream-5.0-pro**。
5. **主色 token 化**:先做高影响面(main.css 按钮/侧栏/Tag 体系 + 关键组件),零散 460 处分批渐进。目标:让"每个主题的可见主色面"真正随主题变,而非只背景卡片变。
6. **废弃预设不用**:`theme.presets`(旧物之家/暮光琥珀/海蓝/森林/日暮/暮紫/樱粉)是旧方案名字,刻意不用;主题池只做「暖居」「光尘」两套(可扩展)。

## 二、现状底座(改动的起点)

### 2.1 主题系统现状(纯前端,无后端)
- **无 Pinia store**:主题是纯工具模块 `../../../frontend/src/theme/index.js`(47 行),`AppSidebar`/`Settings` 各持一个本地 `ref`,靠 localStorage 兜底同步,`useSunLight` 用日出日落驱动深浅。
- **状态形状**:`{ dark: bool, autoMode: bool }`(默认 `{dark:false, autoMode:true}`),localStorage key `ihomy-theme`。
- **应用方式**:`applyTheme` 只 `document.documentElement.classList.toggle('dark', !!t.dark)` + 更新 `meta[name=theme-color]` + 持久化。
- **Element Plus 暗色 css-vars**:`main.js:8` 引入 `element-plus/theme-chalk/dark/css-vars.css`,仅在 `html.dark` 类上生效。
- **自动模式**:`useSunLight.js` 在 3 处(340/354/408 行附近)太阳 `isNight` 变化时调 `applyAutoTheme(isNight)`,只在 `autoMode===true` 时切 `dark`。

### 2.2 CSS 变量组织(`main.css`)
- **浅色 `:root`(1-15 行)**:`--color-primary #3A2E22` / `--color-accent #A8483A` / `--color-bg #EDE4D3` / `--color-bg-2 #E2D5BC` / `--color-card #FAF6EC` / `--color-card-2 #E8DEC8` / `--color-text #3A2E22` / `--color-text-secondary #7A6B5A` / `--color-border` / `--radius` / `--shadow*`。
- **深色 `html.dark`(26-39 行)**:覆写上述 token(注意 `--color-accent` **未覆写**,仍是 `#A8483A`)。
- **过渡(98-99 行)**:`html, body, #app` 上 1s 主题切换过渡。
- **⚠ 缺口**:`--color-accent` 无每主题暗色孪生;主色实际是硬编码 `#b88c6e`(88 处)+ 暗色孪生 `#d4b298`(35 处),与 `--color-accent`(`#A8483A`,22 处)语义脱节。

### 2.3 硬编码颜色(全站摸底)
- 全站硬编码色约 **1671 处**,token 引用约 **429 处**。
- 真实主色硬编码 `#b88c6e` **88 处** + `#d4b298` **35 处**,连同按钮/侧栏/Tag 全套约 **460 处**品牌色散落在 `main.css` + 33 个 `.vue`。

### 2.4 i18n

### 2.5 全局光影(「会呼吸」的现成载体)
**`SunLightLayer.vue`**(15.6KB,纯 DOM/CSS 无 canvas,`pointer-events:none`),z-index 分层:
`bg-blobs(1)→glass-bg(2)→内容(10)→AppSidebar(60)→bright-spot(65)→window-shadow(68)→reflection(72)→vignette(74)→dust(76)→snow/rain(77)→light-layer(78)→lightning(79)→lamp-light(100)`
- `bg-blobs`:5 个预模糊 radial-gradient 色块随机漂移(纯 translate,避免 filter:blur 触发重栅格化)。
- `window-shadow`(21-31):6 条窗框阴影抽象窗户 + `.weather-shadow` 天气覆盖。
- `light-layer`(40-50):丁达尔体积光(screen,mix-blend),内有 light-bloom + light-ray。
- `lamp-light`(53-59):台灯光源(左上 38.2%),钟摆 `@keyframes lampSwing`(main.css 767 行)。
- `dust-layer`(62-77):20 个 screen 发光尘粒。
- `snow/rain`(80-113):`❄`/雨滴,`precipLevel×10`。
- `lightning-flash`(97):雷雨增亮。
- GSAP 在 `useSunLight.js`:`cloudFlicker`(云遮阳 4-8s 随机)、`lightningFlash`、`lampAnim`。

### 2.6 天气 → AI 生图现有链条(Home.vue 576-613 行 `loadWeatherBg`)
- prompt:`一张 {城市} {季节}季{白天/夜晚} {天气现象} 的氛围插画,柔和光影,无文字,竖构图…`。
- 功能链:`FEATURE_WEATHER_BG`(未绑回落 `IMAGE`);前置 `aiApi.status()` → `weatherBg.available` 判定(无则静默回落渐变底)。
- 去重:`description = 天气·{城市}·{天气现象}·{白天/夜晚}·{季节}` → `albumService.findRecentAiPhoto(familyId, desc)` 近 7 天复用,未命中才生成→`saveAiImage` 落「AI 生成」相册。
- 现状只做**天气卡片局部背景**,非全屏。

### 2.7 AI 图片模型池与出图规则
- `sys_family_ai_model`:每家庭多条,`type` ∈ LLM/IMAGE/ASR/LOCAL;字段 base_url/api_key(ENC 加密)/model/timeout_ms/provider/secret_key。
- `doImages`(`AiService.java:206-279`):`POST {base}/images/generations`,OpenAI 兼容体:`model/prompt/n(非组图)/sequential_image_generation(组图)/image(参考图)/size/seed/guidance_scale/watermark/response_format`。
- 现在 dev 图片模型 = `doubao-seedream-5-0-260128`(Seedream 5.0 lite,ark 直连 `https://ark.cn-beijing.volces.com/api/v3/images/generations`,Bearer key)。
- **Seedream 5.0 lite 出图规则**:size 方式1档位 `2K/3K/4K`;方式2 `宽x高` 总像素范围 `[3686400,16777216]`(≥1920×1920);支持组图 `sequential_image_generation`(auto/disabled)、`max_images`、stream、`tools.web_search`。
- **Seedream 5.0 pro(`doubao-seedream-5-0-pro-260628`)出图规则(差异核心)**:
  - size 方式1档位 `1K/1.5K/2K`(默认 2K;prompt 用自然语言描述宽高比/形状/用途由模型定大小);方式2 `宽x高` 总像素范围 `[921600,4624220]`(≈1280×720 起)。
  - **不支持组图**(`sequential_image_generation` 不可用,仅单图)、不支持流式、不支持联网搜索。
  - 新增可选字段 `layer_decomposition`(图层拆分)/`output_format`(png|jpeg)/`background`(transparent|opaque)/`optimize_prompt_options`。
  - 参考图最多 10 张(图生图场景);prompt 中文≤300 字、英文≤600 词。
  - **⚠ 与 lite 混用的坑**:现前端"总像素≥3686400 / 2048x2048…/组图"是 **lite 规则**;给 pro 用下限差 4 倍、档位名不同、且 pro 不支持组图/多 n。
- 模型差异表(详见 `docs/pro`,方舟文档原文,出入参结构一致但取值/能力不同)。

## 三、目标架构

### 3.1 状态
Pinia `stores/theme.js`:`{ theme: 'warm'|'guangchen', mode: 'dawn'|'dusk', autoMode: bool }`。
- 收敛 `AppSidebar`/`Settings` 两个本地 ref 到该 store;`useSunLight` 自动驱动器改写 store 的 `mode`。
- 持久化 key 沿用 `ihomy-theme`;做旧 `{dark, autoMode}` → 新 `{theme, mode, autoMode}` 迁移:
  - `dark:false` → `mode:'dawn'`;`dark:true` → `mode:'dusk'`;`theme` 缺省 `'warm'`。

### 3.2 应用方式
- `theme/index.js` 主题注册表 `THEMES`(暖居 + 光尘,可扩展)。
- `applyTheme`:`html.theme-{id}` + `html.dark`(=dusk,Element Plus 暗色 vars 复用此法);`meta theme-color` 随主题×晨暮。
- 每主题×晨暮一套 token 集(`html.theme-warm`, `html.theme-warm.dark` …)。

### 3.3 主题 token(每主题×晨暮)
建语义 token:`--color-primary`(统一真实主色)/`--color-primary-hover`/dusk 孪生/`--color-accent`(补每主题×晨暮覆写)/`--color-surface*`/`--color-link`/`--color-tag*`。高影响面(按钮/侧栏/Tag)迁移后,"每个主题的主色面"才真正随主题变。

### 3.4「光尘」调色板(晨/暮,示意,阶段 4 渲染预览定稿)
- 晨 dawn:背景暖木米 `#F1E7D6` / 卡片羊皮 `#FBF3E4` / 主色深木 `#8A6A4E` / 强调陶土 `#C9807A` / 点缀鼠尾草绿 `#7C8B6C` / 阴影更暖更柔。
- 暮 dusk:背景深咖 `#241A12` / 卡片暖褐 `#33241A` / 主色琥珀木 `#C9A16E` / 强调陶土 `#E19A8C` / 绿 `#8FA080`,低亮度、近烛光。

### 3.5「光尘」动效签名(在现有光影系统之上做"更高级、更有设计感")
- **尘池(breathing dust)**:尘粒不再匀速,改为"在光柱里缓漫蛇形飘移,遇光变亮、离光变淡",像呼吸。
- **窗光(moving window light)**:窗框光柱角度/强度按真实太阳时刻连续缓移(现有已做,提升缓动与柔化、加纱窗般飘动)。
- **暮色入场**:日落后暖光灯匀速亮起,带极缓钟摆呼吸;晨间渐亮。
- **会呼吸的卡片**:hover 不再生硬放大,改为一层温光浮起(光晕+轻微上浮),克制、柔和。
- 全程遵守"克制动、留白、慢"(呼应设计理念.md)。

## 五、关键技术约束(踩坑备忘)
- Element Plus 暗色 css-vars 由 `html.dark` 驱动——多主题时保持 `html.dark` 随晨暮档,否则 EP 组件颜色不变。
- `--color-accent` 当前未随暗色覆写,是"主题×晨暮"必补缺口。
- 主色是硬编码不是 token——只改背景/卡片 token 不会让"主色面"随主题变;这才是阶段 3 的大头。
- 移动端全局氛围背景需降级(纯渐变+光影层)避免性能问题(阶段 5 定稿)。
