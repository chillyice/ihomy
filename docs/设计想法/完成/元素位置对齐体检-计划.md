## 1. 目标与边界

**目标**:全站页面满足五条几何底线 ——

1. 同一行元素**垂直中线一致**(容差 ±1px);
2. 左右槽位与容器内边距**对齐**(不留单槽左飞);
3. **滚动条不占据布局盒**(不因内容多少改变元素高度/中线);
4. 页面**不横向裁切**(窄屏下每个可点元素都在视口内);
5. 同类元素**尺寸/密度/数字格式**一致(卡片内边距、金额千分位、收支色)。

**范围**:`frontend/src/views/**`、`frontend/src/components/**`、`frontend/src/styles/main.css`。

**不在范围**(自带设计体系,改动会打架):

- 独立产品页 `/kada`、`/bit-pouch`、`/wallpaper`、`/chillyice`(自带配色与版式);
- 全屏游戏页与牌桌(`views/games/**`,`useGameView` 一屏适配自成体系);
- 主题视觉风格本身(暖居/光尘/场景主题的色板与质感,归 `docs/设计想法/主题/`)。

**非目标**:不做功能新增、不改接口、不改数据口径。

## 2. 判定标准(可量化,避免「看着歪」扯皮)

| 类 | 判定 | 阈值 | 取证方式 |
|---|---|---|---|
| **A 垂直偏移** | 子元素中线 `cy` 与容器中线 `cy` 之差 | > 1px 即记 | `getBoundingClientRect()` 取 `(top+bottom)/2` |
| **B 槽位不齐** | 左右槽位内容首/末元素与容器 padding 边线 | > 1px 即记 | 与 `.page-toolbar` 的 `clientLeft/clientRight` 比较 |
| **C 滚动条占位** | 滚动容器的 `offsetHeight − clientHeight > 0`(横向滚动条)| > 0 即记 | 同时看子项是否偏离容器中线 |
| **D 溢出裁切** | 元素 `rect.right` 超出 `.page` 内容盒或视口 | > 0 即记 | 注意祖先 `overflow-x:hidden` 会静默裁掉(不产生 `documentElement` 溢出) |
| **E 尺寸/密度** | 同类卡片内边距不一致 / 同类数字格式不一致 / 收支色硬编码 | 人工判定 | `formatYuan` vs `toFixed(2)`、`#67c23a` 散落处 |
| **F 换行错位** | 窄屏换行后槽位失去对齐或顺序被打乱 | 人工判定 | 390 / 768 两档实测 |

> 判定口径补充:**只有「同一条视觉基线上应当对齐」的元素才比较**。例如表单 `label-position="top"` 的标签与输入框不属同一基线,不记。

## 4. 三类系统根因与建议改法

### 根因 1:内联控件塞进块级容器 → 基线对齐

`el-radio-group`/`el-button` 这类 `inline-flex` 元素,父容器若是 `display:block`(尤其带 `overflow`),垂直位置由**行盒基线与 strut**决定,父容器的 `align-items:center` 只作用在容器这一层,管不到容器内部的控件。

改法(择一,优先 ①):

1. 包装容器改 `display:flex; align-items:center`(`.book-tabs`、`.album-actions` 都适用);
2. 或给控件 `display:flex`(元素级),但会失去「随文本宽度自适应」的直觉,不推荐。

> 体检时注意:这类偏差往往只有 2–4px,肉眼「说不清但觉得歪」,必须靠 `cy` 差值判定。

### 根因 2:滚动条占据布局盒

横向滚动容器(`overflow-x:auto`)在 Windows/经典滚动条或 `scrollbar-width:thin` 下会吃掉 8–12px 高度,且**只在内容溢出时出现** → 同一组件在不同数据量下高度不同、内部元素中线偏移。垂直方向同理会吃掉宽度。

改法(记账本余额条为样板):

- `overflow-x:auto; overflow-y:hidden`(避免隐式纵向滚动条);
- 隐藏原生滚动条:`scrollbar-width:none` + `::-webkit-scrollbar{display:none}`;
- 行高由 chip 决定(去掉 `padding-bottom:2px` 这类不对称内边距);
- 溢出提示改为**边缘渐隐** `mask-image: linear-gradient(90deg, transparent 0, #000 12px, #000 calc(100% - 16px), transparent)`;
- 滚动入口保留:触屏原生横滑;鼠标滚轮映射(仅在「该方向还能滚」时消费 `wheel`,到边缘放行给页面,避免劫持整页滚动);
- 若坚持保留可见滚动条,则必须给容器**固定高度**并让子项 `align-items:center`,不能靠内容自然高度。

### 根因 3:工具栏单槽 + `space-between` → 左飞 + 不可收缩

`.page-toolbar` 用 `space-between` 是为「左标题/右操作」设计的;当页面只提供 `.tb-right`(或只提供 `.tb-left`)时,唯一子元素落在 flex-start,看起来像「漏掉了对齐」。同时 `.tb-right{flex-shrink:0}` 让内容永不换行,窄屏直接顶出容器被裁。

建议**全局一次修掉**(影响 5+ 页面,需逐页目视一次):

```css
/* main.css §页面统一工具栏 */
.page-toolbar .tb-right {
  margin-left: auto;   /* 单槽时也靠右;双槽时被 space-between 覆盖,无副作用 */
  min-width: 0;        /* 允许内部换行 */
  max-width: 100%;     /* 窄屏把宽度收敛回容器,配合内部 flex-wrap 换行 */
  justify-content: flex-end;
  flex-wrap: wrap;
}
```

- 窄屏还需要「整行让位」时,在页面 scoped 里加 `.page-toolbar .tb-right{width:100%}`(或统一放到 `@media (max-width:768px)`);
- **回归清单**:`/member` `/task` `/wish` `/diary` `/book` 五个单槽页面 + 所有双槽页面确认右槽未被推错;
- `PageToolbar` 组件本身不必改(它只负责 teleport 与占位),改的是 `main.css` 的槽位规则。

### 附带两类一致性(建议同批处理,但可独立排期)

- **数字格式**:记账本内 `money()` 统一改用 `utils/money.js` 的 `formatYuan`(千分位);`import { formatYuan } from '@/utils/loan'` 这类再导出引用改为直引 `@/utils/money`(口径单源)。
- **收支色**:`#67c23a` / `#f56c6c` 在 book 四个文件里硬编码;建议在 `main.css` 定义 `--color-income` / `--color-expense`(深浅色两套),各处引用变量(顺带能修深色模式对比度)。

## 5. 体检方法(可复用)

### 5.1 前置

1. 本机起服务:`frontend` 跑 `npm run dev`(5173,代理 `/api` → 8080),后端需在跑(记账本/家庭成员等页要登录态);
2. 登录一次(demo 账号即可,`userInfo` 与 `token` 落 `localStorage` 后刷新仍是登录态);
3. **不要并行跑 `npm run build`**(会争 `dist/` 与 `public/emulatorjs`,见 AGENTS 硬性禁令)。

### 5.2 探测脚本(粘进页面 `evaluate` 即可)

```js
// 一次输出四类问题:工具栏偏移 / 行内控件偏移 / 滚动条占位 / 右侧裁切
(() => {
  const sel = (el) => {
    if (!el) return '?';
    const cls = String(el.className || '').split(/\s+/).filter(Boolean).slice(0, 2).join('.');
    return el.tagName.toLowerCase() + (cls ? '.' + cls : '');
  };
  const rect = (el) => el.getBoundingClientRect();
  const cy = (el) => { const b = rect(el); return (b.top + b.bottom) / 2; };
  const out = { url: location.pathname, toolbar: [], inlineOff: [], scrollbars: [], clipped: [] };

  // A/B 工具栏槽位中线与裁切
  document.querySelectorAll('.page-toolbar, .game-topbar, .fp-topbar').forEach((tb) => {
    const kids = [...tb.children].filter((c) => rect(c).height > 0);
    if (kids.length < 2) {
      if (kids.length === 1) out.toolbar.push({ single: sel(kids[0]), justify: getComputedStyle(tb).justifyContent, right: Math.round(rect(kids[0]).right), tbRight: Math.round(rect(tb).right) });
      return;
    }
    const deltas = kids.map((k) => +(cy(k) - cy(tb)).toFixed(1));
    if (Math.max(...deltas.map(Math.abs)) > 1.5) out.toolbar.push({ sel: kids.map(sel), deltas });
  });

  // A 行内控件相对父容器偏移
  document.querySelectorAll('.el-radio-group, .el-input, .el-select, .el-date-editor, .el-button, .el-checkbox-group, .el-switch').forEach((c) => {
    const p = c.parentElement;
    if (!p) return;
    const pr = rect(p), cr = rect(c);
    if (pr.height - cr.height < 4) return;
    const d = +(cy(c) - cy(p)).toFixed(1);
    if (Math.abs(d) > 1.5) out.inlineOff.push({ el: sel(c), parent: sel(p), delta: d, parentDisplay: getComputedStyle(p).display, boxH: Math.round(pr.height), elH: Math.round(cr.height) });
  });

  // C 滚动条占位
  document.querySelectorAll('*').forEach((el) => {
    const cs = getComputedStyle(el);
    if ((cs.overflowX === 'auto' || cs.overflowX === 'scroll') && el.scrollWidth - el.clientWidth > 2) {
      out.scrollbars.push({ el: sel(el), sbH: el.offsetHeight - el.clientHeight, sw: el.scrollWidth, cw: el.clientWidth });
    }
  });

  // D 右侧裁切(祖先 overflow-x:hidden 会静默裁掉,所以按 .page 内容盒比)
  const page = document.querySelector('.page');
  if (page) {
    const pr = rect(page);
    document.querySelectorAll('.page *').forEach((el) => {
      const r = rect(el);
      if (r.width > 0 && r.right - pr.right > 2 && getComputedStyle(el.parentElement).overflowX !== 'auto' && out.clipped.length < 6) {
        out.clipped.push({ el: sel(el), over: Math.round(r.right - pr.right) });
      }
    });
  }
  return out;
})()
```

## 8. 验收标准
