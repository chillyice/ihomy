## 0. 一句话

**一条统一上报管道 + 两张数据表 + 一个指标目录**,客户端只负责「按目录读样本、按契约 POST」:

```
iOS 快捷指令(Apple 健康)─┐
Android 壳 Health Connect ─┼→ POST /api/health/ingest → 服务端归一/校验/聚合 → family_health_sleep(+stage) / family_health_sample → 网页只读展示
未来 iOS 原生包(可选)  ─┘
```

睡眠不是特例,只是因为它有「一晚 + 分期区间」结构,单独给两张表;其余指标(步数、心率、血氧、体重、运动…)统一走 `family_health_sample`,新增指标 = 在指标目录加一行,不加表、不加接口。

## 3. 数据面设计(按最全设计,按阶段实现)

### 3.1 指标目录(唯一来源)

三处同步,命名与 `DictConst` 同口径:

- 后端:`backend/src/main/java/com/ihomy/common/HealthMetric.java`(code、周期、单位、合理范围、i18n key)
- 数据字典:`sys_dict_item` 中 `dict_type='health_metric'`
- 前端:`frontend/src/utils/healthMetrics.js`(只做显示名/单位/小数位映射,不做范围判断)

**单位由目录定死,上报端不传单位**——传了就只做「与目录一致」校验,不一致整条拒收。避免「同一个指标混进 kg 和 斤」。新增指标 = 三处各加一行,表与接口不动。

**敏感组口径(第三轮拍板)**:

- 目录里**保留**该指标(客户端能力已在,关掉会白丢数据),但**服务端默认拒收**:`HealthIngestService` 在写库前查成员同意开关,未开启 → 整条以 `CONSENT_REQUIRED` 拒收,**不落库、不报错弹窗**(只在设置页统计里显示「敏感指标未开启,已跳过 N 条」)。
- 同意开关存 `sys_user_pref` 的键 `health.consent`(JSON,如 `{"reproductive":true}`),**不复用 localStorage 先行**(这是隐私授权,必须服务端为准);前端开关走专用端点 `GET/PUT /health/consent` 直接写库,不走 `/user-pref` 的推拉同步。
- 关闭开关时提供「同时清除已采集的敏感数据」选项(默认勾选),一次删干净。
- **敏感组数据仅本人可见**:即使有 `health:view`,他人(`family_health_sleep`/`sample` 查询)也不返回敏感指标行,OWNER 同样不例外;要放开需再拍板。

落地规矩:

- **双文件**:`schema.sql`(全量,带 `DROP TABLE`)+ `migrations.sql`(增量、`CREATE TABLE IF NOT EXISTS`,幂等),按 CI 同路径做空库全量导入实测(踩坑速查 §7.4)。
- **表数三处同步**:AGENTS「数据库约定」(`family_` 45→49、`sys_` 30→31)、需求 §6.2 清单、`doc-drift-check` 的期望值——漏一处闸门就红。
- **备份/迁移不用改代码**:备份按前缀自动分档(`family_health_*` → 基础数据、`sys_health_token` → 基础数据,见 `docs/数据备份与迁移.md` 前缀规则),**迁移包包含健康数据**(第三轮拍板),实现时只需在「生成迁移包」的二次确认文案里点明「含成员健康数据」。
- **审计表保留 90 天**:每日 04:20 清理(与 §3.5 的 POINT 清理同一次任务);写入失败只记 WARN,**不阻断读接口**。
- **派生表允许物理删**:`family_health_sleep` / `_stage` 是聚合产物,重算即替换;用 Mapper XML 物理删(MP `deleteById` 是软删语义,踩坑 §后端规范 5),表上不加 `deleted` 列并在 DDL 注释里写明理由。
- 索引按强制规范:等值列在前、时间范围在后;落地前 `EXPLAIN` 两条主要查询(`某成员某区间睡眠`、`某成员某指标趋势`)。

### 3.3 时间与时区口径

- 全表 `DATETIME` 沿用项目既有口径(**服务器本地时间**,无 TZ 列),家人同住一个时区,不引入 TZ 表。
- 上报端必须带 `timezone`(如 `+08:00`),服务端校验偏移在 ±14h 内;`DAY` 类样本按当地日折算 `start_time = 当地 00:00`,`sleep_date` 按当地日期算。偏移与服务器一致时等价于直存。
- `sleep_date` 规则:**入睡时刻早于 12:00 → 归前一天**,否则归当天;`09:00–20:00` 之间开始的会话 `kind=NAP`。

### 3.4 幂等与重算(唯一口径)

| 数据 | 幂等键 | 重复上报 | 厂商修正历史 |
|---|---|---|---|
| `family_health_sample` | `(user_id, metric, start_time, source_app)` | upsert,覆盖值 | 同键 upsert 自然覆盖 |
| `family_health_sleep` | `(user_id, source_app, start_time)` | 先按 `(user_id, source_app, [sleep_date 窗口])` **整窗物理删再插**(重算即替换) | 窗口重算自动纠正 |
| `family_health_sleep_stage` | 随 sleep 行级联重建 | 随重算删插 | 同左 |

重算并发:同一 `user_id + source_app` 的重算按 `user_id` 加 Redis 短锁(30s,失败重试 1 次),避免两个客户端同时上报把一晚删两次插两次。

### 3.5 容量与保留(生产 2GB 内存,必须先算)

- 每小时心率聚合 24 行/人/天,日聚合指标 ~10 行/人/天,睡眠分段 ~30 行/晚/人 → 每人每天 **< 70 行**;11 个用户一年 < 30 万行,可忽略。
- **禁止入库逐点心率**:客户端必须先做小时聚合(Android 用 `aggregate(...)` 按小时,HourlyAggregate),否则单人一天就上千行、且推送包体会被 2000 条上限卡死。
- 单请求上限:样本 **≤ 2000 条**、时间跨度 **≤ 31 天**;超限返回 `400` 并提示分批。
- 清理任务(V12.91 已落地):每日 04:20 清 `period='POINT'` 且 `start_time < now-180d` 的行(与天气日志清理同款;日聚合永久保留)。另按 Q8 的 90 天口径清 `family_health_view_log.createdAt`;**`family_health_sleep` / `family_health_sleep_stage` 永久保留**(分期是睡眠页唯一数据源,行数 ~30 行/晚/人,不值得为省这点空间牺牲历史);天数走 `app.health.point-retention-days` / `view-log-retention-days`,置 0 = 关闭该类清理。

## 4. 上报管道(唯一写入口)

### 4.1 请求契约

```
POST /api/health/ingest
Authorization: Bearer hk_<令牌>      (或登录态 access token,给网页/原生包用)
Content-Type: application/json

{
  "provider": "SHORTCUT",              // SHORTCUT | HEALTH_CONNECT | IOS_NATIVE
  "timezone": "+08:00",
  "samples": [
    {"metric":"STEPS","period":"DAY","date":"2026-11-16","value":8342},
    {"metric":"HEART_RATE","period":"POINT","start":"2026-11-16T08:00:00","end":"2026-11-16T09:00:00","avg":72,"min":58,"max":96,"count":12},
    {"metric":"SPO2","period":"POINT","at":"2026-11-16T23:10:00","value":97},
    {"metric":"WEIGHT","period":"POINT","at":"2026-11-16T07:12:00","value":68.4}
  ],
  "sleep": [
    {"start":"2026-11-15T23:41:00","end":"2026-11-16T00:55:00","stage":"DEEP","source":"Garmin"},
    {"start":"2026-11-16T00:55:00","end":"2026-11-16T06:58:00","stage":"LIGHT","source":"Garmin"},
    {"start":"2026-11-16T06:58:00","end":"2026-11-16T07:03:00","stage":"AWAKE","source":"Garmin"}
  ]
}
```

- `samples[].period=DAY` 用 `date`(当地日),`POINT` 用 `at` 或 `start/end+avg`。
- `sleep[]` 一律传**区间**,不传已聚合的会话——聚合一处在服务端实现,三端共用同一口径(避免「iOS 算的和 Android 算的不一样」)。
- 响应:`{code:0,data:{accepted,duplicated,rejected,rejectedDetail:[{index,metric,reason}]}}`,`rejectedDetail` 最多回 20 条。

### 4.2 服务端归一与校验(顺序固定)

1. `provider` / `metric` / `period` / `stage` 必须命中白名单;命中敏感组(`MENSTRUAL_FLOW`)时先查成员同意开关,未开启 → `CONSENT_REQUIRED` 整条拒收(不落库、不报错弹窗,只在设置页统计里显示「敏感指标未开启,已跳过 N 条」);
2. 范围校验按目录;超范围 **拒收不截断**(截断会把单位错误的数伪装成正常值);
3. 未来时间 > 现在 + 10min 拒收;
4. `timezone` 折算,`DAY` 落当地 00:00、`sleep_date` 按 §3.3 规则;
5. 样本 upsert;睡眠按 `(user, source_app, 窗口)` 重算整窗(§3.4);
6. 写 `sys_health_token.last_ingest_at`(令牌上报时);
7. 返回统计。**部分成功**:不合法的条目单独拒收,合法条目照常入库。

### 4.3 变量上限与防呆

- 单次 `samples+sleep` 合计 ≤ 2000 条;`sleep` 区间合计 ≤ 31 天;
- 每令牌 ≤ 60 次/小时;超限 `429`;
- 每用户每日入库上限 5 万行(防死循环自动化);超限只记日志并拒收,不写库。

### 4.4 令牌(长期、可吊销、最小权限)

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/health/token` | 生成,body `{name}`;明文 `hk_` + 32 字节 base64url **只返回这一次** |
| `GET` | `/api/health/token` | 列表(只回 `token_prefix` / `name` / `last_used_at` / `last_ingest_at` / `revoked`) |
| `DELETE` | `/api/health/token/{id}` | 吊销(只能吊销自己的) |
| `GET` | `/api/health/ping` | 令牌自检:返回本人 userId、familyId、`last_ingest_at`(给快捷指令/排障用) |

- 令牌只够 `POST /health/ingest` 与 `GET /health/ping`,其余接口一律 403。
- 鉴权实现:`HealthTokenFilter`(`Authorization: Bearer hk_...`)→ 按 SHA-256 查 `sys_health_token` → 构造轻量 principal(`userId`/`familyId`/`scope=HEALTH_INGEST`);**不碰 JWT 轮换、不写 refresh、不触发 OPS 判定**。与 `JwtAuthenticationFilter` 的顺序:JWT 先试,失败且形如 `hk_` 才走令牌。
- 明文不落库、不写日志(日志只记 `token_prefix`)。家庭切换后按成员**实时**解析 `family_id`,不信签发时快照(与 JWT 快照的差异在此显式写一行注释)。

## 5. iOS 快捷指令(无 App 通道)

### 5.1 用户侧步骤(写进帮助页)

1. ihomy 网页 → 设置 → **健康数据同步** → 生成令牌(设备名填「iPhone 快捷指令」)→ 复制;
2. iPhone「快捷指令」新建「ihomy 健康上报」;
3. **日聚合**:对 步数 / 静息心率 / 体重 / 血氧 / 呼吸率 / 活动消耗 分别「查找健康样本」(今天/昨天)→「统计总和 / 平均值」→ 存入字典;
4. **睡眠**:「查找健康样本」类型=睡眠分析,范围=昨天 18:00 至今 →「重复」逐条取「开始日期 / 结束日期 / 值」→ 构造 `sleep` 数组中的字典;
5. 「获取 URL 内容」:`POST https://<host>/api/health/ingest`,请求头 `Authorization: Bearer hk_...`、`Content-Type: application/json`,请求体用**词典/JSON 文件**(不要手拼字符串,中文与引号会转义失败);
6. 自动化:「到达时间 每天 09:00」→ 关闭「运行前询问」;也可再加一条「打开 Garmin Connect 时」;
7. 自查:浏览器打开 `/api/health/ping` 或页面上看「最后上报时间」。

### 5.2 已知限制与对策

| 限制 | 对策 |
|---|---|
| 快捷指令跑不了 refresh 流程 | 用 §4.4 的长期令牌;页面显式提示「令牌泄露就来吊销」 |
| 取不到样本「来源」 | `source` 固定 `APPLE_HEALTH`、`source_app` 固定 `APPLE_HEALTH`,展示层写「来源:Apple 健康」 |
| 睡眠分析的「值」在快捷指令里是否给到分期名(深睡/浅睡/REM/清醒)**需真机实测** | 拿得到分期 → `stage_level=FULL`;只有起止 → 只传 `INBED`/`UNSPECIFIED`,`stage_level=SUMMARY`;两者都进同一张会话表 |
| 循环上千样本会慢/超时 | 单次跨度 ≤ 31 天、按指标拆多次调用;首次回填只补最近 30 天 |
| 后台自动化在低电量/未解锁时可能不跑 | 页面显示「最后上报时间」,超过 48h 提示「打开快捷指令手动跑一次」 |
| 本地开发 `http://` 被 iOS ATS 拦 | 只在生产 HTTPS 上验收;开发期用真机连内网 https 或先在 Android 验证管道 |

### 5.3 首版快捷指令范围(P0)

睡眠 + 步数 + 静息心率 + 体重 + 血氧(五项),跑通即算 P0 验收;其余指标按 §3.1 目录逐步加进快捷指令(纯用户侧配置,后端零改动)。

### 5.4 可分享模板(后补)

做一条 iCloud 共享链接的「快捷指令安装模板」(用户点开导入后只填令牌),放帮助页;若用户量足够再考虑。

### 6.2 读取与聚合口径(与 §4.1 契约对齐)

| 指标 | 读法 | 上报 |
|---|---|---|
| 日聚合(步数/距离/能量/楼层/锻炼/站立/正念) | `aggregate(COUNT_TOTAL / TOTAL / AVERAGE, 当地日区间)` | `period=DAY` |
| 心率 | `aggregate(HeartRateRecord.BPM_AVG/MIN/MAX, 按小时桶)` | `period=POINT` + `avg/min/max/count` |
| 静息心率 / HRV / 呼吸率 | 当日记录聚合(多条取平均) | `period=DAY` |
| 血氧 / 体温 / 体重 / 体脂 / 身高 | `readRecords` 逐条(低频指标) | `period=POINT` |
| 睡眠 | `SleepSessionRecord.stages` → 逐段区间 | `sleep[]` 区间(不聚合) |

**禁止**:把逐点心率原始样本直接上报(见 §3.5);跨来源混算(每个 `dataOrigin.packageName` 单独上报一行,服务端一来源一行)。

### 6.3 增量与触发

- 增量:`changesToken` 持久化到 SharedPreferences(按 user + 权限组),首次回填 **90 天**,之后只取变更;
- 触发:App 启动一次(`appStateChange`) + 手动「立即同步」按钮 + 每日一次 WorkManager(P1);iOS 不做后台定时;
- `lastSyncAt` 本地保存,页面显示「最后同步时间」。

### 6.4 部分授权与降级

`requestPermissions` 只返回用户实际授予的集合 → 插件按组读取,**未授权组跳过并把组名回给页面**;页面显示「睡眠已连接 / 体征未授权」。不做「必须全给才能用」。

### 6.5 插件形态

- `frontend/android/app/src/main/java/top/ihomy/app/health/HealthDataPlugin.java`(`@CapacitorPlugin(name = "HealthData")`),方法:`isAvailable()` / `requestPermissions({groups})` / `grantedGroups()` / `sync({days})` / `lastSync()`;

## 11. 验收标准

1. **P0**:快捷指令手动跑一次 → `select metric,start_time,value_num from family_health_sample where user_id=? order by id desc limit 10` 有今日步数/静息心率等;`select sleep_date,total_min,deep_min,stage_level,source from family_health_sleep order by id desc limit 3` 有昨晚记录;再跑一次行数不变。
2. 重复与修正:同一晚追加两段区间再上报 → 该晚仍只有一行且分期分钟数变大(整窗重算生效)。
3. 鉴权:`Bearer hk_...` 只能打 `/health/ingest`、`/health/ping`;吊销后立刻 401;无 `health:view` 的成员读他人 `overview` 得 403;跨家庭 NOT_FOUND;游客空数据不 NPE。
4. 限额:一次 2001 条 → 400;61 次/小时 → 429。
5. Android:未授权体征组时同步不报错、日志只有已授权组;心率入库为小时聚合(单用户单日 < 30 行)。
6. 构建:`.\mvnw.cmd -B clean package` 全绿;`npm run lint` + `npx vitest run` + `npm run build` 通过;`bash scripts/doc-drift-check.sh` 全 [OK](表数/权限码/路由/导航均已同步);空库全量导入 `schema.sql` + 存量库跑 `migrations.sql` 双向通过。

## 15. 明确不做

- ❌ 厂商云 B2B(Garmin Health API / 华为 Health Kit 商务申请)——只在深度字段缺口出现时单独立项。
- ❌ 第三方聚合 SaaS(Terra/Vital/Rook)与数据出境。
- ❌ 服务器侧用账号密码代登录抓厂商数据(违反 ToS、封号风险、需处理 MFA)。
- ❌ 医疗级评分、睡眠呼吸暂停判断、健康告警推送(资质与责任边界)。
- ❌ 健康数据进家庭动态流 / 排行榜 / 积分 / 公开接口。
- ❌ 浏览器端直接读健康数据(W3C 无此 API);「网页读手表」类方案一律不做。
- ❌ 为单个指标建表(新增指标只加目录一行)。
- ❌ **敏感指标(生殖健康)的跨成员展示**:仅本人可见,OWNER 亦然;要放开需重新拍板。
- ❌ **一台设备多账号上报**:payload 不带 `userId`,`userId` 只取令牌;共用手机 = 共用账号。
- ❌ 饮水/营养/咖啡因、情绪/心态、ECG/房颤/跌倒检测、听力与环境噪音、日照时长、GPS 轨迹。
- ❌ 步数/睡眠换积分、家庭排行榜、任何形式的数据竞赛(与「不进动态流」同口径)。
