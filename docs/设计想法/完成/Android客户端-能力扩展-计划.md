## 0. 一页摘要

### 0.1 一句话

第一批把 ihomy **装进了手机**;这一批让它在你**不打开它的时候也有用**。

### 0.2 三条主线

| 主线 | 要解决的问题 | 对应条目 |
|---|---|---|
| **可靠** | 该响的时候响不了、坏了查不出原因 | A1 提醒兜底自愈、A3 诊断回传 |
| **自动** | 什么都要手动打开才知道 | A2 后台未读、B1 相册自动备份 |
| **家庭场景** | 手机/平板只是缩小版网页 | A4 应用锁、B2 锁屏播控、B3 平板看板与相框、B5 手柄 |

### 0.3 判断口径:什么才值得写原生

| 需求 | Web / WebView 能不能做 | 结论 |
|---|---|---|
| App 没启动时到点响铃 | ❌ JS 在后台被冻结,`setTimeout` 不可靠 | 必须原生(第一批已做) |
| 定期(≥15 分钟)在后台拉一次数据 | ❌ 页面关闭即停 | WorkManager |
| 读系统相册全量增量 | ❌ `<input type=file>` 只能用户逐个手选 | MediaStore |
| 锁屏/耳机键控制播放 | ⚠ 能(`navigator.mediaSession`),但**后台持续播放**要前台服务 | 分级做,先做轻的 |
| 离开 App 后要求指纹才能再进 | ❌ 页面不在前台就没有入口 | 原生壳拦截 |
| 界面 / 表单 / 列表 / 图表 | ✅ 全部能做且做得更好 | **一律 Web,不写原生** |

**一句话**:凡是「关掉界面还要继续跑」或「要碰系统数据/系统 UI」的才写原生,其余全在前端。

### 0.4 分期

| 阶段 | 内容 | 估算 | 交付 |
|---|---|---|---|
| **P0** | 可靠性地基:A3 诊断回传 → A1 提醒兜底 → A2 后台未读 | 4–6 天 | 出问题能自己拿到日志;漏排的闹钟能自愈;未读能冒出来 |
| **P1** | 自动化:B1 相册自动备份(+ 表加列) | 3–5 天 | 拍完照不用手动传 |
| **P2** | 家庭场景:A4 应用锁 → B3 平板看板/相框 → B5 手柄 | 4–6 天 | 家里的闲置平板能派上用场 |
| **P3** | 评审制:C1 保险箱自动填充、C2 推送通道 | 另立计划 | 有明确前置条件才启动 |

> 估算是「熟悉这套壳之后」的人日,不含真机验收时间。

### 0.5 关键决策(定了就不再重新讨论)

| # | 决策 | 理由 | 被否备选 |
|---|---|---|---|
| D1 | 继续**自写 Java 插件**,不引第三方原生 npm 包 | 沿用第一批口径:壳里少一个依赖就少一处与 Capacitor 大版本绑定的风险 | `@capacitor/*` 生态包、各种 autofill/播放器 SDK |
| D2 | 后台能力**一律 WorkManager**(系统最短 15 分钟),不做常驻保活、不申请前台服务(除 B2-L2) | 生产求稳 + 国产 ROM 上保活必然失败,不如把「打开 App 即自愈」做好 | 双进程守护、1px 通知保活 |
| D3 | **绝不读写 `@capacitor/local-notifications` 的私有存储格式** | 那是第三方内部实现(SharedPreferences 里的 JSON),插件一升级就碎 | 原生侧直接注册/重排闹钟 |
| D4 | 相册备份的幂等**靠服务端 `checksum` 唯一键**,客户端不算业务规则 | 换机重装、多人同时备份都能兜住 | 客户端记已传文件名(换机即失效) |
| D5 | 后台能力继续用 `type=WIDGET` 最小权限令牌,**新增路径一条条加白**,不开前缀通配 | 白名单多写一行代价很低,通配一次就把写接口也让出去了 | 复用普通 access token |
| D6 | 客户端**不算**农历/日期/月供/循环期次(沿用第一批 D4) | 唯一计算源在服务端(`RepeatSchedule`/`AnniversaryDate`/`utils/loan.js`) | 客户端复刻 |

## 1. 目标与非目标

### 1.1 目标

- **提醒漏了能自愈**:长期不开 App、网页端改过提醒,都能靠一次点击回到正确状态。
- **不打开也有信息**:有人找你、有未读通知,锁屏上能看见(不承诺秒级)。
- **照片自己进相册**:拍完照在 Wi-Fi 下自动上传,不重复、不丢。
- **手机/平板更像「家里的设备」**:离开锁、闲置当看板/相框、接手柄玩游戏。
- **出问题能查**:崩溃与前端报错能拿到本地文件,不必让用户描述。

### 1.2 非目标

- ❌ 不做**即时通讯级**推送(30 分钟粒度,文案要如实说)。
- ❌ 不做 iOS(架构不阻塞,但本期不实现、不验收)。
- ❌ 不改业务口径:提醒/账本/权限仍以服务端为唯一事实源。
- ❌ 不做离线写入(离线只读 + 排队提示)。
- ❌ 不做「杀掉 App 仍常驻后台」。
- ❌ 不为新能力新增一套权限模型(沿用 `@RequirePermission` + 家庭隔离)。

### 2.2 已确认缺失(本计划的靶子)

| # | 缺失 | 证据 | 影响 |
|---|---|---|---|
| 1 | 提醒注册只覆盖 **今天 → +30 天**,上限 200 条 | `src/native/reminders.js` 的窗口与 `MAX_SCHEDULED` | 30 天外的期次从未排过;网页端改过的提醒要等下次开 App 才对齐 |
| 2 | 后台**没有**任何拉取(除卡片 Worker) | `widget/WidgetWorker.java` 只刷卡片 | 不打开就不知道有人找你 |
| 3 | 崩溃 / 前端报错**没有任何落盘** | 全仓 grep 不到 `UncaughtExceptionHandler` / `window.onerror` | 真机问题只能靠用户口述 |
| 4 | 相册**无自动备份**,`content_photo` 无 `checksum` | `schema.sql` 的 `content_photo` 列清单 | 拍照后要手动进相册逐张上传 |
| 5 | 音乐是裸 `<audio controls>`,无媒体会话 | `views/music/Music.vue` L399 | 锁屏看不见曲名,切后台可能被暂停 |
| 6 | 离开 App 无二次校验 | `native/biometric.js` 只服务保险箱 | 手机借人/丢了的窗口期无防护 |
| 7 | 游戏只吃触屏与键盘 | `composables/useGameView.js` | 接了手柄用不上 |

### 2.3 必须接受的三个约束

1. **生产是 2GB 机器**:任何「服务端定时扫全表」「上传就算哈希」的设计都不许进。
2. **WorkManager 最短周期 15 分钟**,系统还会合并批处理并在低电量时推迟 → 后台能力一律按「约 30 分钟」承诺,不写「实时」。
3. **国产 ROM 会杀后台**:华为/小米的「应用启动管理」默认限制非白名单应用的后台任务 → 所有后台能力的**兜底都是「打开 App 就自愈」**,后台只是加速手段。

## 4. 分期与验收

### 4.1 P0 可靠性地基(4–6 天)

顺序刻意是 **A3 → A1 → A2**:先把「出问题能拿到证据」建起来,后两个的真机排查都靠它。

**验收**

1. `adb shell am crash top.ihomy.app` → `<files>/diagnostics/` 出现崩溃文件,含机型/系统/App 版本/堆栈;重启 App 后在设置页能看到条目并导出。
2. 把设备时间调到 9 天后模拟「长期未开 App」→ Worker 发出一条「近期日程」提示通知;点开进 `/plan?tab=today`,随后 `dumpsys alarm` 能看到新的 `TimedNotificationPublisher` 闹钟。
3. 网页端改一条提醒时间 → 不开 App 等一轮 Worker → **本地不会双响**,点提示进 App 后闹钟时间对齐。
4. 收到聊天消息 → 不开 App,约 30 分钟内锁屏出现一条合并通知;再收一条不堆叠(同一 id 覆盖)。

### 4.2 P1 相册自动备份(3–5 天)

**验收**

1. 授权后首次备份:超过 90 天的旧照片**不上传**;近 90 天全部上传到「手机备份」相册。
2. 断网备份 → 失败的逐张重试(下次备份继续),**不重复上传**(服务端返回 `skipped`)。
3. 手机上删掉一张已备份照片再重新备份 → 不产生重复条目。
4. Wi-Fi 开关关掉 → 移动网络下不备份并给出提示;充电开关关掉 → 断连充电也照常备份(开关语义要在 UI 写清)。

### 4.3 P2 家庭场景(4–6 天)

**验收**

1. 应用锁:切后台 6 分钟回 → 指纹门;取消 → 回登录页;系统里删掉指纹后开关自动关闭,不会把用户永久挡在外面。
2. 保险箱页 `adb shell screencap` 全黑(最近任务缩略图同步变黑),离开该页后截图恢复正常。
3. 看板:横屏平板进 `/kiosk`,屏幕常亮;长按 3 秒 + 指纹退出;1 小时后不烧屏(元素有位移)。
4. 手柄:接上后模拟器方向键/AB 可用;小游戏方向键可操作;断开后触屏立刻恢复。

### 4.4 P3 评审制

C1 需先出一页安全评估(明文链路、缓存时长、审计、撤销),C2 需先算清服务器常驻成本。两者都不在本计划的实施范围内。

## 5. 详细设计

### 5.1 A1 提醒兜底自愈

**先看清楚缺口有多大**。现有链路(`src/native/reminders.js`):

- 窗口「今天 00:00 → +30 天」、上限 200 条;
- 触发时机只有三个:**冷启动 4 秒后**、`appStateChange.isActive`(回前台)、**通知动作处理完成后**;
- 重启手机**不用管**:`@capacitor/local-notifications` 自带 `LocalNotificationRestoreReceiver`(已注册 `BOOT_COMPLETED` / `LOCKED_BOOT_COMPLETED` / `QUICKBOOT_POWERON`),会从自己的存储恢复已排闹钟。

所以真实缺口只有两个,不要夸大:

1. **30 天窗口外的期次从未排过**(长期不用手机的用户,或每月重复但恰好跨窗);
2. **网页端改了/删了提醒,而 App 一直没打开** → 本地仍是旧闹钟,可能**多响一次**。

**方案:A 级(自愈提示),不做 B 级(原生注册)**

新增 `reminder/StaleCheckWorker`(WorkManager,每日 1 次,约束「有网」):

```
if (now - lastJsSyncAt > 7 天) {
    items = GET /schedule/occurrences?from=today&to=+30d   // WIDGET 令牌已放行 /schedule/
    if (items 里未来 3 天有 >=1 条 && lastNudgeDate != today) {
        notify(通道 reminders-v2, 标题「最近的日程等你确认」,
               正文「有 M 条日程,点一下打开 ihomy 校准提醒」,
               深链 ihomy://plan?tab=today)
        lastNudgeDate = today
    }
}
```

- `lastJsSyncAt` 由 `reminders.js` 在 `syncNotifications()` 成功后写入(**与插件存储无关的独立键**),原生只读。
- 这条通知**不代表任何一条日程**,不参与对账,不进 200 条上限,点开就是打开 App → `appStateChange` 立刻触发真正的重排。
- **幂等**:`lastNudgeDate` 一天最多一条;已有未读时不叠加。

**为什么不选 B 级(原生直接注册闹钟)**:要复刻 `reminders.js` 的 FNV-1a key 算法、以及插件的私有存储格式;插件升级一次就碎,而且与 JS 侧必然形成两套闹钟源 → **双响**。见 D3。

**成本**:1 天多;风险只剩「提示太吵」,用 7 天与 1 天两条闸门压住。

### 5.2 A2 后台未读通知

**不新增周期任务**,直接扩 `widget/WidgetWorker.java`(已是 30 分钟、已带 WIDGET 令牌与 HTTP 栈):

```
n = GET /notification/unread-count      // 新增白名单
c = GET /chat/unread                    // 新增白名单(取 total 字段)
if (n + c > 0 && (n != lastN || c != lastC)) {
    notify(id = 固定值, 标题 = t('后台通知标题'),
           正文 = 「聊天 2 条 · 通知 3 条」, 两个 action: 打开聊天 / 打开通知)
    lastN, lastC = n, c
}
```

- **固定通知 id** → 后一条覆盖前一条,不堆栈;内容没变就不重发(靠 `lastN/lastC` 比对)。
- **夜间静默 23:00–06:00**,与提醒口径一致。
- 设置页新增开关(默认开),关掉即取消该分支(Worker 仍刷卡片)。
- **文案必须如实**:「约每 30 分钟检查一次」,禁止写成「新消息提醒」。

**风险**:国产 ROM 会限制 WorkManager → 兜底仍是「打开 App 即自愈」(前台 WebSocket 本来就是实时的)。

### 5.3 A3 诊断回传

不自建后台、不接第三方 SDK:

| 层 | 采集点 | 落地 |
|---|---|---|
| 原生崩溃 | `Thread.setDefaultUncaughtExceptionHandler` | `<files>/diagnostics/crash-<ts>.txt`(机型/Android 版本/App 版本/堆栈,≤64KB,滚动留 5 份),**写完后走默认处理**(不吞崩溃) |
| 前端报错 | `window.onerror` / `unhandledrejection` / `console.error` | 内存环形缓冲 200 条;`native/diagnostics.js` 提供 `snapshot()` |

- 设置页「诊断信息」块:显示崩溃份数与前端错误条数 → 「导出」把合并后的文本交给 `@capacitor/share`(用户自己发给我)。
- **不做自动上传**:要新增接收端点、要考虑家庭隔离与隐私,收益不匹配;真需要时再谈。
- 注意 `webContentsDebuggingEnabled` 在生产包必须保持关闭(第一批已如此),诊断靠落盘而非远程调试。

### 5.4 A4 应用锁

- 复用 `IhomyBiometric`(`available` / `verify` / `cancel`),**不新增插件**。
- `appStateChange` 记 `pausedAt`;回前台若 `now - pausedAt > 阈值`(1/5/15 分钟,默认 5)→ `verify()`;取消 → 退出到登录页(不留在页面里)。
- **必须有的降级**:系统里没有可用生物识别、或用户删掉了指纹 → 设置页开关自动关闭(沿用保险箱已有的处理),否则会被永久挡在锁屏。
- **最近任务缩略图**:全局 `FLAG_SECURE` 会让截图/录屏全黑(用户会骂),只在 `/vault` 与设置页保险箱段打开,**离开即清除**。

### 5.5 B1 相册自动备份

**表结构**(表数不变 92,只加列):

```sql
ALTER TABLE `content_photo`
  ADD COLUMN `checksum` VARCHAR(64) DEFAULT NULL COMMENT '内容 SHA-256(客户端计算,自动备份幂等用)';
CREATE UNIQUE INDEX `uk_family_checksum` ON `content_photo` (`family_id`, `checksum`);
```

- 存量数据全 `NULL`,MySQL 唯一索引允许多个 `NULL` → **不影响任何现有照片**,不必回填。
- 不能复用 `source_path`(它的语义是「网盘同步去重路径」,见 `schema.sql` 该列注释)。

**客户端**

- 目标相册:按 `content_photo_album.source_device_id` 找「本机备份相册」,没有就用现有相册创建接口建一个(名字走 i18n,如「手机备份」);**不靠名字匹配**,否则用户手建同名相册会被写进去。
- 游标:`MediaStore.Images` 按 `DATE_ADDED` 增量,游标存 `SharedPreferences`;首次按「近 90 天」截断。
- 上传:逐张 multipart 流式(`FormData` + `File`),**并发 1**(省 WebView 与服务端内存);单张失败记入重试队列,下次备份继续。
- 权限:`READ_MEDIA_IMAGES`(Android 13+)/ `READ_EXTERNAL_STORAGE`(≤12,minSdk 29 需要);Wi-Fi / 充电两个开关。
- **服务端不算哈希**:客户端传 `checksum`,服务端只做唯一键冲突 → 捕获后返回已有 `photoId` 并计入 `skipped`。大文件读全量算哈希会打穿 2GB 机器的内存与 IO。

**风险**:首次全量可能几千张 → 默认 90 天 + 手动「全部备份」二次确认,并在 UI 显示已传/待传条数。

### 5.6 B2 音乐:L1 锁屏播控

- **L1(做,0.5 天)**:`views/music/Music.vue` 播控处接 `navigator.mediaSession`(WebView 支持):`metadata`(曲名/歌手/封面)+ `setActionHandler`(`play`/`pause`/`previoustrack`/`nexttrack`/`seekto`)。锁屏与耳机键即可控制,零原生代码,零体积。
- **L2(不做,见 §9)**:原生 `ExoPlayer` + 前台服务 `mediaPlayback` —— 等于重写播放器(进度/歌词/顺序/随机/后台续播),收益是「切到别的 App 音乐不停」,风险与工时都不匹配。

### 5.7 B3 平板看板 / 相框

- 新增壳内独享路由 `/kiosk`(`meta.standalone`,不套侧栏/底栏):
  - 左:大号时钟 + 日期 + 天气;右:今日日程(来源 `/schedule/upcoming`);底部:相册照片缓慢轮播。
  - **屏幕常亮**:新增极小的 `IhomyScreen` 插件(`keepOn` / `keepOff`),`FLAG_KEEP_SCREEN_ON`,不需要权限。
  - **防烧屏**:元素每 60 秒位移 ±8px(CSS `transform`,不用 rAF 写 ref)。
  - 退出:长按 3 秒 + 指纹(防客人乱点)。
- 入口:`AppSettings` 「看板模式」;平板自动提示一次,不强制。

### 5.8 B5 游戏手柄(前端活)

- `navigator.getGamepads()` 在 Android WebView 可用 → 不需要原生代码。
- 新增 `composables/useGamepad.js`:rAF 轮询手柄状态,**只派发 `KeyboardEvent`,不写任何响应式 ref**(符合 AGENTS 前端规范 15/17);映射方向键 + ABXY → 各小游戏已有的键盘控制;模拟器(EmulatorJS)本身支持手柄,只需在 `useGameView` 里做「手柄已连接」提示。
- 首次按键才生效(可能需要一次用户手势),UI 上给一句提示。

### 5.9 明确不做的三条,理由写在这里

| 能力 | 为什么不做 |
|---|---|
| 投屏(Cast / DLNA) | Chromecast 依赖 Google Play services,国内设备普遍没有;自写 SSDP + AVTransport 的 DLNA 要 5–8 天人日,而「投到电视」的替代方案是电视浏览器直接打开站点,收益不匹配 |
| 地理围栏(到家提醒) | 需要 `ACCESS_BACKGROUND_LOCATION`(商店政策严、国产 ROM 后台定位被杀),家庭场景打开率低,且「回家」用提醒/日历足够 |
| 增量更新(bsdiff) | APK 53.9MB(emulatorjs ≈30MB + ruffle ≈28MB),全量下载在家庭 Wi-Fi 下可接受;增量要维护补丁生成、签名对齐与回滚,链路复杂度远超收益 |

### 5.10 C1 保险箱自动填充:前置条件(只写要点,不排期)

技术上可行:AutofillService 是**原生服务**,明文不进 WebView,反而比现在的「网页里点眼睛看密码」更收敛。障碍在**凭证链**:

- 现在 `POST /vault/{id}/password` **必须重新输入登录密码**(`VaultRevealDTO`),填一次密码才能自动填一次是不可用的体验;
- 要免密,就必须有一条「本机生物识别解锁 → 换取短时只读凭证」的通道(类似 `type=AUTOFILL` 令牌 + 5 分钟本地缓存),而这条通道等于**把保险箱明文暴露给客户端进程**;
- 必须先有:专用只读端点、逐条审计日志、撤销机制、`family_id` 与 `visibility` 双重校验、明文内存清零策略。

→ **先出一页安全评估再谈**,本计划不实施。

### 5.11 C2 推送通道:另立计划

自建 ntfy/UnifiedPush(或 FCM,但国内无 GMS)需要在 2GB 机器上常驻一条长连接或一个中继服务。落地之后:A2 的轮询可以退役,**通知快捷回复(`RemoteInput`)才算有了载体**(第一批 P3 已把它标为「等推送」)。

## 9. 明确不做 / 容易跑偏的地方

- ❌ **原生侧直接注册/重排闹钟**(会碎 + 双响)。
- ❌ **常驻后台保活 / 双进程守护 / 1px 通知**(违背求稳原则,且国产 ROM 上无效)。
- ❌ **原生重写播放器(L2)**,除非用户明确抱怨「切出去音乐就停」。
- ❌ **服务端为去重读整文件算哈希**(2GB 机器读几张 10MB 图就换页)。
- ❌ **自动上传崩溃日志**给服务端(隐私 + 新端点 + 审计,收益不匹配)。
- ❌ **为后台能力放宽家庭隔离或新增一套权限**(后台令牌仍只读、仍按家庭校验)。
- ❌ **客户端算农历/日期/循环期次**(沿用第一批 D4)。
- ❌ **投屏 / 地理围栏 / 增量更新 / 扫码**(理由见 §5.9 与 §3.3)。
- ❌ **把「家庭年鉴 / 年度回顾」当成壳能力**:它是纯前端 + 服务端聚合,该另立功能计划,不要混进本文件。

## 实施差异

> 落地过程中与本文不一致的地方记在这里(格式:`A?/B? — 原计划 / 实际 / 原因`)。

- **B1 — 后台 Worker + SharedPreferences 游标 / 实际只在前台触发,游标存 localStorage**:后台备份的写接口不能放进 `type=WIDGET` 只读白名单,另开写令牌通道超出本批安全面;改为 App 启动/回前台/手动点击触发(10 分钟节流),D4 幂等口径不变。
- **B1 — 按 `content_photo_album.source_device_id` 找备份相册 / 实际新增 `backup_key VARCHAR(64)` 字符串键**:`source_device_id` 的语义是「设备目录映射来源 ID」(存储映射域),混用会搅乱映射相册口径;`android:<设备标识>` 字符串键服务端只校验形状,建相册/找相册/恢复回收站共用一个键,`content_photo_album` 也加了列(原计划只写 `content_photo`)。
- **B1 — 单张失败进重试队列 / 实际单张失败整轮停下,游标停在上一张成功处**:下次备份从游标继续,等价于重试队列但不维护额外数据结构;>30MB 的单张返回 `tooLarge` 跳过但游标照走,不会永远卡住。
- **B2-L1 — 只接 `views/music/Music.vue` 播控处 / 实际全局 `MusicPlayer.vue` 优先接入,页内试听也接了一份**:锁屏场景大头是全局浮窗播放器;两个持有者按 owner 隔离,关闭试听弹窗只清自己的会话。
- **B3 — 平板自动提示一次 / 实际只在设置页加「看板模式」按钮**:自动弹提示会打断正常手机使用;入口保持手动,未进 `navModules.js`。
- **B5 — 模拟器在 `useGameView` 里做「已连接」提示 / 实际模拟器页(`EmulatorPlayer.vue`)完全不接适配器**,只显示「手柄由模拟器直接支持」静态说明——EmulatorJS 自带手柄支持,再派发键盘事件会双输入。
- **A2 — D2「不做常驻保活/不申请前台服务」/ 2026-11-11 V11.98 改为常驻前台服务(30 秒轮询)**:用户明确要求「App 要能后台运行、有消息后台能收到」,30 分钟 WorkManager 满足不了;采用 `foregroundServiceType="remoteMessaging"` + 通知栏一条常驻低优先级通知(Android 硬要求),设置页开关关闭即停,WorkManager 保留为兜底。只读 `chat/unread` + `notification/unread-count`,不开写接口、不扩白名单。
