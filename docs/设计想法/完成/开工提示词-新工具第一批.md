# 工具箱新工具第一批 · 开工提示词

> 复制本文件全文给任意新会话即可开工。目标：在 ihomy 落地三个纯前端工具，并留下可被 bit_pouch 直接消费的清单与代码出口。
> 关联：`docs/设计想法/功能/工具箱/` 为本次设计与实施记录目录；产品关系见 `docs/需求设计说明书.md` §4.12 与 §4.14.1。

## 0. 一句话目标

在 ihomy 工具箱新增 **哈希与校验、随机生成器、时间工具箱** 三个页面，全部纯前端、匿名可用；同时把工具元数据收敛成单一清单，并导出为 bit_pouch 插件可用的 `manifest.ts + core.ts + run.ts + run.spec.js`。

## 1. 背景与产品关系

- ihomy 是各类开发者小工具的**先发与测试平台**；bit_pouch（独立仓 `Projects/bit_pouch`）是这些工具的**实体程序集合**。
- bit_pouch 的插件约定（见其 `.agents/skills/plugin-author/SKILL.md`）：
  - 一个工具 = `src/plugins/<id>/manifest.ts` + `run.ts` + `View.vue`（+ `run.spec.js`）。
  - `run(input, options, ctx)` 必须是纯函数，返回 `{ ok, output?, data?, stats?, error? }`。
  - 错误返回 `ok:false`，`error.message` 按 `ctx.locale` 本地化，禁止抛裸异常。
  - 清单是纯数据：`id / name{zh,en} / description{zh,en} / category / icon / keywords / version / runtime / platforms / offline / order`。
- 因此 ihomy 侧的核心逻辑必须与 `run` 同构，视图只做交互，算法不复制。

## 2. 本次范围（只做这三个）

| 工具 | 路由 | 核心能力 |
|---|---|---|
| 哈希与校验 | `/tools/hash` | MD5 / SHA-1 / SHA-256 / SHA-384 / SHA-512 / CRC32；文本与文件；hex/base64；HMAC（SHA 系）；期望值比对 |
| 随机生成器 | `/tools/generator` | 密码 / PIN / UUID v4·v7 / ULID / NanoID / 随机字节 / 随机整数 / 抽签洗牌分组；熵与强度提示 |
| 时间工具箱 | `/tools/time` | 时间戳（秒/毫秒）↔ 本地/UTC/ISO；时区换算；日期差与日期加减；Cron 解析与未来执行时间 |

明确不做：后端接口、网络探测、二维码、图片处理、颜色工具、运维命令库（留给后续批次）。

## 4. 硬性规范（来自 AGENTS.md）

- 页面根容器 `class="page"`；面包屑 + `PageToolbar`；不写页面级 H1/H2；分区标题 `.section-label`。
- 所有用户可见文案走 `$t()`；中英键结构必须一致；文案字面量 `{`/`}`/`@` 要转义。
- `<script>` 内算法与数据不进模板；`computed` 内禁止 `Math.random()`/`Date.now()`。
- 工具页全部懒加载；重计算放 Worker 或显式按钮触发；输入不落 localStorage（仅偏好可落）。
- 复制按钮统一 `ElMessage.success(t(...))`；失败给可读提示。
- 不新增 npm 依赖（MD5/CRC32/Cron 手写；SHA/HMAC 用 WebCrypto）。
- 新增文件后跑 `npm run lint`、`npx vitest run`、`npm run build`，入口 chunk 不得明显增长（三个页面都是异步 chunk）。

## 5. 核心契约

```js
// 所有 core 导出同构 run
export async function run(input, options, ctx) {
  // ctx = { locale: 'zh'|'en' }
  // 成功: { ok: true, output, data, stats }
  // 失败: { ok: false, error: { code, message } }
}
```

- 错误码稳定、可测：`empty` / `tooLong` / `invalidInput` / `outOfRange` / `invalidAlgorithm` / `cryptoUnavailable` / `fileTooLarge` / `invalidCron` 等。
- 算法函数另行导出，便于 bit_pouch 直接复用与单测（如 `md5(bytes)`、`crc32(bytes)`、`parseTimestamp`、`nextCronRuns`）。
- 不读取 `window`/`document`/`localStorage`/网络；时区通过 `options.timeZone` 传入，默认运行环境时区。

## 6. 页面验收

### 哈希与校验
- 文本：粘贴即出全部选中算法；支持 hex/base64 切换；空串可算（合法）。
- 文件：选择文件后算出同名摘要；超过上限给出可读提示；文件不离开浏览器。
- HMAC：填密钥后出现 HMAC 结果；密钥不落盘、不显示在结果里。
- 比对：粘贴期望值，命中/不命中明确标识（大小写不敏感）。

### 随机生成器
- 密码：长度、字符集、排除易混淆、至少各取一个；显示熵（bits）与强度档位。
- UUID v4 / v7、ULID、NanoID、随机字节、随机整数、抽签/洗牌/分组均可用。
- 批量数量有上限；结果可一键复制；刷新不保留历史。

### 时间工具箱
- 时间戳自动识别秒/毫秒，也可手动指定；同时显示秒、毫秒、ISO、UTC、本地、所选时区。
- 时区选择走 IANA 列表，夏令时由 `Intl` 处理。
- 日期差与日期加减可读；月份加减按日历语义。
- Cron 支持 5 段与 6 段（秒），支持 `*`、`*/n`、`a-b`、列表、月份/星期英文缩写；显示未来 5 次执行；非法表达式给具体字段提示。

## 7. bit_pouch 如何拿到

### 7.1 新功能列表

```bash
cd frontend
npm run tools:export          # 生成 public/toolbox-data/manifest.json 与 tools-export/
```

- 线上地址：`https://ihomy.top/toolbox-data/manifest.json`（匿名可读）。
- 本地开发：直接读 `frontend/public/toolbox-data/manifest.json`。
- bit_pouch 侧按 `id` 与 `version` 对比 `src/plugins/*/manifest.ts`，即可得到「新增 / 有更新」列表；不要按 `path` 判断。

### 7.2 新代码

- `frontend/tools-export/<id>/` 已按 bit_pouch 目录约定生成：
  - `manifest.ts`（含双语名称、描述、关键词、分类）
  - `core.ts`（ihomy 原 core，带 `// @ts-nocheck`，保持函数名与错误码）
  - `run.ts`（`export { run } from './core'`）
  - `run.spec.js`（ihomy 原测试）
- 复制到 `bit_pouch/src/plugins/<id>/`，补一个 `View.vue`（用 bit_pouch 的 `Pane`/`CopyButton`/`SegmentedControl`/`StatChips`/`ErrorNote`），然后：
  ```bash
  cd ../bit_pouch
  npm run check:plugins
  npm run typecheck
  npm test -- src/plugins/<id>/run.spec.js
  npm run build
  ```
- 已存在的插件（hash / timestamp / uuid / regex / jwt）不要覆盖：先看 manifest `version`，按需合并能力，保留 bit_pouch 现有测试。

### 7.3 版本与同步约定

- `registry.js` 每条工具带 `version`；能力变更时递增。
- 生成物（`public/toolbox-data/manifest.json`、`tools-export/`）与源码一起提交，保证 bit_pouch 能从 GitHub 直接取。
- 后续在 CI 的 `doc-drift-check.sh` 增加 `node scripts/export-tools.mjs --check`，防止清单与源码漂移。
