# 成员分组调整与家谱画板连线 跨会话实施计划

> **状态**：未开工（2026-10-30 立项，基线 V10.92）。本文件是该需求的排期、交互口径与验收**唯一来源**；需求 §9.1 有指针。每完成一个阶段按 `AGENTS.md` 归档并提交，同时回填本文阶段状态。
> **立项来源**：用户 2026-10-30 的产品意见（原文）：「成员：1、成员移动到家庭分组。去掉成员分区；2、家谱中的『点击任意两位成员，查看彼此的中华传统称谓』，改为『点击任意两位成员，查看彼此的称谓』；3、在画板可以右键增加成员，在画板上的成员，可以直接通过连线绑定关系，在连线时会让用户选择关系。」
> **交接方式**：新会话先读 `AGENTS.md` → 本文 → 需求 §4.5.6 / §4.11，再按文末开工清单执行。**版本号不要照抄**，按开工时根目录 `VERSION` +1。
> **非目标**：不改 `family_tree` 的关系模型（仍只用 `father_id`/`mother_id`/`spouse_id`）；不做任意关系类型（干亲/邻居/兄弟直连）；不做节点自由摆放与坐标持久化；不改家谱称谓算法与词表；不动「从家庭成员导入」；不改成员页的账号管理（邀请码/角色/移出）。

---

## 0. 一句话方案

三个阶段：①`sys_home_module.member` 从 `social` 组挪到 `family` 组并删掉「成员」分组，同时改家谱称谓提示文案；②后端新增**只改一条关系**的接口（`POST/DELETE /tree/relation`），避开现有全量更新接口误清字段；③画板加右键菜单与「拖拽连线 → 选关系」交互，关系落库后按现有布局算法自动重排。

### 1.5 前端硬约束（与本需求直接相关）

- **指针捕获只在真拖动时做**：`setPointerCapture` 会把 `pointerup` 与 `click` 一起改派，`pointerdown` 就捕获会让卡片/按钮点不动（踩坑速查 §3.35）。连线拖拽必须等移动超过阈值（复用现有 4px 口径）再捕获。

- 可点击非按钮元素用 `v-a11y-click`；`<img>` 必须 `alt`（AGENTS 前端规范 12）。

- 顶部标题、页签、暖居模块名不变（仍叫「家庭成员」/「家谱」）。

### 2.2 画板交互（阶段 C）

```
空画布右键 / 长按  →  [新增成员]（打开现有编辑弹窗的空表单）
节点右键 / 长按    →  [编辑资料] [连接到…] [解除关系 ▸ 父亲 X / 母亲 Y / 配偶 Z] [删除]
节点右侧悬浮手柄     →  拖出虚线 → 落到另一节点 → 关系选择弹窗
```

关系选择弹窗（拖拽 A → B 后）：

```
A（张伟） 与 B（李娟）的关系
( ) A 是 B 的父亲
( ) A 是 B 的母亲
( ) A 与 B 是配偶
( ) A 是 B 的子女（即 B 是 A 的父亲/母亲，按 B 的性别）
[交换方向]                                   [取消] [确定]
```

- 「子女」在前端展开：B 性别=男 → `A.father_id=B`；B 性别=女 → `A.mother_id=B`；B 性别未知 → 先要求选「B 是父亲还是母亲」。
- 落点为空画布 → 取消，不报错。
- 目标已有父亲/母亲 → 弹确认「B 已有父亲 X，是否替换？」；确认后覆盖该侧关系（另一侧不动）。
- 关系保存后 `load()` 重拉列表，布局自动重排（现有算法按父/母/配偶推导，不需要前端算位置）。
- 移动端：右键用长按（500ms）等价替代；拖拽手柄同样可用，手柄尺寸 ≥ 28px。

### 2.3 数据与接口（阶段 B）

- 新增**关系专用**接口，避免 `PUT /tree/{id}` 全量覆盖：
  - `POST /api/tree/relation`，body `{ fromId, toId, kind }`，`kind ∈ SPOUSE|FATHER|MOTHER`，语义：**`fromId` 是 `toId` 的 kind**（FATHER → `to.father_id=from`；MOTHER → `to.mother_id=from`；SPOUSE → 双向）。
  - `DELETE /api/tree/relation?fromId=&toId=&kind=` 解除对应关系（SPOUSE 双向解绑；FATHER/MOTHER 只清目标该侧列）。
- 校验全部复用 `FamilyTreeService` 现有私有方法：同家庭、非自引用、`hasAncestor` 防环、配偶双向绑定、目标不存在 → NOT_FOUND。
- 性别校验：不阻断。FATHER 选到性别为女的成员时前端先提示「该成员性别为女，确认仍设为父亲？」（后端不加硬校验，因为历史数据可能有缺失性别）。
- 两个接口都要 `@OperationLog`（module=TREE，operationType 用标准词，description 中文、不写表名字段）。

> 为什么不在前端拼完整 payload 调 `PUT /tree/{id}`：那要求前端把列表里的字段原样回填（含照片、备注、关联账号、另一方父母），任何一处漏传就清空数据；接口语义也不对（改关系不是改资料）。专用接口同时解决正确性与可维护性。

## 5. 阶段 B：关系接口

### 5.1 接口

```java
@PostMapping("/relation")
@OperationLog(module = "TREE", operationType = "UPDATE", description = "建立家谱成员关系")
public Result<Void> link(@RequestBody @Valid TreeRelationDTO dto)

@DeleteMapping("/relation")
@OperationLog(module = "TREE", operationType = "DELETE", description = "解除家谱成员关系")
public Result<Void> unlink(@RequestParam Long fromId, @RequestParam Long toId, @RequestParam String kind)
```

`TreeRelationDTO`：`fromId`/`toId` 非空且不相等；`kind` 用 `@Pattern` 限制三个值（大写英文，字典口径）。

### 5.2 服务实现（`FamilyTreeService` 新增两个方法）

- `link(userId, familyId, fromId, toId, kind)`：
  1. 两条记录 `require()` 同家庭（沿用现有 NOT_FOUND 写法）。
  2. `FATHER/MOTHER`：`hasAncestor(toId, fromId)` 防环（把 `from` 挂到 `to` 下面时，`from` 不能是 `to` 的后代）；只更新 `to` 的单列（自定义 XML 或 `LambdaUpdateWrapper.set(...)`，**不要** `updateById` 全字段）。
  3. `SPOUSE`：复用 `linkSpouse`（双向），若任一方已有配偶 → 先 `unlinkSpouse` 再绑定（与现有编辑行为一致）。
  4. 返回成功后前端重拉 `/tree/list`（列表已有「单侧 spouse 反补」逻辑，`FamilyTreeService.java:43-53`）。
- `unlink(...)`：`FATHER/MOTHER` 把目标该列置 NULL（**必须 `.set(col, null)`**，MP 默认策略会跳过 null）；`SPOUSE` 双向解绑。
- 事务：两个方法都 `@Transactional`。
- 单测：正常三类、自引用、跨家庭、成环、覆盖已有父亲、解除后列表无悬空引用。

### 5.3 阶段 B 验收

- 只调新接口建立关系后，用 `GET /tree/list` 回读：其余字段（性别/生日/照片/备注/账号/另一方父母）**原样保留**（这是本阶段最重要的回归断言）。
- 成为父母后 `generation` 口径不变（仍由新增时推导，改关系不动它；布局不读它）。

## 6. 阶段 C：画板交互

### 6.1 纯函数先行（`utils/familyGraph.js` 追加 + 单测）

- `nearestNode(nodes, canvasX, canvasY, threshold)` → 命中的节点 id 或 null（用 `x/y/width/height` 或 `cx/cy`）。
- `canvasPoint(clientX, clientY, rect, offsetX, offsetY, scale)` → 画布坐标（把现有变换公式收敛到一处）。

### 6.2 `FamilyTreeGraph.vue`

- 节点新增 `@contextmenu.prevent.stop` → `emit('node-context', { member, x, y })`；视口 `@contextmenu.prevent` → `emit('canvas-context', {x, y})`。

  - 画布菜单：新增成员 → `openEditor(null)`；
  - 节点菜单：编辑 → `openEditor(member)`；连接到… → 进入「点选目标」态（便于触屏）；解除关系 ▸（列出实际存在的父亲/母亲/配偶，点一项调 `treeApi.unlink`）；删除 → 现有 `remove()`。
- 「连接到…」态：点另一个节点 → 打开关系选择弹窗；点空白/再右键 → 取消。
- 关系选择弹窗（`el-dialog`，`width` 按 UI 提示词 §18a 限宽）：选项四类 + 交换方向；确定 → `relationPayload` → `treeApi.link` → `load()`；`needGenderOf` 时先弹性别选择（男/女）再提交。
- 已有父亲/母亲时先确认替换；删除成员已有「清空他人引用」逻辑，复用。
- 所有新文案进 `tree.*` i18n 块（中英）。

### 6.4 `api/index.js`

```js
treeApi.link({ fromId, toId, kind })      // POST /tree/relation
treeApi.unlink({ fromId, toId, kind })    // DELETE /tree/relation
```

### 6.5 反模式（明确不要）

- 不要在 `pointerdown` 就 `setPointerCapture`（会让节点点选、铅笔按钮、右键全部失效，踩坑速查 §3.35）。
- 不要用 `click` 触发连线（触屏上不可靠）；不要用 HTML5 drag&drop（与画布坐标换算冲突）。
- 不要为了让新节点落到右键位置而新增 `x/y` 列——布局是自动推导的，手工坐标会与布局冲突；如确需自由摆放，另立项目（需改布局算法与表结构）。
- 不要在前端重算称谓或关系类型；称谓仍由 `utils/kinship.js` 从三列关系推导。

### 6.6 阶段 C 验收

1. 空画布右键 → 新增成员，出现在图谱（无关系的成员按现有孤立节点规则摆放）。
2. 节点右键 → 编辑/删除/连接到…/解除关系四项可用；移动端长按出同一菜单。
3. 拖手柄 A→B 松手 → 关系弹窗；选「配偶」→ 连线出现 ♥，双向；选「A 是 B 的父亲」→ B 上方出现亲子线，A 的其余资料不变。
4. 选「A 是 B 的子女」且 B 性别为女 → `A.mother_id=B`。
5. 制造成环（把祖先挂到后代下面）→ 后端 400，前端提示且不落库。
6. 解除配偶 → 双方 `spouse_id` 都清空；解除父亲 → 该侧亲子线消失，另一侧保留。
7. 拖节点空白处仍是平移画板；缩放到 20%/250% 时连线落点准确。
8. 刷新页面后关系仍在（落库成功），布局重排正常。

## 12. 待用户拍板

1. **连线方向语义**：本计划用「拖起点是关系主语」（A→B 弹窗里 A 是 B 的父亲/母亲/配偶/子女）。若你更想要「先选关系再拖」的操作顺序，可在弹窗与菜单两处调换，成本很小。
