## 1. 目标与边界

用户需求拆解为六项能力:

| # | 能力 | 说明 |
|---|------|------|
| A | 全局聊天浮窗 | 任意页面(看剧/写日记/看照片时)悬浮收发消息,可拖拽、位置记忆 |
| B | 富内容气泡 | 消息不止文本:图片、站内对象卡(相册/视频/图书/日记/愿望…)、站外链接预览 |
| C | 输入框上方工具条 | 分享/邀请/通话等入口统一放输入框上方 |
| D | 1:1 语音视频通话 | 家庭成员间 WebRTC 通话,聊天流里留通话记录卡 |
| E | 游戏邀请与多人竞技 | 聊天里发游戏邀请卡同玩一个游戏;先异步同种子赛,再加实时对战 |
| F | GBA 联机评估 | EmulatorJS 能否联机 → 本文 §3 已给结论(默认不立项) |

范围:聊天室(`/chat`)与全局浮窗、WS 基础设施、游戏域对战框架(覆盖八个 H5 小游戏)。
**不在范围/非目标**:群聊多房间(聊天室=家庭单一房间,维持现状口径)、语音条消息、通知中心迁 WS(仍 REST 轮询)、群通话、跨家庭聊天、游客聊天(维持登录限定)、消息撤回(§6 待拍板,默认不做)。

## 3. GBA 模拟器联机可行性(结论)

事实(全部本地实测):

1. 本地 EmulatorJS **4.2.3**(`frontend/public/emulatorjs/data/version.json`;emulator.js:203)**自带实验性 netplay 全套前端**——房间创建/加入 UI(emulator.js:1070、5133-5254)、pause/restart 同步协议(:1837-1858)、socket.io 客户端(src/socket.io.min.js)、中文文案(localization/*.json:22)。
2. 但**默认禁用**:须同时 `EJS_DEBUG_XX===true` 且 `EJS_EXPERIMENTAL_NETPLAY===true`(emulator.js:208),并提供可达的 `EJS_netplayServer`(loader.js:106;默认指向官方演示服 emulator.js:268)。本项目三个条件均未设置(全局 grep 无命中)。
3. 需**自建 netplay 服务器**(官方独立仓 EmulatorJS-Netplay:Node.js、TCP 3000、媒体走 WebRTC + STUN/TURN ICE)——即生产要常驻一个新 Node 服务。
4. 数字型 `EJS_gameID` 必填(emulator.js:1172):GbaPlayer 云存档模式已传(GbaPlayer.vue:691),本地 ROM 模式未传。
5. netplay 是输入同步层、与核心无关,mGBA 可用;但官方文档未列支持平台清单,须逐游戏实测。
6. **与现有机制冲突**:存档管线(IDBFS→30s/切后台/离开回写,GbaPlayer.vue:372/544/624-629/793;进房前预置服务端存档 :468-499)与联机零协调——双端各写各的 SRAM、预置会覆盖联机进度;EmulatorJS 无 destroy(踩坑速查 §3.52),换 ROM 整实例重建、房间即散;`EJS_DEBUG_XX` 会同时放开其他调试能力;奖励上报无对局主体字段。

**结论:技术上「能跑通」,但不建议纳入本期**(与 §9.1「3DS 暂不可行」同口径记录)。它需要「生产常驻新服务 + 全局调试开关 + 存档体系冲突改造」三件套,换来的只是实验性体验,收益/风险比差;家庭双人对战需求由 P4 的 H5 对战房间承接(可控、可计分、可上积分)。若坚持实验 → 列为 P5,前置条件:拍板部署 EmulatorJS-Netplay 服务器(2GB 内存预算内 ~50MB)、双端同版本核心、联机会话关闭存档预置与回写、实验开关仅 OWNER 可见、接受核心兼容性逐游戏实测。

## 4. 技术方案要点

### 4.1 消息模型(表扩展,双文件)

```sql
-- schema.sql 全量 + migrations.sql 幂等(按 information_schema 判列存在,照抄既有幂等模式)
ALTER TABLE family_chat_message
  ADD COLUMN msg_type VARCHAR(20) NOT NULL DEFAULT 'TEXT' AFTER content,  -- TEXT/IMAGE/LINK/CARD/GAME_INVITE/CALL
  ADD COLUMN payload      TEXT       NULL          AFTER msg_type;        -- JSON,发送侧校验 ≤4KB
```

- 枚举常量 Java `common/ChatMsgType` + 前端常量映射(含义不入 sys_dict_item,口径同 game_info.type 的 GameConst);payload 为结构化 JSON,渲染按 msg_type 分发。
- CARD payload:`{objType, objId, title, sub, url, cover}`(快照+跳转;对象已删→「内容已删除」占位)。objType 首期:ALBUM/PHOTO/VIDEO/BLOG/DIARY/BOOK/WISH。
- CALL 消息 payload:`{media, result, duration}`(result: ANSWERED/REJECTED/MISSED/CANCELLED)——**通话记录即聊天流内一张卡,不另建表**。
- 旧数据 msg_type 默认 TEXT 零迁移;历史/未读/已读接口与索引 (family_id,id) 不变,新增查询先 EXPLAIN。

### 4.2 WS 协议 v2(单一端点扩展,不新增端点)

| type | 方向 | data | 说明 |
|---|---|---|---|
| message | S→C | 消息视图(含 msgType/payload) | 现状广播,字段扩展 |
| ping / pong | C⇄S | {} | **修复心跳错配**(§2.1 现存 bug) |
| call-signal | C⇄S | {callId,to,event,media,sdp,candidate,reason} | 通话信令,按 to(userId) 定向,不广播 |
| game-signal | C⇄S | {matchId,to,event,…} | 对战同步(P4),房间内定向 |

- handler 增加 userId→sessions 索引;信令按 to 定向投递,目标不在线由超时/离线逻辑落 CALL 消息,不排队补发。
- 上行统一 `{type,data}`;前后端同仓同发布,不留旧格式兼容,一次切换。
- WS 客户端从 Chat.vue 抽出:`composables/useChatSocket.js`(连接/指数退避重连 3→60s/心跳/类型订阅)+ `stores/chat.js`(连接态、未读、最近消息、`share()` 预填)。登录后非 standalone 由 App.vue 触发连接;多标签各持一条连接可接受(家庭规模)。

### 4.3 气泡卡片与输入工具条(B+C)

- 气泡组件族 `components/chat/cards/*`:ImageCard/LinkCard/ObjectCard/GameInviteCard/CallCard;**一律结构化渲染+文本插值,禁 v-html**(OG 抓回的标题/描述也一样);文本消息维持纯文本插值(不引 markdown)。
- `components/chat/ChatComposer.vue`:**工具条在上、输入行在下**——[图片][站内…][链接][游戏邀请][通话];「站内」=统一选择弹窗(分 tab:相册/视频/图书/日记/愿望,复用各现成列表接口,默认过滤 PRIVATE,待拍板 #4;弹窗用 dialog-lg 档位)。页面与浮窗共用。
- 分享注入点(看剧/写日记/看照片场景):PhotoViewer「分享到聊天」(copyShare 先例)、视频播放页、日记详情、图书详情、放映厅当前影片 deep link——统一调 `chatStores.share(card)`:浮窗连接中→预填草稿+可加附言;否则 ElMessage 引导去 /chat。首期做 PhotoViewer+视频+日记+链接,其余注入点顺带。
- 图片消息:复用现有上传通道生成 /files URL 再发 IMAGE(MultipartFile 流式,禁 getBytes),不新增上传接口。

### 4.4 站外链接预览(unfurl)

- 前端发送前判别:目标 URL 命中本站路由→直接发 CARD;否则 LINK。
- 后端 `POST /chat/unfurl {url}`(登录,限流 ≤10 次/分/用户):`ThirdPartyHttp` 抓取,3s 超时、响应 ≤1MB、仅 text/html、**不跟随重定向**(或 ≤2 跳且逐跳校验),解析 og:title/og:description/og:image/site_name,`<title>` 兜底;Redis 缓存 24h,键 `ihomy:chat:unfurl:{md5}`。
- SSRF 防线:仅 http/https;DNS 解析后 IP 落 私网/回环/链路本地/云元数据地址 一律拒绝;失败静默降级为纯链接气泡(不带预览)。
- 渲染:LinkCard=标题+描述+域名+缩略图(img 直连 + referrerPolicy=no-referrer,待拍板 #6),新窗口 `rel="noopener noreferrer"` 打开。

### 4.6 1:1 语音视频通话(D)

- `composables/useWebRTC.js`:getUserMedia→RTCPeerConnection,信令全走 call-signal;媒体 P2P 直连不过服务器。
- 流程:发起(Composer/成员卡选人+音/视频)→ call-invite(对端响铃,无 SDP)→ accept → offer/answer/ice → 通话中(可静音/关摄像头/最小化到浮窗小窗,可拖拽)→ 挂断/拒绝/超时(30s→MISSED)→ 落 CALL 消息卡。忙线:对端通话中回 busy。
- ICE:`stun:stun.l.google.com:19302` + TURN(待拍板 #1,建议自建 coturn Docker ~30MB,与 nginx 同机);无 TURN 打洞失败时降级提示改用文字。
- 环境硬前提:HTTPS(生产已具备);本机 http://localhost 是安全上下文、局域网 IP 不是——双端验证用 localhost 双浏览器 profile。
- iOS Safari:响铃/接听必须 user gesture 触发播放,video 加 playsinline;真机验证列入验收。

### 4.7 游戏邀请与多人(E)

- P1 先落 GAME_INVITE 卡(gameCode+参数,点击跳对应游戏页);P4 升级为可加入的对局。
- 表草案(开工时细化):`family_game_match(id/family_id/game_code/mode(ASYNC_SEED|REALTIME)/seed/host_id/guest_id/status(WAITING|PLAYING|FINISHED|CANCELLED)/host_score/guest_score/winner_id/result_json/created_at/updated_at/deleted)`;双文件+空库实测。
- REST:`POST /game/match`(创建/邀请)、`POST /game/match/{id}/join`、`POST /game/match/{id}/finish`(结算幂等)、`GET /game/match/{id}` 与列表;实时同步走 game-signal 子房间(matchId→sessions)。写接口加 @OperationLog;名次/计数更新用 setSql 原子增量。
- P4a 异步同种子赛(先行):2048(内核纯函数已 spec 化,固定 seed 可重放)——各自打完上报,排行结果卡回聊天;积分复用 family_points_rule 新 feature_code + 每日上限机制(GameInfoService.java:282-321 同款)。

## 8. 风险与回退

| 风险 | 影响 | 对策 |
|---|---|---|
| WS 全局连接与登录态/standalone 切换时序 | 浮窗空数据或幽灵连接 | stores/chat 统一管理连接生命周期;standalone 不连;401 走统一登出 |
| unfurl 被用于探内网/拖垮后端 | 安全/稳定 | §4.4 四道防线(协议白名单/私网 IP 黑名单/超时+体积上限/限流),失败降级纯链接 |
| WebRTC 对称 NAT 打洞失败 | 通话不通 | TURN 兜底(拍板 #1);失败引导改文字 |
| 家庭网络并发(通话+看剧) | 卡顿 | 音频优先档;视频默认低清晰度 |
| payload 超长/畸形 JSON | 渲染异常 | 发送侧 4KB 校验+解析失败降级文本占位 |
| 并行会话改共享文件(i18n/schema/需求) | 互相回退 | 小步提交、git add 只指定具体文件(硬性禁令) |
| 入口体积回涨 | 违反基线 | ChatFloat/卡片族 defineAsyncComponent 懒加载 |
| P5 netplay 实验失控 | 生产多一个常驻服务 | 不拍板不开工;实验限 OWNER 可见+独立开关 |
