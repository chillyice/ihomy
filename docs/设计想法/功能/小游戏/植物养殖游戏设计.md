# 植物养殖小游戏 — 规划设计

> 状态：设计稿（V1）｜ 2026-09-16
> 定位：家庭共养一棵虚拟植物，用「日常照料」把家庭互动、内容创作、积分体系、真实天气串成一个轻量陪伴型小游戏。
> 目标：低门槛、低时间成本（每天几十秒），重「全家一起养」的陪伴感，而非硬核数值。

---

## 1. 设计原则

1. **推导不落库**：阶段、营养、成长进度全部是「当前时刻」的纯函数，读取时实时计算。改公式/阈值无需数据迁移，历史植物自动按新规则解释——这是「后期改动不麻烦」的第一道保险。
2. **数值外置集中**：所有魔法数字收进一个常量文件（后端 `PlantConst` / 前端一处常量），改平衡只动配置不动业务逻辑。
3. **品种与机制解耦**：品种只决定视觉（配色/形态），不影响数值，新增品种零平衡成本。
4. **事件驱动、日志只追加**：照料/收获只写「事件」，不修改历史，时间线天然可回放、可扩展成就。
5. **复用现有系统**：天气走 `WeatherService` 门面（provider 无关），积分走 `PointsService` 流水，通知走 `NotificationService`，不重复造轮子。

---

## 2. 核心玩法循环

```
种植(选品种) ──► 照料(浇水/晒太阳/施肥) ──► 成长(6 阶段推进)
        ▲                                              │
        └──────────── 收获(积分奖励,可换品种) ◄─────────┘
```

- 全家共养**一棵**，任何成员都能照料，共享进度。
- 照料有家庭级冷却，防止单人刷榜；冷却期间其他成员仍可操作（公平性：冷却按「动作」而非「人」）。

## 3. 系统模块设计

### 3.1 品种（Species）

| 品种 | 视觉 | 数值 |
|------|------|------|
| SUNFLOWER 向日葵 | 金黄花朵 | 无差异 |
| ROSE 玫瑰 | 粉红花朵 | 无差异 |
| SUCCULENT 多肉 | 绿色多肉 | 无差异 |

> 扩展：新增品种只需在 `SPECIES` 集合 + 前端精灵配色各加一行，**不动成长逻辑**。

### 3.2 成长阶段（Stage）

固定 6 段，顺序推进，由「累计成长分钟」推导：

| 阶段 | 阈值(累计成长分钟) | 形态 |
|------|------|------|
| SEED 种子 | 0 | 埋土 |
| SPROUT 发芽 | 360（6h） | 两片子叶 |
| SEEDLING 幼苗 | 1440（24h） | 顶叶簇 |
| BUD 花苞 | 2880（48h） | 花苞 |
| FLOWER 开花 | 4320（72h） | 花朵 |
| FRUIT 结果 | 5760（96h） | 花+浆果，可收获 |

> 阶段阈值是可调数组 `THRESHOLDS`，改时长只改这一个数组。

### 3.3 成长模型（核心公式）

```
成长分钟 = 有效时间(×营养倍率) + 累计照料加成
```

- **有效时间**：种植至今的分钟数。缺水枯萎（距上次浇水 > WILT 阈值）后**冻结**，浇水恢复；雨天/雷雨/下雪视为「自动补水」不冻结。
- **营养倍率**：0.7 ~ 1.3，由当前营养等级决定（见 3.4）。
- **照料加成**：浇水/晒太阳/施肥的即时加成，**按当日天气修正后**累加（落库累计值 `care_boost_minutes`），收获时清零。

### 3.4 营养系统（Nutrition）

- 营养 0–100，纯函数推导：**施肥后 100，随 72h 线性衰减到 20；从未施肥基线 50**。
- 营养 → 成长倍率：`0.7 + 营养 × 0.006`（50→1.0x，100→1.3x，0→0.7x）。
- **施肥**：消耗积分 + 立即成长加成 + 重置营养到 100（既立刻见效，也长期改善土壤）。
- 档位展示：`≥75 肥沃 / ≥40 正常 / <40 贫瘠`。

### 3.5 天气系统（Weather）

复用 `WeatherService`（已有多天气源抽象），condition 归一化为 `clear/cloud/rain/snow/fog/thunder`。天气只做**三件事**：照料加成修正、自动补水、页面展示。

| condition | 浇水倍率 | 晒太阳倍率 | 自动补水 |
|-----------|---------|-----------|---------|
| clear 晴 | 1.0 | 1.5 | ✗ |
| cloud 多云 | 1.0 | 1.0 | ✗ |
| rain 雨 | 1.5 | 0.5 | ✓ |
| snow 雪 | 0.8 | 0.3 | ✓ |
| fog 雾 | 0.9 | 0.7 | ✗ |
| thunder 雷雨 | 1.3 | 0.4 | ✓ |
| （无数据） | 1.0 | 1.0 | ✗ |

> 天气不追溯历史，只作用于「照料那一刻」+「当前状态展示」，避免引入需要后台定时任务的历史天气积分。

### 3.6 积分系统（Points）

| 事件 | 积分变动 | 说明 |
|------|---------|------|
| 浇水 | +2 | 冷却限频 |
| 晒太阳 | +2 | 冷却限频 |
| 施肥 | −15 | 先校验余额 |
| 收获 | +30 | 达成奖励 |

- 走 `PointsService.addRecord` 流水，类型 `PLANT_WATER / PLANT_SUN / PLANT_FERTILIZE / PLANT_HARVEST`。
- 形成闭环：照料赚分 → 施肥花分 → 加速成长 → 收获回血。

### 3.7 家庭交互（Interaction）

- **通知**：成员照料/收获时，通过 `NotificationService` 通知其余家庭成员（"XX 给家里的植物浇了水"），type=`plant`。
- **寄语**：照料/收获可附一句 ≤200 字寄语，写进成长日志，成为家庭共享内容。

### 3.8 家庭内容（Content / 成长日志）

- 表 `family_plant_log`：`family_id / user_id / action / message / detail / created_at`，**只追加**。
- 植物页底部时间线展示（昵称 + 动作 + 寄语 + 时间），批量回填昵称/头像避免 N+1。

## 6. 接口设计

前缀 `/api`，均需登录（家庭上下文）。

| 方法 | 路径 | 入参 | 说明 |
|------|------|------|------|
| GET | /plant | — | 状态（含天气/营养/日志） |
| POST | /plant | `{species}` | 种植 |
| POST | /plant/water | `{message?}` | 浇水 |
| POST | /plant/sun | `{message?}` | 晒太阳 |
| POST | /plant/fertilize | `{message?}` | 施肥（扣积分） |
| POST | /plant/harvest | `{species?, message?}` | 收获并开启下一轮 |

错误语义：冷却中/未成熟返回 409；积分不足返回 1008；未种植访问照料返回 404。所有写接口 `@OperationLog`。

## 7. 前端体验

- 页面归属：工具箱（小游戏）模块，路由 `/tools/plant`。
- 布局：植物精灵 + 天气/营养/积分概览条 + 阶段圆点 + 成长进度条 + 照料按钮 + 寄语输入 + 成长日志时间线。
- 30s 轮询对齐家庭最新进度；动作用条件 UPDATE 原子累加防并发/防刷。
- 纯矢量精灵（SVG），无位图资产；视觉遵循项目主题变量与深色模式。

## 8. 扩展性与后期改动点（重点）

> 用户核心关切：后期改起来要便宜。设计上已把「改动成本」压到最低：

1. **改数值** → 只改 `PlantConst` 一处（阶段时长/积分/冷却/营养衰减/天气倍率全在此），业务代码零改动。
2. **改成长公式** → 阶段与营养是纯函数推导、不落库，改公式后所有历史植物立即按新公式解释，**无需数据迁移**。
3. **加品种** → `SPECIES` 集合 + 精灵配色，各加一行。
4. **加阶段 / 改阶段形态** → 改 `STAGES` 与 `THRESHOLDS` 数组 + 精灵 `STAGE_CFG`，成长逻辑自动适配。
5. **加照料动作（如除虫/修剪）** → `care()` 已是「动作类型 + 配置」统一抽象，新增只需加常量 + 一个分支 + 一个接口 + 前端一个按钮。
6. **加天气源/条件** → 复用 `WeatherService` 抽象，游戏层只消费归一化 `condition`，无感知。
7. **加积分事件** → `addRecord` 用流水字符串，加新类型无需改表。
8. **内容沉淀** → 日志只追加、不修改，后续可随时叠加成就/图鉴/统计而不破坏历史。

**预留的后续玩法（阶段三，未实现）**：品种数值差异、成长图鉴/成就徽章、季节或家庭事件、植物照片一键分享到相册、化肥作为积分商城道具、植物状态上首页仪表盘。

## 10. 风险与边界

- **天气是采样不是历史积分**：不追溯历史天气，避免后台定时任务与配额消耗；天气只作用于照料时刻 + 展示。
- **积分并发**：家庭级低并发场景，余额校验不强行加锁（与现有积分商城一致的「ponytail」取舍）。
- **通知噪声**：照料即通知可能偏多，后续可加「安静时段/去重」；当前仅排除了操作者本人。
- **数值平衡**：默认值是「有陪伴感但不肝」的起步值，上线后按实际家庭使用数据再调（改 `PlantConst` 即可）。
