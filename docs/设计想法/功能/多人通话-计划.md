# 多人音视频通话(家庭内)- 计划

> 状态:开发中(2026-11-18 立项即开发,V12.81)。用户拍板:仅家庭内多人音视频;窗口可并列/可切换/可分主次;家庭外(亲友圈/跨家庭)后续再议。

## 1. 背景与范围

现状是严格 1:1 通话(`stores/call.js` 单 pc 状态机,信令 WS `call-signal` 定向转发,end 由服务端落 CALL 卡)。用户要求语音/视频支持多人:

- **范围(已拍板)**:仅家庭内成员;最多 **8 人**(mesh 全连接的上限,超出提示);语音与视频同一套机制。
- **窗口形态(已拍板)**:宫格并列(全员等分)与主次(一大N小,点任一路切主)两种布局,可切换;自视图参与并列。
- **不做**:跨家庭/亲友圈通话、中途再邀请、通话内媒体升级(语音↔视频切换)、服务端混流(SFU)、自动发言人聚焦。

## 2. 拓扑与协议

**全连接 mesh,P2P 直连不过服务器**(沿用现 TURN/coturn 基建)。信令全部复用 WS `call-signal` 定向转发(服务端逐对校验同家庭)。

### 2.1 角色与建连规则(兼容旧端)

- **主叫(caller)**是协议权威:持有名单串行处理 accept。
- **建连方向**:`主叫 → 每个接通者` 由**主叫**发 offer(与旧 1:1 流向一致,新旧端 1:1 完全互通);第 3 人起,**新接通者 → 已接通的非主叫成员** 由新接通者发 offer(新生代才懂 roster,旧端在群组里只保证与主叫通)。
- 应答方 pc 惰性创建:收到 offer 时本地无 pc 就先建(本地流已备好)。

### 2.2 信令事件表(全部带 callId;服务端注入 from)

| 事件 | 方向 | 载荷 | 说明 |
|------|------|------|------|
| invite | 主叫→被叫 | media, group, peers:[{id,name}] | group=true/peers 非空=群组;旧端忽略新字段仍可 1:1 |
| accept | 被叫→主叫 | — | 主叫标记 joined,回 roster、向其余已接通者广播 join,并对该 acceptor 发 offer |
| reject / busy | 被叫→主叫 | — | 与旧一致;全员拒接/忙线→主叫 end(REJECTED) |
| roster | 主叫→新接通者 | peers:[已接通名单(除自己)] | 新接通者据此向名单内非主叫成员发 offer |
| join | 主叫→其余已接通者 | peer:{id,name} | 通报新成员;连接由新成员的 offer 送达 |
| offer / answer / ice | 双向 | sdp / candidate | 与旧一致,但按 (callId, from) 路由到对应 pc |
| leave | 离开者→其余每人 | — | **新事件**:成员自行离开(不落卡不结整通);服务端加入 CALL_EVENTS 转发集 |
| end | 主叫→全体 | reason, duration, media | 服务端转发 + 落 CALL 卡(SETNX 按 callId 全通一张);reason: completed/timeout/rejected |

### 2.3 挂断语义(对齐「房主 end、访客 leave」惯例)

- **主叫挂断 = 结束全通**:向所有状态非终态者发 end(接通过 → reason=completed,时长=主叫计时);一张 CALL 卡。
- **成员挂断 = leave 自己**:其余人继续;若离开后已无其他成员,本地静默收尾(不发 end、不落卡)。
- 主叫异常掉线(无 end):其余成员 mesh 内继续;各自 leave 收尾,该通不落卡(v1 已知限制)。

### 2.4 响铃超时

主叫 30s 定时器:到点仍有 invite 未应答——有已接通者则仅把这些标记超时、通话继续;**无人接通**才 end(timeout) → MISSED 卡。

## 3. 前端结构

- `utils/callMesh.js`(纯函数+spec):参与者列表增删/状态迁移/roster 合并/人数上限,供 store 调度;`MAX_PARTICIPANTS = 8`。
- `stores/call.js` 重写为 mesh 状态机:`participants[]`(每人 {id,name,status,pc,remoteStream})、顶层 status 保留 idle/ringing-out/ringing-in/connecting/active/ended;`layout:'grid'|'focus'` + `pinnedId`;onSignal 按 (event, from) 路由;start(members[], media) 兼容旧单选调用。
- `CallOverlay.vue`:宫格/主次两布局(视频),语音=头像阵列;点任一路切主(focus);自视图镜像;最小化小窗沿用;计时/静音/摄像头/前后置/变焦沿用。
- `ChatComposer.vue` 通话弹窗改**多选**(checkbox,选满 7 人=除我 8 人),底部 语音/视频 两键统一发起。
- `RoomCallPicker.vue`(游戏房间)适配 `start([m], 'AUDIO')`。

## 4. 服务端改动(最小)

`ChatWebSocketHandler.CALL_EVENTS` 增加 `"leave"`(转发集,不落卡)。end 落卡/广播逻辑不变(SETNX 按 callId 天然收敛为一张卡,时长/结果取首个 end)。

## 5. 已知限制

- 旧 APK 混装:1:1 新旧互通;群组里旧端仅保证与主叫连通(旧端单 pc、ICE 只发主叫),群组体验以新版为准。
- mesh 上限 8 人,更多成员请分通;跨家庭/圈待后续立项。
- 主叫异常掉线的通话不落 CALL 卡。
- 通话内语音↔视频切换不做(接受时定档;摄像头不可用自动降级语音沿用)。

## 7. 实施差异

- 实测落地与计划一致;`connect` 状态并入 `connecting`(沿用旧顶层命名,减少 overlay 改动)。
- 主叫对每个 acceptor 的 offer 在 accept 处理时同步发起;roster 与 join 均带 `group:true` 便于旧端静默忽略。
- `watchMedia` 看门狗改为聚合所有 pc 的入站字节,任一路>0 即放行。
- 游戏房间 RoomCallPicker 传单元素数组,行为与旧一致。
