# 家庭日程整合（提醒并入计划 + 纪念日同页 + 愿望单对接）跨会话实施计划

> **状态**:阶段 A 已发 V10.86;B–D 待开发。**版本占用**:V10.87 被「页面遮挡排查 + 层级/遮罩统一」专项占用(A 与 B 之间),故 B/C/D 顺延为 V10.88 / V10.89 / V10.90。
> **交接方式**:新会话先读根目录 `AGENTS.md` → 本文 → `docs/需求设计说明书.md` §4.5.1–§4.5.3 / §7,再按文末「开工清单」逐阶段执行;每完成一个阶段按 `AGENTS.md` 的归档规则写四文档、跑闸门、提交并打 tag。
> **立项来源**:用户 2026-10-29 的产品意见(原文):「今日提醒、家庭计划、纪念日是否能合并到一起,在家庭计划中,今日的计划就是今日提醒,带时间的计划就是提醒;纪念日、小游戏、放映厅可以对接愿望单;物品定位、智能家居、家庭公告、工具箱单独放在一个导航栏分类里,分类叫家庭,在生活之下。」
> 第三条(导航「家庭」分类)**已于 V10.85 落地**,不在本计划范围内。
> **非目标**:不合表(不把 `family_reminder` 物理并进 `family_plan`);不改通知中心 UI 与通知表结构;不做农历重复提醒;不做跨家庭共享;不引新运行时依赖;不动 JWT/权限模型;不合并壁纸的 plan/reminder 两个小组件。

## 0. 一句话方案

**入口合并、数据各自归位**:`/plan` 变成三个页签「今日 / 计划 / 纪念日」;计划的「提醒时间」只落到 `family_reminder`(加 `plan_id` 关联,单向托管);纪念日保留独立表但加「提前 N 天提醒」;愿望单加来源三列,放映厅/纪念日各加一个「加入愿望单」入口。

### 1.2 为什么不合表(设计约束,不要推翻)

- 提醒是**时点行为**(一天一次、勾完结案),计划是**有状态的容器**(子任务 + 进度 + 指派);「重复提醒勾完成」= 终止提醒,「计划完成」= 这件事做完,两者语义不同,合表必须重定义完成态,并迁移通知历史(`contentType='reminder'`)。
- 纪念日是**日期库**(农历/闰月/多成员/倒计时),与计划不同构;塞进计划要给 `family_plan` 加 `calendar`/`is_leap`/成员关联,并重写首页与壁纸的倒计时来源。
- 因此本计划**只合并入口与页面**,表结构只做最小扩展(关联列 + 纪念日提醒设置 + 愿望来源列)。

### 1.4 硬约束(违反即返工)

1. **纪念日必须保持访客可读**:`/plan` 路由本来就是 `meta.public`,合并后「纪念日」页签对游客照常出演示家庭数据;「今日/计划」页签对游客给登录引导并**跳过请求**(现有 `if (!userStore.isLoggedIn) return` 口径)。
2. **同一事实只留一份来源**:计划设的提醒时刻只存 `family_reminder.remind_time`,`family_plan` 不加时间列;倒计时的下次日期只由后端算(`AnniversaryDate` 工具),前端不算。
3. **家庭隔离**:所有新查询带 `family_id`;跨家庭一律 NOT_FOUND(沿用 `require()` 写法)。
4. **枚举大写英文 + 字典**:新增 `wish_source` 必须进 `sys_dict_item` + `DictConst` + 前端 `utils/dict.js`。
5. **提示文案不写实现**:`BizException` 消息只讲用户能做什么,不写表名/字段/内部枚举。
6. **i18n 中英同步**,文案里的 `{`/`}`/`@` 转义,`i18n/message-format.spec.js` 与 `hardcoded-cjk.spec.js` 必须过。
7. **内存缓存**:改 `sys_home_module.enabled` 后必须重启后端才生效(`HomeModuleService` 启动加载全局模块)。
8. **写接口必带 `@OperationLog`**;`@Scheduled` 内异常必须 `log.error(..., e)`(现在 `ReminderService.processDue()` 里是空 `catch`,阶段 A 顺手修)。

## 2. 目标形态

```
/plan  (路由保持 meta.public)
├─ 今日      今天该做的事 = 今天/逾期的计划 + 今天生效的提醒 (+ 阶段 C: 即将到来的纪念日提示行)
├─ 计划      现有计划列表(计划卡片 + 子任务 + 进度),计划可填「提醒时间」
└─ 纪念日    现有纪念日卡片 + 新增「提前 N 天提醒」
```

- 导航:只保留「家庭计划」一个入口(生活组);`/reminder`、`/anniversary` 路由保留并重定向。
- 计划的「提醒时间」= 一次性提醒(`remind_date = target_date`),由服务层托管,不允许在提醒侧单独编辑。
- 重复提醒(每日/每周/每月)继续只在提醒侧维护,在「今日」页签里可见、可勾完成。

## 4. 阶段 A(V10.86)后端:计划带时间 + 关联提醒 + 今日聚合

### 4.1 表结构(schema.sql + migrations.sql 双改,表数仍 85)

`family_reminder` 加一列:

```sql
`plan_id` BIGINT DEFAULT NULL COMMENT '关联计划ID(family_plan.id;NULL=独立提醒)',
KEY `idx_plan` (`plan_id`)
```

- 不加外键(本库统一不用 FK),删除计划时由服务层清理。
- `family_plan` **不加任何列**(时间只存提醒侧)。

### 4.2 实体/DTO

- `entity/Reminder.java` + `private Long planId;`
- `dto/PlanDTO.java` + `private LocalTime remindTime;`(前端传 `HH:mm:ss`)
- `FamilyPlanService.list()` 每条计划补 `remindTime`(批量:`select plan_id, remind_time from family_reminder where plan_id in (...)`,一次查询,禁止循环)。增补后的返回字段:`id/title/description/targetDate/status/createdBy/assigneeName/doneCount/totalCount/tasks[]/remindTime`。

### 4.3 服务规则(全部在 `FamilyPlanService`,单事务)

| 动作 | 规则 |
|---|---|
| 创建计划带 `remindTime` | 必须有 `targetDate`,否则 400「设置提醒时间需要先选择目标日期」;插入计划后插一条 `family_reminder`: `title=plan.title`、`content=plan.description`(截 500)、`remind_date=plan.targetDate`、`remind_time=remindTime`、`repeat_type='ONCE'`、`done=0`、`created_by=plan.createdBy`、`plan_id=plan.id` |
| 编辑计划 | `remindTime` 非空 → 有则更新、无则新建;`remindTime=""`(空串)→ 删除关联提醒;`targetDate` 变化 → 关联提醒 `remind_date` 跟随,并把 `done` 重置为 0(未来还要响)。`remindTime=null`(不传)= 不改(现有 patch 语义) |
| 删除计划 | 物理删除 `where plan_id=?` 的提醒(现有 `planMapper.deleteById` 也是物理删) |
| 计划转 DONE | 关联提醒 `done=1`(手动改状态或子任务全完成都要覆盖:`update()` 与 `syncPlanStatus()` 两处) |
| 提醒勾完成 | **不改**计划状态(避免勾一个提醒把整个计划判完成) |
| 提醒侧编辑 | 有 `plan_id` 的提醒在接口层拒绝编辑标题/时间/重复(`400「该提醒由计划管理，请到家庭计划中修改」`),只允许 toggle-done |

### 4.4 抽公共纯逻辑 `common/RepeatSchedule.java`

```java
/** 某提醒今天是否应触发:ONCE 看日期,DAILY 恒真,WEEKLY 比星期,MONTHLY 比日号 */
public static boolean dueToday(String repeatType, LocalDate baseDate, LocalDate today)
```

- `ReminderService.dueToday()` 改为调用它(行为不变);
- 新增 `common/RepeatScheduleTest`(5 例:ONCE 当天/ONCE 过期、DAILY、WEEKLY 同日/异日、MONTHLY 同日号/异日号;补 2 月 29 与月末日号的边界)。
- `ReminderService.processDue()` 的空 `catch` 补 `log.error("reminder notify failed, reminderId={}", r.getId(), e)`(类上加 `@Slf4j`)。

### 4.5 新接口 `GET /plan/today`

- 权限:登录态(与 `/plan/list`、`/reminder/list` 同口径;游客 401,前端按 `isLoggedIn` 跳过)。
- 返回:

```jsonc
{
  "plans": [
    { "id": 1, "title": "换季大扫除", "targetDate": "2026-10-29", "remindTime": "09:30:00",
      "overdue": false, "overdueDays": 0, "doneCount": 1, "totalCount": 3, "assigneeName": "妈妈" }
  ],
  "reminders": [
    { "id": 9, "title": "吃药", "content": "早饭后", "remindTime": "08:00:00",
      "repeatType": "DAILY", "planId": null, "fromPlan": false }
  ]
}
```

- 取数口径:
  - `plans`: `family_id = ? AND status = 'ACTIVE' AND target_date <= today`,排序 `remind_time` 升序(空排后)→ `target_date` 升序 → `id` 升序;`overdue = targetDate < today`,`overdueDays = daysBetween`。
  - `reminders`: `family_id = ? AND done = 0` 且 `RepeatSchedule.dueToday(...)` 为真,按 `remind_time` 升序;`fromPlan = planId != null`。
- 控制器只做校验 + 调服务(三层规范)。

### 4.6 通知文案/跳转(前端小改)

- `AppSidebar.vue` `notifyType()` 增加 `type === 'reminder' ? t('notify.typeReminder')`;`notify.typeReminder` 中英各一条(中文「提醒」)。
- `onNotifyClick()`: `n.contentType === 'reminder'` → `router.push('/plan?tab=today')`(阶段 B 前 `/plan` 还是老页面,`tab` 参数被忽略也无害;阶段 B 落地后生效)。

## 6. 阶段 C(V10.89)纪念日:提前 N 天提醒

### 6.1 表与表单

`family_anniversary` 加两列(均可空,存量数据不受影响):

```sql
`remind_days_before` SMALLINT DEFAULT NULL COMMENT '提前几天提醒(0或NULL=不提醒,范围1-30)',
`remind_time`        TIME     DEFAULT NULL COMMENT '提醒时刻(空=默认08:00)',
```

- `AnniversaryDTO` 同步两字段;`AnniversaryService.apply()` 写入;校验 `remind_days_before` ∈ 0..30,越界 400。
- 前端纪念日弹窗加「提前提醒」开关 + 天数(1–30)+ 时间(默认 08:00),关闭时两字段提交 `null`。

### 6.2 抽公共日期工具 `common/AnniversaryDate.java`

- 把 `HomeStatsService.nextOccurrence/nextSolar/nextLunar`(110–175 行)原样搬成静态方法:
  `LocalDate nextOccurrence(String calendar, Integer month, Integer day, Integer isLeap, LocalDate today)`。
- `HomeStatsService` 改调该工具(行为必须逐字一致:阳历今年已过顺延、农历今年/明年各试一次、闰月缺失跳过)。
- 新增 `AnniversaryDateTest`(阳历已过/未到、农历闰四月、非法 month/day 返回 null)。

### 6.3 调度 `AnniversaryReminderService`(新类)

- `@Scheduled(fixedDelay = 300_000)`,与提醒同口径:6:00–23:00 之外静默。
- 扫描 `remind_days_before > 0` 的纪念日:算 `next = nextOccurrence(...)`;若 `ChronoUnit.DAYS.between(today, next) == remind_days_before`,且 `now >= (remind_time ?: 08:00)`,且当日未发过 → 给全家成员发通知。
- 通知字段:`type='anniversary'`、`contentType='anniversary'`、`contentId=a.id`、`sourceId=a.id`、`content="纪念日提醒：<名称>（<N> 天后）"`。
- 去重:`family_notification` 里 `type='anniversary' AND source_id=a.id AND created_at >= 今天 00:00` 有记录就跳过(照抄 `ReminderService.notifiedToday`)。
- 通知中心:`notifyType()` 加 `anniversary` 分支(阶段 A 已加 `typeAnniversary` 键);`onNotifyClick()` → `/plan?tab=anniversary`。

### 6.4 今日页签「重要日期」条

- `GET /plan/today` 增加 `events` 段(最多 3 条,来自本家庭 `family_anniversary`,复用 `AnniversaryDate`;字段 `label/date/days/type`)。
- TodayTab 顶部一行提示:`距 <名称> 还有 <N> 天`(当天显示「今天」),点击 → `/plan?tab=anniversary`;无数据整行不渲染。
- 这只是提示,**不生成待办、不进提醒表**。

### 6.5 阶段 C 验收

- 新建「结婚纪念日」提前 3 天 09:00 提醒:把系统日期/测试数据调到 3 天前,调度触发 → 全家各 1 条通知,重复扫描不再发;同日首页与壁纸倒计时数值与改造前一致(回归 `HomeStatsService` 行为)。

## 11. 风险与取舍

| 风险 | 应对 |
|---|---|
| 计划↔提醒双写不一致 | 真值只在 `family_reminder`;所有写操作走 `FamilyPlanService` 单事务;`get today`/`list` 只读 |
| 提醒勾完成顺手把计划判完成 | 明确单向联动:计划 → 提醒,提醒 ↛ 计划 |
| 纪念日对游客不可见(合并回归) | `/plan` 保持 `meta.public`,纪念日页签不做登录门;验收项固定包含游客视角 |
| 导航入口消失(停用两行种子) | 保留行 + `NAV_PATHS` 映射 + 路由重定向;`doc-drift-check` 会校验「启用模块必须有路由」,停用不影响 |
| 旧深链 `/anniversary`、`/reminder` 打不开 | 保留路由并 redirect;grep 全仓点击目标改到位 |
| 首页/暖居/壁纸三处口径不一致 | A 阶段就统一 `/plan/today`;壁纸暂不改,但同一份 due 口径由后端 `RepeatSchedule` 提供 |
| 通知类型新增被当作评论 | 阶段 A 就把 `notifyType` 分支补齐(现有 `reminder` 已中招) |

**明确不做**:把 `family_reminder` 并进 `family_plan`;给计划做「重复」;把纪念日做成待办/计划;合并壁纸的两个小组件;给这三个模块加 `@RequirePermission`(现状是家庭内成员均可操作,改动属另一议题)。
