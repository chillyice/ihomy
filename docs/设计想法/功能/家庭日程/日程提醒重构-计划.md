# 日程提醒重构（月历式家庭日程）跨会话实施计划

> **状态**：未开工（2026-10-30 立项，基线 V10.92）。本文件是排期、口径与验收的**唯一来源**；需求 §9.1 有指针。开发完成一个阶段就按 `AGENTS.md` 归档规则写四文档、跑闸门、提交并打 tag，并把本文对应阶段标 ✅。
> **立项来源**：用户 2026-10-30 的产品意见（原文）：
> 1、「家庭计划改为日程提醒」；2、「点击日程提醒后，会展示一个当月日历，下方默认显示当天的日程、中国传统节日节气、假调休，如果某天有日程、中国传统节日节气、假调休，则显示为一个点，点击后显示某天，最上方进行近期日程提醒」；3、「点击某日，在下方日程可以增加各类事项，可循环的就是纪念日，不可循环的就是事项，带提醒的事项就是提醒，可按照阳历或农历循环，可循环并带提醒的就是每日任务，也可以创建没有日期的计划」；4、「把其他与日程有关的功能合并到此处」。
> **交接方式**：新会话先读根目录 `AGENTS.md` → 本文 → 需求 §4.5.1–§4.5.3 / §7，再按文末「开工清单」逐阶段执行。**版本号不要照抄**：每阶段取开工时的根目录 `VERSION` +1（次位满 100 进位），开工前先 `git status` 与 `cat VERSION`。
> **非目标**（本计划明确不做，别顺手扩范围）：不把四类数据物理合成一张表（理由见 §1.4）；不改通知中心 UI 与 `family_notification` 结构；不做跨家庭共享；不引前端农历/日历依赖（农历/节气/节日全部后端算）；不改壁纸的 plan/reminder 小组件与 localStorage 键；不做日程与外部日历（ICS/CalDAV）互通；不改 JWT/权限模型。

## 0. 一句话方案

把 `/plan` 从「三页签列表页」改成「月历 + 当日详情 + 近期提醒」的单页日程视图；**写操作仍落原来的三张表**（`family_plan` / `family_reminder` / `family_anniversary`），靠一个「是否循环 × 是否提醒 × 是否有日期」的判定函数把用户的四种叫法映射到三张表；新增后端「日历基础数据」（农历/节气/传统节日/法定节假日与调休）与「日程聚合读接口」，农历循环提醒通过扩展 `family_reminder` 与 `RepeatSchedule` 实现。

### 1.3 已确认的技术事实（本次实测，不是推测）

用 `hutool-all 5.8.27`（`pom.xml:26,100-104`，已在 classpath）实测：

| 输入 | `new ChineseDate(LocalDate)` 结果 | 说明 |
|---|---|---|
| 2026-02-17 | lunar=1/1，festivals=`春节` | 农历月/日 **1-based** |
| 2026-03-03 | lunar=1/15，festivals=`元宵节 上元节` | 同一节日可能多个别名，需按名去重归并 |
| 2026-04-05 | lunar=2/18，**festivals 为空**，term=`清明` | **清明是节气不是农历节日**，必须走 `getTerm()` |
| 2026-06-19 | lunar=5/5，festivals=`端午节 端阳节` | |
| 2026-08-19 | lunar=7/7，festivals=`七夕` | |
| 2026-09-25 | lunar=8/15，festivals=`中秋节` | |
| 2026-10-18 | lunar=9/9，festivals=`重阳节` | |
| 2027-02-05 | lunar=12/29，festivals=`除夕` | 除夕由腊月天数自动判定（29/30 都覆盖） |
| lunar 2026-8-15 → 公历 | 2026-09-25，回查 8/15 | 农历→公历可用 `getGregorianDate()` |

结论：**节气与传统节日零新增依赖**；`ChineseDate.getFestivals()` 返回空格分隔字符串、`getTerm()` 返回单个节气名或空串，清明只用后者。
**法定节假日与调休（休/班）本仓完全没有任何数据源**（全仓 grep `holiday|workday|节假日|调休|工作日` 零业务命中），必须新增数据（§5）。

### 1.4 为什么仍然不合表（不要推翻）

- 纪念日有「关联多成员 + 提前 N 天 + 访客可读 + 首页倒计时 + 愿望单来源」，提醒有「当日勾完成 + 到点通知」，计划有「子任务 + 进度 + 指派」；合成一张表要重定义完成态、重建通知历史（`contentType='reminder'/'anniversary'`），收益只是少写几行代码。
- 本计划的合并**只在入口、页面与读侧聚合**；写侧由前端按判定函数路由到既有接口，每张表只补必要的列/表。

- **默认视图 = 月历**；右上角 `[日历|清单]` 切换。清单模式是全部日程的维护入口（类型筛选：全部/纪念日/提醒/每日任务/事项/计划），替代原「全部提醒」维护区与纪念日页签列表。
- 点击日期格 → 选中该日，下方详情切换；点击「近期日程提醒」条目 → 跳到对应日期并选中该事件。
- 游客：月历、节日节气、休班、演示家庭纪念日照常显示（与现有「纪念日访客可读」一致）；日程区与待安排区显示登录引导并且**不发请求**。

### 2.2 新增/编辑交互（统一弹窗，按开关推导类型）

弹窗只问三件事：**日期（可空）、是否循环（不重复/每天/每周/每月/每年阳历/每年农历）、是否提醒（无/当天提醒(时刻)/提前 N 天）**，顶部实时显示推导出的类型徽标（判定规则见 §3）。字段随类型渐进显示：

- 循环 → 显示历法（阳历/农历 + 闰月）与「关联成员」（纪念日独有）；选「提前 N 天」时变成纪念日提前提醒。
- 循环 + 当天提醒 → 变成「每日任务」（循环提醒），显示重复周期与时刻。
- 不循环 + 当天提醒 → 「提醒」。
- 不循环 + 无提醒 → 「事项」（落到计划表，带目标日，无子任务）。
- 无日期 → 「计划」（落到计划表，`target_date` 为空；保存后可进计划详情加子任务）。

## 3. 概念映射（用户叫法 → 判定 → 落表）

| 有日期 | 循环 | 提醒 | 用户叫法 | 落表 | 备注 |
|---|---|---|---|---|---|
| 有 | 无 | 无 | 事项 | `family_plan`（`target_date` 有值，无子任务） | 完成后 `status=DONE` |
| 有 | 无 | 当天时刻 | 提醒 | `family_reminder`（`repeat_type=ONCE`） | 勾完成即 `done=1` |
| 有 | 阳历/农历年循环 | 无 | 纪念日 | `family_anniversary`（`recurring=YEARLY`） | 保留关联成员、愿望单入口 |
| 有 | 阳历/农历年循环 | 当天时刻 | 每日任务 | `family_reminder`（`repeat_type=YEARLY` + `calendar`） | 每次到点可勾当天完成，不终止系列 |
| 有 | 阳历/农历年循环 | 提前 N 天 | 纪念日（提前提醒） | `family_anniversary`（`remind_days_before>0`） | 既有能力，UI 归到纪念日的「提醒方式」 |
| 有 | 每天/每周/每月 | 当天时刻 | 每日任务 | `family_reminder`（现有 DAILY/WEEKLY/MONTHLY） | 既有能力 |
| 无 | — | — | 计划 | `family_plan`（`target_date=NULL`） | 可后补日期 |

**判定函数唯一来源**：`frontend/src/utils/scheduleType.js`

```js
// classify({ hasDate, repeat, remind }) -> 'PLAN'|'ITEM'|'REMINDER'|'ANNIVERSARY'|'TASK'
// repeat: 'NONE'|'DAILY'|'WEEKLY'|'MONTHLY'|'YEARLY'；remind: 'NONE'|'ON_TIME'|'ADVANCE'
```

- `PLAN`：无日期；`ITEM`：有日期 + 不循环 + 无提醒；`REMINDER`：不循环 + 当天提醒；`ANNIVERSARY`：循环 + 无提醒 / 提前提醒；`TASK`：循环 + 当天提醒。
- 该函数是弹窗徽标、保存路由、清单筛选、i18n 文案的共同来源；必须配单测（覆盖上表 7 行）。
- 后端**不做**分类推断：接口各管各的，前端按 `kind` 调对应 api；避免出现「一个全能写接口」的新债。

## 5. 阶段 A：日历基础数据

### 5.1 节假日/调休数据（新增，唯一的数据缺口）

- 新表 `sys_holiday`（**全局数据，`family_id` 不参与**）：

```sql
CREATE TABLE `sys_holiday` (
  `id`         BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
  `year`       SMALLINT     NOT NULL COMMENT '年份',
  `holiday_date` DATE        NOT NULL COMMENT '日期',
  `name`       VARCHAR(50)  NOT NULL COMMENT '名称(如:国庆节、中秋节 / 春节补班)',
  `type`       VARCHAR(20)  NOT NULL COMMENT 'HOLIDAY放假 / WORKDAY补班',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_date` (`holiday_date`),
  KEY `idx_year` (`year`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='法定节假日与调休(全局,按年维护)';
```

- 种子数据**不得凭记忆编**：以国务院办公厅当年通知为准（可参考 `NateScarlet/holiday-cn` 的年度 JSON 校对），按 `(holiday_date, name, type)` 落 `schema.sql` 与 `migrations.sql`。开工时先补 **2026 全年**；2027 数据待通知发布后单独补一条迁移。
- 维护口径写进 `docs/踩坑速查.md`：**每年 11 月国办发通知后补下一年的行；缺年份时日历照常显示节日/节气，只是没有休/班角标**（优雅降级，不报错）。

### 5.2 农历/节气/传统节日聚合服务

- 新类 `common/CalendarDay.java`（纯值对象）+ `service/CalendarService.java`（无状态计算，不缓存月数据）。
- 单日计算顺序：`ChineseDate(LocalDate)` → 农历月/日（**1-based**）、是否闰月、`getChineseDay()` 文案（初一…三十）、`getFestivals()`（按空格切分，映射到中文规范名并去重，如「元宵节/上元节」只留「元宵节」）、`getTerm()`（非空即节气）；再查 `sys_holiday` 当日行得到 `holiday{type,name}`。
- **清明**：只认 `getTerm()`，不要写进节日表。
- 闰月展示：农历闰月给「闰四月」后缀。
- 单测 `CalendarServiceTest`：春节（02-17）、元宵、清明（只出节气）、端午、七夕、中秋、重阳、除夕（2027-02-05）、闰月年、年末 12-31。

### 5.3 接口

`GET /api/public/calendar?month=YYYY-MM`（**免登录**，`SecurityConfig` GET 白名单）

```json
{ "month": "2026-10",
  "days": [
    { "date": "2026-10-18", "lunarMonth": 9, "lunarDay": 9, "lunarText": "初九",
      "lunarMonthText": "九月", "leapMonth": false,
      "term": "", "festivals": ["重阳节"],
      "holiday": null, "weekend": true }
  ] }
```

- 只算请求月（最多 31 天），不落库、不缓存；`month` 非法 → `BAD_REQUEST`。
- 前端**不引任何农历库**：格子里的农历日、节日、节气、休班角标全部用这个响应。

## 6. 阶段 B：循环提醒扩展 + 日程聚合读接口

### 6.1 `family_reminder` 扩展（双向文件同步）

新增列（`migrations.sql` 用 `information_schema` + `PREPARE` 幂等写法，照既有模式）：

| 列 | 类型 | 说明 |
|---|---|---|
| `calendar` | VARCHAR(20) NOT NULL DEFAULT 'solar' | solar/lunar；仅 `repeat_type=YEARLY` 时有意义 |
| `lunar_month` | TINYINT NULL | 农历月（1-12），`calendar='lunar'` 时必填 |
| `lunar_day` | TINYINT NULL | 农历日（1-30） |
| `is_leap` | TINYINT NOT NULL DEFAULT 0 | 闰月标记（与 `family_anniversary` 同口径） |

- `remind_date` 语义补充：`YEARLY` 时为**锚定公历日**（用于展示/排序），判定用 `lunar_*` 或锚定日的月日。
- 字典 `reminder_repeat` 增加 `YEARLY 每年`（`schema.sql:1356-1359` + `DictConst.REMINDER_REPEAT` + 前端 `utils/dict.js`）。
- 索引：现有 `idx_family(family_id, done, remind_time)` 不动；月度聚合按 `family_id` 拉取后内存过滤（家庭规模 <200 行），**先 EXPLAIN 再决定**是否补 `(family_id, remind_date)`。

### 6.2 循环任务「按日完成」新表

现有语义「重复提醒勾完成 = 永久停」不满足「每日任务」。新增：

```sql
CREATE TABLE `family_reminder_check` (
  `id`          BIGINT   NOT NULL AUTO_INCREMENT COMMENT '主键',
  `reminder_id` BIGINT   NOT NULL COMMENT '提醒ID',
  `family_id`   BIGINT   NOT NULL COMMENT '家庭ID(冗余隔离)',
  `check_date`  DATE     NOT NULL COMMENT '完成日期',
  `done_by`     BIGINT   NULL COMMENT '完成人',
  `created_at`  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_reminder_date` (`reminder_id`, `check_date`),
  KEY `idx_family_date` (`family_id`, `check_date`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='循环提醒按日完成记录';
```

- **ONCE 继续用 `family_reminder.done`**（历史行为不变、数据不迁移）。
- 循环（DAILY/WEEKLY/MONTHLY/YEARLY）的「今天完成了吗」= 当日是否有 check 行；`done` 列对循环恒为 0。
- `POST /reminder/{id}/toggle-done` 增加可选 `?date=YYYY-MM-DD`（缺省今天）：ONCE 翻 `done`；循环插/删当日 check 行。
- 通知去重（`ReminderService.processDue`）：ONCE 看 `done`，循环看当日 check 行；**不要**再依赖「今天是否给这个提醒发过通知」作为唯一判据。
- 删除提醒连带删 check 行（自定义 XML，无逻辑删列）。

### 6.3 `RepeatSchedule` 扩展（唯一重复判定源）

- `dueToday` 增加 `YEARLY`：阳历比月日；农历用 `ChineseDate(today)` 的 `getMonth()/getDay()/isLeapMonth()` 与 `lunar_month/lunar_day/is_leap` 比较；`is_leap=1` 而当年无该闰月 → 不触发（与 `AnniversaryDate` 同口径）。
- 为兼容现有调用方，保留旧签名并新增重载：`dueToday(reminder, today)` 或 `dueToday(repeatType, baseDate, today, calendar, lunarMonth, lunarDay, isLeap)`；**禁止**在 Service 里另写一套。
- 单测补：阳历每年（含 2-29 闰年）、农历每年（普通年/闰月年/无闰月跳过）、DAILY/WEEKLY/MONTHLY 回归。

### 6.4 日程聚合读接口

`GET /api/schedule/events?from=YYYY-MM-DD&to=YYYY-MM-DD`（登录）

```json
{ "days": {
    "2026-10-30": [
      { "kind": "TASK", "id": 12, "title": "吃药", "time": "07:30", "done": true, "doneToday": true, "repeat": "DAILY" },
      { "kind": "ANNIVERSARY", "id": 3, "title": "妈妈生日", "time": null, "days": 0, "members": ["妈妈"] },
      { "kind": "PLAN", "id": 8, "title": "换净水器滤芯", "status": "ACTIVE", "remindTime": null },
      { "kind": "PLAN_TASK", "id": 21, "planId": 8, "title": "买滤芯", "done": false }
    ] },
  "undated": [ { "id": 9, "title": "学做三道新菜", "createdAt": "2026-10-12" } ] }
```

- `ANNIVERSARY` 用 `AnniversaryDate` 展开到区间内的发生日（阳历/农历都覆盖），**不新增第二套日期算法**。
- `REMINDER`/`TASK` 用 `RepeatSchedule` 逐日判定；区间上限 62 天（超出 `BAD_REQUEST`），防止误传全年。
- `PLAN` 取 `target_date ∈ [from,to]`（`status != 'CANCELLED'`）；`PLAN_TASK` 取 `due_date ∈ [from,to]`，`planId` 用于跳转。
- N+1 禁令：成员名批量 `selectBatchIds` 回填；计划子任务一次 `in` 查询。
- **游客口径**：该接口加入 `SecurityConfig` GET 白名单，匿名时走 `publicController.resolveVisibleFamilyId`（与 `AnniversaryController.java:33-40` 同口径），**只返回演示家庭的纪念日**（PUBLIC 家庭），其余 kind 为空；不登录不报 401、不 NPE。

`GET /api/schedule/upcoming?days=7`（登录）→ 未来 N 天（默认 7，上限 30）的 `plan/reminder/anniversary` 发生项，按日期升序、同日按时刻，最多 20 条；游客返回空列表。

> 旧的 `/plan/list`、`/plan/today`、`/reminder/list`、`/anniversary/list` **全部保留**，不删不改响应结构。

### 7.2 月历格子规则

- 每格：日期数字 + 农历文案（初一显示月名，其余显示「初二…三十」）+ 最多 2 个语义圆点（日程 / 节日节气）+ 休/班角标。
- 用户要求「有任一内容显示一个点」；实现取**彩色点**（日程=主色、节日=暖色；调休用角标而非第三个点），窄屏（<480px）隐藏农历文案与第二个点，只留一个点 —— 这是可读性增强，不改变判定口径。
- 选中日高亮；今天有描边；非本月格降透明度。
- 数据来源：月历基础数据 `/public/calendar` + `/schedule/events` 的 `days` 键，**两次请求并行**（`Promise.all`）；切月只重拉这两个。

### 7.3 当日详情

- 三个分区：日程（按时刻升序，无时刻在后）、节日节气（含农历与节气名）、假期（休/班 + 名称；无数据隐藏）。
- 日程行：类型徽标（纪念日/提醒/每日任务/事项/计划）、标题、时刻或「全天」、提醒方式、完成控件（提醒/每日任务可勾；纪念日/事项/计划走详情或跳原页）、编辑/删除。
- 空日：显示「这一天还没有安排」+ 添加按钮。
- 游客：日程区换成登录引导，**不发任何需登录请求**（`userStore.isLoggedIn` 先判）。

## 8. 阶段 D：「其他日程相关功能」并入（范围与取舍）

用户第 4 条要求把其他日程相关功能合并到此处。逐项核实后的口径：

| 候选 | 现状 | 是否并入 | 方式 |

| 邀请码过期、保险箱等 | 非日程 | 不并 | — |

- 并入项一律带 `source`（`PLAN_TASK/LOAN/FINANCE/ITEM_EXPIRY`）与跳转目标，**只读**：不可在日程页改删，避免写侧出现第二入口。
- 显示开关存前端偏好（`localStorage`，键 `ihomy:schedule:sources:v1`），默认全开；不落库、不加权限。
- 每类只读来源各写一个 `ScheduleSourceProvider` 接口实现（后端），`ScheduleService` 汇总时遍历实现列表 → 新增来源不改聚合主逻辑。**禁止**在聚合服务里 if-else 堆来源。
