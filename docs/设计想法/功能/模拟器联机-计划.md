# 小游戏模拟器「各自存档 + 各自画面 + 联机」跨会话实施计划

> **状态**:设计定稿,**未开工**(2026-11-15)。推荐起手:A 期(今天可用,0 代码)+ C 期前置 spike(1–2 天);C 期过闸门才立项。
> **立项来源**:用户 2026-11-15「想想办法,怎么实现各自存档并且各玩各的画面且联机」——目标是宝可梦交换、马里奥赛车这类**需要链路(GBA link cable)的游戏**,不是两人玩同一个存档。
> **交接方式**:新会话先读 `AGENTS.md` → 本文 → 需求 §4.13.2(模拟器现状)/§6(表)/§9.1(规划行) → `docs/设计想法/完成/聊天室增强-计划.md` §3(netplay 旧结论,本文不推翻)→ 踩坑速查 §3.52(EmulatorJS 拆 DOM)。
> **非目标(明确不做)**:EmulatorJS 实验性 netplay(见 §2);服务端跑模拟器再串流上行(2GB 内存 + 无法各自存档);NDS 本地无线/街机链路;3 人以上联机;任何 ROM/BIOS 分发。

---

## 0. 一句话

三个条件里,**「各自存档」和「各自画面」现在已经满足**(每人一个浏览器实例 + 服务端按成员分目录的 `.srm`),真正缺的只有**链路**;而链路不是同步层能替代的——EmulatorJS 的 netplay 是「一台实例 + 别人的输入注入」,结构上一辈子只会有一份状态、一份存档。所以路线是:**能今天用就先借桌面内核的链路(A 期)**,同时在浏览器里做**自研链路**的可行性验证(C 期),不指望换框架捡到现成的。

---

## 1. 现状核验(2026-11-15 逐项读代码)

### 1.1 各自存档——已满足,不用新建体系

| 事实 | 证据 |
|---|---|
| 存档按**成员**分目录:`uploads/games/{游戏名}/saves/u{成员id}/`,每个成员只读写自己的目录 | `service/FileService.java:145-146`(`gameSaveDir`)、`:180`、`:225` |
| 前端机种注册表已按核心给出存档后缀与内核内目录,预置/回写走同一路径 | `frontend/src/utils/games/emulatorSystems.js:12-26`(GBA→`mGBA`/`srm`,NDS→`melonDS`/`sav`,街机无存档) |
| 存档四个接口已经在用:列 / 下载 / 上传 / 删 | `controller/GameInfoController.java:110/117/135/143`;前端 `api/index.js:387-395` |
| 运行中 30s、切后台、离开各回写一次 | `views/games/EmulatorPlayer.vue`(存档预置与回写段) |

**结论**:「各自存档」不需要动数据模型。联机只多两件事:**开局问「用我哪个档」**,**结束时各写各的 `.srm`**——两件都是交互层的事。

### 1.2 各自画面——已满足,但与 netplay 的语义互斥

- 每个浏览器/终端各跑一个内核实例,画面不出本机,天然「各玩各的画面」。
- EmulatorJS 的 netplay 却是**一台主实例 + 状态复制**:开关在 `emulator.js:208`(`EJS_DEBUG_XX && EJS_EXPERIMENTAL_NETPLAY`),状态复制在 `emulator.js:5564`,落后 10 帧就暂停等 `:5650`。它的成立前提就是「大家看同一份状态」——所以它给不了各自存档,也给不了真正的链路行为(宝可梦交换这类要靠两个 ROM 各自推进通信寄存器)。

### 1.3 缺的只有链路,而现成核心都没有

- EmulatorJS 4.2.3 用的 7 个核心(含 mGBA)在 WASM 侧**都没有 link cable 实现**;libretro 官方 netplay FAQ 明确写了 GBA/GB/PSP 的 link cable 不可用(netplay 只做输入同步)。
- 现成 WASM 里**唯一带链路语义**的是 `@thenick775/mgba-wasm`(mGBA `feature/wasm` 分支的 npm 分发,MPL-2.0,2026-11-15 仍在提交),导出 `linkLocalStartSession({player1:{romPath,savePath},player2:{...}})` / `linkLocalSetActivePlayer(1|2)` / `linkLocalGetStatus()`——**同页两实例、各自一个 savePath,轮流渲染**。这正好是「各自存档 + 链路」的最小证明,但**只支持 2 人、只支持同页**,README 把「网络链路」列为 planned。
- 网络链路要自己接。可抄的参考:Provenance PR #3431 用自定义 `GBASIODriver` **每帧交换 2 字节 SIODATA8 走 TCP**,已合入;明确写了「2 人 / 仅局域网(~1ms/帧) / 无 rollback」。Rebit 的做法更极端:每端跑**全部**实例,只传输入,靠确定性保证一致。

## 2. 与旧结论的关系(不推翻,换目标)

`docs/设计想法/完成/聊天室增强-计划.md` §3 的结论是「GBA 联机不立项」,判据有三:①要生产常驻一个新的 Node netplay 服务;②要全局调试开关 `EJS_DEBUG_XX`;③与现有存档管线冲突(预置会盖联机进度、双端各写各的 SRAM)。

那三条**全部针对 netplay**,本次依然有效——**netplay 这份结论保持「不做」**。差别在于目标换了:

| | 旧结论(netplay) | 本文(链路) |
|---|---|---|
| 要的效果 | 两人玩同一个状态 | 两个人各玩各的档,通过链路互传数据 |
| 内核数量 | 1 份状态 + 输入注入 | 2 个独立内核 + SIO 字节流 |
| 存档 | 必然只有一份 | 天然各自一份 |
| 现成可用 | 有(实验性) | 没有,要自己做或借桌面端 |

所以本文是**新增一条独立的路线**,不是复活 netplay。§3 里那条「联机会话必须关闭存档预置与回写」的教训要继承下来,写进 C 期的存档时序。

## 3. 方案矩阵

### 3.1 换框架能不能一劳永逸?——不能

| 候选 | 许可 | 有没有链路 | 2 人上限 | COOP/COEP | 结论 |
|---|---|---|---|---|---|
| **EmulatorJS 4.2.3**(现用) | GPL-3.0 | 无(netplay 只是输入同步) | — | 不需要 | 保持现状,只当单机播放器 |
| **`@thenick775/mgba-wasm`** | MPL-2.0 | **有,但只有同页本地链路** | 是(2 player) | **需要**(多线程 WASM) | C1 的技术底座;跨机链路它不给 |
| **RetroArch Web Player**(libretro/emscripten) | GPL-3.0 | 无(netplay 同一份状态;唯一例外是同游戏 GB/GBC 双人,仍是单实例) | — | 部分核心需要 | 换框架收益为负:外壳/存档/多机种全要重做 |
| **纯 JS 内核(jsnes 一类)** | 各异 | 无 | — | 不需要 | 只到 NES 级别,且无链路 |
| **自研/魔改 WASM 核心(C 期)** | 见 §7.4 | 要什么做什么 | 自定 | 需要 | 唯一能满足三条件同时在浏览器里成立的路 |

> 已核实不存在可直接复用的「浏览器 + 跨机 link cable」开源成品:桌面端有(VBA-M / mGBA 的局域网链路、Provenance 的 GBASIODriver),WASM 端没有。

### 3.2 架构层的四种打法(与选哪个库无关)

| 打法 | 谁跑内核 | 状态份数 | 各自存档 | 各自画面 | 跨公网 | 工期 |
|---|---|---|---|---|---|---|
| **N1 输入同步**(EmulatorJS netplay / RetroArch netplay) | 每端各跑,但以主机为权威并互发状态 | 1 | ✗ | ✓(但画面同源) | ✓ | 已评估,不做 |
| **N2 状态复制 / rollback**(netplay 的进阶) | 同上 | 1(带回滚) | ✗ | ✓ | ✓ | 不做 |
| **N3 链路仿真**(本文推荐) | 每端各跑独立实例,只交换 SIO 字节 | 2 | ✓ | ✓ | LAN 容易,公网要抗延迟 | A/B 今天,C 按周 |
| **N4 全实例 + 只传输入**(Rebit 式) | 每端跑全部实例(2 人=各跑 2 个) | 2 | ✓ | ✓ | ✓ | 最重,不给上限 |
| **N5 服务端串流**(服务端跑 mGBA,视频上行) | 服务器 | 1 | ✗ | ✗(同一画面) | ✓ | 违反 2GB/`-Xmx384m` 约束,不做 |
| **N6 异步交换**(不联机,只换存档文件) | 各自 | 2 | ✓ | ✓ | ✓ | 兜底方案,0 成本 |

**判断**:N3 是唯一同时满足三条件且不碰生产内存的路;N6 是它没跑通之前的兜底;N4 是 N3 在公网不可行时的备胎。

### 3.3 可以抄的参考实现

| 参考 | 可抄什么 |
|---|---|
| `Provenance-Emu/Provenance` PR #3431 | 自定义 `GBASIODriver` 的**帧交换节奏**:每帧读写 SIODATA8、2 人、TCP、无 rollback;失败模式的应对(谁先断、超时) |
| `PokemonQuetzal` | 「服务端跑 mGBA + 虚拟链路」的完整形态,当反面参考:它靠服务器算,我们用不起 |
| Rebit | 全实例 + 只传输入的确定性要求清单(定时、随机源、掉帧处理) |
| `@thenick775/mgba-wasm` | `linkLocalStartSession` 的会话结构(两个 ROM、两个 savePath、activePlayer 切换),C1 直接可用 |

## 4. 分阶段方案

### 4.1 A 期(今天可用,**0 代码**):桌面内核链路 + ihomy 当存档账本

思路:链路交给桌面端成熟内核,ihomy 只负责**发档/收档**(它已经有四个存档接口,不需要改)。

1. 双方从 ihomy 存档面板下载自己最新的 `.srm`(文件名与 ROM 同名)。
2. 各自 PC 上用带 GBA 链路的内核(VBA-M / mGBA)加载同一份 ROM + 各自的 `.srm`,起链路(同机双开或局域网,参数以各自文档为准——**这一步先花 30 分钟实测确认**,不要凭记忆写进文档)。
3. 在游戏里完成交换/对战。
4. 退出内核 → 把写回的 `.srm` 从 ihomy 存档面板上传回自己账号。

**成本**:0 代码,最多在帮助页补一节操作说明(可选,不进本期)。
**边界**:必须两台设备(或一台 PC 双开);手机端做不了(浏览器里没有链路)。

### 4.2 B 期(半天~1 天):站内「联机准备间」

把 A 期的四步收进一个页面,免去「自己找文件、自己改名」:

- 入口:`/games/:id/link`(或游戏详情/存档面板内的抽屉),只对**有存档口径的机种**(`emulatorSystems.js` 里 `saveDir` 非空)显示。
- 内容(全部复用现有接口,后端最多加一个「导出文件名规则」):
  - 我的最新存档导出(带机种后缀,`GET /game/{id}/saves/{name}`);
  - 回传上传(校验后缀 = 机种 `saveExt`、大小上限;`POST /game/{id}/saves`);
  - 桌面内核下载/文档外链;
  - 「谁跟我联、用哪个档」的说明卡(纯前端文案)。
- 明确不做:不做房间、不做信号、不做在线状态——**这是文件转运台,不是联机大厅**。

### 4.3 C 期(按周):浏览器内真链路

三段互不依赖,按闸门顺序推进。

**C1 同页双核(1–2 天 spike,2–3 天集成)** — 底座 `@thenick775/mgba-wasm`

- 独立路由(如 `/games/:id/link-lab`),页内起两个实例、各带自己的 `savePath`、按钮切 `activePlayer`。
- 验收价值:证明**链路语义在这套 WASM 里是真的**(交换会改两个 `.srm`),同时拿到 COOP/COEP 的实测影响面。
- 限制:同机同页,两个玩家轮流看一个画面——**不能替代目标场景**,只作技术闸门。

**C2 跨机 LAN + 逐帧交换 SIO(3–5 天 spike,总 2–3 周)** — 要自己编译核心

- 需要内核侧多两个能力:**外部驱动的单帧步进**,**SIO 收发钩子**。
- ⚠ 已核实的硬事实:`mgba.d.ts` 只有 `pauseGame/resumeGame`,**没有逐帧步进 API**;`timestepSync` 是音视频步进,不是可外部驱动的单帧。所以 C2 必须自己用 emsdk 编 mGBA(MPL-2.0,改动文件需开源),不能只写 JS 胶水。
- 链路层照 Provenance 的做法:每帧交换 2 字节 SIODATA8,双方帧锁步;仅局域网(参考实现自报 ~1ms/帧)。
- 房间信令复用现有 WS 定向消息(`game-signal` 通道已在,家庭隔离在服务端校验)。

**C3 全实例 + 只传输入(不给工期上限)** — 只在 C2 证明公网不行时才考虑

- 每端跑 2 个实例、只传输入,靠确定性对齐;要处理定时漂移、随机源、掉帧。
- 收益是抗延迟,代价是双倍 CPU 与一整套确定性工程。**除非明确「必须异地玩」,否则不启动。**

## 5. 验收标准

| 期 | 验收(可判定,不靠感觉) |
|---|---|
| A | 宝可梦:双方进宝可梦中心换完一只 → 两边 `.srm` 都拿到对方的宝可梦 → 分别回传后,重新在网页打开,各自档里都在。**不需要改任何代码** |
| B | 从页面点导出得到 `xxx.srm`;玩完从页面回传后,重新进游戏能读到联机后的进度;后缀/大小不合法时给中文提示且不落库 |
| C1 | 同页两实例通过 `linkLocalStartSession` 完成一次交换,两侧 `.srm` 都变化;全站其他页面不受 COOP/COEP 影响 |
| C2 | 两台设备同 WiFi:完成一次交换,端到端输入延迟可接受(主观 + 记录 30 帧 RTT);断线一方不掉档、不卡死另一侧;退出后各自 `.srm` 与网页存档一致 |
| C3 | 同上但跨公网(弱网 100ms RTT 下仍可完成交换) |

## 6. C 期前置 SPIKE 判定(过不了就不立项)

按顺序做,任一条失败即停止并把结论写回本文(而不是硬推):

1. **能编**:本机用 emsdk 把 mGBA 编出 WASM(`feature/wasm` 基线可编译)→ 加一个「step N frames」导出函数。**这是最大不确定项**。
2. **能钩**:在 WASM 里挂一个 SIO 回调,能读到/写入 SIODATA8,并在单帧边界同步。
3. **能对**:两个实例帧锁步跑 60 秒不漂移(允许 ≤1 帧误差,超出即失败)。
4. **能跑**:同页 C1 的原生链路(`linkLocalStartSession`)在目标设备上跑通一次真实交换(作为「链路语义本身没问题」的对照)。
5. **能装**:COOP/COEP 只加在联机路由的独立 location 上,站内其他页面与 `/files/**` 不受影响。

预算:**2 天**。过 1–4 → 立项 C2;只过 4 → 停在 C1 + A/B;全不过 → 收口成「A/B + N6 异步交换」,本文转 `完成/`。

## 7. 风险与部署约束

1. **COOP/COEP 是全站级开关**。与需求 §9.1 里「PSP/dosbox_pure 需 COOP/COEP,暂不做」是**同一个风险**:加了头,跨源资源要有 CORP,Service Worker 预缓存与 `/files/**` 直出都要复核。**唯一可接受做法**:联机走独立 location(`/games/link/**`)单独加头,别碰全站 nginx 默认头。
2. **生产 2GB / `-Xmx384m`**:游戏运算**一律不上服务器**。ihomy 只做房间信令(复用现有 WS)+ 存档账本(现有表)。房间状态若要落库也只放 Redis。
3. **存档时序必须显式设计**:开局限定「预置一次」,联机期间**只写不读**;结束各写各的 `.srm`。不这么做就会复现聊天室计划 §3 第 6 条的冲突(预置覆盖联机进度)。
4. **许可登记**:`@thenick775/mgba-wasm` 是 MPL-2.0(文件级 copyleft,作为独立 WASM 文件加载一般视为独立文件);自编 mGBA 改动的文件要开源。**引依赖必须登记 `sys_oss_component`**(AGENTS.md 数据库约定)。
5. **ROM 一致性**:链路要求双方**同游戏同版本同语言**(宝可梦尤其),存档与链路协议都对版本敏感。页面要给出「双方必须是同一份 ROM」的明确提示。
6. **性能与拆 DOM**:两个实例同页时,离开必须先 `pause()` + `toggleMainLoop(0)` 再拆 DOM(踩坑速查 §3.52),否则后台实例继续跑、音频叠音。

---

## 8. 明确不做

- EmulatorJS 实验性 netplay(旧结论保持:要常驻新 Node 服务 + 全局调试开关 + 与存档体系冲突)。
- 服务端跑模拟器再串流(内存与带宽都不允许,且拿不到各自存档)。
- NDS 本地无线 / 街机链路(WASM 内核没实现,不在可控范围)。
- 3 人以上链路(现成参考实现全是 2 人)。
- 任何 ROM / BIOS 分发、任何破解版资源。

---

## 9. 待拍板(回答后才能定 C 期范围)

1. **双方是同一 WiFi 同屋,还是异地?** —— 同屋 → C2 够用;异地 → 只有 C3 或 A 期(远程桌面/串流)可行。
2. **手上有没有 PC?** —— 有 → A/B 立刻可用,可以先收货;没有(只有手机/平板)→ A/B 无价值,只能赌 C。
3. **具体要玩哪几个游戏?**(宝可梦哪一代、马里奥赛车是 GBA 版吗) —— 决定链路类型、ROM 一致性与验收用例。
4. **能否接受联机页是独立路由 + 单独 COOP/COEP?** —— 不接受就没有 C 期。

> 前两条不回答也能先做 A 期:它 0 代码、0 风险,而且能立刻回答「链路玩起来到底有没有意思」这个更根本的问题。
