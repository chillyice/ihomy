## 1. 目标与非目标

**目标**

1. 记账本页在任何宽度下**可看可点**:无裁切、无横向溢出、无滚动条造成的位移;
2. 信息层级清晰:月份 → 账户筛选 → 本月三个数 → 明细 + 预算/分类;
3. 右栏常驻可见(预算与超支不该被长列表顶到看不见);
4. 与总账/理财页签**同一套**数字格式、收支色、卡片密度。

**非目标**:不加新账目字段、不改余额/净资产计算口径、不做多人协作/审批、不动贷款记录页签(它复用工具箱组件)。

## 3. 问题清单与改法

### P0-1 窄屏工具栏裁切(点不到)

**现状**:`BookDaily.vue:4-14` 的 `PageToolbar :card="false"` 里只有一个 `.tb-right`(月份 140px + 三个按钮)。

**改法**:

```css
/* main.css:页面统一工具栏(全局,详见对齐体检计划 §4 根因 3) */
.page-toolbar .tb-right { margin-left: auto; min-width: 0; max-width: 100%; justify-content: flex-end; flex-wrap: wrap; }
/* BookDaily.vue scoped:窄屏整行让位,按钮在行内右对齐换行 */
@media (max-width: 768px) { .book-daily .tb-right { width: 100%; } }
```

**验收**:390px 下 `tb-right.right === toolbar.right - 16 (±1)`,所有按钮 `right ≤ innerWidth`,页面 `scrollWidth === clientWidth`。

---

### P0-2 余额条滚动条占位(「没居中」的真因)

**现状**:`bookPage.css:54-63`。`.bs-chips` 是 `overflow-x:auto`(且 `overflow-y` 隐式成为 `auto`)+ `padding-bottom:2px`,原生滚动条只在溢出时出现 → 高度与中线都随数据量变化。

**改法**(样板即规范,可同步给其它横向滚动容器):

```css
.book-balance-strip .bs-chips {
  display: flex; align-items: center; gap: 8px;
  flex: 1; min-width: 0;
  overflow-x: auto; overflow-y: hidden;      /* 关掉隐式纵向条 */
  scrollbar-width: none;                      /* 不占布局盒 */
  padding-bottom: 0;                          /* 去掉不对称内边距 */
  overscroll-behavior-x: contain;             /* 到边不把整页带着滑 */
}
.book-balance-strip .bs-chips::-webkit-scrollbar { display: none; }
.book-balance-strip .bs-chips-wrap {          /* 渐隐提示「还能往右滑」 */
  position: relative; flex: 1; min-width: 0;
  mask-image: linear-gradient(90deg, transparent 0, #000 12px, #000 calc(100% - 16px), transparent);
}
```

- 滚轮映射:仅在 `el.scrollWidth > el.clientWidth` 且该方向还能滚时 `scrollLeft += deltaY` 并 `preventDefault`,到边缘放行(`passive:false` 监听,组件卸载时移除);
- 触屏原生横滑不需要额外代码(容器已 `touch-action` 默认,勿加 `none` 除非实装拖拽);
- chip 语义化:把 `div.bs-chip + v-a11y-click` 改为 `<button type="button">`(样式类不变,消除手写 a11y 属性),顺带 `aria-pressed` 表示筛选态。

**验收**:注入 14 个 chip 前后 strip 高度**完全相同**;chip 中线与 strip 中线差 ≤1px;`.bs-chips` `offsetHeight − clientHeight === 0`。

### P0-3 第二条工具栏右对齐 + 与页签栏的关系

**现状**:两行工具栏(`Book.vue:6-22` 卡片式页签栏 + `BookDaily.vue:4-14` 无卡操作栏),第二行操作贴左,两行之间还有 12px + 54px 的空白带。`docs/UI设计提示词.md §28` 写的是「右侧操作由各页签自带」,即**语义上就该在右边**。

**两个方案(见 §8 待拍板,建议 B)**:

- **A. 合成一条工具栏**:`Book.vue` 的 `PageToolbar` 右槽直接渲染「月份 + 记一笔/周期/导入」,页签切换时 `v-if` 换组;代价是 BookDaily 的月份与三个弹窗要上提(状态搬进 `Book.vue` 或抽 `composables/useBookDaily.js`),改动面大,且总账/理财各自的操作也要上提才统一。
- **B. 保留两层,第二层做「上下文条」**(推荐):不是 `PageToolbar`,而是 `.book-context` 一行 —— 左:月份选择 + 「回到本月」文字按钮;右:`记一笔(primary) / 周期账目 / 导入 CSV`;无卡片外壳、`padding: 0`,与页签栏间距 8px,与余额条间距 10px。桌面总高从 `54+12+50` 降到约 `40+50`,视觉上连成一体;窄屏自动两行(月份一行、按钮一行右对齐)。

```css
.book-context { display: flex; align-items: center; justify-content: space-between; gap: 10px; margin: 8px 0 10px; flex-wrap: wrap; }
.book-context .bc-left { display: flex; align-items: center; gap: 8px; min-width: 0; }
.book-context .bc-right { display: flex; align-items: center; gap: 8px; margin-left: auto; flex-wrap: wrap; }
```

> 「回到本月」用 `el-button text` 只在当前月 ≠ 今天所在月时出现;新增 i18n key `book.backToThisMonth`。

### P1-1 两栏高度失衡 → 右栏 sticky

**现状**:`BookDaily.vue:385-389` 的 `.content` 没有 `align-items`,网格默认 stretch;总账页的 `.lg-main`(`BookLedger.vue:425-430`)有 `align-items:start`,两边不一致。

**改法**:

```css
.content { display: grid; grid-template-columns: minmax(0, 2fr) minmax(0, 1fr); gap: 14px; align-items: start; }
.side { position: sticky; top: var(--book-sticky-top, 16px); align-self: start; }
```

- `minmax(0, …)`:与总账页同口径,防长内容顶破列宽;
- sticky 偏移在两主题下不同:**光尘**页面在文档流滚动 → `top:16px`;**暖居**顶栏胞吐进 `.gc-pin` → 用主题段落设 `--book-sticky-top: calc(pin 高 + 12px)`(若 pin 为 fixed,`16px` 会被它盖住,实测后写死或用 `ResizeObserver` 写变量)。
- 窄屏(单列)时 `position: static`(sticky 在单列无意义且可能卡在视口中段)。

**验收**:1280 下滚到第 20 行时预算卡仍在视口内;`.side` 高度 = 内容高度(不再等于 `.records` 高度)。

### P1-2 明细:按日分组 + 当日小计 + 悬停操作

**现状**:46 行平铺,`padding:10px 0` + 每行虚线;编辑/删除按钮常显(桌面端视觉噪音大)。见 `BookDaily.vue:72-99`。

**改法**:

```
▸ 11月07日 周五                       支出 ¥86.00 · 收入 ¥0.00
  餐饮  午饭            -32.00   建行 → 
  购物  日用品          -54.00   支付宝
▸ 11月06日 周四                       支出 ¥1,151.00
  ...
```

- 分组函数放 `utils/bookLedger.js`(纯函数 + spec):
  `groupRecordsByDate(records) → [{ date, weekday, income, expense, transferCount, items }]`,日期内保持后端顺序,跨日按日期倒序;
- 日期头 12px 次要色 + 右侧当日小计(收入绿 / 支出红,`tabular-nums`),sticky 到列表顶部可选(长列表加分,先不做);
- 行内操作:`@media (hover:hover)` 下默认 `opacity:0`,行 `:hover`/`:focus-within` 变 1;触屏(`hover:none`)常显。**注意**:只做透明度,不 `display:none`,避免键盘 Tab 拿不到;
- 行高统一到 52–56px,行间虚线改为「分组内只在行间、日期头下不加」;
- 明细标题行右侧加「共 N 笔」小字(与筛选态「只看 X · N 笔」同一视觉位)。

**验收**:46 行页面总高下降(目标 ≤ 2000px);分组边界与后端 `recordDate` 完全一致;`groupRecordsByDate` 有单测(空数组、同日多笔、跨月、转账不计入收支小计)。

### P1-3 分类排行加比例条

**现状**:`BookDaily.vue:106-114` 只有名称 + 金额;总账页构成卡(`BookLedger.vue` 的 `.lg-cat` / `.lg-bar`)有占比条和百分比。

**改法**:把 `.lg-cat` 那套(名称 / 金额 / 占比 / 4px 圆角条)抽成 `bookPage.css` 的公共类 `.book-cat-row`(scoped 的 `.lg-*` 就地改名引用或保留别名),记账本右栏与总账页共用;记账本侧不显示百分比也行,但**条必须画**(一眼看出大头)。

**验收**:两侧同类元素间距、条高、圆角一致;分类为 0 时不出空条。

## 5. 交互与状态规范(必须保持不变)

1. **月份**由 `Book.vue` 持有,`v-model:month` 双向;总账点月钻取回到记账本并定位该月(`onPickMonth`)——重排**不得**改成各页签自己存月份;
2. **账户筛选**只在客户端过滤本月明细(`utils/bookLedger.accountRecords`),统计卡/预算/分类排行仍按本月全部口径,筛选生效时必须保留「统计卡与预算仍是本月全部」提示;
3. **只读档位**(`canWriteBook=false`)隐藏:三个入口按钮、管理账户、行内改删、预算管理;整页「不可见」仍走 `el-empty`(不替换成自定义空页);
4. **游客**不发需登录请求,只给 `book.guestEmpty` 引导;
5. 记账弹窗宽度 420px、周期弹窗 720px 等尺寸不改(全局 `--el-dialog-width` 口径);
6. 首页「资产」卡与记账本余额条同源,余额计算不改(唯一口径见 AGENTS「记账余额不落库」)。

## 9. 验收标准(可断言)

**几何(浏览器内 `evaluate` 量,不看截图)**

1. 1280×720:`.book-tabs .el-radio-group` `cy` 与 toolbar `cy` 差 ≤1px;
2. 1280×720:上下文条右组最右元素 `right === toolbar.right − 16 (±1)`,且「记一笔」在右组内最左;
3. 390×844:`document.documentElement.scrollWidth === clientWidth`;上下文条内每个按钮 `right ≤ innerWidth`(「导入 CSV」不再被裁);
4. 余额条:注入 14 个 chip 前后 strip `offsetHeight` **相同**;chip `cy` 与 strip `cy` 差 ≤1px;`.bs-chips` `offsetHeight − clientHeight === 0`;
5. 两栏:46 条明细时 `.side.offsetHeight < .records.offsetHeight`,滚动 1000px 后预算卡 `rect.top` 仍在视口内(±16px);单列(390)时 `.side` 不为 sticky;
6. 明细:页面总高比改造前下降 ≥20%(以改造前实测 3014px 为基准);日期头数量 = 不同 `recordDate` 数。

**一致性**

7. KPI、明细金额、分类排行、余额 chip 四处的 ≥1000 数字都含千分位,且同一条目在四处字符串一致;
8. 收支色在明暗两主题下各取 `getComputedStyle` 结果相同来源(变量),不再出现字面色值。

**功能不回退**

9. 账户 chip 点击过滤/取消、切月保留、账户删除后自动清除筛选仍生效;
10. 只读档位看不到任何写入口;游客只看到登录引导且不发 401 请求(看 access log 无对应 401);
11. `npm run lint`(0/0)+ `npx vitest run` 全绿(含新增分组 spec)+ `npm run build` 成功,入口 chunk 不因本次上涨。

**文档**

12. `docs/UI设计提示词.md §28` 就地改写(版式、上下文条、分组、sticky 口径),`docs/需求设计说明书.md §4.5.5` 补「按日分组/右栏常驻」等用户可见行为;走 `/archive`。
