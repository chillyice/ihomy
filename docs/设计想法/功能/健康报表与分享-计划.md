# 健康报表与分享 — 计划(三段)

> 需求原文(2026-11-19):「自己的健康数据默认只能自己看,但是可以分享;健康报表默认显示最新的数据;报表可以自己自定义,可以自行选择想要展示的数据,制作多种健康卡片;默认展示最近一天的睡眠节奏、近七天的步数与运动消耗、最近一天的心率变化、异常指标告警;增加健身目标(步数/运动消耗卡路里/睡眠时长);对健康数据连续保持程度给予积分奖励(连续几天 8 小时睡眠、连续几天步数、连续几天运动燃烧卡路里)。」
>
> 分享口径(用户 2026-11-19 更正):分享**不是**开放实时数据通道——生成的是「此刻这份报表」的**冻结快照**,链接 7 天可见,到期删除;本人随时可删掉让它立刻失效;敏感指标是否进快照由本人在生成时决定。
>
> 状态:**第一段已落地(V13.26)**,第二段(健身目标)、第三段(连续天数 + 积分)待排期。

### 2. 报表:默认最新数据 + 自定义卡片

**卡片目录唯一来源**:后端 `common/HealthReportCard`(11 张,`MAX_CARDS=12`),前端 `views/health/reportCards.js` 同口径(标题走 i18n `health.report.cards.*`)。

| id | 内容 | 敏感 |
|----|------|------|
| `sleep_last` | 最近一晚睡眠节奏 + 分期 | 否 |
| `sleep_7d` | 近 7 天睡眠时长序列 | 否 |
| `steps_7d` | 近 7 天步数 | 否 |
| `energy_7d` | 近 7 天活动消耗 | 否 |
| `exercise_7d` | 近 7 天锻炼时长 | 否 |
| `resting_hr_7d` | 近 7 天静息心率 | 否 |
| `hr_day` | 最近一天心率变化 | 否 |
| `spo2_day` | 最近一天血氧 | 否 |
| `weight_trend` | 体重趋势(30 天) | 否 |
| `alerts` | 异常指标告警(14 天) | 否 |
| `menstrual_7d` | 近 7 天经期 | **是** |

- **默认五卡** = `sleep_last, steps_7d, energy_7d, hr_day, alerts`(正好覆盖需求里的「最近一天睡眠节奏 / 近七天步数与运动消耗 / 最近一天心率变化 / 异常告警」)。
- **默认最新数据**:`HealthReportService.latestDate()` = max(最近样本日, 最近睡眠清醒日);所有窗口锚到它(`7 天窗口 = latestDate-6 … latestDate`),响应带 `asOf` 供页面显示「数据截至 X」。睡眠按入睡日落库,用「今天」在上午会空,所以必须锚最新数据。
- 接口 `GET /health/report?cards=&date=`(登录,只本人);`cards` 缺省 = 默认五卡,未知 id 丢弃,`alerts` 恒可算。
- 卡片选择存 `sys_user_pref` 键 `health.report.v1`(`utils/userPref.js` 本机 + 账号同步,与首页布局同范式),可一键恢复默认。
- 告警口径(`common/HealthAlerts`,纯函数 + 单测):
  - 参考区间:血氧 95–100%、静息心率 45–100、呼吸 10–24、体温 35.5–37.5、收缩压 90–140、舒张压 60–90、血糖 3.9–7.8 → `WARN`;
  - 个人基线:最近 14 天该指标 ≥7 天均值 ±2σ,超出 → `INFO`(`σ=0` 跳过);
  - 敏感指标永不进告警;最多 5 条,`WARN` 优先、按偏离幅度排序。
- 页面:`/health` 第一个页签由「概览」改「报表」(`?tab=overview` 兼容映射),顶部「数据截至 X」,工具栏「自定义卡片」「分享」。

### 3. 快照分享:7 天只读链接

- 新表 `family_health_share`:`id / family_id / owner_user_id / token(32 hex,uk) / cards(JSON) / snapshot(MEDIUMTEXT,冻结的报表 payload) / include_sensitive / anchor_date / expire_at / view_count / last_viewed_at / created_at`,索引 `uk_token`、`idx_owner`、`idx_expire`。无 `deleted` 列——**物理删除**,按 id 删即内容消失。
- 生成(`HealthShareService.create`):按选中卡片调一次 `HealthReportService.build(userId, cards, consent, anchorDate)` 把结果**整个序列化进 `snapshot`**,`expire_at = now + 7 天`;返回 `id/token/path/expireAt`。
  - 敏感卡片:请求里勾了**且**本人已开启采集同意才保留,否则丢弃;丢弃后为空则回默认五卡且 `include_sensitive=0`。
- 读取(`GET /public/health/share/{token}`,免登录):**只返回 `snapshot`**,不再查任何健康业务表——所有者之后删数据、改设置,都不影响这 7 天里已发出的快照(这正是「截图」语义);累加 `view_count`、`last_viewed_at`,写 `scope=SHARE` 审计(匿名 `viewer_id=NULL` + IP)。过期行读到即删并 404;被删/不存在一律 404。
- 列表 / 删除:`GET /health/share`(本人,最多 50 条:`remainingDays` 向上取整、`viewCount`、卡片摘要、`includeSensitive`)、`DELETE /health/share/{id}`(仅所有者,物理删,链接立刻 404)。
- 清理:`HealthRetentionService` 每日 04:20 的 `purge()` 增加 `HealthShareService.purgeExpired(now)`,`expire_at < now` 行删除;返回三元数组(样本 / 查看审计 / 分享)。
- 前端:`HealthShareDialog.vue`(勾卡片 / 敏感开关 / 生成并复制 / 已有链接列表:剩余天数·查看次数·删除)与公开只读页 `/health/shared/:token`(`meta.public`,`HealthShared.vue` 顶部写「X 分享 · 有效期至 Z」,正文是 `HealthReport readOnly`,无工具栏,便于整页截图)。

CREATE TABLE IF NOT EXISTS `family_health_goal` (
  `id`            BIGINT       NOT NULL AUTO_INCREMENT,
  `family_id`     BIGINT       NOT NULL,
  `user_id`       BIGINT       NOT NULL,
  `metric`        VARCHAR(32)  NOT NULL COMMENT 'STEPS/ACTIVE_ENERGY/EXERCISE_MIN/SLEEP_MIN',

## 第三段:连续天数 + 积分(待排期)

**要做**:连续达标天数落库,每日结算发积分,积分规则可配。

- 表 `family_health_streak`:

```sql
CREATE TABLE IF NOT EXISTS `family_health_streak` (
  `id`              BIGINT      NOT NULL AUTO_INCREMENT,
  `family_id`       BIGINT      NOT NULL,
  `user_id`         BIGINT      NOT NULL,
  `metric`          VARCHAR(32) NOT NULL COMMENT 'STEPS/SLEEP_MIN/ACTIVE_ENERGY',
  `current_days`    INT         NOT NULL DEFAULT 0,
  `best_days`       INT         NOT NULL DEFAULT 0,
  `last_hit_date`   DATE        DEFAULT NULL,
  `updated_at`      DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_metric` (`user_id`, `metric`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

- 结算:`@Scheduled(cron="0 30 4 * * *")`(在 04:20 清理之后跑),按「昨天」判定:
  - 达标 = 当天样本求和 ≥ 该指标目标(第二段的目标,无目标则用内置门槛:步数 8000、睡眠 480 min、活动消耗 400 kcal);
  - 达标 → `current_days+1`、`last_hit_date=昨天`;不达标 → 归零(保留 `best_days`);
  - **幂等**:`UPDATE ... WHERE user_id=? AND metric=? AND (last_hit_date IS NULL OR last_hit_date < 昨天)`,或把结算日在 Redis 记 `ihomy:health:settle:{date}` 抢占,重跑不重复加天、不重复发分。
- 积分:`PointsRuleConst` 加「健康」分组(如 `HEALTH_STREAK_7` / `HEALTH_STREAK_30`),按**里程碑**发分而不是每天发——连续 7 天、30 天各发一次,避免刷分;发分走既有 `PointsService` 明细表,重复发放靠 `(规则, 用户, 里程碑日期)` 唯一约束。
- 报表/积分页:报表加卡片 `streak_7d`(三条连续天数 + 最好记录);积分页「健康」分组列里程碑记录。
- 前端设置页展示当前连续天数与最好记录(只读,由结算任务维护)。
