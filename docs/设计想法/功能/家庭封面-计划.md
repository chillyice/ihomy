> **状态**:批次一已落地(2026-11-13,提交 `c73b738`,随 V12.13 发布);余下 B/C/D 三批**未开工**。**版本号不预占**,开工时按 `VERSION` +1。

## 3. 阶段 B:移动端补齐

### B1 「我的」页头部 banner

- 现状:`.me-header` 是「头像 + 昵称 + 族名」三行信息块。
- 改法:在 `.me-header` 之上加一条 16:9 封面横幅(`aspect-ratio:16/9` 或固定 132px 高，`object-fit:cover`），有封面才渲染；无封面时**整块不占位**（不要留空框）。族名从文字块里保留不动，避免「有封面时族名消失」。
- 细节:横幅与下方卡片的圆角统一 14px；深色模式不加额外遮罩（图本身就是内容）；banner 内不放任何按钮（防止与「设置」入口抢点击）。
- 验收:390×844 与 320 宽两档，横幅高度固定不跳动、不与 TabBar/MobileHeader 重叠；无封面时页面首屏高度与现在一致。

### B2 移动端家庭切换列表加缩略图

- 现状:`MobileMePage.vue:19-36` 每行只有 `f.name` + 当前家庭勾。
- 改法:与桌面口径对齐——44px 圆角方（移动端行高更紧，比桌面 56 小一档）+ 名称 + 勾，`flex-shrink:0`，无封面回落首字母。
- 验收:设备断点变化时行高不塌陷；长家庭名仍省略不换行。

## 4. 阶段 C:上传端收口

### C1 横图裁剪(建议先做)

- 现状:`uploadCover` 原图直传（`FamilySettings.vue:131-139`），任何比例都能进来，靠各展示位 `object-fit:cover` 硬裁；4:3 图塞 44px 方块会丢主体。
- 改法:复用 `components/AvatarCropper.vue`（canvas 裁剪、无外部依赖，目前只被 `views/settings/ProfileSettings.vue:57` 使用），但该组件**输出写死正方形**（`canvas.width = out; canvas.height = out`），需增加 `ratio` prop（默认 1 保持头像行为不变），封面传 `16/9`。
- 产出:裁剪后再 `fileApi.upload`，落 `cover_image`。不做服务端裁剪（前端一次到位，服务端没有图片处理链）。
- 验收:上传 4:3 / 3:4 / 超宽图各一张，裁剪框可缩放拖拽、导出尺寸为 16:9；取消裁剪不发请求；头像路径（ProfileSettings）行为零变化。

### C2 文案改人话(顺手同步)

- 现状:`settings.coverTip` = 「显示在家庭切换与家庭搜索列表中」(`i18n/zh-CN.js:2229` / `en.js:2246`)，批次一之后已经不准确（顶栏/侧栏也用）。
- 改为:「建议上传横图，展示时会按位置自动裁切；会出现在顶栏、侧栏、家庭切换与搜索列表」+ 英文对齐。
- 守门:`hardcoded-cjk.spec.js` 与 i18n 键对齐 spec 必须仍绿。

### C3 清空写 NULL + 换图删旧文件

- 现状两条都缺（§1.2）:清除后库里留 `''`；换图/清除后旧文件成孤儿（测试用例已记）。
- 改法(后端，`FamilyController.update`):
  1. 前端「移除」改为提交 `coverImage: null`（或后端把 `''` 归一成 NULL，二选一，建议**前后端都做**：前端传 null，后端 `isBlank → null` 兜旧客户端）。
  2. 换图/清除时 `fileService.deleteByUrl(oldCover)`，写法照 `AlbumService.java:244`；注意 `deleteByUrl` 内部会连带删缩略图，别重复删。
  3. 只删 `/files/` 前缀的 URL（`/demo/...` 这类随 dist 部署的静态资源不能删）。
- 验收:换图三次后 `uploads/files/<yyyyMM>/` 只剩最后一张；清除后 DB 回读为 `NULL`（不是 `''`）；换成 `/demo/*.svg` 时不删任何文件；游客首页缓存仍按既有 `invalidateHomeCache` 失效。

### C4(可选)压缩与尺寸上限

- 需求不明确，先不做；若做，放在 C1 的 canvas 导出参数里（`toBlob(..., 'image/jpeg', 0.85)` + 最长边 1600），不引第三方图片库。

## 5. 阶段 D:对外门脸(需拍板)

### D1 游客 / 分享落地展示封面

- 可行前提:**只有 `is_public=1` 的家庭**其封面才对游客下发（§1.2/§1.4 已成立），不需要新接口——`/public/home` 的 `family.coverImage` 游客本来就能拿到。
- 候选展示位(按推荐度):
  1. **分享落地首屏顶部**（`/?hid=` 进来后的首页顶部一条横幅 + 族名）——这是「门脸」最正的位置，且天然只对公开家庭生效。
  2. 家庭搜索/加入申请列表已放大到 56px（批次一），可再叠一层「点击看大图」不必要。
- 不建议:登录页(登录前不知道是哪个家庭)、`/cover` 页、首页仪表盘封面卡。

### D2 壁纸 / Kiosk(挂机屏)

- 定位:那块屏最「配」封面，但壁纸页刻意轻量、天气 AI 底图是签名视觉。
- 允许的两种弱形态:①无天气底图时的**兜底底图**（低透明度 + 模糊）；②角落里一张小相框卡片，与照片卡同款拖拽记忆。
- 明确不允许:替换天气 AI 底图、加新的常驻大图组件。

## 7. 测试与验收

- 单测(前端):若给 `AvatarCropper` 加 `ratio`，补 2 例纯函数级断言（比例换算、导出宽高）；`MobileMePage` 的「有无封面」两态用快照/渲染测试覆盖不必强求（该目录现无组件测试）。
- 后端:若做 C3，`FamilyController` 的清除/换图分支要有测试（纯逻辑可测的部分抽到方法里），并验证 `''→NULL` 归一。
- 浏览器实测(本机 nginx dist):先 unregister SW + 清 caches；量几何前注 CSS 杀过渡（IAB 会把 el-dialog 冻结在 `scale(0.94)`）；跨页用 `tab.goto` 不用页面内导航。
- 演示数据纪律:临时给演示家庭挂封面验证后**必须还原**（本次批次一即用 `/demo/seaside-dusk.svg` 验证后改回 NULL），并 `DEL ihomy:home:pub:1` 让缓存重建。
- 回归基线:`npm run lint` 0 error、`npx vitest run`(当前 1115 passed)、`npm run build`(首屏初始 JS 48 chunk ≈1563KB)、后端 `mvnw -B clean package`、文档闸门三道。
