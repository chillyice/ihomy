# 家圃时光后端开发计划

游戏客户端方向已选 Godot。整体架构、Godot 版本与导出方式、服务边界、存档格式和部署位置待定。原 Cocos 架构稿已废弃。本文交接玩家动作、状态和验收场景，供后端会话据此提方案。

## 当前可以体验什么

本机登录成员从 `/home` 便签进入。拆信、备盆、覆土播种和首次浇水走游戏接口，近景从服务器恢复本人窗台 0 号盆的作物与生长阶段。盆里有了嫩芽，在窗台远景也能看到。Godot 近景由游戏仓的 `garden-godot/preview.py` 托管。

美术评审单独使用 `/home?gardenPreview=1`。试玩进度按浏览器、成员和家庭保存。浇水后可立即对照湿土、破土、真叶三种草图，并从近景返回窗台检查落点。

## 开发顺序

| 顺序 | 要回答的问题 | 开发与验收 |
|---|---|---|
| 1 · 入口和身份 | 谁能从哪个家庭进入，落到谁的窗台？ | 复用 ihomy 的成员与家庭身份，约定首页如何获知入口开放状态和可选提示（有信、需照料、平静）。验证同一成员切换家庭、登出、分享页、游戏停用、服务暂时离线。正式入口仍是首页侧边便签。保留现有 `/tools/plant`。 |
| 2 · 第一封信 | 第一次打开信件后，下一步手里有什么？ | 根据玩法稿，首次拆信给予一包当季首盆种与 30 园币。读信、领物和再次阅读要有一致的结果。验证跨设备重复点击、断线重试、两端同时打开只获赠一次。 |
| 3 · 第一盆 | 拿到种子后，怎样完成一个能回访的循环？ | 从备盆、播种、照料、离线生长到首次收获，再种第二盆。先串通一种种子和一只盆。约定服务端时间、耗材扣减、同一盆并发操作、收获入库的规则。以关闭页面再打开、另一台设备续玩、重复收获为验收。 |
| 4 · 家庭接力 | 哪些东西属于个人，哪些可以全家接手？ | 明确个人房间与共享院子的操作权限，选择一个真实接力场景验收，例如一人播种后另一位成员在共享地照料。在样例中检查跨家庭访问和同时操作。 |
| 5 · 后续成长 | 玩家在哪些操作中真的产生了选择？ | 根据试玩再接物品制作、扦插、杂交和技能分支。技能点来源先评估少量任务、成就、累计积分里程碑，区分游戏点数与站内可消费积分。到达最深节点与补齐其他叶节点分别统计，周期由分支深度、点价和试玩反馈决定。 |

## 另一个会话先交付什么

1. 一页架构决策草案。比较 Godot 客户端如何取得当前玩家、怎样恢复进度、何处结算时间与物品，以及弱网时如何处理重复操作。列出需要负责人决定的取舍。
2. 一份可供 UI 使用的示例数据。覆盖入口隐藏、便签平静、有信、待照料、首次窗台与已有一盆这六种情况，给出动作成功、读取失败和再次进入的示例。接口名与存储形式由后端方案确定。
3. 一个可验证的最小闭环。先用两个成员、两个家庭跑通「一封信 → 一盆植物 → 首次收获 → 第二次播种」，记录每一步读写、归属与异常恢复。达成后再协调 Godot 的场景交接、准备完成、返回和恢复。
