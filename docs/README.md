# ihomy 文档索引

> 一页地图:每份文档一句话定位 + 谁该读。新成员/新会话从这里出发,不必通读全部。

## 新人阅读顺序

1. 根 `README.md` —— 项目是什么,30 秒
2. `docs/架构设计.md` —— 系统怎么组成、一个请求怎么走、关键机制为什么这样设计,约 30 分钟通读
3. `AGENTS.md` —— 项目规则与约定(命名/数据库/代码规范/性能/坑速查),写代码前必读;AI 会话自动加载
4. `docs/需求设计说明书.md` —— 只读你负责业务域的 §4 小节 + §6 数据库设计,其余按需
5. `docs/变更归档.md` —— 按需检索(450KB+,**按开头的章节目录定位小节**,不要通读),找历史实现/踩坑/live DB 迁移 SQL

环境搭建与开发账号见本地《新人上手指南》(不入 git,由维护者直接发给新成员)。

## 文档维护规矩

- 新的变更归档**追加到 `docs/变更归档.md` 末尾**,不写回 AGENTS.md(AGENTS.md 只留规则+导航,60KB 上限)。
- 功能需求变更同步 `docs/需求设计说明书.md`,修订记录接续 V9.x 编号、**保持版本降序**。
- **计数口径唯一来源**:表数以 §6.2 清单(与 `schema.sql` 实测 `CREATE TABLE` 条数)为准,实体/Controller/Service/Api/页面/路由数以代码实测为准;改完表或新增页面后,顺手同步 **AGENTS.md 代码结构、`docs/架构设计.md` 数字口径、`README.md`、本索引、`docs/部署指导-*.md`** ——这几处历史上成批滞后过(61/64 张 vs 实际 70 张)。
- 本索引新增/删除文档时同步更新。
