## 1. 工具链与环境

### 1.1 含中文的文件只能走 Read/Write/Edit 工具

- **症状**:PowerShell 折腾过的文件里中文变乱码;含中文的 Java 源文件编译报「非法字符: '\ufeff'」。
- **真因**:PS 5.1 默认 GBK,`Get-Content`/`Set-Content` 会把 UTF-8 中文按 GBK 解码再写回;`[IO.File]::WriteAllText` 默认带 BOM,带 BOM 的 `.java` 会被 javac 拒绝。
- **对策**:含中文的源码/配置/SQL/文档一律用本工具的 Read/Write/Edit 读写。PowerShell 只用于 npm/mvn 构建与 HTTP 冒烟。

### 1.2 脚本化改写文档会吃掉 CRLF

- **真因**:本仓 `core.autocrlf=true`,工作区 md 是 CRLF;而 `io.open(p, encoding='utf-8').read()` 默认把 `\r\n` 折成 `\n`,写回就把整份文件换成 LF(`git diff` 会警告 `LF will be replaced by CRLF`)。
- **对策**:批量/行级改写一律 `open(p,'rb')` 读 + `split(b'\r\n')` + `b'\r\n'.join(...)` 写(零编码风险);小改用 Edit 工具(按文件原约定写)。
- **复核**:`open(p,'rb').read()` 的 `\n` 数减 `\r\n` 数应为 0;提交前 `git diff --stat` 不该看到全文重写。
- **补充(2026-09-29 实测)**:**`Edit` 工具本身也会吃掉 CRLF**——改 `backend/src/main/java/**/*.java` 后**整个文件**变成 LF(实测两个 Java 文件改完 `\n` 减 `\r\n` 分别为 72/125,即全文;同批改的 `.sql`/`.vue`/`.js`/`.md` 却保住了 CRLF,所以**别假定 Edit 保住行尾**)。**难发现的原因**:`core.autocrlf=true` 让 git 提交时自行归一化,`git diff --stat` 只显示真实改动行、不爆整文件 diff。**对策**:改完 `.java` 复核 `d.count(b'\n')-d.count(b'\r\n')`(应为 0),非 0 就 `d.replace(b'\r\n',b'\n').replace(b'\n',b'\r\n')` 写回(只换行尾、UTF-8 中文安全)。

### 1.3 PowerShell 5.1 原生命令传参两坑(start-db.ps1 踩坑)

- ① **不带引号的点号参数会被拆词**:`mysqladmin ping -h127.0.0.1` 实际收到主机 `127`(点号被当参数分隔)。必须写成 `'-h127.0.0.1'`。
- ② **传给原生命令的参数里嵌双引号会被吃掉**:`docker inspect --format '{{ index .X "key" }}'` 必然探测失败。改用无引号模板 `{{.Config.Labels}}` 或行为式判断。
- ③ **.ps1 含中文必须带 UTF-8 BOM**:无 BOM 时 PS 5.1 按 GBK 解析,直接语法错误。Write 工具默认无 BOM,新建中文 `.ps1` 后须补 BOM。

### 1.4 Git Bash(MSYS)路径自动转换坑

- **症状**:`docker cp file ihomy-mysql:/tmp/` 与 `docker exec ... source /tmp/x.sql` 静默失效,报 `error: 2`(找不到文件)。
- **真因**:Git Bash 调 Windows 原生命令(docker.exe 等)时,参数里的 POSIX 风格路径会被自动转成 Windows 路径(`/tmp/x.sql` → `C:/Users/.../Temp/x.sql`)。
- **对策**:**docker 容器内路径参数一律加 `MSYS_NO_PATHCONV=1` 前缀**,如 `MSYS_NO_PATHCONV=1 docker exec ihomy-mysql mysql -e "source /tmp/x.sql"`。

### 1.5 打包 zip 别用 `Compress-Archive`

- **真因**:PS 5.1 的 `Compress-Archive` 写出的条目用**反斜杠**分隔(`wallpaper-engine\index.html`),不符合 ZIP 规范(应正斜杠)。Windows 资源管理器/7-Zip 能忍,Info-ZIP 等非 Windows 解压工具会把整条路径当成一个文件名。
- **对策**:用 Windows 自带 bsdtar——`tar -a -c -f out.zip dir`(`-a` 按扩展名选格式)。壁纸包发布踩过这个坑。

### 1.6 向 MySQL 写入含中文的 SQL

- **禁止**:PowerShell 管道 `Get-Content file.sql | docker exec -i mysql mysql ...`(PS 5.1 管道编码非 UTF-8 → 中文乱码)。
- **本机正确方式**:① 用 Write 写 SQL 文件(UTF-8 无 BOM)→ ② `MSYS_NO_PATHCONV=1 docker cp file.sql ihomy-mysql:/tmp/` → ③ `MSYS_NO_PATHCONV=1 docker exec ihomy-mysql mysql --default-character-set=utf8mb4 ihomy -e "source /tmp/file.sql"` → ④ 清理临时文件。
- **纯 ASCII SQL** 可直接 `docker exec ihomy-mysql mysql -e "..."`。
- **远程**:`scp -P 19068 file.sql root@ihomy.top:/tmp/` → SSH 内 `mysql -e "source /tmp/file.sql"`。
- **别被终端骗**:终端把中文显示成 `?` 是 GBK 终端问题,不代表库内存的是乱码——用 `python -c "import subprocess; ..."` 取回字节比对验证。

### 1.7 构建与运行后端

- **`mvnw.cmd` 必须在 `backend` 目录内调用**:它在**当前目录**找 `.mvn/wrapper`,而 wrapper 在 `backend/` 下;在仓库根调会报「找不到 maven-wrapper.properties / 主类 MavenWrapperMain」。脚本里先 `Push-Location $Backend`(见 `start-all.ps1`/`restart-all.ps1`)。
- **jar 被锁时按 PID 结束本地后端进程**:命令行含 JetBrains/IntelliJ 的是 **IDEA 本体,绝不能杀**;禁止 `taskkill /IM java.exe` 全杀。
- **`clean` 报 `Failed to delete ...\target\surefire-reports`(无后端运行也会遇到)**:上一次 `-B test` 的 fork JVM 句柄或 OneDrive 同步的瞬态锁,与代码无关;`Remove-Item -Recurse -Force backend\target` 手动删掉再重跑即过,别当成代码问题排查(clean 失败致旧资源残留的后果见 §2.18)。
- **必须用完整路径单实例运行**:`C:\Program Files\Java\jdk-21\bin\java.exe -jar target\ihomy-backend.jar`——用 javapath launcher 且同时存在两个 JDK 实例时,8080 请求会被分流,表现为偶发 401/404/500。
- 临时 Maven(本机未装 mvn):`C:\Users\chill\AppData\Local\Temp\opencode\apache-maven-3.9.9\bin\mvn.cmd`;`JAVA_HOME` 用 `C:\Program Files\Java\jdk-21`。
- **接口冒烟要先过首登改密闸门**:种子账号 `admin`/`ops` 带 `sys_user.must_change_password=1`,其访问令牌带 `pwdChange` claim 时 `JwtAuthenticationFilter` 只放行改密与登出——**打任何业务接口都会 403/401**。跑接口冒烟前 `UPDATE sys_user SET must_change_password=0 WHERE username='admin'`,**跑完务必恢复 1**(冒烟脚本用 try/finally 收尾)。

### 1.8 多会话并行改本仓

- **禁用 `git stash`**:path-limited 的 `git stash push` 会把共享文件(i18n/router)里**其他会话未提交的改动**一起回滚,现象是「刚加好的文案与路由突然消失」。
- **他人 stash 不 pop**:取自己那部分只读不写——`git show "stash@{0}:<path>"` 按块插回。
- **别并行 `npm run build`**:会争 `public/emulatorjs` 与 `dist/`。

### 1.9 文档反向漂移:声明了的功能/接口必须在代码里真实存在

- **症状**:`docs/需求设计说明书.md` §4/§7 把一个从未实现的功能写得像已完成(2026-10-05 查实:「密码找回」在 §4.1.4/§7.3/§5.3 被当已实现记载,但后端**零实现**——无 `forgot`/`reset` 接口、无 `JavaMailSender`、external.yml 无 SMTP,前端也明说「联系运维管理员」),读者/AI 会照着文档去调不存在的接口。
- **真因**:归档只做「代码 → 文档」单向(新功能写进文档),从不反向核对「文档声明的功能是否真的落地」;表(`sys_password_reset_token`)与配置段先建、功能后做时,容易把「预留」误写成「已实现」。
- **对策**:①归档自检加一步**抽样反向核对**——文档里出现的接口路径 `grep` 一次代码,功能小节至少确认 Controller/Service 存在;②未实现的功能一律在 §4 明确标注「未实现」并把条目移进 §9,措辞不得用「已完成」;③预留表/预留配置段在文档里写明「预留」,不要与已实现功能混排。
- **取证**:`grep -rn "forgot\|password/reset" backend/src/main/java/` 返回空;`grep -rn "JavaMailSender\|spring.mail" backend/src/main/` 返回空。**(该功能已于 V10.14 实现,以上取证命令不再返回空——此处保留为「反向漂移」教训的历史记录。)**

### 1.10 schema.sql / migrations.sql 手工执行必须带库名(否则只跑前一半)

- **症状**:`docker exec ... mysql -uroot -p -e "source /tmp/migrations.sql"` 跑到中途报 `ERROR 1046 (3D000) ... No database selected` 停住——**前面已执行的语句照常生效**,看着像「跑过了」,其实后面的段(含你本次要补的种子)一条没跑。
- **真因**:`migrations.sql` 不自带 `USE ihomy;`(它假定执行者已选库);`source` 写在 `-e` 里时库上下文只来自命令行参数,不传库名就没有默认库。
- **对策**:一律 `mysql --default-character-set=utf8mb4 -uroot -p <库名> -e "source /tmp/x.sql"`(或 `mysql <库名> < x.sql`);看到 `No database selected` 按**失败**处理并重跑,别当警告略过。空库全量实测要另起一次性容器(现网/开发库的 `schema.sql` 建表带 `DROP`,不能直接导开发库)。
- **取证**:同一条 `source` 加库名后 exit 0,且 `SELECT COUNT(*)` 增量符合预期(本次 `sys_oss_component` 44→49)。

### 1.11 文档/代码一致性闸门(V10.18 起,`scripts/doc-drift-check.sh`)

- **症状/价值**:改了代码忘改文档、或文档写了代码里没有的东西(`§1.9` 那类),评审与 AI 都会照着错的口径走。
- **口径**:`bash scripts/doc-drift-check.sh`(CI 在 checkout 后**最先跑**,无依赖)→ 7 组只读检查:①VERSION 单行且形如 `V<主>.<次>`;②表数一致(AGENTS「**N 张表**」+ 各前缀 / 需求 §6.2 / `README.md`·`docs/README.md`·两版部署指导的「N 表」写法 ↔ `schema.sql` 实际 `CREATE TABLE`);③实体 `@TableName` ↔ 建表(防「表已改名/删除、实体留下」);④mapper 接口无 `@Select/@Insert/@Update/@Delete`;⑤每个 `*Controller.java` 带 `@Tag`;⑥`@RequirePermission("码")` 的码已进 `sys_auth` 种子;⑦启用首页模块 `path` ↔ 前端路由。

### 1.12 shell 脚本:`pipefail` 下 `grep -q` 会让上游「随机失败」(V10.18)

- **症状**:同一脚本多次运行结果不一致——`scripts/doc-drift-check.sh` 的「Controller 都带 `@Tag`」时 OK 时 FAIL,且报的恰是明明有 `@Tag` 的文件。
- **真因**:脚本开头 `set -uo pipefail`。`perl … | grep -q 模式` 中 `grep -q` 一命中即退出,上游 `perl` 收到 SIGPIPE 以 141 退出;`pipefail` 让整条管线取到非 0 → 被当成「没匹配」。是否触发取决于 perl 是否已把输出写完,故**随机**(同一份代码两次跑结果不同)。
- **对策**:别用 `… | grep -q`;先把输出落变量 (`src="$(strip "$f")"; grep -qE '…' <<<"$src"`) 或落临时文件再匹配,或用 `grep -c … >/dev/null`(读完全部输入、不早退)。同理慎用 `| head -1`,改 `grep -m1`。
- **取证**:修前同代码连跑 3 次结果各异;修后连跑 5 次均「17 项 OK / 0 FAIL」,并用一个缺 `@Tag` 的探针 Controller 反向验证仍能抓出(证明不是「改成了永远通过」)。

### 1.13 前端 lint/format 口径(ESLint 9 扁平配置 + Prettier,V10.17 起)

- **症状**:改完前端不知该跑什么;或误以为 `npm run format` 已全仓生效;或新增依赖被 CI 拦下。

### 1.14 工作树在 OneDrive 下:`mvn clean` 删不掉 `backend/target`(V10.74)

- **症状**:`scripts/deploy.ps1`(或 `mvnw clean package`)在 clean 阶段失败:`Failed to delete .../backend/target/classes/com/ihomy/annotation`,但**没有 java 进程占用**;`Get-Item target` 显示 `ReadOnly, Directory, ReparsePoint`(OneDrive 占位/只读标记)。
- **真因**:OneDrive 同步会在构建产物目录上留下 ReadOnly 属性与 reparse point,Maven Clean 用的是普通删除,遇到只读/占位目录直接报错;与代码和依赖无关。
- **对策**:构建前把产物目录整个删掉(OneDrive 的 ReadOnly/ReparsePoint 只影响「普通删除」)。`scripts/clean-build-target.ps1` 做全套:清只读位 → 递归强删 → 重试 5 次 → `cmd rd /s /q` 兜底 → 仍删不掉就改名 `target.stale-<时间戳>` 让 Maven 重建;删除不跟随 junction,不会连带清外部目录。`restart-all.ps1` / `deploy.ps1` / `start-all.ps1` 已在 `mvnw clean` 之前自动调用它,咔哒 `Alt+I` 重建因此不再卡 clean;IDE / 手工构建撞上同一把锁时按咔哒 `Alt+Shift+I`(或直接跑该脚本)。不要为此改 pom 或给 clean 加 `-Dmaven.clean.failOnError=false` 掩盖问题。
- **取证**:删除前 `Get-ChildItem backend\target -Force | Select Attributes` 可见 `ReadOnly, Directory, Archive, ReparsePoint`;脚本在真实 target 上第 1 次尝试即删除成功,只读目录 + junction 用例也通过且外部文件未被删。2026-10-27 记录见 `docs/变更归档.md` V10.77(V10.74 首次记录用 `Remove-Item -Recurse -Force` 手工删除)。

### 1.15 HTML → PDF 走 Chromium:页眉页脚与分页的硬约束(软著材料生成器)

- **页眉页脚**:`Page.printToPDF` 的 `headerTemplate` / `footerTemplate` 由浏览器按 UA 默认样式渲染,其中 `font-size:0`——**模板里不显式写 `font-size` 时整块不可见**;页眉页脚只占用 `marginTop` / `marginBottom` 预留的空间,边距给 0 会与正文重叠。`scripts/soft-copyright/build_manual_doc.py` 的两个模板都内联了字号与边距。
- **分页**:交给 CSS 自动分页时,分页点由行高与字体加载时机决定,页数与每页行数做不到「60 页 × 50 行」;生成器改为**固定页盒**(每页一个定高 `.page`,按行数切分),行数才是确定的。
- **复核必须看两侧**:PDF 侧用 `pypdf` 抽取复算总页数与每页非空行数;DOM 侧量 `scrollWidth/clientWidth`(横向溢出)与 `.code` 底边距页底的距离(纵向裁切)。只肉眼看截图会漏掉最后一行被切掉、或长行被裁。
- **实现与规则**:`scripts/soft-copyright/print_pdf.mjs`(Chromium DevTools,自动找 Edge/Chrome,可用 `CHROME_PATH` 指定)+ 两个 `build_*.py`;材料规格与重新生成步骤见 `docs/软著/README.md`。

## 2. 后端

### 2.1 直改 DB 不生效:启动时预热的内存缓存

`HomeModuleService` 的全局模块在 `@PostConstruct` 预热进内存(**无 TTL、无兜底刷新**),直接 `UPDATE sys_home_module` 不会失效——直改 DB 后必须重启后端才生效(或走模块管理接口触发 evict)。同理适用于其他启动时预热的内存缓存(如保险箱模块排序调整)。

### 2.2 MP `updateById` 会回写实体旧 `updated_at`

- **真因**:MyBatis-Plus `updateById` 把实体字段整体写回,包括 `updated_at` 的旧值,从而抑制 MySQL 的 `ON UPDATE CURRENT_TIMESTAMP`。
- **对策**:依赖 `updated_at` 的表更新必须用 `LambdaUpdateWrapper` 只 SET 业务字段,然后重查(`selectById`)拿新值。
- **已踩实例**:`family_vault_item` 编辑(V10.16 修,症状是前端「更新于」永远停在创建时间);`family_loan`(V9.101)/`sys_media_server`(V9.106)落地时即按上式写法。
- **⚠ 局部更新表单的叠加坑**:保险箱这类「空值 = 本次不改该字段」的表单,用 `LambdaUpdateWrapper` 必须**逐字段判空后再 `set`**,不能一把 SET 全部字段(否则未提交字段被写成 null);并且 **wrapper 里一个 `set` 都没有时会产出非法 SQL**,收集完要 `if (!changed) return` 提前返回。
- **系统性根治(V10.22)**:与其逐处记着换 `LambdaUpdateWrapper`,更稳的是给实体 `updatedAt` 字段加 `@TableField(updateStrategy = FieldStrategy.NEVER)`——`updateById` 生成 SET 子句时直接跳过该列,其余字段照常更新,DB `ON UPDATE CURRENT_TIMESTAMP` 正常触发。全仓 33 个含 `updated_at` 的实体已统一如此。**踩坑**:带 `fill` 的字段会走 `withUpdateFill` 早返回、**绕过 `updateStrategy`**,故其中 7 个原 `@TableField(fill = FieldFill.INSERT_UPDATE)` 的须先降为 `fill = FieldFill.INSERT` 再叠加 `updateStrategy = NEVER`,只加 `updateStrategy` 不生效(实测于 MyBatis-Plus 3.5.5 `TableInfoHelper`;`FieldStrategy.NEVER` 语义=该字段永不进 SET)。此后新增实体凡有 `updated_at` 照此办理。

### 2.3 家谱等表更新 null 字段

`LambdaUpdateWrapper` 必须**显式 SET** 为 null,否则 null 字段不会被写(更新语义是「只更新非 null」)。家谱照片/生日等可清空字段踩过。**实体 `setXxx(null)` 再 `updateById` 同样被整体跳过、字段一个也清不掉**(连带 `updated_at` 也不刷新)——V10.20 查出两例:`sys_user.family_id`(移出成员,被移出者因 `resolveFamily` 回落旧 familyId 仍可访问家庭级读接口)与 `family_task.assignee_id`(放弃任务仍挂原领取人),一律改 `LambdaUpdateWrapper.set(col, null)`;清 `family_id` 还要顺手清该用户当前家庭的 Redis 缓存(`user:curfamily:`),否则仍按旧家庭回落(取证见变更归档 V10.20)。

### 2.4 `authenticationEntryPoint` 必须返回真实 HTTP 401

- **症状**:用户每 2 小时被「未登录或登录已过期」登出,续期从不执行。
- **真因**:前端 axios 只对 **HTTP 401** 触发 refresh;后端只写 JSON 体不设状态码(默认 200)时,续期流程永不执行。
- **对策**:`authenticationEntryPoint` 返回真实 401(JSON 体照写);前端 `request.js` 用共享 `refreshPromise` 让并发 401 共享一次刷新后各自重放(`_retried` 防死循环)。
- **V9.110 起 refresh 单次有效**(轮换拉黑,连带症状都在这一节):普通 refresh 每次使用即拉黑旧令牌,故①**多标签/多端并发**续期靠 **60s 宽限**(宽限内重复提交同一旧令牌返回同一份新令牌)+ 前端 `stores/user.js` 监听 `storage` 事件同步最新令牌,否则另一标签会拿旧令牌续期失败把自己登出;②若现象是「**刚签发的新令牌就被判已拉黑**」,查 JWT 的 `jti`——同秒同用户签发字节会完全相同,轮换拉黑值会与替换令牌撞值(已加 UUID 唯一化);③壁纸令牌是独立 `type=WALLPAPER`(不轮换不拉黑),**别把浏览器那枚 refresh token 给壁纸用**,也别为省事把轮换关掉(壁纸与浏览器会互踢,见 §6 第 5 条)。

### 2.5 判 OPS 只认系统级绑定

- **症状**:家庭 OWNER 每页弹「无权限访问」;运维账号进运维页却按「家长」渲染。
- **真因**:`ops:view` 只是权限码,家庭 OWNER 的角色授权里也带着它(种子「OWNER 拥有全部权限」),但 `OpsAccessFilter` 按**系统级** OPS 绑定放行;而运维账号历史上只建了带家庭占位的那条绑定,`isOps` 恒 false。
- **对策**:前端一律 `userStore.isOps`,禁止 `hasPerm('ops:view')`;OPS 角色的绑定必须带一条 `family_id=NULL` 的系统级行(带家庭占位那条只用于登录时解析出 `role=OPS`)。`family_id` 为 NULL 的语义就是「系统级」,可空列别用占位值填充。

### 2.6 permitAll 接口不许 NPE

- **症状**:未登录 `GET /api/book/summary` 返 500。
- **真因**:接口本在游客放行清单里,但实现直接 `current().getFamilyId()`,游客 `current()` 为 null。
- **对策**:匿名接口按登录态返回**空数据**(游客看不到任何家庭数据),不报错;前端取数前先判 `isLoggedIn`,别打注定 401 的请求。

### 2.7 生产 MySQL 密码策略(轮换踩坑)

生产库启用 `validate_password` MEDIUM(特殊字符/数字/大小写各 ≥1,长度 ≥8)——生成/轮换 DB 密码必须含特殊字符(避开 `' " \ $ |` 转义雷区,建议 `!@%^&*-_+=.`),否则 `ALTER USER` 报 1819。开发 Docker MySQL 无此组件,**同一密码 dev 能过 prod 被拒**。

### 2.8 物理删必须用自定义 XML DELETE;读过逻辑删的数据也只能走 XML

MP 的 `deleteById` 实际是 UPDATE(全局 `@TableLogic deleted`)。照片/相册/视频/图书自 V10.10 起**删除=逻辑删进回收站**(置 `deleted=1`+`deleted_at`,文件保留),只有回收站里的「彻底删除」才走自定义 XML DELETE 物理删 DB + 磁盘文件。

**同一枚硬币的反面**:`selectById`/`selectList(wrapper)` 都被全局逻辑删过滤,`deleted=1` 的行**查不到**——回收站的列表/恢复/超期清理(`RecycleService` + 四表 Mapper XML)必须用自定义 SQL 读已删行,恢复也只能用 XML `UPDATE ... SET deleted=0`(走 `updateById` 会被逻辑删拦掉)。脑图回收站(V9.28)是同一套做法;将来给别的内容表加回收站,照抄这批 XML 语句(`selectTrashByFamily`/`selectDeletedById`/`selectExpiredTrashIds`/`restoreById`),别指望 MP 的常规 API。

### 2.9 内容表 `visibility` 曾是 TINYINT

`content_blog/diary/photo/video/wish` 5 张表的 `visibility` 是 `VARCHAR(20) DEFAULT 'FAMILY'`(PRIVATE/FAMILY/PUBLIC);schema.sql 与 live DB 已对齐,**别再照 TINYINT 写代码或写迁移**。

### 2.10 枚举不再用数字

历史代码里有 0/1/2 判断,已全部改为大写英文单词 + `sys_dict_item` 字典(Java 常量在 `common/DictConst.java`,前端映射 `utils/dict.js`)。**不要写回 0/1/2**。

### 2.11 日记 date 兼容 `yyyy-MM-dd HH:mm`

前端提交的日记日期可能是 `yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm` 两种形态,后端解析必须兼容两者——只按 `yyyy-MM-dd` 解会抛解析异常。

### 2.12 纪念日 Hutool `ChineseDate` 月份 0-based

Hutool 的 `ChineseDate` 取到的月份**从 0 起算**,与公历月份对齐必须 **+1**(否则纪念日整体差一个月)。

另一个方向:`new ChineseDate(lunarYear, month, day, leap)` **不校验月份上界**——传 `month=13` 不抛异常,而是滚到次年正月初一(实测 2026 年传 13 得到 2027-02-06)。所以纪念日日期计算(`common/AnniversaryDate`)必须在进转换前显式判 `month ∈ 1..12`、农历 `day ∈ 1..30`、阳历 `day ∈ 1..31`,否则脏数据不会返回 null 而是算出个看似合法的日期。

### 2.13 Nextcloud 存储设备存的是 DAV 目录地址,不是站点根

`sys_storage_device` 里 NEXTCLOUD/WEBDAV 设备的 `root_path` 形如 `serverUrl|username|ENC(密码)`,其中 `serverUrl` 已被 `StorageService.normalizeDavUrl` 规范化过——**Nextcloud 会被自动拼上 `/remote.php/dav/files/{用户名}`**。所以任何想在站点根上拼路径的功能(例如 V9.109 探测运行版本要打的 `/status.php`)都**不能直接拿它用**,否则 404;正确做法是截到 `/remote.php/` 之前(**保留** Nextcloud 装在子路径如 `https://x/nextcloud` 的情况,别只取 scheme+host)。对照:`sys_media_server.server_url`(放映厅引擎)存的就是站点根,可直接用。

### 2.14 类级 `@RequirePermission` 不生效(切面只看方法注解)

- **症状**:在 Controller 类上挂 `@RequirePermission("x")`,以为全类接口都上锁,实际随便谁都能调;反过来方法上已挂的注解被类上的「同款注解」干扰阅读,分不清到底生效的是哪个。
- **真因**:`RequirePermissionAspect` 的切点是 `@around("@annotation(permission)")`,只匹配**方法级**注解;类上的注解既不被切面读取,Spring 也不会替你装配方法级权限。
- **对策**:权限码一律逐方法写(写在方法上才是生效的那一个);**不许在 Controller 类上写权限注解**。新增权限码前先确认 `sys_auth` + `sys_role_auth` 种子,否则 403 或形同虚设。

### 2.15 mapper XML 注释里不能出现 `--`(后端直接起不来)

- **症状**:构建通过、打包通过,启动时报 `Failed to parse mapping resource: mapper/XxxMapper.xml` + SAXParseException「注释中不允许出现字符串 "--"」,后端起不来。V10.10 回收站改造在 4 个 mapper(Album/ContentBook/Video/Photo)里写了 `<!-- ---------- 回收站 ---------- -->` 风格注释,V10.11 重建后端时才爆出来。
- **真因**:XML 规范禁止注释体内出现连续两个连字符,`----` 分隔线属于非法注释;编译期不校验 mapper XML,只有 MyBatis 运行时解析才炸。
- **对策**:mapper XML 注释分隔线用 `==========` 或纯文字;新增/改 mapper XML 后用 XML 解析器验一下 well-formed(20 个文件脚本全量校验即可)。取证见 docs/变更归档.md V10.11 节。

### 2.16 自定义 logback appender 收不到第三方的日志(`additivity=false`)

- **症状**:新加的 logback appender(如 V10.15 同类异常聚合预警的 `LogAlertAppender`)只挂到 `<root>` 时,**第三方调用失败、访问慢请求这两类日志永远进不来**,预警只能看到 `GlobalExceptionHandler` 的异常——看着像指纹算法漏了,其实是根本没收到事件。
- **真因**:`logback-spring.xml` 里 `ACCESS` 与 `thirdparty` 两个 logger 都是 `additivity="false"`(只写自己的文件、也不再冒泡给 root),**挂在 root 的 appender 与它们无关**。
- **对策**:新 appender 若要覆盖全量日志,必须在 `ACCESS` / `thirdparty` / `<root>` 三处各加一条 `<appender-ref>`;另三条同样要记住的规矩:① Spring 上下文就绪前(sink 未注册)直接丢弃事件,不缓存启动期日志;② appender 内**吞掉一切异常**,绝不能因为预警链路把业务日志打不出来;③ `append()` 里读 `Thread.currentThread().getName()` 前缀跳过自身消费者线程,并在排除 logger 里写上预警服务自己(否则"预警落库失败"会再触发一轮预警,自噬刷屏)。取证见 docs/变更归档.md V10.15 节。

### 2.17 匿名天气响应不能共用一个全局缓存键(V10.19)

- **症状**:访客看到的城市不是自己的——线上 2026-10-05 15:10 一条匿名 `/public/weather` 返回 `"city":"Dallas"`(Meta 抓取爬虫的出口位置);本机复现更直接:先以 `X-Forwarded-For: 8.8.8.8` 请求得到 Ashburn,再换 `36.152.44.95` 请求,拿到的仍是 **Ashburn**,且 Redis 里压根没生成 `ihomy:weather:loc:36.152.44.95`(缓存命中把定位整段跳过了)。
- **真因**:`WeatherService.getWeather/getDetail` 原先是「**先查缓存、后定位**」,而匿名请求的缓存键硬编码为全局 `ihomy:weather:now`(不带坐标)。谁先写谁生效,之后 30 分钟内所有匿名访客都复用第一个人的天气与城市名。
- **对策**:改成**先定位、再按坐标取缓存**,键统一为 `ihomy:weather:now:{坐标}` / `ihomy:weather:detail:{坐标}`(家庭偏好位置加 `fam:` 前缀,避免把家庭自己的城市名标签借给同坐标的匿名访客)。定位本身有 per-IP 6h Redis 缓存,所以提前解析不会多打三方接口。历史遗留的 `ihomy:weather:now` / `ihomy:weather:detail` 键不再被读取,30 分钟内自然过期,无需清理。

### 2.18 Spring Boot 升级线与 Boot 4.x 迁移(V10.20 → V10.32)

- **历史(V10.20)**:parent `3.2.5 → 3.5.16` 升级**零代码改动**(53 项单测 + 运行态冒烟 + `/doc.html` 全过)。3.2.x 支持 2024-11 已终止,别再回退。
- **V10.32 已升到 4.1.1**(3.5.x 的 OSS 支持 2026-06-30 已终止,不支持线别再回退)。Boot 4 的破坏面实测很小,真正咬人的只有五处:
  1. **文档栈换掉才解套**:上游 Knife4j 4.5.0 至今**无 Boot4 starter**(只有个人 fork `com.baizhukui:knife4j-openapi3-boot4-spring-boot-starter`,不引第三方 fork)。改用其上游 **springdoc-openapi 3.1.1**。
  2. **starter 改名**:`spring-boot-starter-web` → `-webmvc`、`spring-boot-starter-aop` → **`spring-boot-starter-aspectj`**(Boot 4 里 `-aop` 直接不存在,编译期就断)。
  3. **Jackson 2 → 3**:`com.fasterxml.jackson.databind.*` → **`tools.jackson.*`**;但**注解包名不变**(仍是 `com.fasterxml.jackson.annotation`,Jackson 3 的 BOM 有意把它钉在 2.21)——所以实体上的 `@JsonIgnore`/`@JsonFormat` 零改动。Jackson 3 异常改**非受检**(`tools.jackson.core.JacksonException extends RuntimeException`),原先包 Jackson 调用的 `catch (IOException)` 会报「永不抛出」,**改捕 `JacksonException`**。`new ObjectMapper()` 在 Jackson 3 仍可用、未弃用。**jjwt 无 Jackson3 实现**,`jjwt-jackson` 保留(Jackson 2 仍在 Boot BOM 托管范围内),两套 Jackson 并存互不干扰。
  4. **MyBatis-Plus 换 starter + 分页另立模块**:`mybatis-plus-spring-boot4-starter` 3.5.17;**分页插件自 3.5.9 起拆出**,只换 starter 会报 `找不到 PaginationInnerInterceptor`,必须补 `com.baomidou:mybatis-plus-jsqlparser`。
  5. **`EnvironmentPostProcessor` 换接口 FQN**:`org.springframework.boot.env.EnvironmentPostProcessor` → **`org.springframework.boot.EnvironmentPostProcessor`**。**注册方式仍是 `META-INF/spring.factories`**——Boot 4 自带 EPP 也写在 spring.factories 里;`META-INF/spring/<fqn>.imports` 那条路**不通**(写了不报错也不加载,症状是外挂配置静默失效、`jwt.secret` 为空启动失败)。
- **构建陷阱**:`mvn clean` 被运行中后端/OneDrive 锁 `target\classes` 时会失败,而**旧资源会留在 `target\classes`**——`spring.factories` 换键名后若没清干净,会读到旧键并报 `Class ... is not assignable to factory type`。换 `META-INF` 下的注册文件后务必确认 `target\classes` 已同步(或跑一次干净构建)。
- **`/doc.html` 入口**:**不能**用 `springdoc.swagger-ui.path=/doc.html` 顶这个 URL——springdoc 页面里的 `./swagger-ui.css` 会解析到 `/api/swagger-ui.css`,不在安全白名单 → 匿名访客拿到**空白页**(HTML 200 但资源全 401)。正确做法:UI 用 springdoc 原生 `/swagger-ui/index.html`(相对资源落在白名单内的 `/swagger-ui/**`),入口靠 `WebMvcConfig` 一行 `addRedirectViewController("/doc.html", "/swagger-ui/index.html")` 保住。
- **台账同步(坐标变更的正确写法)**:Spring Boot 版本在 `sys_oss_component` 占 9 行(package_ref `org.springframework.boot:%`),改 pom 必须同步 `schema.sql` 种子 + `migrations.sql`。**坐标变更一律「先 `DELETE` 旧坐标 + 再 `INSERT IGNORE` 新坐标」,不要 `UPDATE` 改 `package_ref`**——`migrations.sql` 上方的历史种子仍按旧坐标 `INSERT IGNORE`,每次执行都会把改名让出的旧坐标重新插回来,`UPDATE` 改名会撞唯一键 `uk_type_ref`,`DELETE` 式改写对重放免疫(踩过:`spring-boot-starter-web` 改名后重跑报 `Duplicate entry ... uk_type_ref`,台账从 19 行涨到 23 行)。

### 2.19 整体更新被替换成单列 UPDATE 后,其余字段静默不落库(V10.43)

- **症状**:家庭设置页改名称/简介/封面,保存提示成功、接口响应也是新值,但刷新即回退——重查 DB 只有天气三列真的写进去了。
- **真因**:2026-08-16 的天气三件套改造(`e6e7f55`)把 `FamilyController.update` 里的 `familyMapper.updateById(f)` 换成了「只 SET 天气列的 `update(null, w)`」——缩字段更新时**把原来整体更新那行换掉、其余字段没人接收**。PUT 响应取自被改过的内存实体,所以接口冒烟看不出来,**必须「保存 → 全新 GET → 查 DB」三段验证**才暴露。
- **对策**:`FamilyController.update` 恢复 `updateById(f)` 后再叠天气 `LambdaUpdateWrapper`(两者作用列不重叠;`updatedAt` 已 `FieldStrategy.NEVER` 见 §2.2,`updateById` 安全),并在更新后调 `publicController.invalidateHomeCache(f.getId())`(变更点清单见 §9)。同页表单收口为「名称/简介/封面」三字段并加 `@Size` 对照列宽(越界落可读 400)。取证见变更归档 V10.43。

## 3. 前端

### 3.1 ElementPlus dropdown 内嵌 hover 子菜单

用 `visibility` 延迟隐藏,不要用 `display`(否则鼠标移动途中子菜单消失,无法点选)。

### 3.2 CSS `rotate()` 负角度方向反直觉

屏幕坐标 y 向下,负角度把元素下端往**右**摆。「右上 → 左下」的倾斜要写**正角度**。

### 3.3 `animation` 简写会覆盖同元素长写的 `animation-*`

元素上已有 `animation-delay` 之类的长写属性时,再用 `animation` 简写会把它们覆盖。多粒子动画的时长/相位要用 CSS 变量(`--var`)喂进去。

### 3.4 要能被类覆写的内联样式走 CSS 变量

把 `transform` 写死在 `:style` 里就无法被 hover 类覆盖——暖居照片卡牌的位移/旋转/层级因此抽成 `--dx/--dy/--rot/--z`,类名只改变量。

### 3.5 暖居照片卡牌扇形重叠时别用纯 CSS `:hover`

### 3.18 把 `data:` URL 写进 localStorage 会挤爆配额

### 3.20 过期令牌 + 免登录接口 = 静默按游客口径返回(V10.19)

- **症状**:「家庭设置里明明填的是济南,天气却显示青岛(或者别的城市)」;有时准有时不准,像随即波动。实测生产 access 日志同一 IP 交替出现:`user=chillyice@live.com#6 → "city":"济南"` 与 `user=anonymous → "city":"Qingdao"` 每隔一两个小时来回切。同一机制还会让 `/public/sun-info`(日出日落/光影)、`/public/feed`、`/public/home` 悄悄退回游客口径。
- **真因**:access token 只有 2 小时,而 `/api/public/**` 是 `permitAll`——`JwtAuthenticationFilter` 解析过期令牌失败后**静默当作未登录继续放行**,接口照常返回 200。前端只在 **HTTP 401** 时才续期,这类请求永远等不到 401,于是 `PublicController.resolveFamilyLocation()` 里 `currentUser()` 恒为空 → 家庭天气位置失效 → 回退 IP 定位(家庭宽带出口在青岛)。注意:**数据没存错**(`sys_family_info.weather_city` 确实是济南),不要先去怀疑设置页保存失败。
- **对策**:前端 `api/request.js` 请求拦截器加**令牌过期预检**——`utils/jwt.js` 的 `isTokenExpired(token, 30s)` 读 exp,已过期**且刷新令牌仍在有效期**时先 `await renewToken()`(与 401 分支共用同一个 `refreshPromise`,并发只续一次)再挂新令牌发出;`/auth/*` 自身跳过预检(否则续期递归触发自己)。刷新令牌也过期就别预检(按未登录发出去,公开页访客不会被顶到登录页)。副产物:一次页面加载不再出现「6 个请求齐刷刷 401 再各自重放」。
- **排查套路**:怀疑「设置不生效」先看后端 access 日志(`/opt/ihomy/logs/access/`)里的 `user=` 字段——**匿名的就是降级发生的那一次**;再查库确认设置真的落库了(`SELECT weather_lat,weather_lng,weather_city FROM sys_family_info`),最后才看 Redis 缓存键(`ihomy:weather:now*`,`fam:` 前缀说明走的是家庭位置)。取证过程见 docs/变更归档.md V10.19 节。

### 3.21 移动端适配的两个测量陷阱(V10.26)

- **症状一:验桌面端时页面死活停在移动外壳**。用无头 Chrome 模拟 1440×900 验桌面,`#app` 里却只有 `mobile-layout`/`mobile-tabbar`,桌面侧栏与暖居外壳全不渲染。
  - **真因**:`composables/useDevice.js` 的 `detect()` 是「UA **或** matchMedia(768px) 任一命中即移动端」。CDP 只放宽了视口、`Emulation.setUserAgentOverride` 还留着 iPhone UA → UA 那一路照样命中,视口宽度根本不参与决策。

### 3.22 vue-i18n 文案里的字面量大括号与 `@` 必须转义(否则生产整页白屏)(V10.27)

- **症状**:咔哒发布页 `/kada` 打开后**整页空白**,`#app` 里只剩一个注释节点(`<!---->`);诡异的是 `document.title` **已经是新页面的标题**(说明组件挂载过),而对照页 `/wallpaper` 同环境渲染正常。控制台里是一条 `SyntaxError: Invalid token in placeholder: …` / `Invalid linked format`(栈全在 `vue-i18n-*.js` 里)。
- **真因**:vue-i18n 的 message 语法里 `{` 是插值占位符的开始、`@` 是链接消息的开始,想显示**字面量**必须写成 `{'{名字}'}` 与 `{ '@' }` 形式(即 `{'@'}`)。本次踩的两处:新写的 `f8Desc` 里 `{变量名}`(占位符名不是合法标识符 → 编译失败),以及**既有**的 `blog.replyTo: '回复 @{name}'`(`@{` 被当链接语法 → `Invalid linked format`)。
- **为什么难发现(关键)**:同一个编译错,两条构建分支的行为不同(`@intlify/core-base` 的 `getCompileContext`):`NODE_ENV !== 'production'` 时只 `console.error("Message compilation error: …")` 然后**把原始串原样返回**(页面照常渲染、只是文案里的花括号没被替换,像没插值一样);**production 构建下同样的错直接 throw**,而它抛在 `$t()` 里会打断组件渲染 → 那棵子树/整页渲染中止。所以:①**开发环境不报错不代表没病**;②报错栈全在 i18n 包里,看不出是哪条文案,得靠钩子拿原始错误。
- **对策**:文案里的字面量 `{` / `}` / `@` 一律转义(`{'{name}'}`、`{'@'}{name}`);新增 i18n 文案后跑 `npx vitest run`——`src/i18n/message-format.spec.js` 会把两份语言文件的**每条文案**在 dev 分支与 production 分支各编译一遍(dev 抓 `console.error`、production 抓抛错),漏转义即红。
- **排查套路(白屏但标题正常)**:`__vue_app__` 是挂载成功的证据,可以现场挂钩子抓真实错误——`document.getElementById('app').__vue_app__.config.errorHandler = (e, i, info) => …`,再用 `$router.push(当前路由)` 触发一次客户端渲染,错误就会进钩子;顺便可 `app.config.globalProperties.$t('a.b')` 逐条试文案。教训:**standalone 页「标题对不对」会骗人**,判渲染要看 DOM 是否真的出来(本次靠对照页 `/wallpaper` 排除了环境因素)。取证见 docs/变更归档.md V10.27 节。

### 3.23 实测计算样式读到的是「过渡起始值」(V10.29)

- **症状**:把「深色媒体块」注入页面模拟深色偏好后量计算样式,**同一批元素里有的翻了色、有的还是浅色**——例如 `.kcard` 底色已经变深(`--panel` 生效),但它的 `border-color` 仍是浅色 `--line`;`.kdl` 的 `background/color` 也停在浅色。看上去像「某些规则没跟着变量走」,其实是假象。
- **真因**:这些属性上都写着 `transition`(`.kcard` 的 `border-color`、`.kgh` 的 `color`、`.kdl` 的 `background/color`),而**本仓浏览器验证环境(IAB)里 CSS 过渡被冻结、永不推进**,于是计算样式永远停在过渡起点(改色前的那套值);`--bg`/`--panel` 这类**没有过渡**的属性立刻生效,两类元素因此表现不一致。`html` 上还有 `main.css` 的 `transition: background-color 1s`,同一个坑会让「根元素底色没跟着换」的误判出现。
- **对策**:量之前先注入 `*{transition:none !important;animation:none !important}`,再读计算样式;或只对无过渡的属性下结论。**判据**:凡「一部分元素翻了、另一部分没翻」且差异正好落在带 `transition` 的属性上,先怀疑过渡冻结,别去改 CSS 变量链路。另注:注入法本身要取**构建产物里真实的媒体块**(遍历 `document.styleSheets` 找 `CSSMediaRule` 且 `conditionText` 含 `prefers-color-scheme: dark`),别手抄一份,否则验的不是线上那套值。
- **headless Chrome 截图同坑(V10.67 复核)**:`--virtual-time-budget` 只推进定时器,不推进 CSS 过渡,截到的是**起点帧**——`/chillyice` 的日月明明已按接口定位,截图却两颗都停在舞台中心默认位(叠加成一颗,肉眼像「只剩月亮」)。对策:给页面补 `@media (prefers-reduced-motion: reduce){ transition:none }`(本身是无障碍要求),截图加 `--force-prefers-reduced-motion` 即得终态。**窄屏另有一坑**:`--headless=new` 的 `--window-size` 小于约 700px 时仍按 700 宽排版、只截左侧 390,看起来像「右半页被裁/正文不换行」;手机视口用 Playwright(`viewport={width:390,height:844}, is_mobile=True`,本机已装)或读 `document.documentElement.scrollWidth` 判定是否真溢出。

### 3.24 marked 默认透传原始 HTML,v-html 渲染博客正文 = 存储型 XSS(V10.31)

- **症状**:博客正文里写 `<img src=x onerror=…>` 或 `<script>…</script>`,打开 `/blog/:id` 真的执行——正文被注入任意脚本。
- **真因**:marked 自 v5 起**移除 `sanitize` 选项、默认把源文里的原始 HTML 原样透传**进输出(官方口径是「消毒请自行接消毒器」),而 `BlogDetail.vue` 把 `marked.parse(blog.content)` 的结果**直接喂给 `v-html`**,中间没有任何消毒。放大面:`/blog/:id` 路由是 `meta.public`、`BlogService.getDetail` 对 `VIS_PUBLIC` 的跨家庭博客放行,故**任意注册用户发一篇公开博客,就能在任何访客/其他家庭的浏览器里执行脚本**(访问令牌为发 `Authorization` 头必须由前端 JS 持有,脚本可直接读走)。
- **对策**:统一走 `frontend/src/utils/markdown.js` 的 `renderMarkdown()`(`DOMPurify.sanitize(marked.parse(src))`,默认配置即剥离 `<script>`、`on*` 事件属性与 `javascript:` 协议),`marked` 只允许在该文件里导入。**判据**:凡「用户可写内容 → v-html」的链路,先看渲染结果是否过 DOMPurify;守门测试 `src/utils/htmlSink.spec.js` 会在 CI 拦下新增的裸 `v-html` 与非空 `innerHTML/outerHTML`。**别误判成「消毒会删内容」**:DOMPurify 默认保留 `id`/`class` 与表格/代码块,博客目录锚点(`h-*`)不受影响;围栏代码块里的 `<script>` 是 marked 已转义后的文本,不会被删。

### 3.25 内容栏里的弹窗:`fit-content` 撑宽 + 被侧栏/渐隐遮罩盖住或裁掉(V10.34)

- **症状**:运维页「开源组件台账 → 生成升级方案 → 点 AI 评估」后,返回的整块评估结果**被左侧导航盖住**(光尘)或**直接缺一块**(暖居);弹窗实测宽度远超组件声明的 640px(1280 视口下量到 1173px,几乎整屏),窗口越窄越明显。
- **真因(两层,都在弹窗默认渲染路径上)**:
  1. `main.css` 全局弹窗样式写着 `width: fit-content !important; max-width: calc(100vw - 32px) !important`——**`width` prop 被覆盖**,弹窗按内容 max-content 撑宽;AI 评估结果是长段落,于是被撑到接近整屏(`fit-content` 配长文的通用副作用,不止这一个弹窗)。
  2. `el-dialog` 默认 `append-to-body=false`,弹窗**跟着内容栏渲染**(DOM 在 `.app-main` / `.gc-main` 里),两种桌面主题各有一套「盖住」机制:
     - **光尘**:`.app-main` 有 `position: relative; z-index: 10`,自己就是层叠上下文;固定侧栏 `.app-sidebar` 是根级兄弟且 `z-index: 60`。**侧栏整棵子树都画在弹窗之上**,弹窗左溢出部分被盖住(实测 `document.elementFromPoint(48/100/160, …)` 命中 `div.nav-item`,而弹窗左边界在 x=48)。
     - **暖居**:`.gc-main` 带滚动渐隐 `mask`(上下 40px 淡出)。**`mask` 会把该元素的 fixed 后代一起裁到它的 border box 内**(不裁就做不出边缘淡出),于是弹窗超出内容栏的部分**不绘制**(实测把 `.gc-main` 的 `mask-image` 临时置 `none`,同一坐标点立刻命中弹窗)。注意 `mask` 只建层叠上下文、不给 fixed 元素建包含块——弹窗仍按**视口**定位居中,位置看着对、内容却缺一块。
- **对策**:
  - **别让长文吃满 `fit-content`**:带长文本的弹窗在 `main.css` 里给上限,`max-width: clamp(320px, calc(100vw - 2 * var(--shell-nav-w, 0px) - 32px), 640px)`,正文 `max-height: calc(86vh - 132px); overflow: auto`(高度同步收,否则暖居下超高部分照样被 mask 裁掉)。`--shell-nav-w` 是内容栏左边界:光尘侧栏 220px、暖居 studio 外框 20 留白 + 230 侧栏 + 1 边框 = 251px,由 `html:has(.app-sidebar)` / `html:has(.gc-side)` 注入,无侧栏(纯 OPS/沉浸页/移动端)保持 0。
  - **要跳出内容栏时就 `append-to-body`**:弹窗挂到 body 后,遮罩的 `z-index: 63` 在根级高于侧栏 60,mask 也不再套住它——这是「弹窗内容必须完整可见」的兜底手段(本仓 AI 评估弹窗即用此招)。
- **判据/取证手法**:凡「弹窗内容被导航压住、或莫名缺一块」,先量 `getBoundingClientRect()`(看是否宽过内容栏)再用 `document.elementFromPoint()` 看**真实命中元素是谁**(别只看 z-index 数值推断),最后确认该弹窗是否 `append-to-body`。**已知残留**:暖居内容栏的 mask 会裁掉**任何**超出内容栏的弹窗(高度超 ~500px 的编辑类弹窗同样会被切),本次只修了 AI 评估这一个;要根治得让相关弹窗一并 `append-to-body`,或改掉 mask 的存在方式(见 `docs/变更归档.md` 该版「试过但不采用」段)。

### 3.26 flex 行里的百分比 `max-width` 要挂在显式限宽的父级上(V10.45)

- **症状**:聊天室消息气泡不贴头像、自己的消息不靠右,长句右侧留一大片空白;行高也被撑开。
- **真因**:`.msg-body` 是 shrink-to-fit 的 flex 子项(宽度由内容决定),而气泡的 `max-width: 70%` 参照的正是这个「随内容伸缩」的宽度——长句时 body 被拉到接近整行,70% 远大于实际文字宽度,气泡两侧就空出来;`row-reverse` 的自己那一侧也因此看着没贴到头像。
- **对策**:**百分比上限只写一次,挂在显式限宽的父级上**(`.msg-body { max-width: 78%; min-width: 0 }`),气泡自身改 `max-width: 100%`;自己那一行给 body 加 `display: flex; flex-direction: column; align-items: flex-end`,内容整体靠右(别再用 `text-align` 推,它推不动带背景的气泡)。
- 判据:`max-width: %` 只在「宽度不随内容变」的父级上才有意义;flex 行里这种父级必须自己显式限宽并给 `min-width: 0`。

### 3.27 暖居扫光幕布:未插入文档就回填滚动 → 跳顶;`transitionend` 冒泡 → 扫光瞬间消失(V10.52)

- **症状**:暖居内晨↔暮切换时,① 可滚动页(如 `/home`)先跳到顶部,扫光结束再跳回原位置;② 蒙版扫光几乎看不到,页面像「无过渡直接换色」。
- **真因(两处独立)**:
  1. `cloneOldTheme()` 在 `overlay` 还**没插入 document** 时就 `copyScroll(app, clone)`。克隆子树未布局,`scrollTop/scrollLeft` 赋值被丢弃(读到 0、写 0),幕布里的滚动容器从顶部开始渲染;真实页随后被幕布整屏遮住,视觉上就是「跳顶 → 扫完跳回」。
  2. 幕布清理监听写成 `overlay.addEventListener('transitionend', cleanup, { once: true })`。`transitionend` **会从后代冒泡**:切 `html.dark` 时克隆里带颜色过渡的元素(卡片背景/文字)会在几十毫秒内触发第一批 `transitionend`,冒泡到幕布上把 `once` 监听消费掉 → 幕布在第 1 帧就被移除,700ms 的 `--sweep-p` 蒙版刚起步就没了。
- **对策**:①`appendChild` 之后回填滚动位置(顺序就是语义);②监听里判 `e.target === overlay && e.propertyName === '--sweep-p'` 才清理,保留 `setTimeout(过渡时长 + 300ms)` 兜底;**别用 `.theme-sweep-old * { transition: none !important }` 去堵后代的 transitionend**——那是全局钝器(会连带压掉快照自身的过渡语义),过滤事件源就够了;③设完起点 `--sweep-p: -10%` 后 `void overlay.offsetWidth` 提交一次重排,否则过渡会从 `@property` 的 `initial-value: -150%` 起跑(前 1/6 时长都在屏幕外,看起来像延迟)。
- **取证手法**:切暮后用 rAF 采样 `document.querySelector('.theme-sweep-old')` 的 `exists` / `getComputedStyle(o).getPropertyValue('--sweep-p')` / `o.querySelector('.gc-main').scrollTop` 与真实 `.gc-main` 对比。健康值:幕布存活 ~1.7–2.3s,`p` 从 `-10%` 单调推进到 `~106%`,幕布内滚动位置与真实页一致。**别用 headless 截图判断动画是否流畅**(软件渲染只有 2–4fps,是假象)。

### 3.28 单列网格里给子项加 `margin: 0 auto` 会取消拉伸,按内容宽度收缩(V10.57)

- **症状**:bit_pouch 发布页 ≤980px 切成单列后,右侧终端面板本应占满内容栏(390px 视口下应为 344px),实测只有 221px——正好等于终端最长一行文本的宽度,左右留出大片空白;页面没有横向溢出,只查 `documentElement.scrollWidth` 的检查发现不了。

- **对策**:要「限宽 + 居中」时同时写 `width: 100%; max-width: 660px; margin: 0 auto`,让宽度先取满轨道再被 `max-width` 截断。
- **判据/取证**:响应式单列容器里的子块,别只量 `documentElement.scrollWidth`;要量子块自身 `getBoundingClientRect().width` 是否等于父级内容宽。浏览器控制台:在 390px 视口执行 `document.querySelector('.bpterm').getBoundingClientRect().width`(健康值 344,收缩时 221)。

### 3.29 工具箱导出到 bit_pouch:三个契约点

- **症状**:把 ihomy 工具核心复制到 bit_pouch 后,`check:plugins` 报「run.ts 必须 export const run」,或 `typecheck` 因 JS 文件报类型错误;另一个常见问题是复制后忘了带共享依赖。

### 3.30 CSS 选择器多一个空格(`.bpmark (svg)`)整条规则静默失效

- **症状**:bit_pouch 顶栏与发布页贴纸里的内联 SVG 不受尺寸控制——`width/height:100%` 的规则看着写了,实际要么按 300×150 默认尺寸溢出被容器裁掉,要么尺寸全靠 SVG 自身属性;页面不报错、lint/构建都通过。
- **真因**:选择器写成了 `.bpmark (svg)`(类名与括号间有空格)。CSS 里不存在「带括号的类型选择器」这种语法,整条规则被判无效并丢弃。`bit-pouch.css` 里同类笔误共 6 处:`.bpmark` / `.bppatch` / `.bpgh-ic` / `.bpbtn-ic` / `.bprow-ic` / `.bpdl-ic`。浏览器只在 DevTools 的 Styles 面板把这条规则划掉,不会在控制台提示。
- **对策**:后代选择器一律写 `.parent svg`;改样式后到 DevTools 看规则是否被划掉,或直接量元素尺寸(`getBoundingClientRect()`)。**最省事的判据是构建日志**:`npm run build` 会以 `▲ [WARNING] Unexpected "(" [css-syntax-error]` 逐条报出行号,哪怕是 `<style src>` 引入的公共样式表也会报——收尾构建别只看「built in」就放过。本轮还顺带统一了容器圆角:品牌图形自带宽高比例圆角(32 视框 rx=7),容器圆角须按渲染尺寸折算(30px→7px、62px→14px),否则四角会被裁出底色缺口。
- **判据/取证**:发布页执行 `document.querySelector('.bpmark svg').getBoundingClientRect()` 应得 30×30;`.bppatch svg` 旋转 5° 后的包围盒约 67×67;`npm run build` 日志中 `css-syntax-error` 计数为 0。修复记录见 `docs/变更归档.md` V10.64。

### 3.31 共享 CSS 只被一个页面引入 → 从其他入口进入整页无样式(V10.65)

- **症状**:从工具箱点「比特口袋 · 在线工具」进入 `/bit-pouch/tools`,页面只剩无样式的裸 DOM——顶栏 `.bptop` 被撑到 2600px 高、导航竖排成一列;先打开发布页 `/bit-pouch` 再点「在线使用工具」就完全正常,直接刷新工具页同样无样式。控制台没有报错,只有 `.css` 请求压根没发。

### 3.32 直接落在独立页后进站内页,首页数据不初始化(V10.66)

### 3.33 访问打点别用 GET:PWA 缓存 `/api` GET 会让访问数静默少计(V10.74)

- **症状**:咔哒/比特口袋发布页明明有人打开,运维「访问统计」里的产品访问数不涨或明显偏少;下载数正常。
- **真因**:`vite.config.js` 的 PWA `NetworkFirst` 运行时缓存匹配所有 `/api/` GET(排除 vault/auth/ops/profile)。workbox 命中缓存时请求根本不到后端,`AccessLogFilter` 就没有那条日志;打点用 GET 时同一 URL 第二次起基本不回源(离线直接读缓存)。
- **对策**:页面访问打点固定 `POST /api/public/page-view?page=...`(`fetch` + `keepalive`,失败静默)。POST 不进 workbox 运行时缓存,每次到后端留日志,`OpsService.productStats` 也只按 POST 口径统计;别为「简单」改成 GET 或 `<img src>` 打点。
- **判据/取证**:打开落地页后 `logs/access/ihomy-access.log` 应出现 `POST /api/public/page-view?page=kada ... status=200`;`GET /ops/product/stats` 对应产品 `views` 递增。下载数看 `/api/files/{产品}/` 下安装包后缀的 GET,更新清单 `latest.json`、`.sig` 与 4xx 不计。

### 3.34 首帧自适应别只靠 ResizeObserver / rAF(V10.82)

- **症状**:家谱画板的「适应屏幕」正常,但进入页面就是 100% 比例、只看得到几个人;按钮点一下立刻变好。
- **真因**:`onMounted` 时容器还没量出尺寸(Tab 懒渲染、独立页首帧、IAB 验证环境里 `requestAnimationFrame` 与 `ResizeObserver` 回调根本不投递),那次 fit 算出 `clientWidth=0` → 比例被夹到最小值、偏移算成负值;之后就再没有触发点了。
- **对策**:`fit()` 遇到 `clientWidth/clientHeight` 为 0 直接返回(不写脏值),外面套一层「量不到就每 150ms 重试、最多约 3s」的调度;`window.resize` 与(可用时的)ResizeObserver 只作兜底。真实浏览器里 rAF/RO 正常,但后台标签页同样会被节流,别把它当首帧的唯一触发器。
- **判据**:进入页面后 300ms 内 `.ftg-stage` 的 `transform` 应为 `translate3d(x,y,0) scale(<1)` 且所有卡片矩形都落在视口内;仍是 `scale(1)` 说明重试没跑起来。

### 3.35 `pointerdown` 里就 `setPointerCapture` = 容器内一切点击失效(V10.84)

- **症状**:家谱图谱的卡片点不中(选中状态不变、称谓卡不出现),右上角铅笔也点不开编辑弹窗;画板拖动/缩放本身正常。触摸端同样全失效。
- **真因**:指针捕获会把**后续 pointer 事件与兼容鼠标事件**(`pointerup`、`mouseup`、`click`)全部改派给捕获元素。在画板容器上 `pointerdown` 就 `setPointerCapture`,于是卡片上的 press 变成「松手落在画板」,`click` 的目标变成画板,卡片与铅笔的 `@click` 一次都不派发。实测取证:卡片上 pointerdown 的 target 是卡片,pointerup 与 click 的 target 都是 `.ftg-viewport`。
- **对策**:按下时只记录起点,**超过拖动阈值**(4px)真正开始平移时才 `setPointerCapture`——那时本来就要抑制点击。双指捏合可以直接捕获(捏合不产生点击)。捏合抬起一根手指后要用剩下的指针重建起点,否则画板卡住不动。
- **判据**:单击卡片后 `aria-pressed=true`、点铅笔弹编辑框;在 `setPointerCapture` 上打桩记录,普通点击不应有任何捕获记录,拖动超过阈值才有一条画板捕获。

### 3.36 弹窗层级低于装饰光影层 = 页脚浮在蒙层上、暗角画在弹窗上(V10.87)

- **症状**:打开弹窗后遮罩只压暗了内容区,右下角页脚仍然亮着且点得中;光尘的暗角/反射/浮尘、暖居的窗影画在弹窗本体上;照片查看器或阅读器打开时,里面弹出的确认框/设置弹窗反而被它们压住看不见;媒体预览弹窗(声明了 `top="5vh"`)被顶到距顶 14vh。
- **真因**:①`.el-overlay` 被固定为 `z-index: 63 !important`,而光影层占 65–100、页脚 70、回顶 200 —— 蒙层比它们都低;`bd756a2` 当初是故意把弹窗压到光影层之下换氛围,实测视觉更脏。②自建全屏浮层各写各的数(查看器 201、阅读器 200/210、相册光箱 2000、思维导图 2600),比 EP 遮罩 63 高,于是「浮层里的弹窗」反向被浮层盖住。③`.el-dialog { margin-top: 14vh !important }` 写死,组件 `top` 属性(EP 落到**元素内联**的 `--el-dialog-margin-top`)被覆盖。
- **对策**:层级只走 `main.css` 的 `--z-*` 标尺:外壳 60/70 → 光影 65–100 → 浮起操作 120 → 自建沉浸 150 → EP 遮罩 200 → 确认框 210 → popper 240 → toast 260;组件里禁写 ≥100 的裸数字(守门 `styles/zLayers.spec.js`)。间距改成 `margin-top: var(--el-dialog-margin-top, 14vh)`,并在同一规则里给未声明 top 的弹窗回设 14vh。
- **判据**:`getComputedStyle` 读 `.el-overlay` z=200、`.el-popper` 240、`.el-message` 260;弹窗打开时页脚在蒙层下(取 z 对比);`top="5vh"` 的弹窗 `marginTop` = 视口高 ×5%。
- **附带**:`Edit` 工具写 `styles/main.css` 时会把整份文件从 LF 转成 CRLF(git diff 只显示几十行,但 prettier/其他会话会受惊)。改完用 Python 复核 `\r\n` 计数为 0,必要时 `b.replace(b'\r\n', b'\n')` 回写。

## 4. 光影与天文

### 4.0 晨昏地图的五件事(V10.44)

1. **`flex-direction: row-reverse` + `overflow-x: auto` 的初始滚动位置各浏览器不一致**(症状:最右的「第一条」预警被推到视野外,或反过来出现在最左)。**对策**:别去猜符号约定,直接按几何纠正——`el.scrollLeft += firstChild.getBoundingClientRect().right - el.getBoundingClientRect().right`。方向反了也是负增量,自动收敛。窄屏改回 `row` 时同样要重跑一次。
2. **Canvas 拿不到 CSS 变量**,`getComputedStyle` 必须**每次重绘时重读**;模块加载时读一次存成常量,主题一切换色带/底色就全错。触发重绘的时机:mount、`ResizeObserver`、主题/晨暮 `watch`、60s 定时器、地图点击。**不要用 rAF 常驻循环**。
3. **逐像素画色带不必算 `asin`**:太阳高度角在 ±90° 内与 `sin` 同序,直接比 `sin(-0.833/-6/-12/-18)` 四个阈值即可分档,省掉 20 万次 `asin`。但**这四档阈值必须与 `twilightStage()` 用同一个 `>` 语义**(在边界上归下一档),否则地图色带和面板徽标会在阈值附近打架——`terminator.spec.js` 有「Canvas 色带的 sin 阈值分档与 twilightStage 一致」一条测试逐 0.25° 全程比对来钉死这点。
4. **`sun-info` 的缓存只该留给 `slots`**:直射点/当前位置/生成时刻每次请求实时算。若把整个响应缓存成 12 小时,晨昏线会停在 12 小时前的位置,而页面上毫无异常表现。前端据此用 `generatedAt` 算已过分钟数、按 0.25°/min 推进经度;拿不到 `generatedAt` 时按当前时刻起算(误差最多几小时),所以**该字段上线前不要发地图**。
5. **半透明色带的绘制顺序是正确性问题,不是审美问题**:色带必须画在**陆地填充之后**——画之前的话夜半球的大陆仍是原始亮色,晨昏线在欧亚、美洲这些大片陆地上根本看不出来(首次实现就踩了,现象是「晨昏颜色不太好区分」)。反过来,**海岸线要画在色带之上**:夜间色带压到最暗时海陆亮度会收敛到几乎一样(暖居实测 `#676970` vs `#616164`),得靠描边把大陆轮廓捞回来。
6. **色带要多档可分,不能只拉 alpha**:四档若共用一个色相、只把 alpha 从 .10 拉到 .48,肉眼看是一坨。正确做法是**每档换一个色相 + 一级 alpha 台阶**(暖居从暖褐过渡到冷蓝)。改色值时别靠肉眼猜,直接算合成后的亮度台阶:暖居晨底色上陆地亮度 230 → 202 → 160 → 105(相邻差 28/42/55)才算真的分得开。

> 天文算法只留一份来源:直射点与太阳位置由后端 `SolarUtil` 算(见 §4.1),前端 `utils/terminator.js` 只做球面几何。同一事实两份实现必然漂移。

### 4.1 日月与晨昏走纯天文计算,不取天气 API

后端 `SolarUtil.astroTimes` / `moonPhaseInfo` → `GET /public/sun-info`(天气页「日月与晨昏」卡与日历页共用)。和风 v1 `daily[].astro` 其实也带这些字段、实测与本地差 0~2 分钟,但**同一事实只留一份来源**——那 10 个透传字段已删,别再往 `daily` 里塞第二份。

### 4.2 月亮时角必须用地方恒星时

用 `gmstDeg`。照搬太阳那套「距太阳正午分钟数」的近似会算错(月亮每天晚约 50 分钟)。

### 4.3 当日不发生的事件返回空串

极昼极夜、月亮不升不落时,接口返回空串由前端隐藏,**不要填占位假时刻**。

### 4.4 求解策略统一

一律「采样找穿越 + 二分/三分细化」;阈值:太阳 -0.833°、三档晨昏 96°/102°/108° 天顶角、月亮 +0.125°。

## 5. 放映厅媒体引擎(Jellyfin)

模式是「Infuse 式」:**引擎用媒体服务器(Jellyfin)、界面与家庭层 ihomy 自建**。踩坑细节见 `docs/变更归档.md`「放映厅接入媒体引擎」(V9.106)与「S4 打磨」(V9.107)。

1. **续看列表必须带 `fields=SeriesInfo`**——不带给的是分集裸条目,剧名与季集号全缺,只能显示成「S01E01」。
2. **播放走 `static=true` 直连原文件**:URL **必须带容器扩展名**(不带时 Content-Type 报 `video/quicktime`,浏览器可能拒播),且**每次现取**(带 api_key、会过期,不许存进列表)。
3. **海报 `<img>` 走 HMAC 签名中转 `GET /api/media/image-signed`**:签名覆盖 familyId/itemId/type/maxWidth/exp,媒体服务器令牌不出后端(篡改签名/换家庭/换作品一律 401)。
4. **进度上报只报位置就别带 `played`**——会把已看过的翻回未看;自然播完时前端须**静默片尾那次位置上报**,否则 `pause`/`ended` 竞态让位置晚于「看过」落库,该集永远挂在续看。
5. `sys_media_server` **按家庭唯一(uk_family)、不做逻辑删除**(清空即删行);配置读写复用 `storage:manage`(受众同为家长,免新增 auth 种子)。`sys_media_user_config` 同理按「家庭+成员」唯一、无逻辑删除(见第 9 条)。
6. **转码回退地址必须给 `videoBitrate`**——不给时媒体服务器只肯出 128kbps/240p(实测),按源码率取并夹在上下限内才对;地址是 `/Videos/{id}/master.m3u8`,它回的 master 播放列表里只有**相对**子播放列表(参数自动继承,别自己拼绝对地址)。片源编码浏览器放不了(HEVC/10bit 等,后端按 `playable` 判)或直出起播报错,都回退这同一条地址。
7. **两条线路与 `playable` 必须同口径**:`playUrl` 回 `mode`/`hlsUrl`/`playable`,前端按 `mode` 选线路;hls.js 走**动态 `import()`**(独立 chunk ≈595KB,只在转码线路才下载),静态引入会把整包塞进入口。
8. **位图字幕只能烧进画面**:PGS/DVDSUB 没有文本可转 → 标 `burnIn`,选中即重取带 `subtitleStreamIndex` 的转码地址;**从「已烧进去」切回关闭或文本轨时必须再重取一次不带它的地址**,否则字幕关不掉(状态机要求)。文本字幕由后端取回转 WebVTT,走免登录签名端点,**签名必须覆盖 `userId`/`sourceId`**——免登录端点不能变成「换个成员账号或换个媒体源取东西」的后门,改任一参数即 401;**媒体源 id 要随签名带上**(多版本条目字幕挂在自己的媒体源下,拿条目 id 顶替取不到)。
9. **成员账号失效不阻断播放**:成员播放档案(各自续看)配的账号改密/删号后**回落家庭账号**,宁可看到全家共用的进度也别整页打不开;失败原因写日志并在设置页回显。会话令牌按成员分开缓存;删除引擎配置时成员档案一并清掉。
10. **HTTPS 站点 + HTTP 媒体地址 = 混合内容拦截**(部署必踩,接口层查不出):生产站是 `https://`,播放地址填 `http://` 时浏览器会拦掉视频请求——直出与 hls.js 转码取流都放不出来,而**39 项接口断言全绿**(它们不走浏览器)。`public_url` 必须是 HTTPS(同站子域名反代到 NAS 的做法见 `docs/部署指导-Linux.md` §12.2);设置页在 HTTPS 下检测到 HTTP 地址会给出提示。上线务必在真浏览器里放一次。
11. **跨源取流无需额外配置**(已实测,别再排查):Jellyfin 对直出流与 `master.m3u8` 都回 `Access-Control-Allow-Origin: *`,hls.js 的 XHR 能直接取;直出用 `<video>` 本来也不受 CORS 约束。
12. **自动初始化 Jellyfin 必须先 `GET /Startup/User` 再 `POST /Startup/User`**:向导的 POST 只改「已存在」的首个用户(`_userManager.Users.First()`),空库直接 POST 报 500 `Sequence contains no elements`;GET 这一步会初始化并建出默认首个用户。建库扫描的 `Counts` 是**边扫边涨**的,别只看 >0 就放行(等数量连续几次不变)。脚本 `scripts/ci-jellyfin-setup.sh`(CI 与本地一键联调共用)。

**联调环境**:`docker compose --profile jellyfin up -d jellyfin`(镜像默认国内源,可用 `JELLYFIN_IMAGE` 覆盖为官方源;测试媒体挂 `.dev-media/` 已 ignore)→ `bash scripts/dev-jellyfin-seed.sh`(用容器自带 ffmpeg 造 20 秒测试片源 + NFO + 海报,宿主不必装 ffmpeg;Windows Git Bash 已内置 `MSYS_NO_PATHCONV=1`)→ **一键初始化** `bash scripts/ci-jellyfin-setup.sh`(自动完成首次启动向导、建「电影/剧集」两库并等扫描;也可手工访问 `http://localhost:8096` 走向导)→ 设置页-放映厅填地址与账号。接口检查:`IHOMY_TEST_PWD=<密码> python test/automation/media_engine_check.py`(**39 项**;`--read-only` 只跑读类断言)。CI 已接入该检查(`.github/workflows/ci.yml`)。生产上线(引擎放 NAS)见 `docs/部署指导-Linux.md` §12。

## 6. Wallpaper Engine 壁纸包与壁纸页

> 源在 `wallpaper-engine/`(壳页顶层跳转线上 `/wallpaper`;WE 属性 `theme/mode/lang` 走查询参数、`token` 走 URL hash;不含构建产物,ihomy 改版自动跟随;不是前端源码也不是构建产物,不进 dist)。**机制、导入步骤、取证路径的完整说明在该目录 `README.md`**;下面是踩坑要点。

1. **别用跨域 iframe**:WE 的 CEF 渲染 OOPIF 会崩渲染进程——现象是「导入后编辑器预览整片纯灰」,但页面其实已加载并执行,别误判成网络问题。改 `location.replace` 顶层跳转绕过。
2. **WE 分次投递用户属性**:用户**改过**的值(壁纸令牌天生是)晚一拍才到,所以壳页 `go()` 不能挂在第一次 `applyUserProperties` 上(令牌会被整个丢掉)。对策:「拿到令牌再等 400ms 就走、没拿到等到 3s 硬上限」,并在 `Wallpaper.vue` 挂 `wallpaperPropertyListener` 双保险。
3. **WE 是「拷贝」导入**:就地覆盖 `myprojects\<项目名>\index.html` 再重启预览;**`project.json` 千万别覆盖**(属性面板里粘的令牌存在那儿);重新拖导入会新建项目、令牌要重粘。
4. **WE 只在一次加载时读工程文件、无文件监视**:覆盖过去即生效;编辑器开着工程时保存即自动重载。判有没有重读看 `ui\wpcache\monitor<N>base\Default\History`,并先确认壁纸没被 `playbackmaximized=pause` 冻结。
5. **壁纸令牌(V9.110 起为独立类型)**:设置页调 `POST /auth/wallpaper-token` 取一枚 `type=WALLPAPER` 的令牌(不再是浏览器那枚 refresh token)→ 粘到 WE 属性面板 → 页面 `bootstrapToken()` 调 `POST /auth/refresh` 换会话。后端普通 `REFRESH` 令牌每次使用即拉黑(轮换,单次有效,被盗令牌登出后无法续期),**`WALLPAPER` 令牌不轮换不拉黑**,故浏览器会话与壁纸(乃至多个壁纸实例)各持一份、各自滑动续期互不踢。⚠ 想改回「所有 refresh 一律轮换拉黑」前必须先动这里,否则壁纸会立刻失效。**另注**:普通 refresh 轮换有 60s 宽限(并发/多标签重复提交返回同一份新令牌),且 JWT 带 `jti` 保证同秒签发也不会撞值。
6. **本地 IAB/Playwright 点不动这个应用**(持续动画让可操作性检查永不通过):验证交互改在页面内 `el.click()` 派发真实 handler,剪贴板用桩 `navigator.clipboard.writeText` 断言,别误判成 bug。
7. **打包发布用 bsdtar**,别用 `Compress-Archive`(见 §1.5)。

## 7. 部署与线上

### 7.1 nginx 的 `.mjs` MIME(坑)

`mime.types` 默认无 mjs 映射,`.mjs` 会以 `application/octet-stream` 下发,浏览器拒绝执行 module worker / 动态 import。生产 `/etc/nginx/mime.types` 已改为 `application/javascript js mjs;`,**重装或新服务器部署必须补**(否则书架 PDF 查看器、户型图 PDF 底图「加载失败」)。

### 7.2 部署新前端后,老客户端仍在跑旧 bundle(PWA Service Worker 预缓存)

- **真因**:workbox 预缓存(`workbox-precache-v2-https://ihomy.top/`)把旧的 `index-*.js` 连同 SPA 外壳留在浏览器里;新构建要等 SW 更新 + 再访问才生效。
- **症状极易误判**:访问新路由(如 `/wallpaper`)被**旧 bundle** 的兜底路由 `/:pathMatch(.*)*` 接走重定向到 `/home`,看着像「新路由没发布」——实际线上 dist 已是最新。
- **辨认方法**:页内读当前入口脚本 hash(`document.querySelectorAll('script[src]')`)与构建产物名对比(旧的是 `index-vQqJcikP.js` 这种上一版 hash);最准的是 `fetch(src).then(r=>r.text())` 看是否含新路由字符串。
- **冒烟前先清**:`navigator.serviceWorker.getRegistrations()` 逐个 `unregister()` + `caches.keys()` 逐个 `caches.delete()` 再刷新,否则验收结论是错的。用户侧 Ctrl+Shift+R 即可。

### 7.3 生产 nginx 必须开 gzip

站点 conf 的 `server{}` 需有 `gzip` 四行(`gzip on` / `gzip_types` / `gzip_min_length` / `gzip_vary`)。实测入口 JS 343.7→143.2KB、主 CSS 174.2→38.3KB、`/api/public/home` JSON 7.2→1.8KB。**新服务器/重装要核对**(历史上漏过,首屏多传约 336KB)。

### 7.4 数据库迁移双文件规则

结构变更必须**同时**更新 `backend/src/main/resources/schema.sql`(全量版)与 `migrations.sql`(增量、**必须幂等**:`CREATE TABLE IF NOT EXISTS` + `INSERT IGNORE` + `ALTER` 前判存在)。**migrations 跑通 ≠ schema.sql 可用**——改动后要按 CI 同路径做空库全量导入实测(`docker run mysql:8.4.10` 挂 schema.sql 做 initdb → `information_schema` 数表数)。历史踩坑:`family_loan_event` 建表缺逗号只走增量故未暴露,直到全量导入才炸。

**新增列必须随发布执行迁移**(V10.1 的 `sys_user.must_change_password` 就是例子):实体类一加字段,MyBatis-Plus 的 `selectById`/`selectList` 就会把该列写进 SQL,**生产库漏跑迁移 → 登录直接 `Unknown column 'xxx'`,该表所有查询一起挂**(不是只影响新功能)。发布顺序固定为「先跑迁移 SQL,再起新 jar」。

**空库导入实测会把开发库的应用账号密码改回 schema 默认值**(2026-10-29 实测):`schema.sql` 末尾有 `ALTER USER 'ihomy'@'localhost'|'%' IDENTIFIED BY 'ihomy-dev-2026!'`,只要把 schema 导进**正在给开发后端用的那个 MySQL 实例**(哪怕换了库名),应用账号密码就被重置;运行中的后端随即报 `Access denied for user 'ihomy'@'172.19.0.1'` / `HikariPool-1 - Connection is not available`,表现为登录 500、`/api/public/health` 503,而 `mysql -uroot` 手动查询一切正常。对策:①优先起一次性容器(`docker run mysql:8.4.10` 挂 schema 做 initdb)验全量导入;②非要在同一实例验,导入后立刻按 `config/external.yml` 的 `spring.datasource.password` 把两个 host 的密码 `ALTER USER` 回来,再等 Hikari 重建连接;③验「换了库名」的副本只需替换反引号包裹的 `` `ihomy` ``(4 处:CREATE DATABASE / USE / 两条 GRANT),别整串替换。

### 7.5 用 binlog 行像回灌数据(误删/误重置后)

完整案例与取证见 `docs/变更归档.md` 的两条 2026-09-29 运维小节;回灌前先 grep 这两条。要点:

1. **行像是「列序号」,序号跟着当时的表结构走**:事后 `ALTER ... AFTER` 插到中段的列会让其后序号整体偏移(如 `family_item` 的 V9.79 三列、`sys_family_ai_model` 的 `provider`/`secret_key`)。**按「行像列数」挑历史映射**,依据 `migrations.sql` 的 `ALTER ... AFTER` 复原当时列序,行像里没有的列不写进 INSERT 走默认值;按当前列位置硬套会把数据写坏。
2. **`INSERT IGNORE` 是「悄悄写坏」而非报错**:类型不匹配时它截断/钳值(把坐标钳成 9.9999、日期写成零日期、整段错位),只有 `--show-warnings` 看得见。**灌完必须逐条看警告并抽验关键列**,别只看「插入成功」。
3. **`mariadb-binlog` 把负数渲染成 `-1 (4294967295)`**(无符号补码 + 括号内带符号值):解析要按 `^-?\d+ \(\d+\)$` 取回负数,否则当字符串塞进 INT 列会触发「截断但值恰好对」的假象。
4. **主键冲突人工定夺**:`IGNORE` 让已存在的行胜出,回灌前先查有没有别家行占着同一主键;被内容引用的要重映射,无引用的可用新 id 补回(本轮 2 条默认博客分类)。
5. **密文必须用当前盐值重加密**(旧 `ENC(...)` 在新盐值下解不开):留着旧盐值的后端进程**重启前**调 `GET /api/ops/crypto/decrypt` 能批量取回明文;**重加密后跑一次闭环**——解新密文与台账明文逐条比对。
6. **恢复后验四件事**:逐表行数对计划、外键零孤儿、密文闭环一致、内容引用的文件在磁盘上。

### 7.6 CORS 白名单化后,新增域名要配 external.yml(V10.1)

`CorsConfig` 不再反射任意来源,只放行 `app.cors-allowed-origins` 里的来源(基线 `https://ihomy.top` + 本机 5173)。**换域名 / 加新前端地址而忘了在 external.yml 补这一项,症状是浏览器报跨域失败、而用 curl 直连后端一切正常**——同源部署(nginx 反代 `/api`)本不依赖 CORS,所以只有前端直连后端或跨子域的场景才会踩到。

### 7.7 Redis 无密码 + 绑 0.0.0.0(V10.6 已修,改密顺序有硬约束)

**成因/风险**:`docker run -p 6379:6379 redis` 会把端口发布到**所有网卡**且无认证——Docker 直接写 iptables,**绕过 ufw**,防火墙"没开 6379"挡不住;拿到 Redis 即可读写刷新令牌黑名单(让已吊销的 refresh 复活)、验证码与登录限流计数(解限流爆破)、当前家庭选择。

**现状**:生产/开发/CI 统一 `-p 127.0.0.1:6379:6379` + `--requirepass <强密码>`,密码在 external.yml `spring.data.redis.password`(同值);绑定回环是真门闩,密码是第二道。

**改密顺序(反了全站认证失败)**:先写 external.yml → `sudo systemctl stop ihomy-backend` → 停+删+按新参数 run 容器 → `start` → 冒烟。**颠倒症状**:登录报错/验证码 401/每 2h 被登出/限流 429 突增——根因是后端持有的是旧密码,Redis 全线 `WRONGPASS`(后端连接池里的连接也不会自动重认证)。

**取证**:
```bash
docker exec ihomy-redis redis-cli -a '<pw>' --no-auth-warning ping   # PONG
docker exec ihomy-redis redis-cli ping                              # NOAUTH Authentication required.
docker ps --filter name=ihomy-redis --format '{{.Ports}}'           # 应含 127.0.0.1:6379->6379/tcp
grep -i wrongpass /opt/ihomy/logs/server/*.log | tail               # 出现即密码/顺序错了
```
**副作用(可接受)**:Redis 无持久化,重建即清空黑名单/验证码/限流计数/当前家庭(家庭场景风险低)。手工 `redis-cli` 全部要带 `-a` 或先 `export REDISCLI_AUTH`。运行手册:`docs/部署指导-Linux.md` §2.6.1。

### 7.8 `/files/**` 直连无鉴权 + 缺 nosniff/CSP(V10.7 已修)

**症状**:拿到 `/files/...` URL 就能匿名读走任意私有照片/视频/保险箱附件;HTML/SVG 被当文档打开时可执行脚本;且 nginx `location /files/ { alias ... }` 静态直出完全绕过应用。

**真因**:`SecurityConfig` 曾把 `/files/**` 放进 permitAll,生产又由 nginx alias 直出——鉴权链上没有一环。

**现状(V10.7,读路径鉴权,不走全量签名改造)**:
- 判定统一在 Spring:`SecurityConfig` 给 `/files/**` 挂 `.access(FileAccessService)` —— **登录态放行,游客按 URL 反查内容表只放 `visibility='PUBLIC'`**。反查清单在 `mapper/FileAccessMapper.xml`(照片/博客封面/视频+海报/图书封面+文件 + `sys_user.avatar` + 公开家庭的封面/背景乐 + 分享相册的照片与封面),**新增带文件 URL 的内容表必须补进去,否则该表文件对游客一律 403**;`family_vault_item` 刻意不进(保险箱必须登录)。
- 反查结果 60s 内存缓存(容量 5000,到顶整表清空),**查询失败 fail-closed**;改公开后游客最多 60s 才看到图,不做失效钩子。
- **`<img>/<video>` 请求带不了 `Authorization` 头**,登录态只能靠 cookie:登录/注册/刷新响应下发 `ihomy_at`(HttpOnly + SameSite=Lax + Path=/,寿命=访问令牌 TTL),登出清除;`JwtAuthenticationFilter` 发现带 Bearer 但 cookie 缺失/已轮换时**补发**(发版后老会话自愈,否则图片全 403)。**这枚 cookie 只有 `/files` 读取判定认,业务接口仍只认 Bearer** → 没有 CSRF 面;判定不改 `JwtAuthenticationFilter` 是刻意的。
- **nginx `location /files/` 必须改反代**(`proxy_pass http://127.0.0.1:8080/api/files/;`,读 timeout 放大到 3600s),继续 alias 直出 = 绕过上面全部判定;`/files/kada/**` 刻意 permitAll(咔哒安装包免登录下载)。
- **2026-10-27 复核:生产站点 conf 的 `location /files/` 仍是 `alias /opt/ihomy/uploads/;`**(`/etc/nginx/conf.d/ihomy.conf`,与 2026-09-12 起的各份备份一致),即「必须反代」这条线上并未生效。后果:匿名可直接下载 `visibility='FAMILY'` 的文件(实测一本 258 MB 的电子书 `200` 全量下发,同路径 `/api/files/...` 才是 401),且文件下载请求不进后端日志(统计见 §7.13)。改动前先确认这是刻意取舍还是部署遗漏。
- 响应头由 Spring Security header writer **只对 `/files/*` 下发**:`X-Content-Type-Options: nosniff` + `Content-Security-Policy: default-src 'none'; ...`(对图片/媒体子资源无影响,只在把该文件当文档打开时生效);JSON 接口不带。

**顺带的 nginx `add_header` 继承坑(通用,别再踩)**:location 里**只要写了一条 `add_header`,server 级的同类头就整体不再继承**——现网图片/JS 缓存 location 自带 `Cache-Control`,导致 server 级 HSTS 在该 location 失效。对策:该 location 内自己补一行 `add_header Strict-Transport-Security ... always`(部署文档第五节已带)。

**取证**:
```bash
curl -so /dev/null -w '%{http_code}\n' https://ihomy.top/api/files/files/202609/xxx.png   # 匿名私有→401,公开→200
curl -sI https://ihomy.top/api/files/kada/kada.exe | grep -i x-content-type-options        # nosniff
curl -sI https://ihomy.top/api/auth/captcha | grep -i content-security-policy             # 应无输出
```

### 7.9 「未登录访问的效果」= 演示家庭的内容(V10.28 维护清单)

**结论**:不带 `hid`/`home_id` 访问首页时,家庭定位走 `FamilyMapper.selectDefault` → `sys_family_info.is_default = 1`,而这一家同时 `is_public = 1`,所以**游客视图看到的一切都来自 1 号演示家庭**。想知道「没登录打开网站长什么样」,别翻前端,先去库里查这个家庭有什么。

**维护清单(改游客所见时逐条过)**:

- 演示家庭必须 **`is_default = 1` 且 `is_public = 1`**——两个都要。只改 `is_default` 而 `is_public = 0`,游客会被 `PublicController` 的公开性校验挡成 404(整页打不开);只改 `is_public` 而 `is_default` 指向别家,则游客看的是别人家。
- 游客能拿到的东西都带可见性约束:`photos` 只取**公开相册**(`content_photo_album.type='public'`)里的 **`visibility='PUBLIC'`** 照片;动态流只取 blog/diary/photo/video/wish/book 的 PUBLIC 项(Task/Recipe 无 visibility 列,游客模式直接跳过)。**往演示家庭塞内容时忘了把 `visibility` 写成 PUBLIC,游客那边就是看不到**——这是最常见的「加了数据却没效果」。
- 游客分支的 `stats` 与成员视图同源(`HomeStatsService`):成员数 + 今日/近期纪念日。游客视图整包按 `familyId` 缓存 `ihomy:home:pub:{fid}` 5min,所以**纪念日的增删改必须调 `PublicController.invalidateHomeCache`**(否则最长 5 分钟游客看不到改动,见 §9)。
- 演示照片的 URL 指向 `frontend/public/demo/`(随 dist 部署,`/demo/*.svg` 由 nginx 直出),**不走 `/files/` 故不需要登记 `FileAccessMapper` 反查清单**;换成真实照片时若改用 `/files/...`,就必须补进那份清单(见 §7.8)。**演示电子书同理**:书与封面放 `frontend/public/demo/books/`,种子把 `file_url`/`cover_url` 写成 `/demo/books/...`,阅读器(epubjs / pdfjs / `fetch().text()`)按 URL 直接取内容,游客无 token 也能读;生成器 `scripts/gen-demo-books.py`。**相册要游客有照片、书架要游客有书,做法就是「往演示家庭种 PUBLIC 内容」,不用改任何接口**。
- **`/demo/**` 是 nginx 长缓存(`max-age=604800`,7 天)且文件名不带内容哈希**:改一张演示图/一本书若沿用旧文件名,**老访客拿到的还是缓存副本**(开发期实测:封面 SVG 解析失败 → 重跑生成器修好 → 浏览器仍按老 URL 命中缓存,`naturalWidth` 恒为 0,换带查询参数的 URL 才验证到新文件已生效)。演示内容一旦发布,改动请**连文件名一起改**。
- 相册封面不用种子显式给:`AlbumService.resolveCover` 依次取 `cover_url` → `cover_photo_url` → **该相册最新一张照片**,所以只塞照片就够了。
- **`public` 路由 ≠ 游客拿得到数据**(2026-10-14 抓到的第三类缺口):`/tools/mindmap` 路由是 `meta.public`,但 `/mindmap/list` 不在白名单里——游客白打一次 401(GET 不跳登录,于是页面顶成「还没有脑图」白板)。**新开 public 路由时同时问一句:它调的接口游客进得来吗**。收口方式二选一(别半开):①像相册/公告那样给接口解析演示家庭;②前端守卫 `if (!userStore.isLoggedIn) return` + 藏写按钮 + 给「登录后即可…」空态(脑图 V10.30 即此,放映厅/音乐同类)。
- **已知仍有空的游客面:放映厅**。「本地库」`/video/list` 是放行的,但演示家庭 0 条视频,且**视频要真实媒体文件**——本仓不能生成,故游客在 `/cinema` 看到的是登录引导而非列表。要补须先有可公开直链的短视频文件(放 `/demo/` 或 `/files/` 并登记反查)。
- **`permitAll` 不等于游客有内容:接口在放行名单里,但 service 拿 `familyId = null` 会直接返回空**。这类「白名单里却有页面空着」的缺口,2026-10-14 一次清了四处:`/kitchen/menu|/kitchen/recipe/*`(`RecipeService.menu(null)` 返回空分组)、`/anniversary/list`(`anniversaryService.list(null)` 返回空列表,于是首页纪念日卡片有 3 条、纪念日页却写「暂无纪念日」)。**新开一个读类公开接口时先问一句:未登录进来 `familyId` 从哪来**;要展示就给游客解析演示家庭——两种现成写法:①`FamilyMapper.selectDefault()`(相册/厨房做法);②`PublicController.resolveVisibleFamilyId(hid, homeId)`(公告/纪念日做法,顺带支持 `?hid=`/`?home_id=` 且非成员强制 `is_public=1`)。**带 `visibility` 列的表必须在 service 里再按 `PUBLIC` 过滤**(愿望的 `listPublic` 即此)。
- **反过来,「不该给游客看」的模块别用空接口糊弄**:要么不进白名单(401 → 页面由前端给登录引导),要么像 `CascadeController`(照片瀑布)那样接口明确「登录可用」且前端入口也带 `isLoggedIn` 守卫。**半开最糟**:接口放行了、返回空,用户看到的是「暂无数据」白板而不是登录邀请。
- **前端游客面的统一口径**:需登录才有数据的页面,给「登录后即可…」空态 + 藏写按钮 + **跳过注定 401 的请求**(`if (!userStore.isLoggedIn) return`)。不跳过的话,游客打开页面会先打一批 401:GET 静默空、POST 直接跳登录页(见 §3.20),且 `loadError`/`暂无数据` 会顶成「加载失败」这种看着像坏了的观感。已按此收口:记账/任务/计划/提醒/物品定位/家谱/音乐/积分商城/**脑图**。愿望单与「今日推荐(菜谱)」是**例外**(对游客开放,只读演示家庭的 PUBLIC 内容)。**接口在放行名单里却抛 401 也算同类**:`/music/background`(白名单里、服务层 `requireLogin()`)V10.30 改为未登录返回空结果。

**历史缺陷留痕(2026-10-13 修)**:`schema.sql` 给三个演示账号(`demo_owner/member/child`)建 `sys_user_role` 的语句用 `WHERE u.is_fake = 1` 过滤,而账号是按 `is_fake = 0` 插入的(紧邻注释还写着「演示假用户 is_fake=1」,与实际相反)——绑定一条都没建,登录时 `AuthService` 走 `roleCode == null → "GUEST"` 兜底,演示账号登进去就是访客。现按邮箱匹配修好,schema.sql + migrations.sql 双文件同步。**排查同类问题的手法**:看登录响应 `data.user.role` 是不是预期角色,或直接查 `SELECT u.username, r.role_code FROM sys_user u LEFT JOIN sys_user_role ur ON ur.user_id = u.id LEFT JOIN sys_role r ON r.id = ur.role_id WHERE u.email LIKE 'demo%@ihomy.local'`——`role_code` 为 NULL 就是绑定没建。

### 7.10 nginx 静态缓存正则吞掉 `/api/**` 里的 `.js/.css`(2026-10-15 修)

**症状**:接口文档页(`/doc.html`)在新环境/重装后**一片空白**。但 `/api/doc.html` 本身 **302 正常**、`/api/v3/api-docs` 也 **200**——所以很容易误判成「后端没配好」。

**真因**:站点 conf 里给静态资源加的长缓存用的是**正则 location**:

```nginx
location ~* ^/(?!files/).+\.(js|css|png|jpg|jpeg|gif|ico|svg|woff2)$   # 漏了 /api/
```

nginx 的匹配优先级里,**正则 location 高于前缀 location**(`/api/` 这种)。于是 `/api/swagger-ui/swagger-ui.css` 不去反代后端,而是被当成静态资源从 `root /opt/ihomy/frontend/dist` 里找 → 没有这个文件 → **404**。页面 HTML 拿到了,但 CSS/JS 全 404,浏览器渲染出的就是空白页。

**辨认手法**(一眼分辨「后端问题」还是「nginx 问题」):从外部直接打资源 URL

```bash
curl -sI https://<站点>/api/swagger-ui/index.html      # 200 → 后端没问题
curl -sI https://<站点>/api/swagger-ui/swagger-ui.css   # 404 → nginx 抢走了
```

同一个坑还影响过 Knife4j 时代的 `/api/webjars/**`(同样带 `.js/.css`),即**这条规则从加上起就一直在吞 `/api/` 下的静态扩展名**——`/api/doc.html` 返回 200 掩盖了它。

**修法**:负向断言同时排除 `/api/` 与 `/files/`(即 `^/(?!api/|files/)`),改完 `nginx -t && systemctl reload nginx`。已同步进 `docs/部署指导-Linux.md` 站点 conf 片段与 AGENTS「四条部署必查」第 ③ 条。

> 顺带:`/api/doc.html` 的 302 落点会是**绝对地址且 scheme 为 http**(Spring 7 的 `RedirectView` 恒输出绝对 URL,而 Java 侧看不到 nginx 的 `X-Forwarded-Proto`)。浏览器侧由 HSTS 升级到 https,实测可达,**不必**为此开 `server.forward-headers-strategy`(那会连带改变限流取 IP 的口径,风险大于收益)。

### 7.11 后端「服务器状态」版本号恒为 unknown(VERSION 未随部署上传,2026-10-15 修)

**症状**:`GET /api/ops/health` 与运维页「服务器状态」的 `version` 恒为 `unknown`,而前端页脚版本号正常。

**真因**:`HealthController.readVersion()` 是在**进程工作目录**里找 `../VERSION` / `VERSION` 两个相对路径;生产 systemd 的 `WorkingDirectory=/opt/ihomy/backend`,所以实际要找的是 `/opt/ihomy/VERSION`。而后端是以 `java -jar` 起的(`/opt/ihomy` 下那份仓库克隆是早期手工放的,长期不更新),`deploy.ps1` 原先只 scp **jar + dist + migrations**,**从不传 VERSION** → 两个候选路径都不存在 → 回落 `unknown`。

本地开发之所以看着正常:启动脚本把工作目录设在 `backend/`,于是 `../VERSION` 正好命中仓库根的那个文件。

**修法**:`deploy.ps1` 在上传 jar 的同一步把仓库根 `VERSION` 传到 `$RemoteRoot/VERSION`。补历史:此前 `readVersion()` 的候选路径是照着「jar 在 `backend/`、VERSION 在其上一级」写的,只是那个文件一直没被部署,**所以这是一条从功能上线起就存在的静默降级**(不影响探活判定,只影响版本显示)。

**核对**:改完 `curl -s https://<站点>/api/public/health` 应返回 `"version":"V<当前版本>"`。

**注意**:VERSION 上传写在 `deploy.ps1` 的 `if (-not $FrontendOnly)` 分支里,**只更前端(`-FrontendOnly`)时不会传**,健康接口与运维页版本号会停在上一次全量部署的版本(纯前端版本发布时必然滞后一版,如 V10.73 上线后仍报 V10.72)。判断前端是否已更新要看页脚 `__APP_VERSION__` 或线上入口 bundle 哈希,别只看健康接口版本;要让版本号对齐,再跑一次不带 `-FrontendOnly` 的部署即可。

### 7.12 直接打开 `/tools` 返回 nginx 403(与 `public/tools/` 目录同名,V10.65 已修)

**症状**:站内点「工具箱」能正常进入(F5 也行,Service Worker 用预缓存 index 顶住),但 `Ctrl+Shift+R` 硬刷新或地址栏直敲 `https://<站点>/tools` 得到 `403 Forbidden / nginx`,换成 `/tools/` 也一样。

**真因**(V10.65 之前):工具箱导出物 `frontend/public/tools/manifest.json` 构建后是 `dist/tools/` 真目录;nginx 的 SPA 回退是 `try_files $uri $uri/ /index.html`,`/tools` 命中目录后按目录处理、又没有 index 文件,于是 403,**不会**落到 `index.html`。其它 SPA 路由没有同名目录,所以只有这一条。

**对策**:导出清单改放 `frontend/public/toolbox-data/manifest.json`(`npm run tools:export` 已同步),构建产物是 `dist/toolbox-data/`,与任何 SPA 路由都不重名;线上地址变为 `https://ihomy.top/toolbox-data/manifest.json`。旧 URL `/tools/manifest.json` 现在会落到 SPA 的 index.html(不再 403,但也不是清单),外部消费方一律用新地址。**将来在 `public/` 下新增目录前,先对照 `router/index.js` 的路由段**。

**加固(可选)**:站点 conf 也可把回退写成 `try_files $uri $uri/index.html /index.html;`——目录里没有 index 时直接落 SPA,不从 `/tools/` 出 403,对以后的新目录同样生效。

**判据/取证**:`curl -o /dev/null -w "%{http_code}" https://<站点>/tools` 与 `/tools/` 均应为 200;`ls frontend/dist` 不应出现与路由同名的目录。修复记录见 `docs/变更归档.md` V10.65。

### 7.13 运维「产品下载」统计按 access 日志取数恒为 0(2026-10-27 改落库)

**症状**:运维页「访问统计」tab 里「咔哒 · 下载」「比特口袋 · 下载」一直是 0,而同一天的页面访问数正常(2026-10-26 咔哒访问 40 次、下载仍 0)。

**真因**(两层叠加):
- 生产 nginx `location /files/` 是 `alias /opt/ihomy/uploads/;` **静态直出**(见 §7.8),下载请求在 nginx 就被吃掉、**不进后端 access 日志**:连续多日 `grep -c "files/kada" /opt/ihomy/logs/access/ihomy-access*.log` 全为 0,而 `/var/log/nginx/access.log.1` 同一天有 30 次 `GET /files/kada/kada.exe`。
- 原统计代码只认 `/api/files/{产品}/` 前缀(只有反代形态下后端才看得到的 URI),两条前提都不成立,自然永远匹配不到。

**顺带的计数陷阱**:即便改回日志口径也不能数 GET 次数——14 MB 的包会走 Range 分段:2026-10-26 的 30 次 `kada.exe` 请求只来自 4 个 IP(其中 26 次是 206 分段)。落库口径按「下载入口命中一次」计,天然没有这个问题;若将来改用日志口径,须按 `IP + 文件 + 天` 去重。

**历史数据能恢复多少(2026-10-27 实测)**:统计改为落库后,上线前的历史只能从日志反推——**下载**可回收到 nginx 日志保留期(14 天,当时回到 10-13,按 `IP+文件+天` 去重);**访问**只能回到打点功能上线日(2026-10-25),更早没有打点记录;nginx 的 `GET /kada` 页面请求数可粗看趋势,但含爬虫与重复刷新、口径与打点不同,不要混进来。恢复脚本 `scripts/prod-product-stat-backfill.sql`(10-27 当天行先删后按日志口径重写)。

## 8. 性能踩坑与「不建议改」

### 8.1 已踩坑清单(由此固化为强制规范)

100% 缩放卡顿(内联 SVG 替代复杂 path 图标) / backdrop-filter 滚动炸弹(长列表/持续动画下每帧重算) / rAF 每帧写 Vue ref 触发响应式重渲染 / 常驻事件监听器 / 同步 import 阻塞首屏(字体包与大 CSS) / 入口 chunk 过大 / `getBytes()` 上传 OOM / SQL 日志同步 I/O / N+1 查询。

完整过程与取证见 `docs/变更归档.md`「性能优化」小节与 `docs/UI设计提示词.md` §19。

### 8.2 不建议改(成本高/收益低,别再重复论证)

- `TraceIdFilter` 用 `UUID.randomUUID()`(底层 SecureRandom)——单次约微秒,非瓶颈。
- `JwtUtils.parse` 每次重建 parser——jjwt parser build 约微秒,QPS 上千才值得。
- BCrypt 密码加密——安全要求,不可换。
- `StorageService.run` 单线程串行复制——手动触发的一次性任务,非热点。
- MyBatis-Plus 二级缓存——默认未开(正确),二级缓存易脏数据,不推荐。
- `stores/app.js` 不加 sessionStorage 缓存——家庭数据可变,in-memory 已够。
- `api/request.js` 不加请求去重/缓存——失效策略复杂,易脏数据。
- `AppSidebar.vue` 的 23 个 EP 图标同步导入——每个约 1-2KB,树摇后约 30KB,改动态反而增加运行时开销。

### 8.3 计数类字段回写要原子增量,别「先 COUNT 再 SET」(V10.2)

**症状**:并发点赞(或重复提交)后各内容表的 `like_count` 与 `content_like` 行数不再一致,且不会自行恢复。
**真因**:原 `ContentLikeService.syncCount` 先 `countByContent` 再 `SET like_count = ?`——REPEATABLE READ 下两个并发事务各按自己的快照算计数,后写者覆盖先写者(并发两赞都写 1);且当时类上无 `@Transactional`,like 行增删与计数回写不在同一事务,中途失败即永久漂移。
**对策**:计数改 `like_count = like_count ± delta` 原子增量(经 `LambdaUpdateWrapper.setSql`,由行锁串行),delta 按本次实际增删传(插入 `+1`、删除 `-1`、极端重复键兜底后记录已不存在则 `0` 不动,防空增);方法补 `@Transactional`,异常时与 like 行一并回滚;响应里的 `likeCount` 仍实算,保证准确。
**注意**:历史已漂移的值不会自动收敛(该内容下次被切换点赞时才 ±修正),要自愈须另加对账任务(V10.2 未做)。评论数/收藏数等同类计数后续改造沿用此模式。

### 8.4 混向排序的复合索引必须带 DESC,否则仍 filesort(V10.2)

**症状**:列表查询 `WHERE family_id=? AND status=? ORDER BY status, created_at DESC`,已建升序复合索引 `(family_id, status, created_at)`,但 `EXPLAIN` 的 `Extra` 仍有 `Using filesort`。
**真因**:同一个 ORDER BY 里同时出现升序列与降序列时,一次索引扫描只有一个方向,无法同时满足两者(纯降序排序才能靠反向扫描复用升序索引)。
**对策**:`family_plan` / `content_wish` 的 `idx_family` 建成 `(family_id, status, created_at DESC)`(降序索引需 MySQL 8.0.13+,开发与生产均满足)。判据始终是 `EXPLAIN` 看 `Using filesort`,别只看索引列齐不齐。
**取证**:`docs/变更归档.md` V10.2 小节(live DB 同步 SQL + 6 条列表查询的 EXPLAIN 结论)。

### 8.5 总账聚合按月只下发「有记录的月份」,补零与滚动归前端(V10.78)

**症状**:总账表格/趋势图按 12 个月排,直接渲染后端 `byMonth` 会缺月、月份错位,或某年只显示 3 根柱子看不出「空月」。
**真因**:`BookLedgerUtil.aggregate` 用 `TreeMap` 只把有收支的月份放进 `byMonth`(省流量、月数不固定);`opening/closing` 是全时段逐期滚动后的值,所以**某个有记录的月份的 `opening` 已经包含了它前面所有空月的结果**。
**对策**:前端 `utils/bookLedger.js` 的 `fillMonths(byMonth, year)` 取该年首条记录的 `opening` 当滚动起点,按 1~12 月逐槽算 `closing = opening + income − expense`,空月补 0;`totals` 恒为全时段,不随范围变;分类/成员/未归属跟随范围。**只有转账的年份**不在 `byYear` 里(转账不进结余),单年视图要用该年的 `opening` 补一行全 0 的年行。
**取证**:`docs/变更归档.md` V10.78 小节(`BookLedgerUtilTest` 9 例 + `bookLedger.spec.js` 30 例)。

## 9. 缓存失效矩阵
