## 1. 项目概述

### 1.1 项目背景

为家庭成员之间的内容共享与互动记录提供服务,本项目构建家庭内部使用的内容平台,应用名 ihomy。系统支持电脑浏览器、安卓、iOS 三端访问,保证多设备的一致性,以 PWA 形式发布。

### 1.2 项目目标

- 一套代码覆盖 PC 浏览器、安卓、iOS 三端(设备体验一致,PWA 形式)
- 支持家庭角色(家长/成员/孩童/访客),权限分级管理
- 邀请码注册设计,首页模块化快速家庭接入
- 内容模块:博客、日记、相册、放映厅、聊天室、积分商城、任务悬赏、提醒、家庭计划、愿望单、记账、家谱等
- 首页模块化设计可扩展,新功能即插即用

### 1.3 术语表

| 术语 | 说明 |
|------|------|
| PWA | Progressive Web App,可安装到桌面 |
| JWT | JSON Web Token,无状态身份令牌 |
| OWNER/MEMBER/CHILD/GUEST | 家长/成员/孩童/访客 四级角色 |
| OPS | 运维管理员(不属任何家庭) |
| AOP | 面向切面编程,用于自动记录操作日志 |
| RBAC | 基于角色的访问控制(用户-角色-权限三层) |
| share_token | 家庭分享混淆 ID(16 位随机,替代数字 home_id) |

## 4. 功能模块清单(按业务域归档)

### 4.1 认证与账号

#### 4.1.1 注册与登录

- **Controller**: AuthController;**Service**: AuthService;**关键表**: sys_user / sys_user_role / sys_family_info
- 邮箱=账号(uk_email 唯一),大小写不敏感
- 注册必填:邮箱 + 密码 + 确认密码 + 图形验证码
- 注册可带邀请码加入家庭,或创建新家庭(新家庭默认私有 is_public=0;自动注入 9 个默认博客分类)
- 注册成功**不自动登录**,跳转登录页
- 登录请求体:`{email, password, captchaId, captchaCode}`
- **邀请码状态校验**:`status==INVITE_UNUSED` 才放行(曾误写 INVITE_USED)
- JWT 双 token:access 2h + refresh 7d(Redis 黑名单登出失效);claim 含 userId/username/role/familyId/permissions/isOps
- refresh 时按优先级解析当前家庭:Redis > default_family_id > family_id;续期时两个 token 都轮换(滑动续期)
- **HTTP 401 约定**:`authenticationEntryPoint` 必须返回真实 HTTP 401 状态码(JSON 体照写),前端 axios 只对 HTTP 401 触发 refresh 续期
- **演示(访客)账号**:`demo@ihomy.local` / `demo2@ihomy.local` / `demo3@ihomy.local`(演示家庭 OWNER/MEMBER/CHILD,仅存在于开发库);密码不入仓库,登录页预填由前端 `.env.development.local` 的 `VITE_DEMO_*` 提供(仅 vite dev 加载,生产构建不读取)

#### 4.1.2 图形验证码

- **Controller**: AuthController;**Service**: CaptchaService;**存储**: Redis captcha:{id}
- `GET /auth/captcha` 返回 {captchaId, image(base64)}
- 5 分钟 TTL,一次性校验(通过即删);错误/重用返回 1006
- 开发环境固定 `qwer`(`app.captcha-fixed-code`)
- 实现:Java2D 绘制 4 位字符 + 干扰线/噪点

#### 4.1.3 个人资料

## 6. 数据库设计

### 6.1 RBAC 权限模型

采用 RBAC(基于角色的访问控制),用户-角色-权限三层模型:

sys_user ──< sys_user_role >── sys_role ──< sys_role_auth >── sys_auth

- **sys_user**:用户表,不含角色字段(角色通过关联表绑定)
- **sys_role**:角色表,预设 OWNER/MEMBER/CHILD/GUEST + OPS
- **sys_auth**:权限表,定义具体权限点(如 blog:create、album:manage)
- **sys_user_role**:用户-角色关联,同一用户在不同家庭可有不同角色(含 family_id)
- **sys_role_auth**:角色-权限关联,定义某角色拥有哪些权限

### 6.3 命名规则

- **前缀分类**:`sys_`(系统/账号/权限/配置/日志/天气/存储)、`family_`(家庭事务)、`content_`(内容数据)
- **前缀取最顶层祖先类别**;上下级关系体现在表名(如 `sys_user_role`)
- **字段命名**:下划线风格,实体类驼峰映射
- **主键**:`id BIGINT PK`(MyBatis-Plus `@TableId(type=INPUT)`,手动赋值或雪花)
- **软删**:`deleted TINYINT`(MyBatis-Plus `@TableLogic`);**物理删必须自定义 XML DELETE**(MP deleteById 实为 UPDATE)
- **时间字段**:`created_at` / `updated_at`(DATETIME)
- **家庭隔离**:所有业务表带 `family_id`
- **枚举字段**:状态/类型一律大写英文单词(`PUBLISHED/DRAFT/PUBLIC/FAMILY/ACTIVE...`),含义存字典表 `sys_dict_item`,**不用数字**

### 8.2 求稳方案(2GB 内存)

- MySQL 本机部署 + Redis 用 Docker。MySQL 调优后 ~180MB(performance_schema=OFF 省 80-100MB,端口 6306)
- 后端 Spring Boot 以 `ihomy` 应用用户运行(systemd `User=ihomy`)
- JVM 调优:`-Xmx384m -XX:MaxMetaspaceSize=192m -XX:+UseSerialGC -Xss512k`
- 每应用一用户,权利分散;除关键步骤外不用 root
- 详细步骤见 `docs/部署指导-Windows.md` / `docs/部署指导-Linux.md`(脱敏入库版;生产凭证台账在维护者本地)
