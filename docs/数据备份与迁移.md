# 数据备份与迁移

> 站内备份(V12.54 起):运维页统一配置定时备份与保留策略,家庭设置页由家长导出自家数据。
> 恢复一律在服务器上按包内 `RESTORE.md` 执行,**站内不做全库覆盖恢复**(避免误点把线上数据清空)。
> 功能口径见 `docs/需求设计说明书.md` §4.6.12,接口见 §7.5。

## 1. 备份分几档

| 类型 | 包含内容 | 默认时间 | 默认保留 |
|------|---------|---------|---------|
| 基础数据 BASIC | `sys_*` + `family_*` 等除内容档以外的全部表(账号/成员/家庭/权限/配置/家庭事务);备份任务表与密码重置令牌除外 | 每天 02:30 | 7 日 + 4 周 + 3 月 |
| 内容数据 CONTENT | `content_*` + `report_*` + `game_*` 表,以及 uploads 全部文件(硬链接增量) | 每天 03:30 | 7 日 + 4 周 + 3 月 |
| 全量快照 FULL | 全部表 + 全部文件,可独立恢复整站 | 每周日 04:30 | 8 周 + 12 月 |
| 迁移包 MIGRATION | 全量库 + 全量文件,手动生成 | 不定时 | **不自动清理** |
| 家庭导出 FAMILY | 单个家庭的记录 + 被引用的文件 | 家长手动触发 | 30 天 / 每家庭最多 3 份 |

- 基础数据体积很小(几十 MB 级),适合高频备份;内容数据的大头是 uploads 里的照片/视频/图书,文件未变化时用**硬链接**指向上一份备份,只有新增/改动的文件才真正落盘。
- 「日/周/月」是 GFS 三代:同一 ISO 周只留最新一份、同一自然月只留最新一份,三代合并去重后其余文件删除(记录保留为 `PURGED` 供审计)。
- 清理跑两个时机:每个备份任务成功之后 + 每天 05:00 定时。

## 2. 备份目录与产物

```
backups/<yyyyMMdd_HHmmss>_<kind>_<随机>/
  meta.json              清单:版本/类型/行数/文件数/字节数/SQL 的 sha256
  RESTORE.md             该包的恢复步骤(随包生成,类型不同提示不同)
  db/basic|content|full|family-data.sql.gz
  files/                 内容/全量/家庭包才有
    files.manifest.jsonl 逐文件清单(路径/大小/修改时间/是否硬链接)
```

- 根目录由 `app.backup.dir` 决定,留空时取 **uploads 同级** 的 `backups/`(生产即 `/opt/ihomy/backups`),**不放进 uploads**,避免被 nginx `/files/` 直接下载。
- 备份目录若确实落在 uploads 内,快照会自动排除备份目录自身。

## 3. 运维页怎么用

运维页 →「备份与迁移」(仅 OPS):

1. 顶部四张卡:备份占用(含硬链接共享的**实际磁盘占用**)、磁盘可用、下次自动备份、最近一次成功。
2. 四个按钮:立即备份基础数据 / 内容数据 / 全量、生成迁移包(全量与迁移包会二次确认)。同一时刻只允许一个任务,执行中按钮置灰,列表 5 秒轮询。
3. 「定时与保留策略」:总开关 + 三个任务的时间(选时间即可,非标准周期可切 cron 六段式输入)+ 各项保留份数 + 家庭导出清理规则;下方一行实时摘要说明当前生效规则。保存后立即重注册 cron,无需重启。
4. 任务列表:类型/触发(手动·定时)/状态/开始时间/耗时/体积/文件数/数据行/结果说明;已完成的可下载与校验,任何非执行中的任务可删除(仅删文件,记录留作审计)。

「校验」会比对 `meta.json` 的哈希、把 SQL 完整解压一遍、按清单逐文件检查存在性,返回缺失文件数——换服务器前建议对最近一份全量做一次校验。

## 4. 恢复步骤(服务器上做)

包内 `RESTORE.md` 是同一份流程的随包副本,以它为准:

```bash
# 1) 停后端
sudo systemctl stop ihomy-backend

# 2) 建空库并导入(全量包)
mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS ihomy CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
gunzip -c db/full.sql.gz | mysql -uroot -p ihomy

# 3) 恢复上传文件
rsync -a files/ /opt/ihomy/uploads/

# 4) 起后端并冒烟
sudo systemctl start ihomy-backend
curl -s https://<域名>/api/public/health
```

- **基础包**不含文件,文件要从同一时期的 CONTENT/FULL 包恢复;**内容包**不含账号与家庭配置,基础数据要从同一时期的 BASIC/FULL 包恢复。
- **家庭包**保留原始 `family_id` / `user_id`,建议只恢复到**全新空实例**;目标库已有数据时先核对家庭与用户 ID 是否冲突。
- 恢复前先对当前库做一次快照:`scripts/prod-backup.sh` 会做这件事(`mysqldump` 单事务 + gzip 校验),恢复脚本 `scripts/prod-restore.sh <dump> <目标库>`。

## 5. 配置项

`application.yml` 默认值,生产可在 `external.yml` 覆盖(改完重启后端):

| 键 | 默认 | 说明 |
|----|------|------|
| `app.backup.dir` | 空(= uploads 同级 `backups/`) | 备份根目录,建议单独一块盘或 NAS 挂载点 |
| `app.backup.min-free-gb` | 1 | 开跑前要求磁盘至少剩这么多 GB(另加 256MB 余量),不够直接拒绝 |
| `app.backup.max-total-gb` | 20 | 备份目录实际占用上限,超了拒绝开新任务,需先删旧备份 |
| `app.backup.download-max-gb` | 4 | 站内 zip 下载上限,超过提示直接在服务器复制备份目录 |

定时策略本身不在 yml 里,存在 `sys_parameter.name = backup.policy`(JSON,由运维页维护)。

## 6. 与服务器备份脚本的关系

- **站内备份**:面向「迁移 / 误删找回 / 单家庭导出」,包是自包含的(SQL + 文件 + 清单),可以直接搬到新服务器。
- **`scripts/prod-backup.sh`**:面向「本机灾备」,只做 mysqldump + uploads 只增不删的增量同步,由 systemd timer 每天 03:00 执行,留 14 天。两者互补,不要互相替代。

## 7. 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 点立即备份提示磁盘空间不足 | 触发 `min-free-gb` 或 `max-total-gb`,先删旧任务(列表操作列)或调小保留份数,再确认备份盘余量 |
| 提示「已有备份任务在执行」 | 同一时刻只跑一个任务;等列表状态不再是「执行中」,或看是否上次进程被杀(重启后端会把残留 `RUNNING` 标为失败) |
| 下载失败 / 拿到的是错误 | 包超过 `download-max-gb` 会直接报错,按提示在服务器上 `scp`/`rsync` 备份目录;业务失败时前端会显示后端返回的提示 |
| 校验报文件缺失 | 备份期间有人手工删过备份目录里的文件,或磁盘写满导致复制中断;直接重跑一份,旧包可删 |
| 内容备份没怎么变大 | 正常:未变化的文件是硬链接,`logicalBytes`(逻辑体积)会一直涨,实际占用看「备份占用」卡 |
| 定时没触发 | 看策略总开关与单项开关、cron 是否六段式、服务器时区;日志按 tid 查 `ihomy-backup` 线程的 `backup` 关键字 |

## 8. 新增表时要做什么

`BackupTableSpec` 决定每种备份包含哪些表:

- 前缀 `content_` / `report_` / `game_` → 自动进内容数据与全量;其余前缀 → 自动进基础数据与全量。
- **永不进备份**的两类:备份任务自身(`sys_backup_job`)与一次性敏感令牌(`sys_password_reset_token`)。
- 家庭导出按「表里有 `family_id` 列就按 family_id 过滤」:全局种子表(角色/权限/字典/节日/参数/开源台账等)与没有 family_id 的表不进家庭包;归属关系特殊的表(如 `sys_user_pref` 按 user_id、`sys_chat_dm_message` 按收发双方)要在 `BackupTableSpec.familyFilter` 里补一条规则,否则该表的数据不会出现在家庭导出里。
- 带文件 URL 的表要先在 `mapper/FileAccessMapper.xml` 登记游客可读范围(与「文件存储」规则一致),家庭导出才会把被引用的文件一起打进包里。

表结构改动后仍须同步 `schema.sql` + `migrations.sql`(幂等),并跑一次空库全量导入实测。
