# ihomy 日志规范(backend_logs 分支)

> 面向开发人员。业务/运维人员排查问题请看 [日志问题分析方法](./日志问题分析方法.md)。

## 1. 三类日志文件

日志根目录由 `logging.file.path` 决定(生产 `/opt/ihomy/logs`,开发 external.yml 覆盖为 `D:\WorkSpace\ihomy\logs`),按天滚动,保留 `app.log-retention-days` 天(默认 7,各类有总量上限):

| 文件 | 内容 | 写入方 |
|------|------|--------|
| `logs/access/ihomy-access.log` | 客户端调接口:每请求一条(method/URI/入参/操作人/IP/状态/业务code/耗时/响应摘要) | `AccessLogFilter` 自动,**业务代码不用管** |
| `logs/server/ihomy-server.log` | 应用内部流程 + SQL 语句及入参(不记结果集) + 框架 ERROR(含堆栈) | 业务代码 `log.xxx()` 自动进;SQL 由 `SqlStatementLog` 自动 |
| `logs/thirdparty/ihomy-thirdparty.log` | 出站调第三方 API:请求/响应/耗时/状态/失败堆栈 | `ThirdPartyHttp` 统一封装,**新功能必须走它** |

控制台(开发终端)输出与 server 相同内容但**不含 SQL**(防刷屏)。开发时看 SQL:`Get-Content D:\WorkSpace\ihomy\logs\server\ihomy-server.log -Wait -Tail 100`。

## 2. 六要素

每条日志固定包含:``时间  级别  线程  [tid]  位置(logger)  内容``

```
2026-09-01 11:23:41.284 [tomcat-handler-2] [tid:aa7a219127e84630] DEBUG m.s.c.i.mapper.BlogMapper.selectList - ==>  Preparing: SELECT ...
```

消息体要求覆盖业务叙事:谁(用户)、做什么(动作)、入参、结果、耗时。例如:

```java
log.info("[createBlog] 用户#{} 创建博客 id={}, title={}", userId, blogId, title);
```

## 3. tid(链路号)规则

- **HTTP 请求**:`TraceIdFilter` 自动生成 16 位 tid,写入 MDC + 响应头 `X-Trace-Id`,整条请求链路的业务日志/SQL 全部自动携带。入站带 `X-Trace-Id` 头则透传(方便前端/网关指定)。
- **@Async 异步线程**:`AsyncConfig` 的 MDC TaskDecorator 自动把提交线程的 tid 复制到异步线程(操作日志落库、设备映射任务都受益)。**不要再自己 new 线程跑业务**;确需自管线程池时,给 executor 设置同款 TaskDecorator。
- **WebSocket 消息**:每条消息独立 tid(`ChatWebSocketHandler` 手动 MDC.put),握手请求的 tid 只代表建连。
- **定时任务/系统内部触发**:无 tid(显示 `[tid:]`),属正常。
- tid 在三类文件间天然关联,运维页「详细日志」按 tid 一键检索。

## 4. 级别标准

| 级别 | 用途 | 例子 |
|------|------|------|
| ERROR | 需人工介入的失败,**必须带异常对象**(打堆栈) | `log.error("[sync] 设备映射任务失败 deviceId={}", deviceId, e)` |
| WARN | 可自动恢复但需要关注 | 三方调用失败已降级、慢接口(>3s,access 自动)、业务校验拒绝 |
| INFO | 关键业务节点(创建/删除/状态变更/外部调用) | 创建博客、加入家庭、调天气 API |
| DEBUG | 调试细节,生产也不关(SQL 日志恒为 DEBUG) | 中间变量、分支走向 |

禁止:`e.printStackTrace()`;`log.error("xx: " + e)` 丢堆栈(要 `log.error("xx", e)`);日志里拼敏感信息。

## 5. 报错必须打堆栈

```java
// 对
catch (Exception e) {
    log.error("[importData] 导入失败 fileId={}", fileId, e);   // e 作为最后一个参数,SLF4J 自动展开堆栈
    throw new BizException(ResultCode.INTERNAL_ERROR);
}
// 错:丢失堆栈
log.error("导入失败: " + e.getMessage());
```

全局兜底:`GlobalExceptionHandler` 对未捕获异常打 `log.error("系统异常", e)` 进 server 日志。业务异常(BizException)只打 WARN 一行,不打堆栈(预期内失败,无分析价值)。

## 6. 三方调用规范

**新增任何第三方 HTTP 调用必须走 `com.ihomy.common.ThirdPartyHttp`**,自动获得 thirdparty 日志(出/入/耗时/状态/失败堆栈/URL 脱敏):

```java
ThirdPartyHttp.Resp r = ThirdPartyHttp.get("myservice", url, Map.of("Authorization", "Bearer " + jwt), 10000);
if (r.ok()) {
    JsonNode node = mapper.readTree(r.body());
}
```

- `service` 名用作 logger 后缀(`thirdparty.myservice`),取短小稳定标识(weather/baidu/ipapi/bing)。
- 大文件流式下载不适用(响应是 GB 级流),参考 `StorageService.baiduOpen` 手动打 `Loggers.thirdParty("baidu")` 日志。
- API key/token 类 query 参数与 Authorization 头自动打码,不要自己拼进日志消息。

## 7. access 日志自动记录说明

- 入参:JSON body / 表单参数(multipart 只记长度);上限 4KB,超出截断。
- 响应:≤512 字符整体记录;超过只记 `{"code":N,"message":"..."}`(防列表接口刷屏)。
- 敏感字段自动打码:password/token/accessToken/refreshToken/secret/captcha/authorization 等(见 `AccessLogFilter.SENSITIVE_JSON`)。**新增敏感字段记得进清单**。
- 失败(HTTP≥400 或业务 code≠0)或慢(>3s)自动升 WARN,`grep WARN` 即可捞出问题请求。
- WS 握手只记请求行(包装流会破坏 Tomcat 协议升级),消息级日志在 ChatWebSocketHandler。

## 8. SQL 日志

`mybatis.sql.*` logger 恒为 DEBUG,只进 server 文件:每条业务 SQL 记 `==> Preparing`(语句)与 `==> Parameters`(入参),不记结果集。MyBatis 框架内部日志(SqlSessionUtils 等)挂 `mybatis.sql.internal` 前缀压回 INFO,防会话管理噪音。

临时关闭 SQL 日志(排查问题时别关):`logging.level.mybatis.sql: info`。

## 9. 运维页「详细日志」

- 接口:`GET /api/ops/logs/trace?tid=xxx&date=yyyy-MM-dd`(缺省今天),扫描三类文件按 tid 精确匹配,按时间线合并返回,堆栈作为消息一部分。
- 前端:运维管理 → 详细日志 tab;操作日志表格 TID 列点击直达;支持 `/ops?tab=trace&tid=xxx` 分享链接。
- 前端任何 5xx 报错 toast 都会带 `[tid:xxx]` 前缀(`request.js`),用户报障时直接拿这串检索。

## 10. 保留与容量

- 按天滚动,`app.log-retention-days`(默认 7,可配置)天删除;各类 totalSizeCap:server 2GB / access 1GB / thirdparty 1GB;启动时清理过期(cleanHistoryOnStart)。
- 异步落盘(AsyncAppender + neverBlock):日志高峰宁可丢日志也不阻塞业务线程。
