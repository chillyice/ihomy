# ihomy 需求规格说明书

> 本文档为 ihomy 家庭共用软件的完整需求规格。按功能模块归档,弱化版本号,着重以业务域组织,便于新会话快速理解项目全貌。
> 代码事实以 `backend/src/main/java` + `resources/schema.sql` 为准,如需检索先 `grep` 再动手。

---

## 1. 项目概述

### 1.1 项目背景

为家庭成员之间的内容共享与互动记录提供服务,本项目构建家庭内部使用的内容平台,应用名 ihomy。系统支持电脑浏览器、安卓、iOS 三端访问,保证多设备的一致性,以 PWA 形式发布。

### 1.2 项目目标

- 一套代码覆盖 PC 浏览器、安卓、iOS 三端(设备体验一致,PWA 形式)
- 支持家庭角色(家长/成员/孩童/访客),权限分级管理
- 邀请码注册设计,首页模块化快速家庭接入
- 内容模块:博客、日记、相册、放映厅、聊天室、积分商城、任务悬赏、提醒、家庭计划、愿望单、记账、家谱等
- 首页模块化设计可扩展,新功能即插即用

### 1.3 术语表

| 术语 | 说明 |
|------|------|
| PWA | Progressive Web App,可安装到桌面 |
| JWT | JSON Web Token,无状态身份令牌 |
| OWNER/MEMBER/CHILD/GUEST | 家长/成员/孩童/访客 四级角色 |
| OPS | 运维管理员(不属任何家庭) |
| AOP | 面向切面编程,用于自动记录操作日志 |
| RBAC | 基于角色的访问控制(用户-角色-权限三层) |
| share_token | 家庭分享混淆 ID(16 位随机,替代数字 home_id) |

## 2. 产品定位

- 家庭内部使用的私密内容共享平台
- 父母可快速上手,不要求技术背景
- 内容以家庭为单位隔离,跨家庭不可见

### 2.1 用户角色

系统设四级家庭角色 + 一个运维角色,权限从高到低:

| 角色 | 标识 | 定位 | 典型用户 |
|------|------|------|----------|
| 家长 | OWNER | 家庭管理者,拥有全部权限 | 父母/家庭管理员 |
| 成员 | MEMBER | 家庭普通成员,可发布和管理自己的内容 | 成年家庭成员 |
| 孩童 | CHILD | 受保护成员,内容可见性可自行控制,部分功能受限 | 家庭中的小朋友 |
| 访客 | GUEST | 非家庭成员,仅可浏览公开内容 | 未登录用户/外部访客 |
| 运维 | OPS | 系统运维管理员,不属任何家庭,只能访问 /api/ops/** | 系统运维人员 |

### 2.3 运行环境

| 端 | 运行方式 |
|----|----------|
| PC | Chrome/Edge/Firefox,可安装为 PWA |
| Android | 浏览器或添加到主屏幕;后期可 Capacitor 套壳 |

### 2.4 安全约束

- 全站 HTTPS(iOS PWA 强制要求)

- 注册必须有邀请码或创建家庭(防止滥用)

## 3. 技术架构

### 3.1 总体架构

前后端分离。前端 Vue3 PWA 构建产物;后端 Spring Boot 提供业务接口与权限;MySQL 持久化数据;Redis 缓存/令牌/控制限流/消息计数;本地磁盘或 NAS 存储文件。

### 3.2 前端技术栈

| 技术 | 用途 |
|------|------|
| Vue 3.4+ / Vite 5 | 框架与构建 |
| Vue Router 4 / Pinia 2 | 路由与状态管理 |
| Element Plus | 组件库(PC 与移动端通用) |
| Axios | HTTP 请求,JWT 拦截 + 401 自动刷新 |
| vite-plugin-pwa | PWA 支持 |
| GSAP | 入场动画与光影补间 |
| vue-i18n | 中英双语国际化 |
| marked v18 | Markdown 渲染(heading renderer 接收 {text, depth} 对象) |

### 3.3 后端技术栈

| 技术 | 用途 |
|------|------|
| Spring Boot 3.2 (JDK 21) | 主框架 |
| Spring Security 6 + JWT | 认证授权 |
| MyBatis-Plus 3.5 | ORM |
| Spring AOP | 操作日志自动记录 |
| Spring Mail | SMTP 邮件(密码找回) |
| Redis | 缓存、令牌、消息计数、限流 |
| Knife4j | API 文档 |
| Hutool | ChineseDate 农历转公历 |

### 3.4 数据库与存储

- **MySQL 8.4**:用户/家庭/内容/相册/博客/评论/权限/群组/操作日志等(49 张表)
- **Redis**:JWT 刷新令牌黑名单、验证码、消息未读计数、限流控制
- **文件存储**:本地磁盘(开发期)/ NFS 挂载 NAS(未来);DB 存 `/files/...` 完整 URL,与物理根解耦

## 4. 功能模块清单(按业务域归档)

> 以下为已实现功能的完整清单。每个模块包含:Controller/Service/关键表/要点。

### 4.1 认证与账号

#### 4.1.1 注册与登录

- **Controller**: AuthController
- **Service**: AuthService
- **关键表**: sys_user / sys_user_role / sys_family_info
- **要点**:
  - 邮箱=账号(uk_email 唯一),大小写不敏感
  - 注册必填:邮箱 + 密码 + 确认密码 + 图形验证码
  - 注册可带邀请码加入家庭,或创建新家庭(新家庭默认私有 is_public=0)
  - 注册成功**不自动登录**,跳转登录页
  - 登录请求体:`{email, password, captchaId, captchaCode}`
  - **邀请码状态校验**:`status==INVITE_UNUSED` 才放行(曾误写 INVITE_USED)
  - JWT 双 token:access 2h + refresh 7d(Redis 黑名单登出失效)
  - JWT claim 含 userId/username/role/familyId/permissions/isOps
  - refresh 时按优先级解析当前家庭:Redis > default_family_id > family_id

#### 4.1.2 图形验证码

- **Controller**: AuthController
- **Service**: CaptchaService
- **存储**: Redis captcha:{id}
- **要点**:
  - `GET /auth/captcha` 返回 {captchaId, image(base64)}
  - 5 分钟 TTL,一次性校验(通过即删)
  - 错误/重用返回 1006
  - 开发环境固定 `qwer`(`app.captcha-fixed-code`)
  - 实现:Java2D 绘制 4 位字符 + 干扰线/噪点

#### 4.1.3 个人资料

- **Controller**: ProfileController
- **关键表**: sys_user
- **要点**:
  - `GET/PUT /profile`(nickname/avatar/birthday/gender)
  - `GET/PUT/DELETE /profile/label`(身份标签)
  - 头像裁剪缩放:zoom 0.5-3,滚轮+滑块(AvatarCropper 组件)

#### 4.1.4 密码找回

- **Controller**: AuthController
- **Service**: AuthService
- **关键表**: sys_password_reset_token
- **要点**:邮箱自助找回,token 30 分钟过期

#### 4.1.5 运维账号

- **Controller**: AuthController
- **Service**: AuthService
- **关键表**: sys_user_role(family_id 可空)
- **要点**:
  - `ops / ops@ihomy.local` 初始密码 admin123
  - OPS 角色绑定 family_id=NULL
  - `buildTokens` 返回 `isOps` 标志
  - 前端 `userStore.isOps` / `userStore.isPureOps`(纯 OPS 无家庭角色)

### 4.2 家庭与成员

#### 4.2.1 家庭管理

- **Controller**: FamilyController
- **Service**: MultiFamilyService
- **关键表**: sys_family_info
- **要点**:
  - `GET/PUT /family`(@family:manage)
  - `POST /family` 创建新家庭(已登录用户,绑定 OWNER+切换当前家庭)
  - `share_token` 16 位随机(注册时生成)
  - `is_demo` 演示家庭标记
  - `music_url/music_title` 背景音乐
  - `weather_lat/weather_lng/weather_city` 天气地区偏好(空=IP 自动定位)
  - `is_public` 访客公开开关

#### 4.2.2 多家庭切换

- **Controller**: AuthController
- **Service**: MultiFamilyService
- **存储**: Redis user:curfamily:{id}
- **要点**:
  - 家庭双概念:sys_user.family_id=主家庭(注册归属);当前家庭=会话级概念
  - `GET /auth/families` 返回 {familyId, name, role, isPrimary, isDefault, isCurrent}
  - `POST /auth/family/switch {familyId, setDefault?}` 校验角色绑定后更新 Redis+重签 token
  - `POST /auth/join {inviteCode}` 凭码加入(不自动切换)
  - 同一用户不同家庭可有不同角色(`sys_user_role.family_id` 区分)
  - 演示家庭 `is_demo=1` 标记;假用户 `is_fake=1` 禁止登录

#### 4.2.3 成员管理

- **Controller**: MemberController
- **Service**: MemberManagementService
- **关键表**: sys_user_role / family_invitation_code
- **要点**:
  - `GET /member/list`(含 role_code+label)
  - `PUT /member/{id}/role` 变更角色
  - `DELETE /member/{id}` 移除成员(不能移除自己)
  - `POST /member/invite`(生成码)
  - `GET /member/invite`(码列表)

#### 4.2.4 公开家庭搜索与入家申请

- **Controller**: FamilyController
- **关键表**: family_apply
- **要点**:
  - `GET /family/search?keyword=` 搜索公开家庭
  - `POST /family/apply` 申请入家
  - `GET /family/apply/list` 申请列表
  - `PUT /family/apply/{id}?action=approve|reject` 审核通过绑 MEMBER+通知

#### 4.2.5 家庭分享与混淆 ID

- **Controller**: PublicController
- **关键表**: sys_family_info.share_token
- **要点**:
  - `?hid=<share_token>` 优先于 `?home_id=`
  - 访客访问私有家庭 hid → NOT_FOUND
  - 演示家庭 share_token 固定 `98a06619927f11f1`
  - 家庭设置页展示「家庭分享链接」(`/?hid=`)并提供复制按钮

## 6. 数据库设计

### 6.1 RBAC 权限模型

采用 RBAC(基于角色的访问控制),用户-角色-权限三层模型:

```
sys_user ──< sys_user_role >── sys_role ──< sys_role_auth >── sys_auth
```

- **sys_user**:用户表,不含角色字段(角色通过关联表绑定)
- **sys_role**:角色表,预设 OWNER/MEMBER/CHILD/GUEST + OPS
- **sys_auth**:权限表,定义具体权限点(如 blog:create、album:manage)
- **sys_user_role**:用户-角色关联,同一用户在不同家庭可有不同角色(含 family_id)
- **sys_role_auth**:角色-权限关联,定义某角色拥有哪些权限

### 6.3 命名规则

- **前缀分类**:`sys_`(系统/账号/权限/配置/日志/天气/存储)、`family_`(家庭事务)、`content_`(内容数据)
- **前缀取最顶层祖先类别**;上下级关系体现在表名(如 `sys_user_role`)
- **字段命名**:下划线风格,实体类驼峰映射
- **主键**:`id BIGINT PK`(MyBatis-Plus `@TableId(type=INPUT)`,手动赋值或雪花)
- **软删**:`deleted TINYINT`(MyBatis-Plus `@TableLogic`)
- **时间字段**:`created_at` / `updated_at`(DATETIME)
- **家庭隔离**:所有业务表带 `family_id`
- **枚举字段**:状态/类型一律大写英文单词(`PUBLISHED/DRAFT/PUBLIC/FAMILY/ACTIVE...`),含义存字典表 `sys_dict_item`,**不用数字**

### 6.4 visibility 字段(5 张内容表)

| 值 | 含义 |
|----|------|
| PRIVATE | 仅自己 |
| FAMILY | 家庭可见 |
| PUBLIC | 公开 |

> 注:schema.sql 与 live DB 已对齐(曾误写 TINYINT)。visibility 字段关联 `content_visibility` 表记录可见成员/群组(预留,当前仅用 PRIVATE/FAMILY/PUBLIC 三值)。
