##### 首页频闪排查与修复(frontend_performance 分支,2026-08-31,已结案)

**最终根因(用户实测确认)**:Edge 硬件加速下的 GPU 合成路径 bug(驱动/MPO 层,非应用代码)。证据链:① 关闭硬件加速 → 不频闪;② Chrome 同页面 → 不频闪;③ 切走再切回浏览器窗口(触发 DWM 全量重建)→ 频闪消失;④ 刷新页面 → 频闪复现。用户侧处理:开关一次硬件加速+重启 Edge 已恢复;**若复发**依次尝试:更新显卡驱动 → 注册表禁用 MPO(`HKLM\SOFTWARE\Microsoft\Windows\Dwm` → `OverlayTestMode`=5)→ 应用内 Settings 关"毛玻璃"(no-glass 全局禁 backdrop-filter,应用侧唯一规避开关)。

**保留的修复(应用侧真实问题,与驱动 bug 无关)**:

- **L 形 hover 死角(列表消失的真因)**:子面板 absolute 挂在 wrapper 右侧(`left:100%; top:0`),hover 区域 = 触发行(38px 高)∪ 右挂面板(x≥菜单右缘)。触发行正下方(x<菜单右缘、y>触发行底)属「退出登录」行——鼠标斜向下够第二个家庭时**先穿出这个死角 → wrapper `:hover` 丢失 → 面板瞬间 `display:none`**,且消失后移入原面板区域不会恢复(display:none 无可 hover 目标),必须回到触发行重来(即"第二次才正常")。**规则:纯 CSS hover 子菜单的容忍期必须用 `visibility` 延迟隐藏而非 `display` 切换**——延迟窗口内元素仍可 hover,鼠标到达面板即恢复 hover 链;真离开(如移向退出登录)300ms 后才隐藏。

- **下拉数据要"打开即完整"**:依赖 open 事件异步拉取会导致菜单打开后长高跳动、新项突然出现在静止鼠标下方(浏览器会在 DOM 变化时重算 :hover,产生非预期 hover)。挂载时预加载 + 打开时刷新的组合两者兼顾。
- 复现方法论:静态 CSS 分析无法定位(几何上触发项与面板无缝衔接),需真实浏览器逐帧记录(panel display/wrapper :hover/popper 位置)+ `cua.move` 分步走位;`document.elementFromPoint` 验证命中链。

**验证**:①斜向下穿死角路径 (100,780)→(140,790):面板保持 visibility:visible,到达后 opacity 恢复 1、hover true;②移向「退出登录」停留:300ms 宽容期内仍可见,超时正确隐藏;③幽灵 bar display:none(EP 仍尝试 fade-in 但被挡);④点头像外部关闭/重开正常;⑤`npm run build` 入口 chunk 237.27KB(gzip 93.38KB)在基线内,后端零改动。

**踩坑(冒烟 E2E 实测抓到)**:
- **JDK HttpURLConnection 不支持自定义 HTTP 方法**:`setRequestMethod("PROPFIND")` 直接抛 `ProtocolException: Invalid HTTP method: PROPFIND`,且无系统属性可放行——自定义方法必须走 `java.net.http.HttpClient`(`HttpRequest.method(name, publisher)` 支持任意方法)。已固化进 ThirdPartyHttp.request:标准方法(GET/POST/HEAD/OPTIONS/PUT/DELETE/TRACE)仍走 HttpURLConnection,其余走 HttpClient。
- **WebDAV 请求路径必须百分号编码**:中文目录名直接拼 URL 畸形;encodePath 按 UTF-8 段编码(URLEncoder 的 `+` 转回 `%20`);响应 href 解码时字面 `+` 先转 `%2B`(URLDecoder 会把 `+` 转成空格,破坏文件名)。
- **encodePath 首段为空时不能丢前导 `/`**:`split("/", -1)` 首段空被跳过导致 `/测试相册` 编码成无前导斜杠的畸形 URL(冒烟映射浏览子目录 500 抓到)——改为按下标补分隔符。
- 测试环境坑(非代码):自建 WebDAV 测试服务器带请求体的方法必须先排空 body,否则 keep-alive 连接上残留 body 被下一请求行误解析成 Bad request(400);测试脚本请求签名 URL 时注意其本身已含 `/api` 前缀(拼 BASE 会成 `/api/api/`)。

- **token 节约**:put 上下文 items 由 JSON 数组(`{"id":123,"name":"厨房抽屉","aliases":"抽屉"}` ~20 token/行)压缩为紧凑"名称(别名1/别名2)"逐行文本(~8-12 token/行)——**去 id**(AI 无需回传物品 id,后端按名称/别名 SQL 匹配)与 JSON 键名开销,items 部分 token 约省一半;rooms/furnitures 保留 id+name 最小 JSON(AI 需回传目标 id,压缩格式有误提取风险);find 无上下文清单(本来就不发);system prompt 已精简 + temperature 0.2 + JSON 模式。大户型(150 items 上限)单次 put 约省 2000+ token。

##### 全局 AI 配置移除,只保留家庭 AI 配置(2026-09-08,V9.47)

**背景**:V9.43 引入按家庭配置时保留了「家庭行 > 全局 app.ai.* yml 兜底」双层解析。实际运行发现双层语义带来理解成本(设置页占位符要展示全局值、删除配置回退全局、"跟随全局"文案遍布),而生产全局 app.ai 段本就已注释停用(V9.43 起)、dev 两家庭的真实值也早已配在家庭 DB 行——全局兜底实际从未承担生效职责,遂整体移除,配置来源收敛为唯一:家庭行。

**规则/决策**:
- **resolve 只读本家庭行**:无行或主配置字段(base_url/api_key/model)空 = 该家庭未启用;`timeout_ms` 缺省 30000(`DEFAULT_TIMEOUT_MS` 常量,原 yml 兜底 30000 同值);FamilyAiConfigService 删除全部 10 个 `@Value("${app.ai.*}")` 全局字段。

- **yml 段删除而非留空**:application.yml 与 external.yml.template 的 `app.ai` 段整体移除(留一行注释指向家庭配置),避免"配置了也不生效"的误导;dev `config/external.yml` 同步移除(tshl/ark 真实值保留在演示家庭/小窝 DB 行,ENC 密文入库,不入 git)。
