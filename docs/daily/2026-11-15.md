# 2026-11-15 变更记录

## 暖居背景待机浮现:浮现中点一下就收起图片,不穿透到后面的按钮(V12.26)

- 需求(移动/触屏设备):暖居外壳的天气 AI 底图在长时间静止后会浮到最前。浮现期间该层原本 `pointer-events:none`(点击穿透),触屏平板/宽屏触屏没有「移动鼠标」这一步先把图片撤掉,手指一点就落在图片后面的卡片/按钮上 —— 误触。期望行为:点图片 = 收起图片,这一下不执行后面任何操作。
- 变更:`frontend/src/components/warm/WarmLayout.vue`
  - `.gc-weatherbg.revealed` 由 `pointer-events:none` 改 `auto` + `touch-action:none`,模板加 `@click.stop.prevent="dismissBgReveal"`:浮现中由图片自己接管这一下,只收起图片(同时清掉待触发的计时),不冒泡、不执行下层动作。
  - 划动同样收起:触屏上「划了却什么都不发生」会以为卡住,故 `@pointerdown/@pointermove` 记起点,位移超过 `SWIPE_SLOP=18`(浏览器此时不再补 click)即收图;万一仍尾随一个 click,`swallowTrailingClick` 在**捕获阶段**吃掉(`SWALLOW_CLICK_MS=500`),不落到后面的按钮上。收完下一次滑动即正常滚页面。
  - 触屏没有 `mousemove`,新增 `pointerdown` / `pointermove` 活动入口(`onTouchActivity`,滑动复位按 250ms 节流):轻点/滑动都算活动,**轻点空白背景板同样起算「静止 1 分钟」**,避免改动后触屏彻底触发不了浮现。
  - 新增 `TOUCH_GUARD_MS=800`:触屏轻点会紧跟一个合成 `mousemove`,若它先把图片收起,紧随的 `click` 就会落到下层 —— 最近一次触摸后的 `mousemove` 一律不参与复位/计时;浮现中收到触摸 `pointerdown` 也不再提前撤图,交给 `click` 收。
  - 计时/复位抽成 `bgActivity(x,y)` 单点,鼠标与触屏共用同一套「命中背景板 → 重新起算」判定。
- 交互口径:
  - 桌面鼠标语义不变:一动鼠标图片就撤(此时 `pointer-events` 已回 `none`,这一下的点击照常落在鼠标所指的元素上);只有「鼠标完全不动、直接点」才会被图片吃掉一次(同样是防误触)。
  - 触屏(安卓平板 app/触屏 Windows):轻点空白背景板开始计时 → 1 分钟后图片浮现 → **轻点或划动(>18px)即收起,这一下不执行后面任何操作**。
  - 收图后不自动重新起算,下一次指针活动(点在背景板/移动鼠标)才重新计时,避免刚关掉就又冒出来。
- 文档:`docs/UI设计提示词.md` §17 天气背景待机浮现那条按新口径改写(`pointer-events:auto` + 点击只收起 + 触屏合成事件守卫)。
- 验证:前端 `npm run lint` 0 error(改动文件 `prettier --write` 通过);`npx vitest run` **1180 passed**;`doc-drift-check` / `gen-code-map --check` 见收尾结果。
- 遗留:手机端(移动布局)不走暖居外壳,长时空闲是屏保 `ScreensaverOverlay`(本就吞掉点击、不穿透),本次不涉及;该交互需真机触屏(安卓平板/触屏 Windows)实测一遍「浮现 → 轻点 → 图片消失且未进入任何页面」。
