## 11:30 未开灯时整页偏冷灰：天光与环境暗度改暖色乘色（V15.20）

- 现象：开灯时页面是暖纸色，**关灯后整页偏冷灰**（晴天、白天）。本机实测（headless Chrome + CDP，11:20 晴、太阳高度角 31.4°）：整页均值 (185,173,159)，背景纸色 (241,231,214) 被压到 (208,200,186)、色度 27 → 23，而同时间点被阳光直射的纸面仍到 250 以上——乘色把整页拉到「背光」那一档，且天光乘色本身是半天空色的灰蓝。
- 成因：关灯时 `--lamp-mask: none`，两层 multiply 覆盖全页——`.bright-spot.sky-tint`（晴日不透明度 8.4%，乘色 = 一半天空色，如 rgb(109,115,121) 冷灰）与 `.room-shade`（纯黑，环境暗度 9.2%）。两者亮度口径正确，缺的只是暖色：乘色层在 luminance 不变时能挪动的色度有限（不透明度 × 通道差），所以只改色不改深度。
- 改动 `frontend/src/utils/windowLight.js`：
  - `skyLighting()` 的乘色按 `skyLevel` 混入暖中性 `[1.08, 1, 0.88]`，并按 luma 归一到原值（**亮度严格不变**），晨昏/阴雨 `skyLevel` 低时仍保留冷调；`tintLuma` 取未取整的通道，曝光曲线在相邻采样点连续。
  - 新增 `AMBIENT_SHADE_RGB = [64, 38, 16]` 与 `ambientShadeLayer(lumaShade)`：环境暗度改用暖褐乘色，不透明度按色值自身亮度回推（`lumaShade / (1 - luma)`，上限 1），因此 `(1-opacity×(1-luma))` 与原来的 `(1-roomShade)` 完全等价——曝光与「直射出现/消失时被遮点不变暗」的连续性口径都没变。
- `useSunLight.js` 新增 `roomShadeLayer`（`roomShade` 保持亮度口径供模型与用例使用）；`SunLightLayer.vue` 的 `.room-shade` 改为吃 `roomShadeLayer`（`background: rgb(64,38,16)` + 回推后的不透明度），CSS 里不再写死 `background: black`。
- 实测（同场景，CSS 覆盖成新值后同帧对比）：整页均值 (185,173,159) → (187,172,157)；背景纸色 (208,200,186) 色度 23 → (211,199,182) 色度 29，luma 200.7 前后一致（亮度不变、只是由灰转暖）。
- 亮度那一档未动：整页仍比无光影时暗约 16%，这是「阴影深度」的口径（设置 → 光影 → 阴影深度，130 → 70 可再提亮约 5%）。若还要更亮再压这条曲线。
- 验证：`node scripts/related-tests.mjs --run` 7 个 spec 108 项通过（含新增 `windowLight.spec.js` 用例：暖褐乘色的亮度等价、通道 R>G>B、不透明度 ≤1）；`eslint` 0 error / 0 warning；`prettier --check` 干净。

## 15:36 白天进站不再先闪暮色：日表未到时不自动切晨暮（V15.21）

- 现象：手机白天进站，页面自己按「晨 → 暮 → 晨」连续扫两次。
- 成因：`useSunLight.js` 的晨暮自动档 watcher 用 `sunScene` 判定昼夜，而 `/public/sun-info` 未返回前 `sunScene` 是占位夜景——`getSunScene(null, 0)` 回落 `{ altitude: -30 }`，`isNight` 恒为 true。挂载即 `applyAuto(true)` 扫一遍到暮色（还写进 localStorage），日表到达后再按真实高度角扫回晨色；手机网络慢，暮色停留够久，两次扫光看得很清楚。桌面上两次间隔 <500ms，容易被当成一次闪烁。
- 改动 `frontend/src/utils/useSunLight.js`：watcher 里先 `setSunContext`（手动切换的扫光方向不受影响），再 `if (!activeSunInfo.value) return` —— 真实日表（含光照测试的预览日表）落库后才自动切晨暮。副作用一并修掉：以前取不到日表（离线/接口失败）会把暮色写进偏好卡一整天，现在保持上次的晨/暮不动。
- 验证：`npx vitest run src/utils/useSunLight.spec.js` 19 passed，其中新增用例断言日表 pending 时 `applyAuto` 不被调用、数据到达后只调用一次 `applyAuto(false, { sweep: true })`；临时去掉门禁时该用例确实失败（证明测中的就是占位夜景这条路径）。`node scripts/related-tests.mjs --run` 9 spec / 45 项通过；eslint 0、prettier `--check` 干净。未做真机复验。
