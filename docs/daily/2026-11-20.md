## 00:55 连连看音效静默回归:补回「解码失败 / 上下文未 running」两条静音路径(V13.53)

- 反馈(原话):「宠物连连看的音效没有了」
- 排查:在 IAB(nginx:80 托管 dist)装探针(`createBufferSource` + AnalyserNode)复测,**本机 Chrome 里三段音效都正常解码并起播**(click 0.021s / match 0.47s,消除音采样峰值 0.1447),资源与构建都没问题 —— 问题出在 V13.38 换 Web Audio 时留下的两条**静默失败**路径:
  1. `if (!buffer) return`:样本解不出来(个别 WebView 拒解短样本,或解码还没做完就点)时**完全没有声音**,而此时已经没有 `<audio>` 兜底了(旧实现本身就是 `<audio>`)。
  2. `ctx.resume().catch()` 之后**立刻** `source.start()`:悬挂态(suspended / iOS interrupted)里起播会被引擎直接吞掉;若该设备上 resume 一直不落地(手势没被认),就变成每一句都「点了没声音」。
- 改法(`frontend/src/views/games/PetLinkLink.vue`):
  1. 缓冲缺失(解码失败/未完成)→ 该音改走 `<audio>`(`htmlOnlyKeys` 记账,失败后不再等缓冲);`startBuffer()` 起播抛错也走这条路。多一两百毫秒可以接受,**没声音不行**。
  2. 上下文非 running 时先 `resume()`,**落地后**再起播;300ms 没落地同样退回 `<audio>`。
  3. 新增 `unlockAudio()`:挂 `pointerdown`(capture)+ `keydown` 全局监听,菜单里点「开始游戏」那一下就把上下文拉起来,进局第一次点牌时已是 running。
  4. `ensureAudioContext()` 补 `state !== 'closed'` 判断,不复用已关闭的上下文。
- 验证(IAB + dist,先退 SW 清 caches):
  - 正常路径:连点三张牌 → `createBufferSource` 3 次、`state='running'`、`<audio>` 播放 **0** 次。
  - 兜底路径:把 `createBufferSource` 改成抛错(等价于缓冲不可用的设备)→ 三次点击全部落到 `<audio>`(`data:audio/wav` 三段真播放),无未捕获异常。
  - 坑:IAB 的 SPA 路由离场靠 rAF,不派发 → 页面永久卡在 `fade-leave`(连 `transition-duration:1ms` 也救不回),没法用「回大厅再进」重挂组件拿解码失败场景,兜底验证只能改用「起播抛错」触发。
