**决策**:

- **只在前台跑**(App 启动/回前台/手动点击):后台写接口不能放进 `type=WIDGET` 只读白名单,另开写令牌通道超出本批安全面;与计划 §5.5 的 Worker 差异记入计划「实施差异」。
- **备份相册按 `backup_key = android:<设备标识>` 字符串键找**,不用计划原写的 `source_device_id`:该列语义是「设备目录映射来源 ID」(BIGINT),混用会搅乱映射相册口径;且字符串键换机/重装可重新生成、服务端只校验形状。
- 不刷积分;单张失败整轮停下(游标停在上一张成功处),下次续传;90 天窗口外走「全部备份」二次确认。

**表**(`schema.sql` + `migrations.sql` 末尾幂等迁移,表数仍 92):

```sql
content_photo       + checksum VARCHAR(64) NULL + UNIQUE KEY uk_family_checksum(family_id, checksum)
content_photo_album + backup_key VARCHAR(64) NULL + UNIQUE KEY uk_family_backup_key(family_id, backup_key)
```

存量全 NULL 不回填(MySQL 唯一索引允许多个 NULL)。

## 11:15 修复:语音/视频通话拿不到摄像头、麦克风(浏览器与 App 双线)(V11.94)

### 决策

- **「存到文件」改为「存到图书馆 / 放映厅 / 相册」**:`FileService` 能落到 `{upload-dir}/files/{yyyyMM}/`,但站内没有通用文件列表入口(`StorageController` 的系统设备不支持浏览),存进去等于用户再也找不到;改为落到有列表、能预览、能分享的既有页面,分享动作才有闭环。
- **文档/视频惰性复制**:只是「用 ihomy 打开看一眼」不该先拷几百 MB 进缓存;`getPending` 只给元数据,用户点保存才 `prepare`。图片仍立即复制(需要缩略图且单张 ≤10MB),行为与第二批一致。
- **payload 升到 v2 但保留 `skipped` 总数**:旧字段继续回传只为兼容,前端实际按 `skippedImages` / `skippedDocs` 分开展示,避免把「图片超 9 张」说成「文件超 500MB」。
- **VIEW 只列 `image/*` 与 `application/pdf`**:视频的「打开方式」不在本批验收内,列了就要处理播放器与解码边界;`video/*` 只接系统分享。同一 intent-filter 内多 `<data>` 的属性合并语义已在注释里写明,避免后人误以为是「且」。
- **PDF「打开方式」保留 `image/*` VIEW 的风险先不摘**:部分 ROM 把「用其他应用打开」的候选合并展示,可能出现「用 ihomy 打开」抢在 PDF 阅读器前;本批先按提示词保留,真机确认扰民再按备选方案收掉图片 VIEW。**已知风险,记在此。**
- **卡片分不清「没有账本读权限」与「本月无记录」**:`/book/summary` 对游客/无 READ 档位返回全零摘要(与「没记」同形),卡片只能显示「本月还没有记录」。要区分得让摘要接口回传权限态,属接口变更,本批不做。**已知限制。**
- **提示条只读 localStorage**:点进去是设置页,回来重新挂载自然更新;不在相册页调 `photoBackupPending()`(会触发原生扫 MediaStore,和「看一眼相册」的成本不相称)。
