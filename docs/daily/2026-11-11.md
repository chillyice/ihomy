**决策**:

- **只在前台跑**(App 启动/回前台/手动点击):后台写接口不能放进 `type=WIDGET` 只读白名单,另开写令牌通道超出本批安全面;与计划 §5.5 的 Worker 差异记入计划「实施差异」。
- **备份相册按 `backup_key = android:<设备标识>` 字符串键找**,不用计划原写的 `source_device_id`:该列语义是「设备目录映射来源 ID」(BIGINT),混用会搅乱映射相册口径;且字符串键换机/重装可重新生成、服务端只校验形状。
- 不刷积分;单张失败整轮停下(游标停在上一张成功处),下次续传;90 天窗口外走「全部备份」二次确认。

**表**(`schema.sql` + `migrations.sql` 末尾幂等迁移,表数仍 92):

```sql
content_photo       + checksum VARCHAR(64) NULL + UNIQUE KEY uk_family_checksum(family_id, checksum)
content_photo_album + backup_key VARCHAR(64) NULL + UNIQUE KEY uk_family_backup_key(family_id, backup_key)
```

存量全 NULL 不回填(MySQL 唯一索引允许多个 NULL)。

## 11:15 修复:语音/视频通话拿不到摄像头、麦克风(浏览器与 App 双线)(V11.94)

- 现象:1:1 通话(视频与纯语音)在浏览器与 App 内都起不来,提示「摄像头/麦克风权限被拒绝」,连语音也失败。
- 根因(两条,归因不同):
  - **App(确定根因)**:`AndroidManifest.xml` 从未声明 `CAMERA` 与 `MODIFY_AUDIO_SETTINGS`。WebView 侧 `getUserMedia` 会走 Capacitor 的 `BridgeWebChromeClient.onPermissionRequest`,它把 `CAMERA` / `RECORD_AUDIO` / `MODIFY_AUDIO_SETTINGS` **一起**交给系统申请;只要清单里缺其中一条,`RequestMultiplePermissions` 返回 denied,Capacitor 就 `request.deny()` 整组 —— 所以表现是「摄像头和麦克风都没权限」,不是只缺一个。
  - **浏览器侧**:不是代码 bug,是环境 —— ①局域网 IP 的 http 页面不是安全上下文,浏览器直接摘掉 `mediaDevices`/按 `SecurityError` 拒绝;②宿主壳自己拦权限(微信/QQ/钉钉内置浏览器、Electron 壳、ZCode 内置浏览器都不弹授权)。此前这两种情况一个被笼统提示成「请用浏览器打开再试」、另一个和「用户点了拒绝」无法区分,文案指不到用户能做的事。
- 变更(前端):
  - `composables/useWebRTC.js`:新增 `mediaEnvError()` 拉流前预检(非安全上下文 → `insecure`,无 `getUserMedia` → `unsupported`);`SecurityError` 从 `denied` 里拆出来映成 `insecure`;失败时 `console.warn` 原始错误名(排查用)。
  - `stores/call.js`:`start()` 在发 invite **之前**做环境预检并记 `failReason`,失败不再让对端白响铃;通话 id 抽 `newCallId()`,`crypto.randomUUID` 缺失时回落时间戳+随机串(原先在建通话时直接抛错,连提示都没有)。
  - i18n 中英:新增 `chat.call.errInsecure`;`errDenied` 补两条可操作路径(浏览器地址栏站点设置 / 手机「设置 → 应用 → ihomy → 权限」);`errUnsupported` 去掉「请用浏览器打开」(App 内就是壳)。
- 变更(原生):
