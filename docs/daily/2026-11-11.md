**决策**:

- **只在前台跑**(App 启动/回前台/手动点击):后台写接口不能放进 `type=WIDGET` 只读白名单,另开写令牌通道超出本批安全面;与计划 §5.5 的 Worker 差异记入计划「实施差异」。
- **备份相册按 `backup_key = android:<设备标识>` 字符串键找**,不用计划原写的 `source_device_id`:该列语义是「设备目录映射来源 ID」(BIGINT),混用会搅乱映射相册口径;且字符串键换机/重装可重新生成、服务端只校验形状。
- 不刷积分;单张失败整轮停下(游标停在上一张成功处),下次续传;90 天窗口外走「全部备份」二次确认。

**表**(`schema.sql` + `migrations.sql` 末尾幂等迁移,表数仍 92):

```sql
content_photo       + checksum VARCHAR(64) NULL + UNIQUE KEY uk_family_checksum(family_id, checksum)
content_photo_album + backup_key VARCHAR(64) NULL + UNIQUE KEY uk_family_backup_key(family_id, backup_key)
```

存量全 NULL 不回填(MySQL 唯一索引允许多个 NULL)。

  - **标准通知模板,不做自定义 RemoteViews 卡片**:自定义布局在锁屏折叠态会被系统裁高,而锁屏正是本需求的落点;标题/正文在折叠态固定给出「什么天、几度、要不要带伞」,展开才给细节。视觉靠大图标(分档配色)+ 城市副标题 + 强调色。

  - **调度口径**:周期任务 + 首次延迟(不用精确闹钟、不做保活,与 `StaleCheckWorker` 同口径);发之前校验「与目标时刻相差 ≤180 分钟」,整夜关机/跨时区不会半夜补推;`last_weather_date` 保证一天一条,预览不占当天名额。
  - **必须已登录(WIDGET 令牌)**:服务端按家庭天气偏好位置解析坐标,无令牌会退化成服务器 IP 定位(机房城市),所以没令牌静默跳过;后端零改动(`/public/**` 本来就在 WIDGET 白名单内)。
  - 默认开(与后台未读同口径),关闭即撤当天残留通知;打开开关时顺手请求一次通知权限。
- 接口/表/路由变化:无新增接口/表/路由;新增只读调用 `GET /public/weather/detail`(WIDGET 令牌,已白名单)。
- 踩坑:
  - `NotificationChannel(IMPORTANCE_DEFAULT)` 不给 sound 时 `getSound()` 返回系统默认提示音 `content://settings/system/notification_sound`——「没设声音」≠ 静音,必须 `setSound(null, null)`;设备内用例第一次就抓到了。
  - 通道级 `setLockscreenVisibility(PUBLIC)` 在 Android 14 读回 `NO_OVERRIDE(-1000)`,通知自身 visibility 也可能被置 NO_OVERRIDE;锁屏展示最终由系统「锁屏显示全部/隐藏敏感内容」策略决定,别把这两个字段当硬保证。
  - `connectedDebugAndroidTest` 每次会卸载被测包,新装的 debug 包默认没有 POST_NOTIFICATIONS:用例里用 `UiAutomation.grantRuntimePermission` 自补,不依赖手工准备。
