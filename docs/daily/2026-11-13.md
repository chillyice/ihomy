## 12:55 Android 壳状态栏颜色跟随 App 主题(修「看不清字」)

- 现象:App 主题(暖居/光尘 × 晨/暮,autoMode 日出日落自动切)与系统深浅色常常相反,状态栏图标/底色不跟主题时就是「深图标压深底」,时间电量看不清。
- 根因(两条叠加):
  1. `frontend/src/native/statusBar.js` 只换图标深浅,且只认 `dark` class,底色完全没管。Capacitor 8 只在 WebView ≥140 且 `viewport-fit=cover` 时让页面真正延伸到底(内核 `SystemBars` 的 `insetsHandling=css`);老 WebView 走「给 WebView 加 padding」分支,那条露出的是 Android 主题的 `windowBackground`,跟**系统**深浅色走,与 App 主题无关。
  2. Capacitor 8 内核自带 `SystemBars`(`Bridge.registerAllPlugins` 里无条件注册),它记住自己的样式并在 configuration change(旋转/系统深色切换/字体缩放)时重放;legacy `@capacitor/status-bar` 不记忆,事件过后图标被盖回 `DEFAULT`(跟系统)。
- 改法(只动 `frontend/src/native/statusBar.js`):
  - 图标样式改走 `SystemBars.setStyle`(`@capacitor/core` 导出):配置变更后仍保留我们的选择,顺带把底部手势条图标一起管住。
  - 深浅判定不再只看 class,改读「状态栏后面那块颜色」= html 根底色(主站 `--color-bg`,独立页 kada/比特口袋/chillyice 各自接管 html 底色),按感知亮度 `0.299r+0.587g+0.114b` 除以 255 以 0.55 分界;解析不出来才退回 `dark` class。
  - 内容**没有**延伸到底(`--safe-area-inset-top` 为 0 或未注入)时,用 legacy `StatusBar.setBackgroundColor` 把那条刷成页面底色;延伸到底时保持透明(多刷一层会盖住页面顶部,首页筛选条就贴在最上面)。
  - 观察器加 `style` 属性(SystemBars 把安全区尺寸内联成 CSS 变量),80ms 去抖;`prefers-color-scheme` 变化与 `visibilitychange`(回前台)各补一次对齐。
