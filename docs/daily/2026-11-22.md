## 13:30 修复麻将补杠点了没反应（V14.13）

- 变更：平面/立体麻将的「补杠」按钮点后无效——碰出过的牌再摸到一张时按钮会亮，但点击后副露不变、按钮也不消失。根因是杠意图统一 `{ type:'gang', gangType:'angang'|'bugang' }`，而 `applySeatGang` 解构读了 `type`（恒为 `'gang'`），永远走暗杠分支；补杠暗手只有一张、凑不满四张直接 return，状态不变等待重试，点多少次都一样。暗杠恰好需要四张所以碰巧能用，且 AI 补杠同样空转会陷入「电脑思考中」死循环。
- 决策：修消费端不修生产端——三处意图构造（AI `Mahjong.vue:1008`/`Mahjong3d.vue:429`、玩家点击 `Mahjong.vue:1375`/`Mahjong3d.vue:663`）口径一致，只有两处解构错位，改为 `applySeatGang(seat, { kind, gangType: type })`（`Mahjong.vue:1150`、`Mahjong3d.vue:526`），一处一行。
- 验证：vite dev + 受控局面（碰北风 + 牌墙全北风）实测 2D/3D 补杠全链路——按钮自然亮起、点击后碰变明杠、岭上牌补位、选项清空、出牌继续；暗杠场景（四张同牌）回归通过；`eslint .` 0 告警、vitest 147 文件 1597 用例全绿、改动文件 prettier 通过。
- 踩坑：症状=按钮可见但点击无任何反应；真因=action 双字段（type=大类/gangType=细分）在唯一消费点解构错字段，暗杠分支「凑巧正确」掩盖了 bug；对策=新增「大类+细分」型 action 时，消费端解构必须用细分字段名（或构造端直接放 type），并用受控注入局面做端到端点击验证，不依赖随机对局。

## 13:51 修复浅色模式下麻将托管按钮看不清（V14.14）

- 变更：浅色（暖居晨色）模式下麻将房间局的「托管」键深褐字压在深色毡面浮层上几乎不可读。根因：暖居主题给次级键的底色是半透明的 `--color-line`（rgba(138,106,78,0.1)）配深褐字，落在对局区深绿毡面的 `.my-actions` 浮层上就是「深底深字」；`.ft-actions`（对抗牌局）在 `main.css:3048` 有白玻璃覆写，麻将操作条没有对应处理。
- 决策：在 `main.css` `.ft-actions` 块后为 `.page.game-shell .my-actions .el-button:not(primary/danger/link/text)` 补同一套白玻璃口径（常态/hover/禁用三档，warning 类型的托管开启态同样覆盖），主按钮（吃/碰/胡）保持品牌色。托管开/关两态此前在各主题下本就同色（光尘浅色两态都是浅米底），本次只修对比度不改两态区分，状态另有席位「托管」徽标与 `aria-pressed` 表达。
- 验证：vite dev + 麻将房间局实测——暖居浅色下托管键（开/关两态）均为白玻璃底白字，光尘浅色/深色临时切类复核一致；`eslint .` 0 告警、vitest 147 文件 1597 用例全绿、main.css prettier 通过。未跑 `npm run build`（纯 CSS 改动 + 并行会话在占用 dist）。
