## 11:30 每日早安保留随机云实现并加云层样式开关(V12.66)

- 背景:V12.59 的整屏程序化天气场景(云朵由代码画出)被 V12.62–V12.65 的天气照片版替换。按用户要求把那一版随机云找回来,与照片版并存,由设置页开关二选一。
- 变更:
  - 新增 `frontend/src/components/morning/MorningSceneRandom.vue`(取自 V12.59 的 `MorningScene.vue`,独立组件,scoped 样式与 `ms-*` 关键帧不与照片版冲突),整屏仍全部由代码生成:天空渐变、太阳/月亮与旋转光柱、程序化柔边云、雨/雪/雾/雷粒子、随风落叶。
  - 云是一朵一个 DOM 元素,每朵由 7–11 层随机位置/半径/透明度的 `radial-gradient` 叠成,再整体 `filter: blur()`,形状每次重建都不同;位置、尺寸、明暗、速度随机,相位均匀铺开,开屏不会全挤在一侧。
  - 补齐 V12.65 新增的「阴天」:`hasClouds`、落叶风力判定、日/夜云色、阴天密度与灰蓝天空都按阴天单独取值(比多云更沉,天顶灰蓝、地平线仅剩一条浅色)。
  - 风向沿用后端 `wind360`(来向)分解成屏幕分量,`--dx/--dy` 控制漂移距离,风力越大周期越短(210s → 8 级约 35s);南北风时给最小横向分量,避免云只上下挪。
  - `frontend/src/utils/morning.js` 新增 `cloudStyle`(`'photo' | 'random'`,默认 `'photo'`,常量 `MORNING_CLOUD_STYLES`),`normalizePrefs` 按白名单归一化,未知值回落图片云。
  - `MorningOverlay.vue` 用 `sceneComponent` computed 在 `MorningScene.vue` 与 `MorningSceneRandom.vue` 间切换,天气、昼夜、风向风力、降水强度、动效开关原样透传;设置页的「预览场景 / 实况时段 / 白天夜间」对两套渲染都生效。
  - 设置页「每日早安」新增「云层样式」:图片云、随机云两个开关互斥,关掉当前这个自动落到另一种(始终有一种生效),切换即写 localStorage。
  - i18n 新增 `morning.cloudStyle` / `cloudStylePhoto` / `cloudStyleRandom` / `cloudStyleHint`(中英对齐)。
- 决策:①随机云单独成组件而不是在照片场景里加分支:两套渲染的 DOM、CSS 变量与关键帧完全不同,分开写互不牵连,也便于以后单独替换;②开关用两个互斥 switch 而不是下拉:用户明确要「图片云开关和随机云开关」,关掉一个立即落到另一个,不会出现两种都关的空白背景;③默认仍为 `photo`,老用户升级后画面不变。
- 验证:

  - Chromium 实测(`localhost:5173`,admin 账号):随机云模式渲染 **11 朵 DIV 云**,`filter: blur(20.7px)`、单朵背景渐变约 1.8 kB、`--dx: -152vw`;预览阴天得到 `ms-cond-overcast` + 灰色天空渐变,夜间得到 `ms-night` + 深色天空;关闭天气动效后为 `ms-static`,云定格在行程中段(`matrix(1,0,0,1,-547.7,0)`、opacity 0.66)。

## 11:45 随机云改为只换云层并增加云的种类(V12.67)

- 背景:V12.66 把随机云做成了自带天空、太阳光柱与粒子的整屏场景,切到随机云会把天气照片和光尘光照一起换掉。用户要求**只换云**,底图与光照必须保持现状。
- 变更:
  - 新增 `frontend/src/components/morning/RandomClouds.vue`:只画云的一层,铺在 `MorningScene.vue` 的天气照片之上;天空、太阳/月亮、光束、雨雪雾、闪电、压暗层全部仍由 `MorningScene.vue` 负责。
  - 删除 `MorningSceneRandom.vue`;`MorningScene.vue` 新增 `cloudStyle` 属性,`photo` 走原来的云朵贴图,`random` 换成 `RandomClouds`;`MorningOverlay.vue` 恢复单一场景组件并透传 `prefs.cloudStyle`,不再切换整个场景组件。
  - 云的种类(按天气加权抽签,并用抽样袋循环,保证同一屏里不止一种):积云(向上鼓的云泡 + 暗云底)、积雨云(砧状云顶 + 立起来的云塔 + 更黑的云底)、层云 / 雨层云(极宽极扁的云幕)、卷云(细长丝缕)、高积云(成排小云团)、层积云(半透明云底 + 中等云泡)、雾堤(贴地雾带)。
  - 每种云有各自的高宽比、宽度区间、透明度与模糊比:积雨云高耸(比例 0.6–0.95、更不透明),卷云薄扁且模糊更小(细丝不能按宽云的距离糊),晴天只放 3–4 朵卷云/高积云点缀,阴雨雷才铺满天。
  - i18n 提示改为「两种云共用同一张天气照片与光照,只换云层」。
- 决策:①随机云只做「云层」而不是整屏场景:背景照片与光尘光照是 V12.62–V12.65 的成果,开关只该决定云怎么画;②抽样袋而非纯随机:纯权重随机偶尔会把整屏抽成同一种云,抽样袋保证每种天气的几种云都能出现;③晴天保留少量高空卷云,和照片版晴天的薄云观感一致。
- 验证:
  - `npx vitest run` **115 文件 1334 项全过**;`npm run lint` 0 error / 0 warning;改动文件 Prettier 通过;`npm run build` 通过。
  - 首屏 initial JS **48 chunk / 1611.87 kB / gzip 552.79 kB**;早安抚层懒加载 chunk `MorningOverlay` **26.34 kB**、CSS 从 18.24 kB 降到 **12.03 kB**(天空/太阳/粒子样式随旧场景删除)。
  - 真实浏览器实测(`localhost:5173`,admin):随机云模式照片仍加载(`cloud-day.webp`,`ms-loaded`)、太阳层 `ms-solar` 与日盘在,云是 **11 个 `.rc-cloud`**;图片云模式仍是 **3 个贴图 `.ms-cloud`** + 同一张照片 + 光照。
  - 用同一组件的无头 Chromium 截图核对形态:多云天出现卷云丝缕、高积云小团与积云团;雷雨出现 15–18 层的积雨云塔(高宽比最高 1.07)与扁平雨层云;晴天只有几缕卷云 + 太阳。截图仅作形状核对,实际观感以站内为准。
  - 无新增/变更接口、路由、表结构与 live SQL;`VERSION` 改 V12.67。

## 16:10 数独难度改为按人解技巧分层,专家档不再靠基础技巧推完(V12.68)

- 背景:四档难度过去只按挖空数量区分(EASY 40 / MEDIUM 48 / HARD 52 / EXPERT 56)。实测 EXPERT 有 10/20 只靠「唯一余数 + 唯一位置」就能推完、15/20 停在区块摒除以内,与 HARD 几乎没有区分度。
- 变更:
  - `frontend/src/utils/games/sudoku.js` 新增人解技巧评级 `ratePuzzle`(导出)与 `RATING_TIER`:1 唯一余数 / 2 唯一位置 / 3 区块摒除(宫线互斥) / 4 数对(裸对、隐对) / 5 X-Wing / 6 以上都推不动(需试探)。评级按阶梯逐级试用,取「解完用到的最高阶技巧」,推不完记为 6。
  - 评级与生成同口径:`extraGroups`(对角线/窗口)当额外单元、`regions`(不规则区)替代九宫、`parity`(奇偶标记)限制候选;候选掩码复用 `buildMasks`,给定数字本身冲突时按未解处理,不会把带冲突的盘面误判为已解。
  - 难度 → 评级区间(EASY/MEDIUM 1–2、HARD 3–4、EXPERT 5–6)。挖空后评级,命中区间即收;不中则同一终盘最多挖两次、之后换终盘重来(HARD 16 轮、EXPERT 18 轮),全不中留最接近区间的一档。
  - 挖空目标 HARD 52→56、EXPERT 56→58(随机挖空在唯一解约束下饱和于 22–24 个给定,再高自然停)。
  - 评级卡档只作用于「盘面数字即全部线索」的变体 CLASSIC / DIAGONAL / WINDOW / ODD_EVEN;GREATER / THERMO / KILLER / 连续·罗马 / 不连续 / 摩天楼 / 等差 / 回文 / JIGSAW 自带额外线索,仍按挖空数生成(EXPERT 挖空目标同样提至 58)。
- 决策:①按技巧评级而不是继续加挖空数:实测 56→62 挖空对技巧层级几乎无影响(唯一解上限约 24 个给定);②相邻档区间不重叠,HARD 不再混进专家题、EXPERT 也不会落回基础技巧;③评级做到 X-Wing 而不是二分「唯一位置能不能推完」,否则专家与困难仍贴在一起;④EXPERT 实测多为 6 档(需试探或超出 X-Wing 的链式技巧)——随机挖空几乎不产出恰好停在 X-Wing 的盘面,这是刻意的取舍。
- 验证:
  - `npx vitest run` **116 文件 1345 项全过**,其中 sudoku spec 51 项含新增 5 项(简单/中档 ≤2 档、困难 3–4 档且不越档、专家 ≥5 档且未解、冲突盘面不误判、变体口径与填满终盘恒为 1 档)。
  - Node 直测 30 个种子:EASY 全 1 档、MEDIUM 1–2 档、HARD 28/30 落 3–4 档(2 个兜底为 2 档)、EXPERT 1 个 5 档 + 29 个 6 档;生成耗时 HARD p50 52ms / p90 243ms / 最大 700ms,EXPERT p50 36ms / p90 192ms / 最大 383ms(与既有 KILLER 生成 1.8–2.5s 同量级,出题前有 loading 遮罩)。
  - 18 个变体 EXPERT 仍全部唯一解;评级收敛校验:168 个被评级器推完的盘面与终盘逐格一致(无错误消元),冲突盘面返回未解。
  - `npm run lint` 0 error / 0 warning,改动文件 `prettier --write` 通过;无新增/变更接口、路由、表结构与 live SQL;`VERSION` 改 V12.68。
