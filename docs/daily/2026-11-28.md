## 02:04 物品定位的房子可以共享给另一个家庭一起维护（V15.33）

- 房子可授权给自己所属的另一个家庭，对方成员可以一起增删改房间、家具与物品，编辑户型图；物品搜索与 AI 找物同样覆盖共享房子。房子本身仍归房主家庭，删除房子与调整共享只归房主家庭的家长；别人录入的私密物品只有作者本人能看到。
- 授权落新表 `family_house_share`（一行一条授权，撤销即物理删除）。共享单元是房子，房间/家具/物品继承房子权限；协作方写入的行仍记房主家庭，`created_by` 记实际操作人，户型图与食材统计不会分叉。未挂进房子的物品（家具库/散放）不参与共享。
- 权限判定唯一入口 `HouseShareService`，`ItemService` 全部读写改走请求期 `ViewerScope`；共享房子列表带 `shared`/`ownerFamilyName`，前端标「共享自 X」并隐藏删除入口；家长在房子列表点共享按钮选择目标家庭。接口 `GET/PUT/DELETE /item/house/{id}/shares`。
- 验证：后端新增 12 项单测通过（`HouseShareServiceTest`、`ItemServiceShareTest`），`related-tests` 后端 35 项通过。开发库建表后端到端冒烟 18 项断言全通过：授权/撤销、列表来源家庭、协作方建房间家具物品、取用食材、找不到时按不存在处理、共享房删不掉、AI 找物命中共享房物品、撤销后立即失联；随后清空冒烟数据。前端 ESLint、i18n 四道守门、构建通过。
- 本机开发库建表 SQL（生产上线随全文迁移执行，幂等）：

```sql
CREATE TABLE IF NOT EXISTS `family_house_share` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
  `house_id` BIGINT NOT NULL COMMENT '被共享的房子ID(family_house.id)',
  `grantee_family_id` BIGINT NOT NULL COMMENT '被共享家庭ID(sys_family_info.id)',
  `created_by` BIGINT DEFAULT NULL COMMENT '授权人ID',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '授权时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_house_grantee` (`house_id`, `grantee_family_id`),
  KEY `idx_grantee` (`grantee_family_id`, `house_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='房子协作共享表(物品定位)';
```

- 已知边界：AI 放物（自然语言登记位置）与助手找物工具仍只覆盖本家；食材到期提醒、统计仍按 `family_id` 只发房主家庭。生产把「和岳府」共享给「我爱我家」需发布后在房子列表操作，或对生产库补一条授权行。
