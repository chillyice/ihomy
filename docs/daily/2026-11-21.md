## 11:52 牌局回合计时器后台自愈:电脑不再「思考到死」(V14.5)

- 变更:用户报「单人游玩电脑玩家持续思考不动」。排查定盘两成因,六处 AI 入口统一加自愈:
  - 成因一(链条死亡):回合引擎零错误恢复——麻将 `runGameLoop` 是长 async 循环且调用处无 `.catch`,`resolveClaims` 内部 async IIFE 无 try/catch(异常=承诺永不 resolve=主循环永久挂起);四款牌局是 `drive → setTimeout(apply) → seatAction → drive(next)` 链,任一环抛异常整链熄火,轮次冻在 AI 座位。
  - 成因二(后台节流):AI 停顿与回合超时全压 `setTimeout`,页面隐藏(切标签/切 App/锁屏)时浏览器节流(桌面后台约 1 次/分钟、手机挂起),回前台前表现为电脑长思不落子;房间局 35s 交棒超时在房主端,房主切后台全桌跟着拖。
  - 单机与网络无关:AI 落子全在浏览器本地纯函数里算,只有房间局信令与终局领奖走网络。
  - 修复:新增 `utils/games/wakeTimers.js`(`createWakeTimers()`:schedule/cancel/destroy,登记 visibilitychange,回前台只补触发**已到期**句柄,未到期维持原计时;同一句柄只触发一次,补触发后原定时器再响不重复);麻将两版 `sleep/waitSeat/ask` 超时全部走登记表 + `runGameLoop(...).catch(兜底流局)` + `resolveClaims` IIFE `.catch(resolve(null))`;四款牌局 `aiTimer` 走登记表 + `runStep` 包裹 AI/真人回调(异常记日志后按电脑口径 `seatAction(seat, null)` 续跑,二次失败才中止);`useCardRoomPlay.waitAct` 35s 超时走登记表。
- 决策:
  - 兜底收尾用「流局」而不是猜状态续跑:麻将 catch 点可能在 apply 中途,状态一致性不可证,`endDraw` 是现成的安全收尾(结果页有流局文案);四款牌局 `seatAction(seat, null)` 走 AI 兜底路径,抛错源几乎都在改动前的纯函数判定段,续跑安全,守卫 `mySession/turn` 防过期双动。
  - 唤醒带 deadline 判定(回前台只触发 `now >= deadline` 的句柄):AI 停顿与 35s 超时共用同一语义——快速切走再切回(未到期)不提前触发,过了期限才立即补跑;own claim 超时(麻将碰杠胡 8s/10s)顺带获得同等待遇。
  - 不换 Web Worker / 服务器 AI:Worker 后台一样被冻结挂起且 AI 不吃 CPU,服务器跑 AI 给单机引入真网络依赖。方案二(到期时间戳 + 低频 tick 状态机)留待观察后再评估。
  - 各实例(6 视图 + useCardRoomPlay)独立 `createWakeTimers()` 并在卸载 `destroy()`,监听器不跨页泄漏;vitest 环境是 node,visibility 源可注入替身。
- 验证:prettier 全 unchanged;lint 0 error/0 warning;vitest **1579 passed / 142 文件**(基线 1572/141 + 新 spec 7 条);build ✓ 9.70s;入口闭包 **43 chunk / 1481.06KiB**(V14.4 基线 1481.00KiB,+0.06KiB 噪音,wakeTimers 只被懒加载游戏页引用不进入口)。后端未动,接口测试跳过。
- 踩坑:后台标签页 setTimeout 节流(桌面约 1 次/分钟、手机挂起)会拖长一切「定时器驱动的回合制」——机制与对策在 `utils/games/wakeTimers.js` 头注释;判别口诀:卡住时开 Console,有 `Uncaught (in promise)` = 引擎异常死链,无报错且刚切过后台 = 节流。
