## 平板判定:平板走 PC 端布局(V11.83)

- 背景:旧 `useDevice` 只有 `isMobile` 一档(UA 命中 Android/iPhone/iPad **或** 视口 ≤768px),平板被算进移动端,10 英寸屏上仍是单列 + 底部 Tab。
- 判定口径(`utils/platform.js` 新增纯函数 `classifyViewport` + 常量 `TABLET_MIN_SHORT_SIDE=600` / `NARROW_MAX_WIDTH=768`):
  - `tablet` = iPad(含 iPadOS 13+ 伪装 Mac + 多点触摸)**或** Android 且屏幕短边 ≥ 600 CSS px(= Android 官方 `smallestScreenWidthDp ≥ 600`);
  - `phone` = 非平板的 iPhone / Android;
  - `narrow` = 窗口宽 ≤ 768px(桌面拉窄、平板分屏);
  - `mobile`(是否用移动端布局)= `phone || narrow` → **平板且窗口够宽时为 `false`**,即走 PC 布局。
- 落地:`composables/useDevice.js` 三档导出 `isPhone` / `isTablet` / `isMobile`,启动算一次并监听 `matchMedia(768px)` change、`resize`、`orientationchange`(分屏/旋屏都会改 `innerWidth`)。10 处 `isMobile` 消费点无需改动,平板变 `false` 即自动拿到 PC 表现(`App.vue` 走 `AppSidebar` + `app-main`)。
- 不用 UA 的 `Mobile` 标记单独判平板:部分国产平板 UA 也带 Mobile(已写进用例),短边才是系统口径。**坑**:iPhone UA 里含「like Mac OS X」,必须先排除 iPhone/iPod 再按「Mac + 多点触摸」认 iPadOS,否则 iPhone 会被判成平板(有对应用例防线)。
- 行为变化:
  - 手机横屏(宽 800)不再掉回 PC 布局(旧逻辑只看宽度会给出 PC 侧栏);
  - 平板分屏压到 ≤768px 退回移动端布局,拖宽即恢复;
  - 平板走 PC 布局后 `ChatFloat` 浮窗不显示(`v-if="isMobile"`),聊天入口在侧栏「聊天」;日记本双页跨页按内容区宽度等比缩放(`spreadScale`),不溢出。

## 聊天室首屏一直转圈(浮窗从不拉历史)

- 现象:PC/iPad 打开聊天室(尤其从右下角浮窗进入),页面框架出来了,消息区一直转圈;WS 推来的消息能露在遮罩后面,但转圈不停,偶现。
- 根因:`ChatMessages` 的 `v-loading` 由 `chatStore.hydrated` 控制,`hydrated` 只在 `loadHistory()` 里置真;而 `loadHistory()` 只有 `/chat` 页 `onMounted` 调,**`ChatFloat` 展开从不调** → 只走浮窗这个入口时永远等不到历史,转圈停不下来(同会话点过一次 `/chat` 才恢复,故表现为偶现)。三个放大器:①`Promise.all` 让 `/chat/unread` 与 `/chat/history` 任一失败就整条 reject,`hydrated` 永不置真 → 永久转圈;②`Chat.vue` 先 `await loadHistory()` 再 `ensureConnected()`,历史慢/失败连 WS 都不建;③`loadHistory` 整体覆盖 `messages`,加载期间 WS 推到的新消息会被吞掉。
- 修法:
  - `utils/chatMsg.js` 新增纯函数 `mergeMessages(cached, incoming, keep)`:按 id 去重、升序、只留最近 `keep` 条(带 spec)。
  - `stores/chat.js` 的 `loadHistory({force})`:页面与浮窗同时挂载时共享同一个 Promise 只发一次请求;改 `Promise.allSettled` 分路处理,任一失败仍置 `hydrated=true` 走空态,不再永久转圈;结果与已有缓存按 id 合并而不是覆盖;新增世代号,登出后在途请求回来按旧世代丢弃(防串号)。
  - `ChatFloat.expand()` 展开即调 `loadHistory()`——浮窗与 `/chat` 页共用同一份缓存,谁先打开谁拉。
  - `Chat.vue` 改为先 `ensureConnected()` 再 `loadHistory({ force: true })`(不 await):历史慢不再拖住 WS,进页仍刷新一次。
  - `ChatMessages` 的 `loading` 改为 `!hydrated && !messages.length`:已经看到消息就不再盖遮罩。
- 排查事实(证明不在服务端):生产 `GET /api/chat/history` cost=37ms、`GET /api/chat/unread` cost=49ms;家庭 2 全表只有 12 条消息;`family_chat_message` 有 `idx_family(family_id,id)` 复合索引;聊天页 chunk 仅 968B/20KB。
- 接口/表/路由变化:无。
- 验证:`npx eslint .` 0 error 0 warning;改动文件 `prettier --write` 后无格式变更;`npx vitest run` **938 passed**(+3 = `mergeMessages` 用例);未跑 `npm run build`(并行会话正在出 Android 包,避免争 `dist/`);未做真机复验。
