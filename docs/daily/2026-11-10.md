## Android 客户端 P2 桌面卡片(V11.78)

- 变更:三张桌面卡片(今日概览 4×2 / 今日提醒 4×2 / 纪念日倒计时 2×2)+ WIDGET 令牌 + 原生数据层。
  - 后端:`type=WIDGET` 令牌(`JwtUtils.generateWidgetToken`,30 天 `jwt.widget-token-expire`,角色/家庭随令牌快照;`AuthService.refresh` 与 WALLPAPER 并列滑动续期不轮换;`POST /auth/widget-token` 签发,无 cookie——卡片不该拿到 /files 读权);`JwtAuthenticationFilter` 对 WIDGET 令牌做**最小权限白名单**:仅 GET 的 /schedule/**、/weather/**、/public/**、/anniversary/**、/reminder(list),白名单外与写接口直接 401,禁用账号按库校验失效。新增 `WidgetTokenTest` 5 例,后端全量 347 passed。
  - 原生(`top.ihomy.app.widget`,全部 Java,无 Kotlin/Compose):`WidgetPrefs`(令牌+快照缓存)、`WidgetRepository`(HttpURLConnection 零依赖拉 occurrences)、`WidgetWorker`(WorkManager 30 分钟周期 + 一次性触发,失败保旧缓存)、`Today/Reminder/CountdownWidgetProvider`(RemoteViews 三态:未登录/加载中/正常,深链 ihomy://)、`WidgetBridgePlugin`(setWidgetToken/clearWidgetToken/refreshWidgets,load 时注册周期任务)、`ApiBase`(与 .env.app 同步的原生基址常量)。依赖 `androidx.work:work-runtime:2.10.1`。
  - 前端:`src/native/widgets.js`(watch 登录态+家庭 id,防抖 POST /auth/widget-token → 原生桥下发;登出自动清)、`deeplink.js` 支持自定义 scheme 手动剥前缀、`native/index.js` 接线。
  - Manifest:3 个 card receiver + `ihomy://` VIEW intent-filter(桌面卡片深链入口)。
- 决策:①RemoteViews 直写替代 Glance(免 Kotlin+Compose 工具链,产物相同);②卡片 v1 只读(最小权限与「后台完成」冲突,点卡片进 App 完成);③今日概览精简为日期+最近 3 条(农历禁算/天气未读后补);④WIDGET 令牌角色家庭做签发时快照,续期时刷新(切家庭由 JS 监听重新签发下发)。
- 踩坑:①自定义 Capacitor 插件必须 `registerPlugin` 在 `super.onCreate` **之前**,晚了 JS 侧报 not implemented;②`ihomy://plan?date=` 这类自定义 scheme 别用 `new URL()` 解析——Chromium 把 `//plan` 塞进 pathname 导致路径丢失(冷启动深链实测修复为手动剥前缀);③ AnniversaryDTO.recurring 是 Integer 字典码不是字符串。
- 验收(模拟器 API 34):启动器组件选择器枚举出「ihomy 3 widgets」;令牌→Worker→缓存链路实测(SharedPreferences 快照含 occurrences 正确数据,纪念日 days=4 为服务端计算);`ihomy://plan?date=2026-11-12` 冷启动直达 `/plan?date=2026-11-12`;白名单外请求 401(单测);最终生产配置包回归通过、无崩溃。卡片视觉摆位与截图留真机 30 秒手动步骤。开发库测试数据(reminder 42 / anniversary 106)已清理。
- 注意:卡片数据流依赖后端 `/auth/widget-token` + `/schedule/occurrences`,**生产需部署 V11.77+ 后端后卡片才有数据**(未部署时卡片显示「正在加载…」不报错)。
