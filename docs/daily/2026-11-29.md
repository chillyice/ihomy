## 01:16 家圃时光后端 MVP 进 ihomy（V15.50）

- `com.ihomy.garden` 落地最小闭环：窗台便签状态、能力协商、花园全景、窗台影子快照、每日拆信（一天一封、可补 3 天）、备盆/播种/浇水/晒太阳/施肥/收获、五层任务与领奖、家庭市集（挂单/买入/下架 + 系统收购与卖种子包）、批量播种与批量照料、世界阶段推进、技能树加点与重置，共 25 个 `/garden` 接口。除 `GET /garden/meta`（能力协商）外都要登录。
- 数据落在独立的 `games` 库 11 张 `garden_*` 表（跨库访问：实体 `@TableName("games.garden_*")`，Mapper XML 写全限定表名），不动 ihomy 主库任何表；建表脚本不在本仓，唯一来源是独立游戏仓 `home_garden_moments/db/schema.sql`（含 DROP，只用于空库）与 `migrations.sql`（幂等）。业务账号 `ihomy` 需要 `games` 库的 DML 授权，否则接口一律报错。
- 内容与数值走 `resources/content/garden/{crops,mail,skills,solar_terms,tasks,venues}.json`；判定在 `garden/core` 纯函数（生长、节气、天气事件、周挑战、来信、猫草），整数毫秒/基点、无随机；写操作带 `Idempotency-Key`，同键重放回首次结果。
- 首页便签入口仍只在 DEV、本机 localhost 或 `?gardenPreview=1` 时挂载（`App.vue` 的 `devGardenReview || localGardenReview`），生产游客与成员默认看不到，正式开放条件与开关待定。
- `doc-drift-check.sh` 第 3 项改为「带库名前缀的实体不参与本库比对」，跨库实体单独打一行说明——家圃 9 个 `games.garden_*` 实体的建表脚本在游戏仓，拿 ihomy 的 `schema.sql` 比对必然误报。
- 生产建库（空库初始化，`schema.sql` 之后执行授权）：
  本机开发库与游戏仓 `db/schema.sql` 结构已比对，118 个列完全一致。

```sql

-- 然后导入 home_garden_moments/db/schema.sql（含 DROP TABLE，只对空库执行一次）

GRANT SELECT, INSERT, UPDATE, DELETE ON `games`.* TO 'ihomy'@'%';
FLUSH PRIVILEGES;
```

## 02:05 安卓壳冷启动与启动页无缝交接（V15.50）

- 冷启动不再「纸面启动页 → 白屏 → 整页突然出现」。`MainActivity` 在 `super.onCreate` 前 `SplashScreen.installSplashScreen`，启动页保留到业务首帧真正上屏；`App.vue` 在路由就绪、首屏画完后的第二个 `requestAnimationFrame` 置 `window.__ihomyBootPainted = true`，壳每 60ms 轮询，最多等 8 秒（前端起不来宁可露一次白页，也不一直停在启动页）。撤启动页前的空白由 WebView 自绘底色兜住，取 `logo_splash_canvas`（跟深浅色走）。
- 启动窗口与主任务交接只保留一次转场：`MainActivity` 主题换 `IhomyMain`，与 `AppTheme.NoActionBar` 一起把 `windowAnimationStyle` 设为四个 `activity*Animation = @null`；`LauncherActivity` 加 `FLAG_ACTIVITY_NO_ANIMATION`，并同时走 `ActivityOptions.makeCustomAnimation(0,0)` 与 `overridePendingTransition(0,0)`（部分 ROM 只认其中一条）。否则华为/鸿蒙会把两个窗口当成任务切换画成横向滑入，看起来像换了个应用。
- 验证：前端 lint 0 error/0 warning，`App.vue` 过 Prettier（工作区 CRLF 已改回 LF），4 个守门 spec 10 项、全量 177 个文件 1951 项通过。壳内前端打进 APK，本条只发 dist 不会生效，随本次 APK 发布。
