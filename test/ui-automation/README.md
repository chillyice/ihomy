# UI 自动化(ui-automation)

本目录存放 **UI 黑盒自验证**的方法说明与**截图证据**。当前 UI 自动化以「内置浏览器(IAB)黑盒 GUI + 截图管线」方式执行,用于脑图等前端交互模块的验收;证据以截图形式落盘归档。

## 目录

```
ui-automation/
├── README.md                 # 本文件:方法 + 证据规范
└── gui-test-screenshots/     # 脑图 GUI 自验证截图证据(23 张,MM-101~133)
```

## 截图证据规范

- **命名**:`<模块前缀>-<用例号>_<要点>.png`,如 `m117_bold_applied.png`(模块=脑图,用例 MM-117,要点=加粗已应用)。
- **对应关系**:每张截图对应 `cases/功能测试用例.md` §32 的一条 MM 用例,用例号见文件名前缀。
- **入库要求**:证据截图是位图资产,归档即可,不需压缩(非 `frontend/src/assets` 装饰性资源,不入前端 bundle)。

## 用例与证据对照

| 用例段 | 用例号 | 证据 |
|--------|--------|------|
| 脑图 MM | MM-101~133 | `gui-test-screenshots/m1xx_*.png`(22 项通过 + 6 项留人工,详见 `cases/功能测试用例.md` §32.1) |

> 完整执行结果(API 15/15、GUI 22 过 / 6 留人工)与发现缺陷(BUG-5/6/7/8)见 `cases/功能测试用例.md` §32.1 及 `docs/变更归档.md`「脑图第四批」小节。

## 方法说明(如何做 UI 自动化)

1. **黑盒 GUI 驱动**:内置浏览器(IAB)1280×720 视口 + 截图管线,模拟真实点击/输入/滚动;无法覆盖的场景(原生文件选择框、原生确认框、下载文件内容核验、全屏 API、中文 IME 合成输入、beforeunload 原生框)一律**留人工点验**,在结果中显式标注,不在工具上死磕。
2. **API 先行**:可走接口的断言先用 API 自动化覆盖(见 `automation/`),GUI 只验证「渲染/交互可见效果」。
3. **证据必留**:每条 GUI 用例通过/失败都保留截图,文件名标注用例号,方便回归比对。

## 约定

- 新增模块的 GUI 截图,按模块建子目录或沿用 `<模块前缀>-<用例号>_<要点>.png` 命名,并在本 README「用例与证据对照」登记。
- 截图随用例走:用例改动/删除时同步增删对应证据。
