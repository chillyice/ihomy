# 测试结果 / 执行记录(results)

本目录归档**测试结果与执行记录**:一次测试活动**逐条用例的执行明细**(通过/失败/阻塞/留人工)与**缺陷跟踪**。与 `reports/` 分离——结果=明细与证据,报告=结论。

## 命名规范

```
<日期>_<范围>_执行结果.md    例: 2026-09-19_脑图回归_执行结果.md
```

## 执行结果模板

```markdown
# <范围>执行结果

> 版本 / 日期 / 测试人 / 环境 / 账号(家庭)

## 汇总
| 总数 | 通过 | 失败 | 阻塞 | 留人工 | 通过率 |
|------|------|------|------|--------|--------|

## 逐条结果
| 用例ID | 标题 | 结果(通过/失败/阻塞/留人工) | 备注/证据 |
|--------|------|------------------------------|-----------|
| MM-101 | xxx | 通过 | 截图 m101_list.png |

## 缺陷跟踪
| # | 严重度 | 缺陷 | 关联用例 | 状态 | 修复记录(指向 docs/变更归档.md) |
|---|--------|------|----------|------|-------------------------------|

## 留人工项与原因
| 用例ID | 原因 | 建议人工步骤 |
|--------|------|--------------|
```

## 约定

- 用例级的执行记录也可直接回填到 `cases/功能测试用例.md` 对应模块的「执行记录」小节(沿用 §32.1 先例:API 15/15、GUI 22 过 / 6 留人工)。
- **缺陷状态**用统一词:`待修复` / `已修复` / `留人工` / `无需修复`;修复后在同文档补「修复记录」指向 `docs/变更归档.md` 对应小节。
- 截图/日志等证据链接到本目录或 `ui-automation/gui-test-screenshots/`,不重复拷贝大文件。
