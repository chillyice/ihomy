# 测试报告(reports)

本目录归档**测试报告**:一次测试活动(版本发布前验收、功能域回归、专项测试)的**结论性文档**。报告回答「结论是什么、测了什么、发现了什么缺陷、修没修、能不能发」,与 `results/` 的执行明细分离(报告=结论,结果=明细)。

## 命名规范

```
<日期>_<范围>_测试报告.md    例: 2026-09-19_脑图回归_测试报告.md
```

## 报告模板

```markdown
# <范围>测试报告

> 版本:V9.xx / 分支:xxx ｜ 日期:YYYY-MM-DD ｜ 测试人:xxx ｜ 环境:本地 8080 / dev 库 / 账号 xxx

## 1. 结论
一句话结论 + 是否可发布(可发布 / 有条件发布(列条件) / 不可发布)。

## 2. 范围与用例
- 覆盖模块:xxx(对应 cases/功能测试用例.md §N)
- 执行用例:总数 X,通过 Y,失败 Z,阻塞/留人工 W
- 未覆盖/未执行:xxx(及原因)

## 3. 缺陷清单
| # | 严重度 | 缺陷描述 | 关联用例 | 状态(已修复/待修复/留人工/无需修复) |
|---|--------|----------|----------|--------------------------------------|
| 1 | P0 | xxx | MM-xxx | 已修复 |

## 4. 关键发现
(高风险点/性能/兼容性/易漏点的验证结论,可引用 cases/功能测试用例.md §34)

## 5. 回归说明
(修复项是否回归通过;遗留项与影响)

## 6. 附件
(执行明细见 results/<同日期>_<范围>_执行结果.md;截图证据见 ui-automation/gui-test-screenshots/)
```

## 约定

- 历史报告曾以「测试报告缺陷修复」小节形式内嵌在 `docs/变更归档.md`(如工具箱脑图 V9.19/V9.30),自本目录建立后,**新报告落 `reports/`**,同时可在 `docs/变更归档.md` 留一行索引。
- 报告写结论与缺陷,不堆用例逐条明细;明细放 `results/`。
