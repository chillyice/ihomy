# ihomy 测试资产目录

> 本目录聚合 ihomy 项目**全部测试相关资产**:测试用例、接口自动化脚本、UI 自动化脚本与截图证据、测试报告、测试结果/执行记录。分类清晰、按域归档,是测试、验收、回归的单一入口。
>
> 由原分散位置迁入:全站用例原在 `docs/功能测试用例.md`,脑图 GUI 截图原在 `test/gui-test-screenshots/`(迁移见根目录 `docs/变更归档.md` 与本文档「维护规矩」)。

## 目录结构

```
test/
├── README.md                # 本文件:测试资产总览、导航、约定
├── cases/                   # ① 测试用例(唯一权威版)
│   └── 功能测试用例.md       #   全站 341 条用例 + 执行记录 + 风险清单 + 附录统计
├── automation/              # ② 接口自动化脚本(API)
│   ├── README.md            #   运行方式、依赖、约定
│   └── smoke_login.py       #   登录冒烟脚本(标准库,可本地/CI 重复执行)
├── ui-automation/           # ③ UI 自动化(黑盒 GUI + 截图证据)
│   ├── README.md            #   GUI 自动化方法、截图证据规范
│   └── gui-test-screenshots/ #  脑图 GUI 自验证截图证据(23 张,MM-101~133)
├── reports/                 # ④ 测试报告(归档)
│   └── README.md            #   报告模板 + 归档命名规范
└── results/                 # ⑤ 测试结果 / 执行记录 / 缺陷跟踪
    └── README.md            #   结果归档规范 + 缺陷跟踪约定
```

## 各分类说明

| 分类 | 内容 | 面向 |
|------|------|------|
| `cases/` | 全站功能测试用例(唯一权威版,含执行记录与风险清单) | 测试、验收、回归 |
| `automation/` | 可重复执行的接口自动化脚本(登录冒烟等,标准库无第三方依赖) | 本地自测、CI、回归 |
| `ui-automation/` | UI 黑盒自验证脚本/方法说明 + 截图证据 | 脑图等前端交互验收 |
| `reports/` | 每次测试活动的**报告**归档(结论 + 缺陷 + 修复) | 发布前验收、复盘 |
| `results/` | 每次测试活动的**结果/执行记录**归档(用例逐条结果、缺陷清单) | 回归追踪、审计 |

## 快速导航

- **要跑全站用例**:看 `cases/功能测试用例.md`——§0.1 测试环境与账号矩阵 → §1~33 各域用例 → §34 风险点与易漏点 → 附录 A 统计。
- **要跑登录冒烟**:`automation/smoke_login.py`(用法见 `automation/README.md`)。
- **要执行脑图 GUI 回归**:对照 `cases/功能测试用例.md` §32 的 MM-101~133,证据截图规范见 `ui-automation/README.md`。
- **要写测试报告/结果**:模板见 `reports/README.md`、`results/README.md`。

## 与 CI / 构建验证的关系

- **CI**(`.github/workflows/ci.yml`):每次 push/PR 自动做「前后端构建 + compose 起库导 schema + 后端启动 + captcha/login 冒烟」——这是仓库自给自足的最低门禁。`automation/smoke_login.py` 即从 CI 冒烟逻辑提取的**可本地重复执行版**,两者断言等价。
- **构建验证基线**(`AGENTS.md` §验证基线):后端 `mvnw clean compile`、前端 `npm run build`(入口 chunk 体积)、接口测试(外部 autotest_framework 项目,不在本仓库)。

## 维护规矩

1. **用例唯一权威版在 `cases/功能测试用例.md`**:新增/修改用例直接改该文件,不要另起用例文件;新域用例接续既有「§N 模块」章节,并在「附录 A 用例统计」同步数字。
2. **报告与结果分离归档**:一次测试活动 = 一份报告(`reports/`)+ 一份结果(`results/`),按日期命名(模板见各分类 README)。用例级执行记录也可直接回填到 `cases/功能测试用例.md` 对应模块的「执行记录」小节(沿用 §32.1 先例)。
3. **截图证据归 `ui-automation/gui-test-screenshots/`**:命名沿用既有 `MM-XXX_描述.png` 风格(模块-用例号-要点)。
4. **历史归档不回溯改写**:`docs/需求设计说明书.md`/`docs/变更归档.md` 中指向 `docs/功能测试用例.md` 与 `scripts/test_mm_api.py` 的**历史修订记录保持原样**(是当时的真实路径,属归档事实);本目录迁移后的最新路径以本 README 与 `AGENTS.md` 文档清单为准。
5. **敏感数据不入库**:测试账号密码、生产凭证一律不写进本目录文件;开发环境固定验证码 `qwer`、dev 账号见本地《新人上手指南》(不入 git)。
